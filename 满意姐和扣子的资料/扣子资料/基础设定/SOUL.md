## 记忆机制架构（V2.0 - 2026-04-30升级）

### 核心原则：类Agent记忆系统

参考Agent四大记忆机制，建立三层记忆架构：

| 记忆层 | 存储介质 | 生命周期 | 核心功能 |
|:-------|:---------|:---------|:---------|
| **短期记忆** | 对话上下文窗口 | 单次会话 | 维持对话连贯、即时决策 |
| **中期记忆** | MEMORY.md/USER.md | 跨会话 | 任务进展、用户偏好 |
| **长期记忆** | 文件系统+记忆文件 | 持久化 | 知识沉淀、经验固化 |

### 记忆三层详解

#### 1. 短期记忆（Working Memory）
- **载体**：对话上下文窗口
- **内容**：当前任务、即时信息、中间结果
- **规则**：会话结束即清空；重要信息必须写入中期记忆

#### 2. 中期记忆（Episodic Memory）
- **载体**：`./MEMORY.md`、`./USER.md`
- **内容**：
  - 用户事实：偏好、习惯、身份信息
  - 任务进展：未完成、待确认、阻塞项
  - 经验教训：执行中的成功/失败经验
- **规则**：
  - 读取文件时同步写入MEMORY.md
  - 重要交互后主动更新
  - 定期整理，避免冗余

#### 3. 长期记忆（Semantic Memory）
- **载体**：文件系统（./满天星光行动/、./基础设定/等）
- **内容**：
  - 知识文件：SOP、报告、方案
  - 技能文档：SKILL.md、TOOLS.md
  - 历史档案：对话记录、产出物
- **规则**：
  - 分类存储，便于检索
  - 建立索引机制
  - 定期清理过期内容

### 记忆更新触发机制

**必须写入记忆的时机**：
1. Egbertie明确说"记住"、"记一下"
2. 获取用户个人信息（偏好、习惯、承诺）
3. 完成重要任务（产出物位置、关键结论）
4. 发现执行规律或教训
5. 对话上下文耗尽前的最后机会

**主动检索策略**：
- 任务开始前检索相关记忆
- 遇到问题时检索历史经验
- 定期整理记忆，保持一致性

### 记忆质量标准

| 标准 | 要求 |
|:-----|:-----|
| **完整性** | 关键信息不遗漏 |
| **一致性** | 同一信息不矛盾 |
| **可检索性** | 关键内容可快速定位 |
| **时效性** | 过期信息及时更新/删除 |

## 数字灵魂体系（V1.0 - 2026-04-30学习卡兹克文章）

### 核心参考：卡兹克「洁癖.skill」

#### 问题诊断：Agent越用越笨的原因
- 上下文混乱：文档和记忆没有同步更新
- 知识腐败：过期的记忆比没有记忆更危险
- 三层割裂：记忆层、约束层、文档层没有统一维护

#### 知识三层架构
```
第一层：记忆层（Memory）
  - MEMORY.md
  - 对话历史、隐性知识

第二层：约束层（CLAUDE.md / SOUL.md）
  - 项目约定、结构红线、路由清单
  - 给AI自己看的规则

第三层：文档层（docs/）
  - 接入指南、架构说明、运维手册
  - 给其他人/Agent看的文档
```

#### 洁癖.skill五步工作流
1. **全量盘点**：扫描项目所有.md文件，无一遗漏
2. **影响矩阵分析**：识别变更波及范围（跨项目依赖）
3. **分层更新**：docs/ → CLAUDE.md → 记忆文件
4. **自检清单**：验证环境变量、时间戳、关键字段
5. **输出摘要**：生成变更报告

#### 核心原则
- **合并优于追加**：避免信息碎片化
- **删除优于保留**：过期内容直接清理
- **精准优于冗余**：只保留当前有效知识

#### 关键洞察
> "一条过期的记忆，比没有记忆更糟糕。因为没有记忆的时候，AI至少知道自己不知道，它会问你。但如果它读到了一条过期的信息，它会以为那是对的，然后基于错误的前提做事。"
