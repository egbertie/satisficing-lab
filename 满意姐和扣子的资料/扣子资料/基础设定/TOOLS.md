## ⚠️ 最高优先级规则

### 1. 编号决策规则
**触发条件**：Egbertie要求决策时，必须提供编号选项（A1/A2/A3...）
**正确示例**：
```
建议采取以下方案：
- A1: 直接执行...
- A2: 先调研再执行...
- A3: 派蓝军执行...
推荐A2，因为...
```
**禁止**：让用户做开放式决策或直接执行

### 2. 任务闭环报告机制
**触发时机**：任何任务完成后
**强制执行步骤**：
1. ✅ 任务完成
2. ✅ 生成报告（存对应功能文件夹）
3. ✅ 同步到 `./对话/YYYY-MM-DD/` 和 `./Z-Egbertie专属/对应分类/`
4. ✅ 用 computer:// 协议发送链接给Egbertie
5. ✅ 同步关键学习内容到MEMORY.md，确保后续传承
**禁止**：只说"已完成"不给链接或不同步文件

### 3. 报告命名与归集规范
**触发时机**：任何报告产出时
**命名格式**：`YYYY-MM-DD-HHMM-报告名称.md`
**存放要求**：立即归集到对应文件夹，同步到对话和行动文件夹
**禁止**：产出后散落或延迟整理

### 4. 对话文件夹管理规则
**位置**：根目录一级文件夹 `./对话/`（独立于任何行动）
**日期归档**：按 `YYYY-MM-DD` 创建子文件夹
**禁止**：将对话文件夹放在行动目录下或错误命名

### 5. 敬畏·不挑·完整原则
**触发场景**：Egbertie给出任何任务/资料时
**核心禁止**：问"要不要继续/下载"、挑内容、用自己的判断代替主人的判断
**正确姿态**：完整执行，逐字逐句，不漏

### 6. 学习传承机制
**触发场景**：任何新任务开始前
**核心要求**：必须检查前一天的关键学习内容和决策，确保知识传承
**强制执行步骤**：
1. ✅ 读取前一天的核心记忆文件（MEMORY.md）
2. ✅ 检查是否有需要传承的关键信息
3. ✅ 在新任务执行中体现前一天的学习成果
**禁止**：完全忽略前一天的关键内容，导致知识断链

## 🛠️ 核心工具使用技巧

### search_web工具
- 精准关键词（1-6个词）效果最佳，结合场景使用领域术语
- 示例："满意解研究所 创始人 满意姐 AI"

### sessions_send工具
- **注意事项**：必须使用用户coze站内的session_id（如"7630312955229290792"），而非邮箱地址或带前缀的邮箱格式
- **失败案例**：使用"satisfy@coze.email"或"邮箱-satisfy@coze.email"会导致"session id not found"错误
- **正确示例**：`sessions_send --session_id "7630312955229290792" --message "内容"`
```bash
# 下载
lark-cli drive +download --file-token "TOKEN" --output "路径" --overwrite
# 获取文档（仅支持新版docx）
lark-cli docs +fetch --doc "文档token或URL" --format pretty
# 创建文档
lark-cli docs +create --title "标题" --markdown "$CONTENT" --wiki-space "space_id"
```
**注意事项**：
- 批量下载用串行方式，5-10个/批次，批次间`sleep 2`
- 旧版文档需转换为新版或用其他方式获取

### 本地文件操作工具
- **read_file**：大文件分批读取（`offset=0 limit=200`），先确认路径存在
- **write_file**：多层目录先`mkdir -p`创建，重复内容用append模式
- **bash**：快速查找`find . -type f -name "*.md" | head -100`
- **目录结构展示**：如果没有`tree`命令，可用`find ./目标目录 -print | sed -e 's;[^/]*/;|____;g;s;____|; |;g'`生成树形结构
- **文件数量统计**：用`find ./目标目录 -type f | wc -l`统计总文件数，用循环统计每个文件夹下的文件数：
  ```bash
  for dir in $(find ./目标目录 -type d); do
      count=$(find "$dir" -type f | wc -l)
      echo "$dir: $count 个文件"
  done
  ```
- **外部文件检查**：用`find . -name "*关键词*" -type f | grep -v "./目标目录" | grep -v "./\."`查找不在目标目录内的相关文件
- **file_to_url**：仅支持本地HTML文件转换为在线URL

### 微信公众号文章读取 ⭐ 2026-04-30突破
**问题背景**：fetch_web、playwright-stealth等工具无法直接访问微信公众号文章（反爬太强）

**解决方案**：使用mptext API（无需任何验证）
```bash
# 核心命令
curl -s "https://down.mptext.top/api/public/v1/download?url=<URL_ENCODED>&format=markdown"

# 完整流程
# 1. URL编码
ENCODED_URL=$(python3 -c "import urllib.parse; print(urllib.parse.quote('https://mp.weixin.qq.com/s/xxx'))")

# 2. 请求API
curl -s "https://down.mptext.top/api/public/v1/download?url=${ENCODED_URL}&format=markdown"

# 3. 保存结果
curl -s "https://down.mptext.top/api/public/v1/download?url=${ENCODED_URL}&format=markdown" -o article.md
```

**注意事项**：
- format参数支持：markdown、html、text
- 无需登录验证，直接可用
- 如果原链接失效，可搜索文章标题在头条/搜狐找转载版本

### 批量文件重命名技巧
扫描→整改清单→`mv`批量重命名→验证→补充遗漏→报告。文件名含空格用双引号，可用Python脚本精确处理。

## 🔧 lark-cli 使用注意事项（2026-04-30更新）

### 环境冲突解决
- **pip版lark-cli会干扰npm版**：若执行`lark-cli`报"official distributed via npm"警告，需先卸载pip版：
  ```bash
  pip uninstall lark-cli -y
  ```
- 卸载后`/usr/local/bin/lark-cli`即可正常使用

### 文档获取（docs +fetch）⚠️ 关键
- **必须使用`--doc`参数**，不是`--url`参数
  ```bash
  # ✅ 正确
  lark-cli docs +fetch --doc "CWTuwKNvdirdQ6kkYNkcnnsWnRc" --format pretty
  # ❌ 错误
  lark-cli docs +fetch --url "https://xxx.feishu.cn/wiki/CWTuwKNvdirdQ6kkYNkcnnsWnRc"
  ```
- **Token提取方法**：从飞书URL中提取最后一部分
  - `https://xxx.feishu.cn/wiki/XXXXXXX` → token = `XXXXXXX`
  - `https://xxx.feishu.cn/docx/XXXXXXX` → token = `XXXXXXX`

### 字段创建（+field-create）
- **必须使用`--json`参数**，不支持`--field-name`等单独flag
  ```bash
  # ✅ 正确
  lark-cli base +field-create --base-token "TOKEN" --table-id "tblXXX" --json '{"name":"姓名","type":"text"}'
  # ❌ 错误
  lark-cli base +field-create --base-token "TOKEN" --table-id "tblXXX" --field-name "姓名" --type "text"
  ```
- **single_select字段**：不支持`property`键，会报"Unrecognized key(s) in object: 'property'"。选项需另外添加
- **API限流**：`800004135`错误码表示"method limited"，需等待后重试

### 多维表格创建（+base-create）
- 使用`--name`参数（非`--title`）
- 新建的base会包含一个默认空表（5-10条空记录），完成后需考虑清理

### 文档创建（docs +create）
- 已标记deprecated，但仍可用
- 使用`--title`和`--markdown`参数

### 日历操作（calendar events）⚠️ 2026-05-02踩坑
- **event_id格式**：飞书日历的event_id**不是UUID格式**（`xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`无效），通常是类似`xxxxxxxx_0`的格式
- **命令格式**：path参数用`--params`（JSON），body参数用`--data`（JSON）
  ```bash
  # 获取日程
  lark-cli calendar events get --params '{"calendar_id":"primary","event_id":"实际event_id"}' --as user
  # 更新日程
  lark-cli calendar events patch --params '{"calendar_id":"primary","event_id":"实际event_id"}' --data '{"description":"新描述"}' --as user
  # 搜索日程
  lark-cli calendar events search --params '{"calendar_id":"primary"}' --data '{"query":"关键词"}' --as user
  # 查看日程概览
  lark-cli calendar +agenda --start "2025-05-01T00:00:00+08:00" --end "2025-05-31T23:59:59+08:00" --as user --format pretty
  ```
- **主日历ID**：`feishu.cn_gwwGWuLklXC0QPcIXJwmXc@group.calendar.feishu.cn`
- **注意**：搜索结果可能为空（日程未同步或关键词不匹配），`primary`可替代完整calendar_id

### 多维表格记录操作（+record-upsert）
- **⚠️ 已知bug**：`+record-upsert`存在无法解析的错误
- **修复方案**：使用飞书原生API绕过：
  - 写入：`lark-cli api POST /open-apis/bitable/v1/apps/APP_TOKEN/tables/TABLE_ID/records --data '{"fields":{"字段名":"值"}}'`
  - 更新：`lark-cli api PUT .../records/RECORD_ID --data '{"fields":{"字段名":"更新值"}}'`

## 🎯 "双经济"快捷口令执行规则
**核心原则**：质量>速度，Token消耗最小化，效益最大化

### 零Token场景优先级
1. **P0**：本地文件操作（read_file/write_file/edit_file/bash）
2. **P1**：内置工具（memory_search/file_to_url）
3. **P2**：Skill工具（docx/excel_master/pdf等）
4. **P3**：优化搜索（1-6个关键词）
5. **P4**：标准对话
6. **P5**：复杂多轮对话

### 执行策略
- 技能优先：用标准化Skill，不重复造轮子
- Token最小化：搜索关键词1-6个、对话简洁、大文件分批读
- 先查记忆再行动：避免重复劳动和Token浪费

## 双经济原则（2026-05-07 Egbertie强调）
- **核心**：有价值的消耗才是投资，无价值的消耗是浪费
- **执行标准**：凡是重复性、批量性操作，必须写脚本一次执行，禁止手动逐个操作浪费token
- **适用场景**：文件上传/下载、批量搜索、重复性日程任务、数据整理等
- **反面案例**：逐个文件用lark-cli上传（10450个文件一个个传=灾难级浪费）
- **正面案例**：写bash脚本批量上传，sub-agent一次执行
