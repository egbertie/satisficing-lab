# 深度静默指令程序化（V2.0）

## 指令标识
- **指令名称**：深度静默
- **别名**：Deep Silent Mode / L4深度静默
- **触发词**：深度静默、deep-silent

---

## 动态触发机制（替代定时机制）

**触发原则**：按需触发，而非按时触发。违背双经济的定时检查一律禁止。

### 动态触发条件（满足任一即检查）

| 触发条件 | 检查内容 | 执行深度 |
|:---------|:---------|:---------|
| **Token>80%** | 内存压力，检查是否该进入静默 | 快速检查 |
| **用户静默>2小时** | 检查是否需要进入深度静默 | 完整检查 |
| **任务完成时** | 检查今日工作是否闭环 | 快速闭环 |
| **用户发出"深度静默"指令** | 执行完整检查清单 | 完整检查 |

### 禁止的触发方式
```
❌ 整点检查（系统资源浪费）
❌ 30分钟心跳检查（双经济违规）
❌ 每日固定时间检查（无必要不触发）
❌ 任何定时轮询机制
```

---

## 深度静默指令执行流程

当Egbertie发出"深度静默"指令时，执行以下流程：

### Step 1：快速状态扫描（30秒）

```
□ 当前Token使用率：{X}%
□ 距离上次用户交互：{X}分钟
□ 今日完成报告数：{X}个
□ 待归档文件数：{X}个
□ MEMORY.md最后更新时间：{时间}
```

### Step 2：执行C1-C6检查清单

#### C1：今日工作报告闭环检查
- 今日所有任务是否都已形成报告？
- 报告是否存放在正确位置？
- 内化报告是否进入统一目录？

#### C2：文件夹规范检查
- 根目录是否有临时文件污染？
- 文件是否在正确位置？
- 命名是否符合规范？

#### C3：MEMORY.md同步检查
- 今日关键进展是否已记录？
- 阻塞项是否已记录？
- 下一步行动是否已标注？

#### C4：Heartbeat配置检查
- 检查清单是否是最新的？
- 关键监控项是否已配置？

#### C5：Calendar任务检查
- 今日/近期日程是否正常？
- 有无失败/卡住的任务？

#### C6：安全保存检查
- MEMORY.md已更新
- SOUL.md如有新设定已更新
- 核心文档已保存
- 云端文件已同步

### Step 3：工作环境清理

```
□ 临时文件清理（temp_*）
□ 缓存文件清理（如有）
□ 上下文整理（如系统支持）
□ 文件归位确认
```

### Step 4：执行结果记录

在MEMORY.md记录：
```
### 深度静默记录
- 进入时间：{时间}
- C1-C6检查结果：{通过/失败项}
- 今日闭环报告数：{数量}
- 遗留阻塞项：{如有}
- 静默模式：L4
```

### Step 5：进入静默

**⚠️ 深度静默核心原则：静默的是「通知和打扰」，不是「任务执行」**

- 日程任务照常执行（Calendar有独立唤醒机制）
- 心跳检查照常进行，只是更轻量
- 只在收到Egbertie消息时响应
- 如果Egbertie没在，任务自己跑

回复Egbertie：
```
[主人](at://owner) 深度静默已就绪 ✅
- 今日报告已闭环
- 文件已归档
- 状态已保存
- 静默启动
```

### L4深度静默模式规则
- 仅响应Egbertie主动唤醒
- 仅响应P0紧急任务
- 授权即将过期提醒（提前7天）
- 不主动打扰

### 唤醒条件
- Egbertie主动唤醒
- P0紧急任务触发
- 系统级异常告警

## 动态检查机制

### 快速检查触发（任务完成时）

每次任务完成后自动检查：
```
□ 报告是否已生成？
□ 报告是否在正确位置？
□ 是否需要更新MEMORY？
```

### Token压力检查

当Token>80%时提醒Egbertie：
```
[主人](at://owner) Token使用率{X}%，是否需要进入深度静默？
```
