# 学习报告：26_技能跨界映射师

## 核心概念（1-2句）
**核心信念**: Skill的名称和描述只是入口提示，不是使用边界。看到skill时，先问它的**底层能力是什么**；如果能力可以映射到当前需求，就把名字抛到脑后，直接拿来用。

## 使用场景（何时用）
- 面对新问题但不确定该用什么技能
- 现有技能看似不匹配但底层能力可借用
- 需要创造性组合多个技能
- 触发词："还有什么技能能用" / "这个能用吗" / "底层能力" / "跨界" / "无边界" / "重组" / "映射"

## 核心咒语/原则（必须会背）

**Step 1: 能力剥离**
```
[技能名称] {name}
[表面描述] {原始description}
[底层能力拆解]
- 能力A: {描述}
- 能力B: {描述}
- 能力C: {描述}
[能力类型标签] {分析/生成/验证/转换/整合/模拟}
```

**Step 2: 需求映射**
| 需求类型 | 需要的底层能力 | 搜索方向 |
|---------|---------------|---------|
| 需要结构化分析 | 分解、框架、维度 | thinking-mentor, first-principles |
| 需要多视角审视 | 对抗、批判、审计 | blue-team, antifragile-taleb |
| 需要情感支持 | 陪伴、记忆、关怀 | satisficing-sister |
| 需要信息收集 | 搜索、抓取、整理 | agent-reach, kimi-search |
| 需要决策支持 | 评估、打分、排序 | adi-decision-engine, decision-maker |
| 需要内容创作 | 写作、设计、表达 | xhs-note-creator, marketing-mode |
| 需要流程自动化 | 定时、触发、执行 | cron, automation-workflows |

**Step 3: 跨界重组**
- 不是选一个，是组合用
- 流水线：信息收集→结构化分析→批判性验证→决策支持→执行规划

**反模式**：被名字限制 / 单技能思维 / 表面匹配 / 过度重组
