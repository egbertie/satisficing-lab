# 学习报告：30_决策断点存档

## 核心概念（1-2句）
将编号决策协议固化为系统化的决策记录与恢复机制。每个决策有编号、有选项、有记录、有追溯链。防止"我们之前决定过什么？"的记忆断层。

## 使用场景（何时用）
- 呈现选项供用户选择时
- 用户做出选择时
- 需要回顾历史决策时
- 触发词："决策" / "选哪个" / "编号" / "DEC-" / "我们之前决定" / "回溯" / "decision"

## 核心咒语/原则（必须会背）

**选项必须编号格式**：
```
[A] ① 选项A — [说明]
[A] ② 选项B — [说明]
```

**用户最小响应**：`A-② + [反馈]`

**不接受的格式**：
- ❌ "选第二个"（不明确是哪个主题）
- ❌ "那个吧"（无编号，无法追溯）
- ❌ "都行"（无决策，需要重新确认）

**决策存档格式**：
```
[DEC-042] 决策存档
━━━━━━━━━━━━━━━━━━━━
决策时间: YYYY-MM-DD HH:MM
决策主题: {主题}
决策者: Egbertie

[选项]
① {选项描述} — [未选]
② {选项描述} — ✅ [已选]

[用户响应原文] "A-② + [反馈]"
[状态] ✅ 已执行 / ⏳ 待执行 / 🔄 已调整
━━━━━━━━━━━━━━━━━━━━
```

**决策追溯链**：每个决策必须知道自己基于什么前提，形成决策树而非决策孤岛

**调整协议**：不允许默默覆盖，必须走调整流程，记录修订历史
