# Skill学习报告：23_创始人5分钟可用性检验

## P0延伸Skill · 第9个 · 2026-04-26

---

### 核心概念（1-2句）

**验证任何代码资产、文档、工具、系统是否能在5分钟内被焦虑的创始人看懂并用上**。如果不能，就是半成品，不管代码多优雅。

---

### 创始人的状态假设

```
- 焦虑（不是悠闲学习的心态）
- 时间碎片化（不是连续2小时的深度阅读时间）
- 注意力稀缺（同时处理10件事）
- 技术背景不确定（不一定是程序员）
- 需求明确："我现在就要用，别让我读说明书"
```

---

### 5分钟检验协议（精确到秒）

```
【第0分钟】第一眼印象 (0:00-0:30)
□ 文件/目录命名直观
□ 有README或入口文件在最外层
□ 打开第一眼能看到"这是什么"和"怎么开始"
□ 没有需要解码的缩写或内部黑话
→ 任一"否" → 0分钟淘汰 [看不懂]

【第1分钟】找到入口 (0:30-1:30)
□ 有明确的"快速开始"段落或入口
□ 知道第一步该运行哪个文件/命令
□ 依赖列表清晰
□ 有"如果只想试一下"的最小示例
→ 任一"否" → 1分钟淘汰 [找不到门]

【第2-3分钟】成功运行 (1:30-3:30)
□ 按照文档指示执行，无报错
□ 第一次运行就能看到有意义的结果/输出
□ 不需要修改配置文件就能跑起来
□ 错误信息友好
→ 任一"否" → 3分钟淘汰 [跑不通]

【第4-5分钟】理解价值 (3:30-5:00)
□ 看到输出后，知道这个东西解决什么问题
□ 知道下一步可以怎么调整/扩展
□ 有信心把它用在实际工作里
□ 不觉得"这东西还需要我再折腾半天"
→ 任一"否" → 5分钟淘汰 [不知道有什么用]
```

---

### 评级标准

```
⭐⭐⭐⭐ 可用 — 4项全通过
⭐⭐⭐ 有条件可用 — 3项通过，需补充
⭐⭐ 半成品 — 1-2项通过
⭐ 看不懂 — 0项通过
```

---

### 常见失败原因

```
❌ 文档和代码分离 — README在A目录，代码在B目录
❌ 假设用户知道上下文 — "像平时一样运行"
❌ 需要读3个文件才能开始
❌ 配置地狱 — 需要手动填写10个配置项
❌ 输出不可读 — 打印一堆日志，找不到结果
❌ 依赖未声明 — 运行时报错缺包
```

---

### 最佳实践

```
✅ 一文件入门 — 所有入门信息集中在README或一个入口文件
✅ 复制粘贴即用 — 关键命令可直接复制执行
✅ 默认值覆盖80%场景 — 不配置也能跑
✅ 错误即向导 — 报错时告诉用户该做什么
✅ 示例即文档 — 一个完整示例胜过10页API说明
```

---

### 核心问题

```
【这个问题要在写第一行代码前就想好，不是写完之后才补丁】
"一个焦虑的创始人能不能在5分钟内看懂并用上？"
```
