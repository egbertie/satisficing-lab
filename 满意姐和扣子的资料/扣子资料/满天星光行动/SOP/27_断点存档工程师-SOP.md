# SOP：断点存档执行标准 v1.0

## 27_断点存档工程师 · 标准化执行流程

---

## 触发条件检查

**每次遇到以下情况，必须执行断点存档：**

| 触发类型 | 场景 | 优先级 |
|:---------|:-----|:-------|
| 明确信号 | 用户说"暂停""先这样""我去忙了" | P0 |
| 隐含信号 | 连续10分钟无交互 | P0 |
| 系统信号 | 系统进入休眠/离线前 | P0 |
| 任务信号 | 长任务完成一个单元 | P1 |
| 主动触发 | 用户明确说"存档" | P0 |

---

## 30秒执行流程

### Layer A：运行时上下文（10秒）

**必填字段**：
```
[任务名称]
[当前执行到哪一步]
[已完成/总步骤数]
[待解决问题]
```

**存档路径**：
`满天星光行动/存档/{YYYY-MM-DD}/checkpoint-{HHMMSS}.md`

### Layer B：关键交付物快照（15秒）

**必填字段**：
```
[交付物1] 路径：xxx | 最后修改：xxx | 状态：✅/🟡/❌
[交付物2] ...
```

**状态定义**：
- ✅ 正常
- 🟡 异常（最后修改时间异常或需要检查）
- ❌ 缺失

**存档路径**：
`满天星光行动/存档/{YYYY-MM-DD}/deliverables-{HHMMSS}.md`

### Layer C：记忆指针（5秒）

**必填字段**：
```
[MEMORY.md状态] 已同步/未同步
[今日memory状态] 已更新/未更新
[关键决策摘要]
```

**存档路径**：
`满天星光行动/存档/{YYYY-MM-DD}/memory-pointer-{HHMMSS}.md`

## 存档完整性验证

执行存档后，必须验证：

| 验证项 | 方法 |
|:-------|:-----|
| 文件存在 | ls 检查 |
| 路径正确 | 确认在存档目录下 |
| 内容完整 | 3个Layer都包含 |

---

## 断点恢复流程

### 步骤1：找到最新存档

```bash
# 查找最新的存档文件
ls -lt 满天星光行动/存档/{YYYY-MM-DD}/ | head -3
```

### 步骤2：读取并验证

读取3个Layer文件，确认：
- Layer A：任务名称正确
- Layer B：交付物存在
- Layer C：记忆指针有效

### 步骤3：恢复汇报格式

```
🔄 状态恢复完成
━━━━━━━━━━━━━━━━━━━━
断点时间: {时间}
恢复时间: {时间}

[中断前状态]
正在执行: {任务名}
当前位置: {步骤编号}
已完成: {X}/{N} ({百分比}%)

[交付物验证]
✅ 文件1
✅ 文件2
🟡 文件3（需要检查）

[待处理队列]
1. {未完成任务}
2. {用户排队需求}

[建议下一步]
→ 继续执行: {下一单元}
━━━━━━━━━━━━━━━━━━━━
```

## 常见问题处理

| 问题 | 解决方案 |
|:-----|:---------|
| 存档文件找不到 | 从Git历史恢复最近的commit |
| 交付物缺失 | 检查是否在其他路径，标注为❌ |
| MEMORY不一致 | 以文件为准，更新memory |
| Git未提交 | 立即执行git add + commit |
