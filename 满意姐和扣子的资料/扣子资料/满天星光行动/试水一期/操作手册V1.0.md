## 二、P0-1 入口设计执行指南

### 2.1 三种入口形式

| 入口形式 | 优先级 | 配置难度 | 适用场景 |
|:--------:|:------:|:--------:|:---------|
| **Bot菜单** | ⭐⭐⭐ | 低 | 扣子App内用户 |
| **落地页** | ⭐⭐ | 中 | 外部流量转化 |
| **分享链接** | ⭐⭐ | 低 | 社群/邮件/私信传播 |

### 2.2 Bot菜单入口配置步骤

```
【Step 1】进入扣子后台
  → 打开 https://coze.cn
  → 登录满天星光账户
  → 进入Bot编辑界面

【Step 2】配置Bot菜单
  → 进入"快捷入口"设置
  → 添加菜单项:
    名称: 合伙人诊断
    图标: 🔍
    关键词: ["合伙人诊断", "开始诊断", "1"]

【Step 3】配置欢迎话术
  → 标题: 合伙人诊断
  → 欢迎语: 欢迎使用满天星光合伙人诊断服务
  → CTA按钮: [立即开始诊断]

【Step 4】保存并发布
  → 保存配置
  → 点击「发布」
  → 等待审核通过（通常10分钟内）
```

### 2.3 入口验证检查清单

```
□ Bot菜单"合伙人诊断"按钮已配置
□ Bot欢迎语显示正常
□ "立即开始诊断"按钮可点击
□ 点击后进入快速问卷流程
□ Bot菜单入口全流程测试通过（3次）
□ 落地页跳转链路测试通过
□ 分享链接生成正常
□ 二维码可正常扫码
□ 各入口追踪参数配置正确
```

## 三、P0-2 问诊问卷执行指南

### 3.1 问卷结构

```
快速问卷 (3题) ──────┬────── SKU分流
                     │
深度问卷 (20题) ─────┴──────→ 报告生成
  ├── 模块1: 基本信息 (Q1-Q5)
  ├── 模块2: 问题诊断 (Q6-Q10)
  ├── 模块3: 决策风格 (Q11-Q15)
  └── 模块4: 期望目标 (Q16-Q20)
```

### 3.2 快速问卷配置步骤

```
【Step 1】创建快速问卷流程
  → 进入满天星光Bot编辑
  → 新建对话流: "快速诊断"
  → 触发条件: 用户发送"开始"或点击菜单"合伙人诊断"

【Step 2】配置问题节点
  问题1 - 创业阶段:
  - 类型: 单选
  - 变量: startup_stage
  - 选项映射: A=初创期, B=成长期, C=成熟期

  问题2 - 核心问题:
  - 类型: 单选
  - 变量: core_problem
  - 选项映射: A=合伙人选择, B=股权分配, C=权力边界, D=利益分配, E=关系维护

  问题3 - 期望帮助:
  - 类型: 单选
  - 变量: expectation
  - 选项映射: A=快速, B=系统, C=陪伴

【Step 3】配置提交动作
  → 保存用户答案至用户画像
  → 根据Q3自动推荐SKU
  → Q3选B时: 跳转到深度问卷
  → Q3选A时: 推送卡牌咨询入口
  → Q3选C时: 推送SKU-B服务入口

【Step 4】测试验证
  → 全流程测试至少3次
  → 确认Type映射准确
  → 确认SKU分流正常
```

### 3.3 深度问卷配置步骤

```
【Step 1】创建深度问卷流程
  → 新建对话流: "深度诊断"
  → 触发条件: 快速问卷Q3选择B后跳转

【Step 2】配置4个模块
  模块1: 基本信息（Q1-Q5）
  模块2: 问题诊断（Q6-Q10）
  模块3: 决策风格（Q11-Q15）
  模块4: 期望目标（Q16-Q20）

【Step 3】配置提交动作
  → 保存所有答案
  → 触发报告生成
  → 返回报告链接

【Step 4】测试验证
  → 20题全部测试
  → 模块引导语正常显示
  → 进度可视化正常
  → 提交后报告生成正常
```

### 3.4 问卷验证检查清单

```
□ 快速问卷3题可正常答题
□ Type映射逻辑正确
□ SKU分流规则生效
□ 深度问卷20题可正常答题
□ 模块引导语清晰
□ 问卷进度可视化
□ 提交后可正常生成报告
□ 报告内容与问卷回答一致
```

## 四、P0-3 报告模板执行指南

### 4.1 报告结构（15页）

```
引言篇 (2P): 封面 + 摘要
诊断篇 (4P): Type诊断 + 图腾分析
分析篇 (5P): 冲突分析 + 5Why追溯
预警篇 (2P): Top5风险预警
决策篇 (3P): 3条路径 + 资源推荐
附录篇 (1P): 术语解释 + 反馈通道
```

### 4.2 PDF生成配置步骤

```
【Step 1】选择PDF生成方案
  → 推荐: HTML模板 + 服务端渲染 + puppeteer导出
  → 或: Coze PDF技能

【Step 2】设计HTML模板
  → 15页结构，对应模板设计
  → CSS: 使用A4尺寸 @page规则
  → 字体: 使用系统默认字体保证兼容性

【Step 3】配置数据注入
  → 接收问卷数据: userData = {answers, type, scores...}
  → 模板变量: {{user.name}}, {{report.type}}, {{report.date}}
  → 条件渲染: {{#if risk1}} 显示风险1 {{/if}}

【Step 4】生成与交付
  → 用户完成问卷 → 触发报告生成
  → 生成PDF → 上传CDN → 返回URL
  → 发送消息: "您的报告已生成 [查看链接]"
```

### 4.3 报告验证检查清单

```
□ 报告封面信息完整（用户、时间、编号）
□ Type类型与问卷回答一致
□ 核心发现与问卷数据匹配
□ 冲突分析逻辑合理
□ 5Why追溯有深度
□ 风险预警覆盖全面
□ 决策路径可执行
□ 资源推荐相关
□ PDF格式规范，可正常打开
□ 报告阅读体验流畅
```

## 五、P0-4 通知系统执行指南

### 5.1 通知通道架构

```
通知系统
├── 邮件通道（正式通知）
│   ├── 触发条件：报告生成完成
│   ├── 优先级：高
│   └── 适用场景：诊断报告送达、里程碑通知
├── 短信通道（提醒通知）
│   ├── 触发条件：用户未在24小时内查看报告
│   ├── 优先级：中
│   └── 适用场景：报告提醒、限时优惠
└── 站内信通道（辅助通知）
    ├── 触发条件：即时
    ├── 优先级：低
    └── 适用场景：系统消息、操作反馈
```

### 5.2 邮件通道配置

| 配置项 | 说明 |
|--------|------|
| 发件人名称 | 满意解研究所 |
| 发件人邮箱 | notification@mzgdg.com |
| 邮件主题前缀 | 【满天星光行动】 |
| 送达率目标 | ≥95% |
| 打开率目标 | ≥60% |

### 5.3 短信通道配置

| 配置项 | 说明 |
|--------|------|
| 签名 | 满意解研究所 |
| 短信长度 | ≤70字（单条） |
| 送达率目标 | ≥98% |
| 到达时效 | ≤30秒 |

### 5.4 Egbertie操作步骤

**Step 1: 配置接收渠道**
1. 打开满天星光行动小程序/网页
2. 点击「个人中心」→「通知设置」
3. 确认邮箱地址已正确填写
4. 确认手机号码已正确填写（如需短信通知）
5. 选择偏好的通知方式

**Step 2: 体验邮件通知**
1. 完成问诊问卷并提交
2. 等待系统生成报告（约5分钟）
3. 检查邮箱（可能在垃圾邮件箱）
4. 打开邮件，确认：
   - 发件人显示「满意解研究所」
   - 主题包含【满天星光行动】
   - 正文包含报告概要
   - 「查看完整报告」按钮可点击

**Step 3: 体验短信通知**
1. 完成Step 2后，等待24小时
2. 或者联系技术支持触发短信测试
3. 检查手机短信
4. 确认短信内容符合模板规范

### 5.5 通知时间规则

| 事件 | 通道 | 延迟 | 备注 |
|------|------|------|------|
| 报告生成完成 | 邮件 | 即时 | 优先发送邮件 |
| 报告生成后24小时未查看 | 短信 | 24小时后 | 仅发送一次 |
| 问卷提交确认 | 邮件 | 即时 | 感谢通知 |
| 报告有效期提醒 | 短信 | 报告生成后7天 | 可配置 |

### 5.6 通知验证检查清单

```
□ 邮件发送：报告生成后5分钟内送达
□ 短信发送：提醒触发后30秒内送达
□ 邮件格式：排版正常、无乱码
□ 链接可用：点击跳转至正确页面
□ 退订功能：短信回复TD后停止发送
□ 偏好设置：用户可自定义通知方式
□ 邮件主题包含【满天星光行动】
□ 发件人显示「满意解研究所」
□ 报告概要内容与实际报告一致
□ CTA按钮清晰可见、可点击
□ 短信签名显示【满意解研究所】
```
