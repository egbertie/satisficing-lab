## 二、P0-1 入口设计执行指南

### 2.1 三种入口形式

| 入口形式 | 优先级 | 配置难度 | 适用场景 |
|:--------:|:------:|:--------:|:---------|
| **Bot菜单** | ⭐⭐⭐ | 低 | 扣子App内用户 |
| **落地页** | ⭐⭐ | 中 | 外部流量转化 |
| **分享链接** | ⭐⭐ | 低 | 社群/邮件/私信传播 |

### 2.2 Bot菜单入口配置步骤

```
【Step 1】进入扣子后台
  → 打开 https://coze.cn
  → 登录满天星光账户
  → 进入Bot编辑界面

【Step 2】配置Bot菜单
  → 进入"快捷入口"设置
  → 添加菜单项:
    名称: 合伙人诊断
    图标: 🔍
    关键词: ["合伙人诊断", "开始诊断", "1"]

【Step 3】配置欢迎话术
  → 标题: 合伙人诊断
  → 欢迎语: 欢迎使用满天星光合伙人诊断服务
  → CTA按钮: [立即开始诊断]

【Step 4】保存并发布
  → 保存配置
  → 点击「发布」
  → 等待审核通过（通常10分钟内）
```

## 三、P0-2 问诊问卷执行指南

### 3.1 问卷结构

```
快速问卷 (3题) ──────┬────── SKU分流
                     │
深度问卷 (20题) ─────┴──────→ 报告生成
  ├── 模块1: 基本信息 (Q1-Q5)
  ├── 模块2: 问题诊断 (Q6-Q10)
  ├── 模块3: 决策风格 (Q11-Q15)
  └── 模块4: 期望目标 (Q16-Q20)
```

### 3.2 快速问卷配置步骤

```
【Step 1】创建快速问卷流程
  → 进入满天星光Bot编辑
  → 新建对话流: "快速诊断"
  → 触发条件: 用户发送"开始"或点击菜单"合伙人诊断"

【Step 2】配置问题节点
  问题1 - 创业阶段:
  - 类型: 单选
  - 变量: startup_stage
  - 选项映射: A=初创期, B=成长期, C=成熟期

  问题2 - 核心问题:
  - 类型: 单选
  - 变量: core_problem
  - 选项映射: A=合伙人选择, B=股权分配, C=权力边界, D=利益分配, E=关系维护

  问题3 - 期望帮助:
  - 类型: 单选
  - 变量: expectation
  - 选项映射: A=快速, B=系统, C=陪伴

【Step 3】配置提交动作
  → 保存用户答案至用户画像
  → 根据Q3自动推荐SKU
  → Q3选B时: 跳转到深度问卷
  → Q3选A时: 推送卡牌咨询入口
  → Q3选C时: 推送SKU-B服务入口

【Step 4】测试验证
  → 全流程测试至少3次
  → 确认Type映射准确
  → 确认SKU分流正常
```

### 3.3 深度问卷配置步骤

```
【Step 1】创建深度问卷流程
  → 新建对话流: "深度诊断"
  → 触发条件: 快速问卷Q3选择B后跳转

【Step 2】配置4个模块
  模块1: 基本信息（Q1-Q5）
  模块2: 问题诊断（Q6-Q10）
  模块3: 决策风格（Q11-Q15）
  模块4: 期望目标（Q16-Q20）

【Step 3】配置提交动作
  → 保存所有答案
  → 触发报告生成
  → 返回报告链接

【Step 4】测试验证
  → 20题全部测试
  → 模块引导语正常显示
  → 进度可视化正常
  → 提交后报告生成正常
```

### 3.4 问卷验证检查清单

```
□ 快速问卷3题可正常答题
□ Type映射逻辑正确
□ SKU分流规则生效
□ 深度问卷20题可正常答题
□ 模块引导语清晰
□ 问卷进度可视化
□ 提交后可正常生成报告
□ 报告内容与问卷回答一致
```

## 四、P0-3 报告模板执行指南

### 4.1 报告结构（15页）

```
引言篇 (2P): 封面 + 摘要
诊断篇 (4P): Type诊断 + 图腾分析
分析篇 (5P): 冲突分析 + 5Why追溯
预警篇 (2P): Top5风险预警
决策篇 (3P): 3条路径 + 资源推荐
附录篇 (1P): 术语解释 + 反馈通道
```

### 4.2 PDF生成配置步骤

```
【Step 1】选择PDF生成方案
  → 推荐: HTML模板 + 服务端渲染 + puppeteer导出
  → 或: Coze PDF技能

【Step 2】设计HTML模板
  → 15页结构，对应模板设计
  → CSS: 使用A4尺寸 @page规则
  → 字体: 使用系统默认字体保证兼容性

【Step 3】配置数据注入
  → 接收问卷数据: userData = {answers, type, scores...}
  → 模板变量: {{user.name}}, {{report.type}}, {{report.date}}
  → 条件渲染: {{#if risk1}} 显示风险1 {{/if}}

【Step 4】生成与交付
  → 用户完成问卷 → 触发报告生成
  → 生成PDF → 上传CDN → 返回URL
  → 发送消息: "您的报告已生成 [查看链接]"
```

### 4.3 报告验证检查清单

```
□ 报告封面信息完整（用户、时间、编号）
□ Type类型与问卷回答一致
□ 核心发现与问卷数据匹配
□ 冲突分析逻辑合理
□ 5Why追溯有深度
□ 风险预警覆盖全面
□ 决策路径可执行
□ 资源推荐相关
□ PDF格式规范，可正常打开
□ 报告阅读体验流畅
```
