## Skill 16：双轨诚实审计

### 核心原理（3句内）

1. **防止自欺欺人**：63%的"已完成"任务实为半成品，双轨审计用独立视角（蓝军+满意姐）对抗自我原谅
2. **互相不商量**：蓝军（挑刺对抗）和满意姐（温暖务实）各自独立出报告，确保多元视角
3. **必须≥1个问题**：红线禁止输出"一切正常"，确保审计有实质价值

### 关键使用场景

- 每日日终自动审计（18:00后）
- 周深度审计（周日）
- 手动触发词："双轨审计"、"验收今日工作"、"FIN验证"

### 容易忽略的细节

| 细节 | 说明 |
|------|------|
| 蓝军vs满意姐必须独立 | 商量后就不是双轨，失去了制衡价值 |
| 审计的是工作不是人 | 聚焦交付物和流程，不人身攻击 |
| Token消耗也在审计范围 | 警惕"向内集邮"的浪费 |
| 必须有整改清单 | 发现问题还要给出具体行动 |

## Skill 17：编号决策协议

### 核心原理（3句内）

1. **每个决策都有身份证**：用DEC-XXX编号，让决策可追溯、可复盘、可追责
2. **2个以上选项必须编号**：避免用户决策疲劳，格式为`[A] ① 选项A — [说明]`
3. **改决策必须留痕**：修改历史决策要走调整流程，记录原因和影响

### 关键使用场景

- 呈现2个及以上选项时（触发编号规则）
- 用户选择后（触发存档流程）
- 需要追溯历史决策时

### 容易忽略的细节

| 细节 | 说明 |
|------|------|
| 选项不超过5个 | 超过5个=没有聚焦，用户会决策疲劳 |
| 不存档不做决策 | 用户确认后必须立即存档 |
| 最小响应格式 | `A-② + [反馈]`，简洁明了 |
| 决策调整要说明原因 | 不能静默修改，必须走调整流程 |

## Skill 18：五维决策工作坊

### 核心原理（3句内）

1. **五步流程按序走**：土(聚贤才) → 金(满意解) → 水(洞察) → 木(伦理) → 火(行动)，跳维有风险
2. **把理论变按钮**：30分钟个人版/2小时团队版，让五维决策变成可执行的标准流程
3. **追求满意解而非最优解**：[金]维度核心是定义"足够好"，拒绝完美主义陷阱

### 关键使用场景

- 重大个人决策（30分钟个人版）
- 团队战略/产品/资源决策（2小时团队版）
- 触发词："启动五维决策工作坊"、"土金水木火走一遍"

### 容易忽略的细节

| 细节 | 说明 |
|------|------|
| [水]维度要记录直觉 | 不纯理性，直觉也是信息 |
| [木]维度检查信任影响 | 信任优先于短期利益 |
| [火]维度要有最小步骤 | 不能只说"执行"，要有可操作的起点 |
| 不走完五维不做决策 | 跳过任何一维都有风险 |
