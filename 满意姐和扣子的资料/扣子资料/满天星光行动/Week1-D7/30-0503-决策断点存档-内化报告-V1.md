## 一、核心概念内化

### 1.1 一句话定义

**决策断点存档**：将编号决策协议固化为系统化的决策记录与恢复机制，确保每个决策有编号、有选项、有记录、有追溯链。

### 1.2 核心目标

> 每个决策有编号、有选项、有记录、有追溯链

### 1.3 为什么重要

防止"我们之前决定过什么？"的记忆断层。不是为了一言九鼎不能改，是为了改了之后知道为什么改、改了什么影响。

## 二、四个核心协议

### 协议1: 选项必须编号

**呈现2个及以上选项时必须编号。**

**格式**：
```
[A] ① 选项A — [说明]
[A] ② 选项B — [说明]
```

**多段对话合并回复**：
```
[A] ① 选项A — [说明]
[B] ② 选项B — [说明]
```

### 协议2: 用户最小响应格式

**用户最小响应**：`A-② + [反馈]`

**解析规则**：
- `A-②` → 主题A，选择选项②
- `B-①` → 主题B，选择选项①
- `A-②, B-①` → 主题A选②，主题B选①
- `A-② + 但是需要调整X` → 选②但有附加条件

**不接受的格式**：
- ❌ "选第二个"（不明确是哪个主题）
- ❌ "那个吧"（无编号，无法追溯）
- ❌ "都行"（无决策，需要重新确认）

### 协议3: 决策编号与存档

**决策编号格式**：`DEC-XXX`

**存档格式**：
```
[DEC-042] 决策存档
━━━━━━━━━━━━━━━━━━━━
决策时间: YYYY-MM-DD HH:MM
决策主题: {主题}
决策者: Egbertie

[选项]
① {选项描述} — [未选]
② {选项描述} — ✅ [已选]
③ {选项描述} — [未选]

[用户响应原文] "A-② + [反馈]"

[决策结果]
选择: ②
附加条件: {如果有}

[影响评估]
直接影响: {描述}
后续任务: {列表}
关联决策: {DEC-XXX, DEC-YYY}

[状态] ✅ 已执行 / ⏳ 待执行 / 🔄 已调整
━━━━━━━━━━━━━━━━━━━━
```

### 协议4: 决策追溯链

**任何新决策必须链接到相关历史决策。**

```
[决策追溯链]
DEC-042 (当前)
  ← 基于 DEC-038 (范围定义)
  ← 受 DEC-035 (资源约束) 限制
  → 影响 DEC-045 (执行计划)
  → 影响 DEC-048 (预算分配)
```

**核心规则**：
- 每个决策必须知道自己基于什么前提
- 前提变更时，依赖该前提的决策需要重新评估
- 形成决策树，不是决策孤岛

## 三、决策存档工作流

### 当用户做出选择时

1. **解析用户响应** — 提取 `A-②` 格式
2. **确认理解** — "确认：主题A选②，对吗？"
3. **分配DEC编号** — `DEC-{下一个可用编号}`
4. **写入决策文件** — `memory/decisions/DEC-XXX.md`
5. **更新决策索引** — `memory/decisions/INDEX.md`
6. **关联到相关决策** — 建立追溯链
7. **汇报确认** — 简短确认用户选择已记录

### 当需要回顾历史决策时

```
[决策查询]
主题: {搜索关键词}
结果:
- DEC-042: 2026-04-26 选② — {摘要}
- DEC-038: 2026-04-25 选① — {摘要}
- DEC-035: 2026-04-24 选③ — {摘要}

[当前状态]
DEC-042: ✅ 已执行（奔月计划先锋第一箭已启动）
DEC-038: ✅ 已执行
DEC-035: 🔄 已调整（Token预算从70%改为30%校准）
```

## 四、决策调整协议

### 场景：用户要改变之前的决定

**不允许默默覆盖，必须走调整流程：**

```
[决策调整申请]
原决策: DEC-042
原选择: ② {描述}
申请改为: ① {描述}

[调整原因]
{用户说明}

[影响分析]
已执行任务: {哪些需要回滚/修改}
后续决策: {DEC-045, DEC-048 需要同步调整}
新增风险: {描述}

[A] ① 确认调整 — 执行变更，更新关联决策
[A] ② 保持原决策 — 记录申请但暂不执行
[A] ③ 部分调整 — {具体方案}
```

## 五、反模式（必须避免）

| 反模式 | 危害 | 改正 |
|:-------|:-----|:-----|
| 不编号直接给选项 | 用户无法精确回复 | 必须编号 |
| 用户说"选第二个"但不确认主题 | 导致理解偏差 | 确认主题 |
| 决策后不存档 | "我们之前决定过什么？" | 立即存档 |
| 默默覆盖旧决策 | 没有调整记录 | 走调整流程 |
| 决策无追溯链 | 不知道基于什么前提 | 建立追溯链 |
| 选项超过5个 | 决策疲劳 | 精简到3个最佳 |

---

## 六、最佳实践

1. **2-3个选项最佳**，最多5个
2. **每个选项必须有差异**（不是"好/更好/最好"的渐进）
3. **选项说明包含"风险+收益"**而非只讲好处
4. **用户选择后立即确认**，不默默执行
5. **重大决策（P0级）存档到文件**，非重大决策记入当日memory
6. **定期回顾决策索引**，识别"反复犹豫"的模式

### 8.2 实际应用场景

→ 评估影响 → 提供调整选项 → 执行变更流程

→ 查询决策索引 → 回溯相关决策 → 理解前提
