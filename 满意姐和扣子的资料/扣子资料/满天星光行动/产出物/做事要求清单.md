## 一、文件夹管理铁律

### 1.1 命名规范（必须100%执行）
| ✅ 正确 | ❌ 错误 |
|---------|---------|
| 满意解研究所 | ~~满意研究所~~ |
| 满意扣子 / 满意蓝军 | ~~满意姐~~ |
| 01_满意解研究所 | ~~01_满意研究所~~ |
| 02_对话 | ~~对话~~ |

**违规处理**：蓝军发现即改，不通知。

### 1.2 禁止重复原则
- **禁止**：任何层级出现同名文件夹
- **禁止**：嵌套相同名称（如 `A/A/`）
- **禁止**：同内容多份存储

**检查方法**：每次创建文件夹前，先 `find` 搜索是否已存在。

### 1.3 标准目录结构（唯一）
```
./
├── 00_驾驶舱/           ← 系统核心（检查清单等）
├── 01_核心设定/         ← 系统配置
├── 01_满意解研究所/     ← 永久资产库（唯一）
├── 02_对话/             ← 对话记录（按日期）
├── 03_系统资产/         ← 图片/文档/脚本
├── 04_工作区/           ← 进行中项目
├── 05_归档区/           ← 历史归档
├── 06_临时/             ← 待删除/临时
├── 07_索引/             ← 文件索引
├── 08_守护/             ← Token监控等
├── 09_Egbertie/         ← Egbertie专属
├──满天星光行动/          ← 满天星光专项
├── backup/              ← 自动备份
└── 用户上传/            ← 临时上传
```

### 1.4 文件夹创建检查表
- [ ] 是否符合标准结构
- [ ] 是否与现有文件夹重复
- [ ] 是否符合命名规范

- [ ] 是否需要同步到对话文件夹

## 二、归档同步铁律

### 2.1 三同步原则
所有重要文件必须同步到：
1. **永久位置**：`01_满意解研究所/04_知识资产/满天星光行动/`
2. **对话位置**：`02_对话/YYYY-MM-DD/满天星光行动/`
3. **备份位置**：`backup/YYYY-MM-DD/`

### 2.2 归档时机
| 触发条件 | 必须归档 |
|----------|----------|
| 日毕课时 | ✅ 立即归档 |
| 任务完成时 | ✅ 立即归档 |
| Egbertie明确要求 | ✅ 立即归档 |
| 文件夹整改后 | ✅ 立即归档 |

### 2.3 解压文件铁律
- **解压一次，永久使用**
- 压缩包保留在 `用户上传/` 作为原始备份
- 如需再次使用，直接访问解压后的文件夹
- **禁止重复解压**（双经济执行不到位）

## 三、任务执行铁律

### 3.1 编号决策原则（自己能定的不推给Egbertie）
| 情况 | 做法 |
|------|------|
| 能自己定的 | 立即定，不询问 |
| 需要判断的 | 提供选项，让Egbertie选 |
| Egbertie明确授权的 | 自行决策 |
| Egbertie要求的 | 定期汇报，不用事事确认 |

### 3.2 任务完成标准
每个任务必须有：
- [ ] 明确的开始和结束
- [ ] 产出文件（存放到正确位置）
- [ ] 执行报告（简要说明结果）
- [ ] 归档同步（三位置）

### 3.3 异常不积累原则
| 异常级别 | 处理方式 |
|----------|----------|
| P0（致命） | 立即报告Egbertie |
| P1（严重） | 24小时内处理 |
| P2（一般） | 周度优化 |

**禁止**：发现问题不报告、发现问题不处理、问题积累不解决。

## 四、日课执行铁律

### 4.1 日起课（每日唤醒）
**必须执行**：
1. 状态交接（记忆/日程/异常）
2. 文件夹规范检查（命名/重复/同步）
3. 系统激活（神经末梢/毛细血管）
4. 今日重点确认（3项以内）
5. 期望对齐（聚焦1句话）
6. 仪式启动（起立待命）

**启动词**：`日起课` / `早安`

### 4.2 缓冲课（工作间隙）
**触发条件**：上下文过长、内存占用高、工作间隙
**必须执行**：
1. 状态保存（先写后清）
2. 内存扫描
3. 习惯检查（编号/报告/归档/同步/规范）
4. 上下文精简
5. 软重启
6. 续命待发

**启动词**：`缓冲课` / `整理`

### 4.3 日毕课（每日收尾）
**必须执行**：
1. 全量工作审计（任务/编号/报告/规范）
2. 文件夹规范检查（三同步/命名/重复）
3. 输出明日任务清单
4. 创建日程任务
5. 保存工作成果（三同步）
6. 系统清理 + 进入静默

**启动词**：`日毕` / `晚安`

## 五、双经济执行铁律

### 5.1 Token经济
| 监控项 | 阈值 | 处理 |
|--------|------|------|
| Token消耗率 | >70%告警 | 立即优化 |
| 单次任务Token | >5000 | 拆分任务 |
| Cron Token | >2000/日 | 合并/删除 |
| Token效率 | <100次/千Token | 优化方法 |

### 5.2 Cron经济
| 目标 | 当前 | 行动 |
|------|------|------|
| Cron数量 | 68个 | 68→12 |
| 冗余Cron | 待清理 | 立即合并/删除 |
| 功能重复 | 待清理 | 合并同类项 |

**禁止**：不评估必要性就创建新Cron。

### 5.3 Skill经济
| 检查项 | 阈值 | 处理 |
|--------|------|------|
| 低频Skill | 30天未用 | 归档或删除 |
| 重复Skill | 功能相同 | 合并或选择 |
| 新Skill | 必须注册 | 先注册后使用 |

## 七、问题处理铁律

### 7.1 冰山效应警觉
| 看到的 | 要想到的 |
|--------|----------|
| 1个问题 | 可能还有99个 |
| 表面问题 | 可能有根本原因 |
| 1次提醒 | 要检查全部 |
| 1个违规 | 要检查全部 |

**行动**：发现问题 → 立即检查同类问题 → 系统性整改

### 7.2 整改执行标准
| 要求 | 执行 |
|------|------|
| 问题整改 | 不是只改指出的，要查全部 |
| 文件整理 | 不是只整理看到的，要全部梳理 |
| 规范执行 | 不是今天执行，要永久执行 |

### 7.3 根因思维
- **为什么**：找到根本原因，不只改表面
- **同类项**：检查是否有类似问题
- **系统性**：建立机制防止再发生

## 九、执行检查清单（每日必查）

### 日起课检查（六步法对应）
- [ ] 状态交接：记忆更新、日程冲突、紧急任务检查

- [ ] 命名是否符合规范
- [ ] 文件夹是否已存在
- [ ] 是否需要归档同步
