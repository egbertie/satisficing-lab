## 第一章：设计原则

### 1.1 核心理念
- **清晰优先**：任何人都能快速定位文件
- **按归属存放**：信息放其应在之处
- **双重同步**：标准存放 + 当日对话文件夹
- **可追溯**：版本、历史、来源清晰可查

### 1.2 命名规范

#### 通用规则
| 要素 | 规范 | 示例 |
|:-----|:-----|:-----|
| 字符集 | 中英文、数字、下划线、短横线 | ✅ 可用 |
| 空格 | 禁止 | ❌ 禁用 |
| 特殊字符 | 禁止 | ❌ 禁用 |
| 大小写 | 推荐小写 | 推荐 `report.md` |

#### 文件名结构
```
[类型前缀]_[主标题]_[版本]_[日期].md
```

| 类型前缀 | 含义 |
|:---------|:-----|
| `SOP_` | 标准操作流程 |
| `SPEC_` | 规格说明书 |
| `RPT_` | 报告文件 |
| `NOTE_` | 笔记/备注 |
| `PROC_` | 处理记录 |
| `MEMO_` | 备忘录 |

#### 目录命名
```
[层级前缀]_[目录名称]
```

| 层级前缀 | 含义 |
|:---------|:-----|
| `00_` | 系统/核心层 |
| `01_` | 第一层业务 |
| `02_` | 第二层业务 |
| `_` | 临时/辅助（以单下划线开头） |

## 第三章：报告存放机制

### 3.1 标准流程

```
[生成报告]
    ↓
[判断归属] → 放入对应项目目录
    ↓
[同步复制] → 同步一份到当日对话文件夹
```

### 3.2 报告归属规则

| 报告类型 | 标准存放位置 |
|:---------|:-------------|
| 知识资产入库报告 | `满意解研究所/04_知识资产/入库报告/` |
| 产品设计报告 | `满意解研究所/02_产品体系/01_产品设计/` |
| 案例分析报告 | `满意解研究所/02_产品体系/02_案例库/` |
| 运营管理报告 | `满意解研究所/03_运营体系/` |
| 技术实现报告 | `满意解研究所/06_技术配置/` |
| 对话处理报告 | `对话/YYYY-MM-DD/` |

### 3.3 同步规则

**强制同步**：所有报告在标准存放后，必须同步一份到当日对话文件夹

**命名格式**：
```
对话/YYYY-MM-DD/[原文件名]
```

## 第四章：文件查找机制

### 4.1 查找路径优先级

1. **MEMORY.md** - 首先查询记忆文件
2. **满意解研究所/09_索引/** - 查询索引目录
3. **对话归档** - 按日期查找历史对话
4. **项目资源区** - 深度搜索项目文件

### 4.2 关键词检索

使用 `grep` 或文件搜索时，优先检索：
- 文档标题中的关键词
- MEMORY.md 中的锚点路径
- 索引文件中的映射关系

## 第五章：生命周期管理

### 5.1 版本控制

| 阶段 | 状态 | 命名后缀 |
|:-----|:-----|:---------|
| 草稿 | 创作中 | `-draft` |
| 审核 | 待确认 | `-review` |
| 定稿 | 正式发布 | `-V1.0` |
| 更新 | 修订版 | `-V1.1` |

### 5.2 清理规则

| 目录 | 清理周期 | 清理规则 |
|:-----|:---------|:---------|
| `_临时/` | 每周 | 超过7天未访问则删除 |
| `_待删除/` | 每月 | 确认后统一删除 |
| `对话/归档/` | 每季度 | 超过90天归档至长期存储 |

## 附录：常见问题

### Q1: 文件名有空格怎么办？
立即重命名，使用短横线或下划线替代。

### Q2: 不知道文件该放哪里？
先放 `对话/YYYY-MM-DD/`，再在 MEMORY.md 中记录，后续整理。

### Q3: 临时文件处理？
统一放入 `_临时/`，每周五下午定期清理。
