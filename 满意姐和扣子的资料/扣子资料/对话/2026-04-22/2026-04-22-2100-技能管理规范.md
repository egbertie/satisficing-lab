> 版本：v1.0

## 一、总则

本规范旨在建立扣子（Coze）智能体技能的全生命周期管理体系，实现技能的**标准化获取、分类管理、优先级调度、质量评估与持续优化**。

### 核心目标
- 技能资产可视化、可追溯、可复用
- 建立统一的技能选型与评估标准
- 保障技能质量与系统稳定性
- 推动扣子自制技能的规划与发展

## 四、技能获取流程

### 4.1 流程总览

```
用户需求 → 意图识别 → 平台匹配 → 搜索发现 → 评估筛选 → 安装配置 → 验收测试 → 正式启用
```

### 4.2 详细步骤

#### 步骤1：需求捕获
- **触发条件**：用户表达技能相关需求
- **输入**：用户需求描述（关键词/功能描述）
- **输出**：标准化的技能需求单

#### 步骤2：意图识别与平台选择
| 用户输入特征 | 推荐平台 | 说明 |
|-------------|---------|------|
| 提供URL | 用户指定平台 | 按场景4执行 |
| 提及"虾评" | 虾评Skill平台 | 场景2 |
| 提及"ClawHub" | ClawHub | 场景3 |
| 仅描述功能 | Coze技能商店 | 场景1 |
| 泛化需求 | 多平台综合搜索 | 场景组合 |

#### 步骤3：技能搜索
```
搜索优先级：
1. Coze官方技能商店（优先）
2. 虾评Skill平台（高质量评测）
3. ClawHub（版本管理能力强）
4. 用户指定平台
```

#### 步骤4：质量评估（详见第五章）
- 功能匹配度评分
- 用户评价调研
- 技术可行性验证
- 风险等级评估

#### 步骤5：安装执行
| 平台 | 安装方式 | 凭证要求 |
|-----|---------|---------|
| Coze商店 | `python scripts/install_skill.py <skill_id>` | 无需 |
| 虾评平台 | 下载ZIP→解压→安装 | 注册获取API Key |
| ClawHub | `clawhub install <name> --registry=https://cn.clawhub-mirror.com` | GitHub OAuth |

#### 步骤6：验收测试
- 读取 SKILL.md 理解触发条件
- 执行基础功能测试
- 验证与现有技能的兼容性
- 记录测试结果

#### 步骤7：注册入库
- 更新技能清单
- 补充元数据（版本、来源、依赖）
- 归档安装包和配置

### 4.3 技能获取决策树

```
用户需要XXX技能
      │
      ▼
是否指定平台？
  ├─ 是 → 访问指定URL → 读取agent指南 → 按指南安装
  │
  └─ 否 → 是否指定平台名称？
            ├─ 是 → 使用对应平台
            └─ 否 → Coze商店优先搜索
                      │
                      ▼
              搜索结果如何？
                ├─ 找到满意技能 → 用户确认 → 安装
                ├─ 结果不理想 → 扩展到虾评/ClawHub
                └─ 均无合适 → 标记自制需求
```

## 五、技能使用优先级

### 5.1 优先级矩阵

| 优先级 | 条件组合 | 处置方式 | 响应要求 |
|:-----:|---------|---------|---------|
| P0 | 官方预置 + 核心高频 | 直接加载使用 | 即时响应 |
| P1 | 官方预置 + 常用标准 | 按需加载 | 秒级响应 |
| P2 | 第三方市场 + 评测推荐 | 验证后使用 | 标准响应 |
| P3 | 用户指定 + 场景明确 | 按指南执行 | 确认后执行 |
| P4 | 实验性/未验证 | 谨慎评估后使用 | 告知风险 |

### 5.2 技能组合策略

| 任务类型 | 优先加载 | 备选技能 | 禁用组合 |
|---------|---------|---------|---------|
| 文档报告生成 | docx + excel_master | file-processor, pdf | - |
| 数据可视化 | echart + excel_master | drawio-generator | - |
| 飞书集成 | lark_cli | agent-browser | - |
| 浏览器操作 | agent-browser | - | - |
| 技能管理 | skill-assistant | - | - |

### 5.3 动态调度规则

1. **会话启动时**：加载 P0/P1 类技能到内存
2. **任务执行中**：按需动态加载 P2/P3 类技能
3. **任务完成后**：释放非核心技能
4. **资源紧张时**：优先保障 P0 类技能资源

## 六、技能质量评估

### 6.1 评估维度

| 维度 | 权重 | 评估指标 | 评分标准 |
|-----|:---:|---------|---------|
| 功能完整性 | 25% | 功能覆盖率、边界处理 | 0-10分 |
| 性能表现 | 20% | 响应时间、资源占用 | 0-10分 |
| 稳定性 | 20% | 错误率、异常恢复 | 0-10分 |
| 易用性 | 15% | 文档质量、交互体验 | 0-10分 |
| 安全性 | 10% | 权限控制、数据保护 | 0-10分 |
| 可维护性 | 10% | 代码质量、更新频率 | 0-10分 |

### 6.2 评估流程

```
技能安装 → 基础测试（24h） → 正式评估 → 评分定级 → 准入/拒绝/整改
```

| 评估等级 | 综合得分 | 处置结果 |
|:-------:|:-------:|---------|
| A | ≥8.5 | 优先推荐，高频使用 |
| B | 7.0-8.4 | 标准使用，定期复审 |
| C | 5.5-6.9 | 谨慎使用，需要监控 |
| D | <5.5 | 限制使用或移除 |
