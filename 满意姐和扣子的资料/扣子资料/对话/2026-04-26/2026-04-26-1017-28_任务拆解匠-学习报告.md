# 学习报告：28_任务拆解匠

## 核心概念（1-2句）
**核心信念**: 任何复杂任务都可以拆成3-5分钟可完成的最小单元。拆不开是因为还没拆够细。

## 使用场景（何时用）
- 复杂任务需要分解时
- 任务预估超过10分钟时
- 需要多人/多阶段协作时
- 触发词："拆解" / "拆分" / "分阶段" / "最小单元" / "U1" / "单元" / "从哪下手" / "任务分解"

## 核心咒语/原则（必须会背）

**最小可执行单元定义**：
1. **时间边界**: 可在3-5分钟内完成
2. **完成标准**: 有明确的"完成"判定
3. **独立保存**: 完成后可独立落盘/提交
4. **原子性**: 不可再拆

**3分钟法则**: 如果一个Unit的描述超过3句话，它还可以拆。

**三轮拆分法**：
1. Round 1: 阶段拆分（粗粒度）
2. Round 2: 任务拆分（中粒度）
3. Round 3: 单元拆分（最小粒度）

**依赖类型**：
| 类型 | 符号 | 含义 |
|------|------|------|
| 强依赖 | → | U2必须在U1完成后执行 |
| 弱依赖 | ⇢ | 可并行，但最好等U1 |
| 无依赖 | ∥ | 完全并行 |

**优先级排序公式**：
```
优先级分 = 阻塞度×3 + 不确定性×2 + 价值密度×1.5 + 外部依赖×(-1)
```

**反模式**：不拆直接干 / 拆太细（<1分钟）/ 拆太粗（>10分钟）/ 忽略依赖 / 没有完成标准
