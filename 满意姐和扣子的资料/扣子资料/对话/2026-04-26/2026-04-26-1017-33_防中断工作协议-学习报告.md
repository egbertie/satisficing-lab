# Skill学习报告：33_防中断工作协议

## P0延伸Skill · 第13个 · 2026-04-26

---

### 核心概念（1-2句）

**长任务防中断保护的标准化工作法**。防止半途而废、中途失忆、恢复困难。核心原则：进度可视化、单元化执行、串行不并行、存档即保险。

---

### 5层防中断保护

```
机制1: 进度追踪文件 — 「战场地图」
机制2: 单元化执行 — 「拆到拆不动」
机制3: 串行不并行 — 「一件一件来」
机制4: 防中断存档 — 「存档即保险」
机制5: 恢复协议 — 「从哪里跌倒，从哪里站起来」
```

---

### 机制1：进度追踪文件

**强制格式**：
```markdown
# [任务名称] — 进度追踪

**任务**: [一句话描述]
**启动时间**: YYYY-MM-DD HH:MM
**防中断状态**: 🔄 进行中 / ⏸️ 暂停 / ✅ 完成

---

## 完成清单

### [U1] 单元名称 ✅
**状态**: 完成 | **Git**: [hash] | **产出物**: [路径]

### [U2] 单元名称 🔄
**状态**: 进行中 | **已完成**: [步骤] | **待完成**: [步骤]

### [U3] 单元名称 ⏳
**状态**: 待启动 | **依赖**: [前置单元]
```

---

### 机制2：单元化执行

**拆分标准**：
| 单元类型 | 完成标准 | 预计时间 | 可中断点 |
|:---------|:---------|:---------|:---------|
| 代码单元 | 可运行、可测试 | 15-30分钟 | 每函数后 |
| 文档单元 | 一个完整章节 | 10-20分钟 | 每小节后 |
| 创建单元 | 一个完整文件夹+文件 | 5-15分钟 | 每文件后 |
| 审核单元 | 一个完整检查项 | 3-10分钟 | 每检查后 |

**3分钟法则**：如果3分钟内想不清楚怎么拆，先做原型

---

### 机制3：串行不并行

```
执行流程:
启动单元A → 执行A → 完成A → 更新进度 → Git提交
→ 确认A状态=✅ → 启动单元B → ...

禁止行为:
❌ "我先做A，同时准备B的材料"
❌ "A还差一点点，我先开个头做B"
❌ "多个单元同时推进，效率更高"

原因:
并行=上下文切换损耗+记忆混乱+恢复困难
串行=每个单元完整落盘=随时可中断=随时可恢复
```

---

### 机制4：防中断存档

**3层存档协议**：
| 层级 | 动作 | 时间 | 内容 |
|:-----|:-----|:-----|:-----|
| L1 | 更新进度追踪文件 | 30秒 | 单元状态、Git hash、产出路径 |
| L2 | git add + git commit | 60秒 | 本次单元的全部变更 |
| L3 | 更新memory/YYYY-MM-DD.md | 90秒 | 关键决策、关键产出、下一步 |

**存档口诀**：
```
完成即存档
存档即落盘
落盘即保险
保险即自由
```

---

### 机制5：恢复协议

```
恢复步骤:
1. 读取进度追踪文件 → 确认最后完成的单元
2. 读取Git log → 确认最后提交的hash
3. 检查工作区状态 → 确认是否有未提交的变更
4. 读取memory文件 → 确认关键上下文
5. 更新进度追踪 → 标记"恢复时间"
6. 重新执行当前单元的"5秒自检"
7. 继续执行

恢复时间目标: 从"收到恢复指令"到"开始执行" ≤ 3分钟
```
