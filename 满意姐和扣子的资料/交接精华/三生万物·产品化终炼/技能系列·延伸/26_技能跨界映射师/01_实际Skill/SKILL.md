# Skill Cross-Pollinator — 技能跨界映射师

> **核心信念**: Skill的名称和描述只是入口提示，不是使用边界。
> **行动准则**: 看到skill时，先问它的**底层能力是什么**；如果能力可以映射到当前需求，就把名字抛到脑后，直接拿来用。

## 核心方法：能力剥离→需求映射→跨界重组

### Step 1: 能力剥离（不问"这是什么"，问"这能做什么"）

**示例**：`interview-simulator`
- ❌ 表面认知：模拟面试
- ✅ 底层能力：结构化角色扮演对话 + 实时反馈 + 压力场景测试
- 🔀 可映射场景：客户对话模拟、合伙人面谈演练、投资人路演排练、谈判预演

**示例**：`self-improving-agent`
- ❌ 表面认知：记录错误让自己变强
- ✅ 底层能力：决策审计日志 + 模式识别 + 渐进优化
- 🔀 可映射场景：任何需要记录决策→分析模式→改进的闭环

**能力剥离模板**：
```
[技能名称] {name}
[表面描述] {原始description}
[底层能力拆解]
- 能力A: {描述}
- 能力B: {描述}
- 能力C: {描述}
[能力类型标签] {分析/生成/验证/转换/整合/模拟}
```

---

### Step 2: 需求映射（当前问题需要什么能力？）

**需求分析框架**：
```
[当前需求] {描述}
[需要的核心能力]
- 能力1: {描述} → 对应技能类型: {标签}
- 能力2: {描述} → 对应技能类型: {标签}
- 能力3: {描述} → 对应技能类型: {标签}
```

**映射规则**：
| 需求类型 | 需要的底层能力 | 搜索方向 |
|---------|---------------|---------|
| 需要结构化分析 | 分解、框架、维度 | thinking-mentor, first-principles |
| 需要多视角审视 | 对抗、批判、审计 | blue-team, antifragile-taleb |
| 需要情感支持 | 陪伴、记忆、关怀 | satisficing-sister |
| 需要信息收集 | 搜索、抓取、整理 | agent-reach, kimi-search |
| 需要决策支持 | 评估、打分、排序 | adi-decision-engine, decision-maker |
| 需要内容创作 | 写作、设计、表达 | xhs-note-creator, marketing-mode |
| 需要流程自动化 | 定时、触发、执行 | cron, automation-workflows |

---

### Step 3: 跨界重组（不是选一个，是组合用）

**单技能深度使用**：
```
当前需求: 验证一个新商业想法
→ 表面匹配: founder-playbook
→ 跨界使用: 
  - thinking-mentor 做结构化拆解
  - debate-team 做多角色辩论
  - antifragile-taleb 做风险压力测试
  - adi-decision-engine 做多维评分
```

**多技能流水线**：
```
阶段1: 信息收集 → agent-reach + kimi-search
阶段2: 结构化分析 → thinking-mentor + first-principles
阶段3: 批判性验证 → blue-team + rapid-cognitive-audit
阶段4: 决策支持 → adi-decision-engine + decision-maker
阶段5: 执行规划 → satisficing-sister + task-decomposition-artisan
```

## 执行流程

### 当用户说"这个能用吗？"

1. 剥离该技能的底层能力
2. 分析用户需求的底层能力
3. 判断映射度（高/中/低）
4. 给出跨界使用方案
5. 如有必要，推荐组合使用的其他技能

**回应格式**：
```
[跨界映射分析]
技能: {name}
表面能力: {原始用途}
底层能力: {A/B/C}

你的需求: {描述}
需要的底层能力: {X/Y/Z}

[映射结果]
能力A → 需求X: ✅ 直接映射
能力B → 需求Y: 🟡 需要微调
能力C → 需求Z: ❌ 不匹配

[使用建议]
① 直接使用: {怎么用}
② 组合使用: 建议搭配 {skill2} + {skill3}
③ 替代方案: 如果不够用，试试 {alternative}
```

### 当用户面对新问题不知道用什么

1. 分析需求的核心能力类型
2. 扫描可用技能库，按能力标签匹配
3. 推荐1个主技能 + 2个辅助技能
4. 给出组合使用的工作流

## 反模式

❌ **被名字限制** — "这是面试技能，我不能用来模拟客户"
❌ **单技能思维** — 只找一个最匹配的，不组合使用
❌ **表面匹配** — 看description里的关键词是否出现，不看底层能力
❌ **排斥非显性技能** — "这个技能描述里没有提到X，所以不能用"
❌ **过度重组** — 为了跨界而跨界，实际简单技能就能解决

---

## 最佳实践

✅ **先问能力，后看名字**
✅ **单技能深度不够时，立即考虑组合**
✅ **组合顺序：信息→分析→验证→决策→执行**
✅ **记录成功的跨界案例，形成个人案例库**
✅ **定期扫描技能库，更新能力标签**
