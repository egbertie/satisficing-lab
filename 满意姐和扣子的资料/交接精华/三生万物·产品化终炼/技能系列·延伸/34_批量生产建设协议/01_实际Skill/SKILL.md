## 一、核心机制 — 5步批量生产

### 机制1：模板先行 — 「一次写好，复制百遍」

**定义**  
批量创建前，先写1个完美模板，验证通过后再批量复制。

**模板标准**
```
模板必须经过4级验证：
1. 内容完整性 — 该写的都写了
2. 格式规范性 — 命名、结构、层级统一
3. 可替换性 — 变量位置清晰标注
4. 创始人5分钟可用性 — 焦虑创始人能看懂

模板验证通过标准：
- 替换变量后，文件直接使用，无需二次修改
- 命名规则与系列其他文件一致
- 没有遗漏的分类（如02/03/04）
```

**模板创建流程**
```
写第1个文件（原型）
    ↓
验证通过（4级验证）
    ↓
标记为"模板"
    ↓
提取变量列表
    ↓
准备批量替换
```

**退化信号** 🚨
- 边写边复制，第3个发现前面格式错了
- "先写几个试试，后面再统一"
- 文件命名不一致（有的用01_有的用1_）

---

### 机制2：清单核对 — 「按清单，不凭记忆」

**定义**  
批量创建前，必须有完整的文件清单。按清单执行，不凭记忆。

**强制清单格式**
```markdown
# 批量生产清单 — [任务名称]

## 批次1：[批次名称]
| # | 文件夹 | 文件 | 状态 |
|---|--------|------|------|
| 1 | XX_[名称]/01_实际Skill/ | SKILL.md | ⏳ |
| 2 | XX_[名称]/02_使用说明与实操指引/ | 01_设计理念.md | ⏳ |
| 3 | XX_[名称]/02_使用说明与实操指引/ | 02_快速上手.md | ⏳ |
| ... | ... | ... | ... |

## 验证检查
- [ ] 全部文件已创建
- [ ] 命名格式统一
- [ ] 内容变量已替换
- [ ] Git已提交
```

**清单创建时机**: 模板验证通过后立即创建
**清单更新时机**: 每完成一个文件立即标记状态

---

### 机制3：批量生成 — 「用脚本，不用手」

**定义**  
能用脚本批量生成的，不用手工复制。减少人为错误。

**脚本化标准**
```python
# 批量生成示例
folders = [
    "01_实际Skill", "02_使用说明与实操指引",
    "03_全开源文档", "04_微信传播版本"
]
files = {
    "01": ["SKILL.md"],
    "02": ["01_设计理念.md", "02_快速上手.md",
           "03_深度解析.md", "04_协作.md"],
    "03": ["01_开源协议.md", "02_贡献指南.md",
           "03_版本历史.md", "04_关系图.md"],
    "04": ["麦肯锡电梯演讲版.md"]
}

# 批量创建
def create_skill_package(skill_name, skill_number):
    for folder in folders:
        os.makedirs(f"{skill_number}_{skill_name}/{folder}", exist_ok=True)
    # ... 复制模板并替换变量
```

**手工创建场景**
- 内容差异大，无法模板化
- 需要深度定制的内容（如SKILL.md核心协议）
- 数量少（<5个文件）

---

### 机制4：逐个验证 — 「生产一个，验证一个」

**定义**  
不是全部生产完再验证，是生产一个、验证一个。

**验证标准**
| 验证项 | 通过标准 | 检查方式 |
|:-------|:---------|:---------|
| 文件存在 | 路径正确，文件已写入 | `ls` / `cat` |
| 命名统一 | 符合系列命名规则 | 目视检查 |
| 内容替换 | 变量已替换为实际内容 | 抽样阅读 |
| 格式正确 | Markdown语法无误 | 渲染测试 |
| 链接有效 | 内部链接指向正确 | 点击测试 |

**验证时机**: 每个文件创建后立即验证
**批量验证时机**: 全部完成后执行全量检查

---

### 机制5：批次提交 — 「一批一提交，不堆到最后」

**定义**  
不是全部文件创建完再Git提交，是每批次完成后立即提交。

**提交策略**
```
批次1完成（如7个技能）
    ↓
验证通过
    ↓
git add + commit "feat: 批次1 — 7个技能"
    ↓
批次2开始
```

**提交信息格式**
```
feat: 批次X — [数量]个[任务类型] [描述]
```

## 二、使用流程 — 批量生产完整SOP

### 阶段1：准备（10分钟）

```
确认批量生产需求
    ↓
写第1个文件（原型）
    ↓
4级验证原型
    ↓
标记为模板
    ↓
提取变量列表
    ↓
创建批量生产清单
    ↓
准备生成脚本（如需要）
```

### 阶段2：生产（按清单执行）

```
读取清单第1项
    ↓
创建文件（脚本或手工）
    ↓
立即验证
    ↓
标记清单状态 = ✅
    ↓
下一项
```

### 阶段3：批次提交（每批次后）

```
批次文件全部创建+验证
    ↓
git status 检查
    ↓
git add .
    ↓
git commit -m "feat: 批次X — ..."
    ↓
更新进度追踪
```

### 阶段4：全量验证（全部完成后）

```
全量清单核对
    ↓
抽样深度检查
    ↓
命名一致性检查
    ↓
全量Git提交
    ↓
完成汇报
```

## 四、实战场景 — 满分/及格/不及格对比

### 场景：批量创建25个技能的全套文件

| 等级 | 执行方式 |
|:-----|:---------|
| **不及格** ❌ | 边想边写，边写边改。写到第10个发现命名格式错了，前9个全部返工。最后Git提交时，文件太多，提交信息混乱。 |
| **及格** 🟡 | 先写了2个作为模板，然后批量复制。但中途发现03文件夹少了一个文件，后面补充。Git一次性提交全部。 |
| **满分** ✅ | 先写1个原型，4级验证通过后标记为模板。创建批量清单（250项）。用脚本批量创建文件夹结构。手工写核心内容（SKILL.md），复制模板填充通用内容。每批次完成后立即验证+Git提交。全部完成后全量核对，0遗漏。 |
