## 一、系统守护类（你的"免疫系统"）

---

### 1. system-guardian.py · 系统健康统一守护中枢

**一句话**：你的"身体体检仪"。每天自动扫描系统健康，发现问题自动报警+自动清理。

**它是干嘛的？**
想象你有一台服务器，这个脚本就是每天给服务器做体检的医生。它检查：
- 磁盘够不够（会不会满了？）
- 内存够不够（会不会卡死？）
- Token花超了没有（预算还剩多少？）
- 后台任务有没有异常（有没有脚本跑崩了？）

**什么时候跑？**
- 自动：每周日 03:17（OpenClaw cron定时）
- 手动：你随时可以说"系统扫一下"
- 触发：磁盘超过75%时自动启动清理

**如果出问题了，你会看到什么？**
```
🔴 危险：磁盘使用率 85%（>75%阈值）
🟡 警告：Token本周已消耗 78%
🟢 健康：基线错误率 0.02%
```

**你需要做什么？**
- 看到🔴危险：立即告诉满意姐"磁盘检查一下"
- 看到🟡警告：关注，但不需要立即行动
- 看到🟢健康：不用管，继续工作

**常用指令**：
```bash
python3 scripts/system-guardian.py auto       # 自动巡检+清理
python3 scripts/system-guardian.py scan       # 只看报告，不动手
python3 scripts/system-guardian.py full-clean # 全盘大清理（慎用）
```

## 二、Token经济类（你的"财务管家"）

---

### 3. token-tracker-zero.py · Token零消耗监控器

**一句话**：你的"记账本"。每天自动算Token花了多少、还剩多少、用得快还是慢——而且记账本身不花Token。

**它是干嘛的？**
想象Token是你的零花钱：
- 每天自动算"今天花了多少"
- 每周自动算"本周花了多少、还剩多少"
- 如果发现花得太快，自动喊"降频"（省着点用）
- 如果快用完了，自动进入"静默模式"（不说话了，只干最紧急的事）

**什么时候跑？**
- 自动：每次heartbeat（约30分钟一次）
- 自动：每日结算时
- 手动：你想查Token时

**如果出问题了，你会看到什么？**
```
⚠️ 本周Token消耗 85% → 建议进入L2休眠（降频33%）
🔴 今日消耗超预算50% → 仅保留P0任务
```

**你需要做什么？**
- 看到⚠️：知道接下来系统会自动"省着点用"，你不需要操作
- 看到🔴：检查是不是有任务在疯狂消耗Token，必要时喊满意姐停掉后台任务
- 平时不用管，系统自动处理

**重要**：这个脚本"看账本不花钱"——它读的是本地文件，不调用API，所以监控本身零消耗。

---

### 4. token-circuit-breaker.py · Token熔断器

**一句话**：你的"保险丝"。Token花太快了，自动"断电"保护。

**它是干嘛的？**
想象你家里的电表：
- 用电量正常 → 一切照常
- 用电量突然暴增 → 保险丝跳闸，保护电路

对应到Token：
- 日消耗<30%周预算 → 正常
- 日消耗>30% → 自动降频50%（省着点）
- 日消耗>50% → 只保留P0（最紧急的）
- 连续异常3次 → 暂停所有后台任务

**什么时候跑？**
- 自动：每次token-tracker-zero结算时联动触发
- 手动：你想测试熔断机制时

**如果出问题了，你会看到什么？**
```
🔴 熔断触发：Level 2 — 仅保留P0任务
原因：今日消耗52%，超过50%阈值
```

**你需要做什么？**
- 看到熔断：理解系统在"自我保护"，不是因为坏了
- 不需要手动恢复，系统自动在下一个周期解除
- 如果频繁熔断，跟满意姐说"Token预算需要调整"

### 5. token_monitor.py · Token实时监控

**一句话**：你的"实时余额表"。想看Token余额时，它告诉你"还剩多少、用了多少"。

**它是干嘛的？**
比token-tracker-zero更轻量，只做一件事：
- 读取当前Token消耗数据
- 输出一个简洁报告

**什么时候跑？**
- 手动：你想查Token时
- 自动：系统需要快速了解Token状态时

**如果出问题了，你会看到什么？**
```
今日: 45,000 tokens
本周: 320,000 tokens (32%)
档位: L1 正常
状态: 🟢
```

**你需要做什么？**
- 平时不用管，想看余额时随时查
- 不需要做任何操作

### 6. token_weekly_reporter.py · Token周报生成器

**一句话**：你的"周报秘书"。每周三自动生成Token周报，告诉你"这周花得值不值"。

**它是干嘛的？**
每周三09:00自动跑，生成一份报告：
- 本周消耗总量
- 消耗最多的任务是什么
- 后台任务 vs 前台任务的比例
- 下周期建议（该增预算还是该省？）

**什么时候跑？**
- 自动：每周三 09:00（OpenClaw cron）
- 手动：你想提前看周报时

**如果出问题了，你会看到什么？**
报告会显示在 `A-manyige/汇报/日报/` 目录下，文件名 `token-weekly-report-YYYY-MM-DD.md`

**你需要做什么？**
- 每周三看一眼报告（5分钟）
- 如果报告显示"后台任务消耗占比>50%"，考虑调整自动化策略
- 如果报告显示"异常峰值"，回顾那天做了什么

### 7. conversation-guardian.py · 对话守护

**一句话**：你的"门卫"。防止敏感信息泄露、防止对话被滥用。

**它是干嘛的？**
检查每次对话内容：
- 有没有敏感信息（密码、API Key、个人隐私）
- 有没有违规内容
- 对话上下文是否异常（比如突然被要求做不该做的事）

**什么时候跑？**
- 自动：每次对话开始前快速扫描
- 自动：发现异常时拦截

**如果出问题了，你会看到什么？**
```
⚠️ 检测到敏感词：[关键词]
🔴 对话被拦截：包含疑似API Key
```

**你需要做什么？**
- 看到⚠️：检查一下对话内容，确认是否误报
- 看到🔴：立即停止，检查是不是有人试图获取敏感信息
- 平时不用管，自动运行

## 七、FAQ（创始人常问）

**Q1：这些脚本会自己跑崩吗？**
A：有可能，但概率很低。如果跑崩了，system-guardian会检测到并通知你。

**Q2：我需要学Python才能用这些吗？**
A：完全不需要。所有脚本都是自动运行的，你只需要看懂上面的"你需要做什么"部分。

**Q3：如果看到🔴危险，我该怎么办？**
A：喊满意姐。说"system-guardian scan"或直接描述问题。满意姐会处理。

**Q4：这些脚本花Token吗？**
A：大部分不花。token-tracker-zero、token_monitor等是本地计算，零消耗。只有需要调用API的才会花Token（比如案例采集）。

**Q5：我能关掉某个脚本吗？**
A：可以，但不建议。每个脚本都有它的职责，关掉等于关掉一道防线。如果确实需要调整，跟满意姐说。

**Q6：脚本出问题了，我怎么知道？**
A：三个渠道：
1. 系统守护的告警（最直接）
2. 晨报中的异常摘要（每天看）
3. 满意姐主动通知（P0紧急时）
