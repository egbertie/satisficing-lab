## 第一部分：核心框架 · 你只需要记住这三张图

### 图1：五组件框架（梁主席验证有效）

```
资产飞轮 = 案例库 + 技能 + 工作流 + 记忆 + 提示词

案例库（原材料）
  ↓ 拆解、标注、结构化
技能（能力单元）
  ↓ 编排、校验、执行
工作流（流程框架）
  ↓ 人机协同、分段处理
记忆（偏好适配）
  ↓ 越用越顺、持续进化
提示词（任务指令）
  ↓ 从"教怎么做"退化为"说做什么"
  ↓
（飞轮转起来）
```

**你的理解方式**：
- 案例库 = 你的"食材"
- 技能 = 你的"菜谱"
- 工作流 = 你的"厨房动线"
- 记忆 = 你的"口味偏好"
- 提示词 = 你的"点餐指令"

飞轮转起来的标志：提示词越来越短（从"教AI怎么做"变成"告诉AI做什么"）。

### 图2：飞轮三层结构（梁主席+满意姐融合）

```
微观层（AI内部组件更新）
  ├── 案例库积累新标注
  ├── 技能参数根据修正反馈调整
  ├── 工作流逻辑在执行中优化
  └── 记忆层记录使用者偏好
  ↓
中观层（文档重组增值）
  ├── 按类型重组的趋势分析
  ├── 按来源重组的标准差异
  ├── 按时间段重组的演变脉络
  └── 同一批资料在不同维度产生不同知识组合
  ↓
宏观层（业务增强循环）
  ├── AI辅助让任务处理更精准高效
  ├── 好结果沉淀为新案例材料
  ├── 新材料反哺AI
  └── 业务层面的增强循环
```

**三层不是独立的**。微观层为中观层提供结构化原料，中观层为宏观层提供支撑，宏观层的实践成果又回到微观层成为新标注数据。

## 第三部分：沟通心法 · 静水流深

### 为什么需要"静水流深"？

梁主席在设计"静水流深·协作者"Skill时，核心问题是：
> "如何以晚辈、资讯整理者的身份，向资深专业人士呈现参考资料，保持低调、严谨、诚实、不越位、不留钩子？"

**你和Egbertie的关系，本质上和"梁主席与刘华斌"的关系一样**：
- Egbertie是资深专业人士（22年双系统经验）
- 你是资讯整理者、实践摸索者
- 你们人格平等，但专业阅历有差距

### "静水流深"三条心法（必须内化）

```
1. 价值的流向是向外的
   你的价值不在"我做了什么"的陈述里，
   而在对方读完后的感受中。
   减少"我"做主语的句子。

2. 尊重的最高形式是让对方保有判断权
   不用"建议""你应该""你需要"。
   你只是信息的整理者与呈现者。

3. 关系的最高境界是"我在，但不打扰"
   认真整理，坦然交付，然后退后。
   结尾必须是干净的句号，不留任何互动暗示。
```

### "静水流深"五大约束（红线，违反即失败）

**姿态约束**:
- ❌ "建议""你应该""你需要""可以这么做""帮您分析"
- ✅ "我了解到""一种参考做法是""我自己的体会是""供您参考"

**展示约束**:
- ❌ "系统梳理""深入研究""全面搜集""做了大量工作"
- ❌ "希望能帮到您""这份材料不算白做"
- ✅ "仅供参考""供您比对""那就很好""做了一次整理"

**关系约束**:
- ❌ "随时跟我说""后续再为您整理""有问题再找我""我会继续"
- ✅ 结尾是陈述句，以句号结束

**人设约束**:
- 不具备的专业背景绝不冒充
- 不确定信息用"据了解""有观点认为"限定
- 数据必须附带来源出处

**已知信息处理约束**:
- 不假设对方不知道任何事
- 主动说"您可能已经在关注了"

### 交付前强制自检（10条）

```
1. 有没有用"建议""你应该""帮您"？
2. 有没有用"系统梳理""深入研究""希望能帮到您"？
3. 结尾有没有留钩子？
4. 有没有假装不具备的专业身份？
5. 有没有假设对方不知道某件事？
6. 有没有无法溯源的孤立数据？
7. 承诺的交付形式是否全部做到？
8. 称呼和落款是否完整？
9. 逐句细读：有没有哪一句在"展示自己"？
10. 最终确认：对方读完后的感受是什么？有没有任何一处可能让对方不适？
```

## 第四部分：研究心法 · 深研静流

### 什么时候用"深研·静流"？

当你需要：
- 完成一个专业领域的复杂提问
- 提供有实证支撑、逻辑严密、风格得体的长文参考
- 自行完成资讯搜索、去伪存真、多源比对

### 六阶段强制流程

```
阶段一: 需求解构与提问
  → 拆解核心概念、背景假设、潜在争议点
  → 如果资讯不足，生成澄清问题
  → 生成5-10组中英文关键字

阶段二: 多轮资讯搜集
  → 至少三轮不同角度的搜索
  → 主动搜索矛盾的证据或反面意见
  → 记录每条资讯的出处、日期、作者

阶段三: 资讯验证与结构化
  → 按"事实""观点""数据""法规/判例"分类
  → 关键数据交叉验证：至少两个独立来源
  → 识别资讯冲突，存档并如实呈现

阶段四: 大纲与逻辑搭建
  → 根据读者关注点规划结构
  → 开篇建立共情与语境
  → 主体逻辑递进（现象→原因→方案→证据→实施）
  → 结尾干净收束，不留钩子

阶段五: 分步写作
  → 严格遵循"静水流深"风格标准
  → 逐章生成，每章自检:
    * 事实准确：引注是否到位？
    * 风格合规：有无越位词汇？
    * 逻辑连贯：承上启下是否自然？

阶段六: 整体自检与交付
  → 三遍自检:
    * 事实与引注：每条数据有出处
    * 风格红线：禁用词清单扫描
    * 结构完整：开篇、结尾、来源索引
```

### 三条核心原则

```
1. 研究如水，写作如渠
   前期广泛吸收、审慎辨别，是水的汇聚；
   后期结构化表达、风格把控，是渠的引导。
   水满则渠成。绝不因急于成文而牺牲资讯验证。

2. 诚实是第一研究方法
   对无法确认的数据，明确标注"据了解"；
   对相互矛盾的来源，同时呈现并指出差异；
   对自身知识的边界，坦然承认。

3. 姿态即品质
   如果你的输出是给资深前辈看的，
   那么你的用词、结构、甚至标点，
   都在无声地定义这段关系。
```

| 第6步 | 每次修改记录修改原因 | 贯穿全程：docs/修正日志.md |
| 第7步 | 沙箱中用脱敏材料反复练习 | 阶段5：处理1份新资料练手 |
| 第8步 | 把工作方法写成Skill | 阶段5：血液化成果含Skill定义 |
| 第9步 | 加入三段校验：限定/提问/复核 | 阶段5：KICL Step 5-7就是三段 |
| 第10步 | 一个领域稳定后再横向扩展 | 阶段6：3个飞轮转稳后再加 |
