```

│   ├─ GET /courses

│   └─ GET /courses/:id/progress
└─ 依赖：用户服务、订单服务

服务3：测评服务（Test Service）
├─ 职责：测评问卷、结果计算
├─ 数据：问卷表、题目表、结果表
├─ API：
│   ├─ GET /tests
│   ├─ POST /tests/:id/start
│   ├─ POST /tests/:id/submit
│   └─ GET /tests/:id/result
└─ 依赖：用户服务、AI服务

服务4：订单服务（Order Service）
├─ 职责：订单、支付、退款
├─ 数据：订单表、支付表
├─ API：
│   ├─ POST /orders
│   ├─ POST /orders/:id/pay

│   └─ POST /orders/:id/refund
└─ 依赖：用户服务、通知服务

服务5：内容服务（Content Service）
├─ 职责：文章、视频、资料

│   ├─ GET /contents
```

### 3.2 API设计规范

```
【RESTful规范】

URL设计：
├─ 资源名用复数：/users, /courses
├─ 层级关系：/users/:id/orders
├─ 动词用HTTP方法：GET/POST/PUT/DELETE
└─ 版本控制：/v1/users

请求格式：
├─ Content-Type: application/json
├─ 编码：UTF-8
└─ 字段：驼峰命名

响应格式：
{
  "code": 200,
  "message": "success",
  "data": { ... },
  "timestamp": 1714003200
}

错误码：
├─ 200：成功
├─ 400：请求参数错误
├─ 401：未认证
├─ 403：无权限
├─ 404：资源不存在
├─ 500：服务器错误
└─ 503：服务不可用

【鉴权设计】
├─ JWT Token：Access Token + Refresh Token
├─ Token有效期：Access 2小时，Refresh 7天
├─ 刷新机制：自动刷新
├─ 注销机制：Token黑名单
└─ 权限控制：RBAC（角色权限）
```

## 第四部分：数据架构

### 4.1 数据库设计

```
【核心表结构】

用户表（users）
├─ id: BIGINT PK
├─ email: VARCHAR(255) UNIQUE
├─ phone: VARCHAR(20) UNIQUE
├─ password_hash: VARCHAR(255)
├─ name: VARCHAR(100)
├─ avatar: VARCHAR(500)
├─ role: ENUM('user', 'coach', 'admin')
├─ status: ENUM('active', 'inactive', 'banned')
├─ created_at: TIMESTAMP
└─ updated_at: TIMESTAMP

课程表（courses）
├─ id: BIGINT PK
├─ title: VARCHAR(255)
├─ description: TEXT
├─ price: DECIMAL(10,2)
├─ level: ENUM('初级', '中级', '高级')
├─ status: ENUM('draft', 'published', 'archived')
├─ created_at: TIMESTAMP
└─ updated_at: TIMESTAMP

订单表（orders）
├─ id: BIGINT PK
├─ user_id: BIGINT FK
├─ course_id: BIGINT FK
├─ amount: DECIMAL(10,2)
├─ status: ENUM('pending', 'paid', 'refunded')
├─ pay_method: ENUM('wechat', 'alipay')
├─ created_at: TIMESTAMP
└─ updated_at: TIMESTAMP

测评表（tests）
├─ id: BIGINT PK
├─ user_id: BIGINT FK
├─ type: ENUM('PMM', 'DMS', 'CRA')
├─ score: DECIMAL(5,2)
├─ result: JSON
├─ created_at: TIMESTAMP
└─ updated_at: TIMESTAMP

【数据安全】
├─ 加密：敏感字段加密存储（AES-256）
├─ 备份：每日自动备份+异地备份
├─ 审计：操作日志记录
├─ 脱敏：测试环境数据脱敏
└─ 归档：历史数据归档
```

---

### 4.2 缓存策略

```
【缓存分层】

L1：本地缓存（Caffeine）
├─ 数据：热点数据
├─ 容量：10MB
├─ TTL：5分钟
└─ 适用：配置信息、字典数据

L2：分布式缓存（Redis）
├─ 数据：会话、计数、排行榜
├─ 容量：1GB
├─ TTL：根据业务设定
└─ 适用：用户会话、缓存页面

L3：CDN缓存
├─ 数据：静态资源
├─ TTL：1天-30天
└─ 适用：图片、视频、JS/CSS

【缓存更新】
├─ 主动更新：数据变更时更新缓存
├─ 被动更新：TTL到期后更新
├─ 预热：启动时加载热点数据
└─ 淘汰：LRU策略
```

## 第六部分：安全架构

### 6.1 安全体系

```
【分层防护】

层1：网络安全
├─ DDoS防护：阿里云DDoS高防
├─ WAF：Web应用防火墙
├─ 防火墙：安全组+ACL
└─ VPN：运维访问VPN

层2：应用安全
├─ 鉴权：JWT + RBAC
├─ 防注入：参数化查询
├─ 防XSS：输入过滤+输出编码
├─ 防CSRF：Token验证
└─ 防爬虫：验证码+限流

层3：数据安全
├─ 加密：传输TLS 1.3 + 存储AES-256
├─ 脱敏：测试环境脱敏
├─ 备份：每日备份+异地
├─ 审计：操作日志
└─ 销毁：过期数据安全删除

层4：运维安全
├─ 访问控制：跳板机+审计
├─ 漏洞扫描：定期扫描
├─ 应急响应：安全事件预案
├─ 合规：等保2.0（远期）
└─ 培训：安全意识培训

【合规要求】
├─ 等保2.0：三级（远期）
├─ GDPR：欧盟用户数据处理（远期）
├─ 个人信息保护法：符合中国法规
├─ 数据安全法：数据分类分级
└─ 网络安全法：安全责任
```
