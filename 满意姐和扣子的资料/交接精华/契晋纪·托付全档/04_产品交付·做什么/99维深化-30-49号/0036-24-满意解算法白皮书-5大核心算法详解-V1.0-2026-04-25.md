## 第一部分：算法设计哲学

### 1.1 核心原则

```
【原则1：可解释性优先】
├─ 每个算法结果都能解释"为什么"
├─ 不做"黑盒"模型
├─ 用户能看懂评估逻辑
└─ 例：匹配度80分 → "因为互补性90分，价值观85分..."

【原则2：多维度综合】
├─ 单一指标不可靠
├─ 至少3个维度交叉验证
├─ 权重根据场景动态调整
└─ 例：早期团队看重互补性，成熟团队看重价值观

【原则3：数据驱动+专家经验】
├─ 70%数据驱动（统计模型）
├─ 30%专家经验（Egbertie 22年经验固化）
├─ 不盲目信数据，也不唯经验论
└─ 例：算法给出建议，但最终决策在人

【原则4：持续迭代】
├─ 算法不是一成不变
├─ 根据用户反馈、案例结果持续优化
├─ A/B测试验证改进效果
└─ 例：每季度更新一次权重参数

【原则5：隐私保护】
├─ 用户数据加密存储
├─ 算法训练用脱敏数据
├─ 评估结果仅用户本人可见
└─ 符合GDPR/个人信息保护法
```

## 第二部分：核心算法详解

### 2.1 合伙人匹配度算法（Partner Matching Model, PMM）

```
【算法目标】
评估两个合伙人之间的匹配程度，0-100分。

【输入维度】（5大维度，25个子维度）

维度1：互补性（权重30%）
├─ 技能互补：技术vs市场、产品vs运营
├─ 性格互补：内向vs外向、理性vs感性
├─ 经验互补：行业经验vs创业经验
├─ 资源互补：资金vs人脉、技术vs渠道
└─ 评估方式：自评+互评+第三方观察

维度2：价值观（权重25%）
├─ 创业动机：财富vs理想vs成就感
├─ 风险偏好：保守vs激进
├─ 时间观念：长期主义vs短期回报
├─ 诚信标准：对"底线"的定义
└─ 评估方式：情景测试+深度访谈

维度3：沟通风格（权重20%）
├─ 表达习惯：直接vs委婉
├─ 冲突处理：对抗vs回避vs协作
├─ 反馈偏好：即时vs定期
├─ 决策参与：独裁vs民主
└─ 评估方式：DISC测评+沟通模拟

维度4：能力评估（权重15%）
├─ 核心能力：技术/市场/产品/运营
├─ 学习能力：成长速度
├─ 执行力：从想到做的速度
├─ 领导力：带团队能力
└─ 评估方式：历史项目复盘+能力测试

维度5：承诺度（权重10%）
├─ 时间投入：全职vs兼职
├─ 资金投入：出资比例
├─ 精力分配：优先级排序
├─ 退出意愿：长期vs短期
└─ 评估方式：承诺清单+行为验证

【算法公式】
匹配度 = Σ(维度得分 × 维度权重)

其中：
├─ 每个维度得分 = 子维度平均（去掉最高最低）
├─ 维度权重根据公司阶段调整
│   ├─ 种子期：互补性40% + 价值观20% + ...
│   ├─ 天使期：互补性30% + 价值观25% + ...
│   └─ A轮后：互补性20% + 价值观30% + ...
└─ 最终得分：0-100，保留1位小数

【结果解读】
├─ 90-100：高度匹配（理想合伙人）
├─ 80-89：良好匹配（需关注弱项）
├─ 70-79：一般匹配（需要磨合）
├─ 60-69：较低匹配（风险较高）
└─ <60：不匹配（建议 reconsider）

【算法验证】
├─ 历史案例回测：算法预测 vs 实际结果
├─ 准确率目标：>75%（预测匹配度高且实际合作成功）
├─ 持续优化：每季度根据新案例调整权重
└─ 人工复核：算法结果由教练人工复核
```

### 2.2 决策成熟度评分算法（Decision Maturity Score, DMS）

```
【算法目标】
评估创始人/团队的决策成熟度，0-100分。

【评估维度】（5大维度，20个子维度）

维度1：决策意识（20%）
├─ 是否意识到决策的重要性
├─ 是否有决策流程
├─ 是否记录决策
└─ 是否复盘决策

维度2：信息收集（20%）
├─ 收集信息的全面性
├─ 信息来源的多样性
├─ 信息验证的严谨性
└─ 信息更新的及时性

维度3：分析能力（20%）
├─ 逻辑分析能力
├─ 数据分析能力
├─ 风险评估能力
└─ 情景规划能力

维度4：执行能力（20%）
├─ 决策速度
├─ 执行力度
├─ 调整灵活性
└─ 结果追踪

维度5：反思能力（20%）
├─ 决策复盘频率
├─ 错误承认度
├─ 改进意愿
└─ 学习速度

【算法公式】
成熟度 = Σ(维度得分 × 维度权重)

其中：
├─ 每个维度得分 = 子维度加权平均
├─ 权重根据角色调整
│   ├─ CEO：决策意识25% + 执行能力25% + ...
│   └─ COO：执行能力30% + 分析能力25% + ...
└─ 最终得分：0-100，保留1位小数

【等级划分】
├─ 90-100：决策大师（可独立复杂决策）
├─ 80-89：决策高手（需偶尔指导）
├─ 70-79：决策熟手（需要系统学习）
├─ 60-69：决策新手（需要大量指导）
└─ <60：决策初学者（建议从基础开始）

【应用】
├─ 课程推荐：根据成熟度推荐适合的课程
├─ 辅导强度：成熟度低→高强度辅导
├─ 团队配置：成熟度低→配决策教练
└─ 成长追踪：每季度复测，看成长曲线
```

### 2.3 冲突风险评估算法（Conflict Risk Assessment, CRA）

```
【算法目标】
评估合伙人关系中的冲突风险，0-100分（分数越高风险越大）。

【风险指标】（5大类，20个指标）

指标1：沟通频率异常（权重20%）
├─ 定义：沟通频率低于历史平均50%
├─ 数据采集：企业微信/邮件/会议记录
├─ 计算：(历史平均 - 当前频率) / 历史平均
└─ 阈值：>50%为高风险

指标2：决策分歧率（权重20%）
├─ 定义：重大决策中合伙人投票不一致的比例
├─ 数据采集：决策记录
├─ 计算：分歧次数 / 总决策次数
└─ 阈值：>30%为高风险

指标3：情绪指标（权重15%）
├─ 定义：沟通中的负面情绪占比
├─ 数据采集：NLP分析企业微信/邮件文本
├─ 计算：负面情绪词频 / 总词频
└─ 阈值：>20%为高风险

指标4：角色模糊度（权重15%）
├─ 定义：职责重叠或空白的程度
├─ 数据采集：决策权矩阵对比
├─ 计算：重叠职责数 / 总职责数
└─ 阈值：>25%为高风险

指标5：外部压力（权重15%）
├─ 定义：融资压力、业绩压力、竞争压力
├─ 数据采集：财务数据+市场数据
├─ 计算：综合压力指数
└─ 阈值：>70分为高风险

指标6：历史冲突（权重15%）
├─ 定义：过去6个月的冲突次数和强度
├─ 数据采集：冲突记录+双方自评
├─ 计算：加权平均冲突强度
└─ 阈值：>3次重大冲突为高风险

【算法公式】
风险分 = Σ(指标得分 × 指标权重)

其中：
├─ 每个指标得分：0-100，根据阈值映射
├─ 权重根据公司阶段调整
└─ 最终得分：0-100，分数越高风险越大

【风险等级】
├─ 0-30：低风险（绿色）→ 日常维护
├─ 31-50：中风险（黄色）→ 预警，加强沟通
├─ 51-70：高风险（橙色）→ 立即干预，教练介入
├─ 71-90：极高风险（红色）→ 紧急处理，可能需调解
└─ 91-100：危机（深红）→ 立即启动危机处理流程

【预警机制】
├─ 每周自动计算风险分
├─ 风险分>50：自动通知Egbertie+相关教练
├─ 风险分>70：自动启动干预流程
└─ 每月生成风险趋势报告
```

### 2.4 股权动态调整算法（Equity Dynamic Adjustment, EDA）

```
【算法目标】
根据合伙人贡献变化，动态调整股权比例。

【输入参数】

参数1：初始股权（Initial Equity）
├─ 定义：创业初期的股权分配
├─ 来源：合伙人协议
└─ 权重：基础值

参数2：贡献度（Contribution）
├─ 定义：合伙人在各维度的贡献
├─ 维度：
│   ├─ 资金投入（30%）
│   ├─ 时间投入（25%）
│   ├─ 业绩贡献（25%）
│   ├─ 资源引入（10%）
│   └─ 风险承担（10%）
├─ 评估周期：每季度评估
└─ 评估方式：自评+互评+数据验证

参数3：成熟期（Vesting Period）
├─ 定义：股权兑现的时间进度
├─ 标准：4年vesting，1年cliff
├─ 计算：已工作时间 / 总vesting时间
└─ 已成熟股权 = 初始股权 × 成熟比例

参数4：调整因子（Adjustment Factor）
├─ 定义：根据贡献度变化的调整系数
├─ 计算：当前贡献度 / 初始贡献度
└─ 调整幅度：单次不超过±5%

【算法公式】
调整后股权 = 已成熟股权 × (1 + 调整因子)

其中：
├─ 调整因子 = (当前贡献度 - 初始贡献度) / 初始贡献度
├─ 调整上限：单次±5%，累计±20%
├─ 调整周期：每年1次（或重大里程碑时）
└─ 调整需全体合伙人一致同意

【示例】
初始：
├─ 合伙人A：50%股权，初始贡献度100
├─ 合伙人B：50%股权，初始贡献度100

1年后：
├─ 合伙人A贡献度：120（超预期）
├─ 合伙人B贡献度：80（低于预期）

调整因子：
├─ A：+20% → 调整上限+5%
├─ B：-20% → 调整上限-5%

调整后（假设都成熟25%）：
├─ A：50% × 25% × 1.05 = 13.125%
├─ B：50% × 25% × 0.95 = 11.875%
├─ 未成熟部分：按新比例分配

【边界条件】
├─ 单次调整不超过±5%
├─ 累计调整不超过±20%
├─ 调整需全体一致同意
├─ 创始人保留一票否决权
└─ 调整后需更新合伙人协议
```

### 2.5 五维综合评估算法（Five-Dimension Assessment, 5DA）

```
【算法目标】
综合评估合伙人/团队的五维决策能力。

【五维定义】（与五维决策框架对应）

维度1：土·伦理底座（Ethics）
├─ 权重：20%
├─ 指标：诚信度、责任感、公平意识、价值观一致性
├─ 评估：情景测试+历史行为验证
└─ 得分：0-100

维度2：金·满意解标准（Satisficing）
├─ 权重：20%
├─ 指标：决策效率、满意解接受度、时间管理能力、优先级排序
├─ 评估：决策模拟+时间日志分析
└─ 得分：0-100

维度3：水·洞察本质（Insight）
├─ 权重：20%
├─ 指标：第一性原理应用、5Why分析、本质把握、直觉准确性
├─ 评估：案例分析+深度访谈
└─ 得分：0-100

维度4：木·信任治理（Trust）
├─ 权重：20%
├─ 指标：信任建立速度、信任维护能力、信任修复能力、透明度
├─ 评估：信任问卷+行为观察
└─ 得分：0-100

维度5：火·行动转化（Action）
├─ 权重：20%
├─ 指标：执行力、决策速度、试错勇气、调整灵活性
├─ 评估：项目复盘+行为数据
└─ 得分：0-100

【算法公式】
五维总分 = Σ(维度得分 × 维度权重)

其中：
├─ 每个维度权重：默认20%，可根据场景调整
├─ 早期团队：火·行动30%，土·伦理15%
├─ 成熟团队：土·伦理25%，水·洞察25%
└─ 最终得分：0-100，保留1位小数

【五维雷达图】
├─ 可视化：5维雷达图
├─ 强项：得分最高的2个维度
├─ 弱项：得分最低的2个维度
├─ 建议：针对弱项的训练建议
└─ 应用：课程推荐、辅导重点、团队配置

【五维组合类型】
根据五维得分组合，分为12种类型：
├─ 类型1：土强金弱（ Ethics强，Satisficing弱）
├─ 类型2：水强火弱（ Insight强，Action弱）
├─ ...（详见12类型冲突案例库）
└─ 每种类型对应不同的发展建议
```

```

└─ 评估指标：准确率、召回率、F1值

【模型部署】
├─ 实时计算：用户提交后立即计算
├─ 批量计算：每周批量更新风险分
├─ API接口：供其他系统调用
└─ 监控：模型性能监控、异常告警
```

### 3.2 算法验证

```
【验证指标】

指标1：准确率（Accuracy）
├─ 定义：算法预测正确的比例
├─ 目标：>75%
├─ 计算：正确预测数 / 总预测数
└─ 验证方式：历史案例回测

指标2：召回率（Recall）
├─ 定义：实际有问题，算法也预测有问题的比例
├─ 目标：>80%
├─ 计算：正确预测有问题 / 实际有问题总数
└─ 验证方式：风险案例回测

指标3：精确率（Precision）
├─ 定义：算法预测有问题，实际确实有问题的比例
├─ 目标：>70%
├─ 计算：正确预测有问题 / 算法预测有问题总数
└─ 验证方式：预测结果验证

指标4：F1值
├─ 定义：精确率和召回率的调和平均
├─ 目标：>75%
├─ 计算：2 × (精确率 × 召回率) / (精确率 + 召回率)
└─ 综合评估模型性能

【验证周期】
├─ 每周：监控模型性能
├─ 每月：生成验证报告
├─ 每季：模型优化迭代
```
