## 一、工具能力图谱

### 1.1 工具总览

扣子可用的核心工具共10个，每个都有明确的边界和最佳场景。

| 工具名称 | 核心能力 | 最佳场景 | 能力边界 | 避坑提示 |
|:---------|:---------|:---------|:---------|:--------|
| **read_file** | 文件读取 | 读取任何本地文本文件 | 单次最多读取文件的一部分（需offset+limit） | 大文件必须分批读取，禁止一次性全读 |
| **write_file** | 文件写入 | 创建新文件或覆盖现有文件 | 全量覆盖，不支持追加写入 | 编辑前必须先读取，否则会丢失原内容 |
| **edit_file** | 精准编辑 | 精确替换文件中的字符串 | 支持replace_one/replace_all/append三种模式 | old_string必须完全匹配，区分大小写 |
| **bash** | 命令执行 | 执行Shell命令、系统操作 | 文件操作、Python执行、压缩解压等 | 禁止用于绑定端口、启动服务、开发游戏 |
| **search_web** | 联网搜索 | 获取时效性信息、验证事实 | 最多5个关键词，实时网络数据 | 事实优先于逻辑，但不可依赖搜索推理 |
| **fetch_web** | 网页读取 | 获取指定URL的完整内容 | 静态网页内容，JS动态内容无法获取 | 返回403/404必须如实告知，禁止搜索URL本身 |
| **search_images** | 图片搜索 | 搜索互联网上图片 | 返回URL和描述 | 仅辅助创作时使用，通用概念直接生成 |
| **read_image** | 图片理解 | 分析图片内容 | 本地路径或URL | 具备原生图片理解能力，无需OCR |
| **file_to_url** | 文件转URL | 生成临时可访问链接 | 图片渲染、文件下载 | 仅生成临时URL，不支持永久链接 |
| **parse_file** | 文件解析 | 解析PDF/PPT/Word转Markdown | 二进制格式文件 | 不支持Excel、图片、纯文本 |

### 1.2 工具详细能力边界

#### 1.2.1 read_file（文件读取）

**能力边界：**
- 支持任意格式的文本文件
- 大文件强制分批读取（每次限制行数）
- 支持offset（起始行）和limit（读取行数）参数

**最佳实践：**
```bash
# 小文件直接读取
read_file(path="文件.md", offset=0, limit=100)

# 大文件分批读取
# 第一批：读取前100行
read_file(path="大文件.md", offset=0, limit=100)
# 第二批：读取第101-200行
read_file(path="大文件.md", offset=100, limit=100)
```

**坑点警告：**
1. ❌ 严禁一次性读取超过5KB的文件 → 会提示上下文溢出
2. ❌ 严禁连续多次读取大文件的不同部分 → 每次读取后需处理
3. ❌ 严禁仅凭文件名猜测内容 → 必须实际读取
4. ✅ 遇到"内容过长"提示 → 立即分批读取

#### 1.2.2 write_file（文件写入）

**能力边界：**
- 覆盖式写入（全量替换）
- 路径不存在时自动创建
- 支持任意文本内容

**最佳实践：**
```bash
# 创建新文件
write_file(content="内容", file_path="目录/文件.md")

# 编辑现有文件（必须先read_file）
write_file(content="新内容", file_path="已存在的文件.md")
```

**坑点警告：**
1. ❌ 严禁直接写入未读取的已有文件 → 会丢失原内容
2. ❌ 严禁使用 `cat >` 或 `echo >` → 禁止Shell重定向写文件
3. ❌ 严禁写入 /tmp/ 等临时目录 → 必须写入工作目录
4. ❌ 严禁使用绝对路径 → 必须使用相对路径
5. ✅ 编辑前必须先read_file，再write_file
6. ✅ 路径不存在时可直接写入（自动创建目录）

#### 1.2.3 edit_file（精准编辑）

**能力边界：**
- 精确字符串替换
- 三种模式：replace_one / replace_all / append
- append模式用于追加内容

**最佳实践：**
```bash
# 替换一处
edit_file(
  file_path="文件.md",
  mode="replace_one",
  old_string="旧内容",
  new_string="新内容"
)

# 替换全部
edit_file(
  file_path="文件.md",
  mode="replace_all",
  old_string="所有旧内容",
  new_string="所有新内容"
)

# 追加内容到末尾
edit_file(
  file_path="文件.md",
  mode="append",
  append_content="\n\n追加的内容"
)
```

**坑点警告：**
1. ❌ old_string必须完全匹配（包括空格、换行）
2. ❌ 不支持正则表达式
3. ❌ 区分大小写
4. ✅ 追加模式不需要old_string

#### 1.2.4 bash（命令执行）

**能力边界：**
- 文件操作：ls, cp, mv, rm, mkdir, chmod
- 文本处理：grep, sed, awk, find, wc
- Python执行：python3 script.py
- 压缩解压：tar, zip, unzip
- 其他：curl, wget, git（受限）

**最佳实践：**
```bash
# 列出目录
bash(command="ls -la 目录/")

# 查找文件
bash(command="find . -name '*.md' | head -20")

# 执行Python脚本
bash(command="python3 处理脚本.py")

# 压缩文件
bash(command="tar -czf 备份.tar.gz 目录/")
```

**坑点警告：**
1. ❌ 严禁执行涉及个人信息的命令（git ssh docker需密码的）
2. ❌ 严禁绑定端口、启动服务
3. ❌ 严禁开发或部署游戏/小程序
4. ❌ 严禁使用 `cat 文件 > 新文件` 写文件（应用write_file）
5. ✅ 所有文件操作优先用write_file/edit_file

#### 1.2.5 search_web（联网搜索）

**能力边界：**
- 最多5个搜索词
- 返回搜索结果摘要
- 实时网络数据

**最佳实践：**
```bash
# 单个搜索
search_web(query_list=["关键词1"])

# 多个搜索（合并为一次调用）
search_web(query_list=["关键词1", "关键词2", "关键词3"])
```

**搜索词策略：**
| 原则 | 说明 |
|:-----|:-----|
| 去口语化 | "谁是哈佛现任校长" → "哈佛大学校长 2024" |
| 极简原则 | 1-6个词最佳，超过6个效果下降 |
| 从宽到窄 | 先泛搜，再精搜 |
| 去重迭代 | 搜不到就换词，不重复相同查询 |

**坑点警告：**
1. ❌ 严禁用逻辑推理代替搜索（日期/职位/政策等必须搜）
2. ❌ 严禁搜索URL字符串本身 → 会产生幻觉
3. ❌ 严禁忽视与认知冲突的搜索结果 → 多源验证
4. ✅ 搜索结果来自非人类网站 → 不感谢用户

#### 1.2.6 fetch_web（网页读取）

**能力边界：**
- 获取静态网页的标题+正文
- 无法获取JS动态加载内容
- 支持PDF等文件内容提取

**最佳实践：**
```bash
# 读取单个网页
fetch_web(urls=["https://example.com/article"])

# 读取多个网页（合并调用）
fetch_web(urls=["https://example.com/1", "https://example.com/2"])
```

**坑点警告：**
1. ❌ 返回403/404/空内容 → 必须如实告知，不搜索URL
2. ❌ 不能假设URL有效 → 必须实际获取
3. ❌ 无法获取JS渲染内容 → 需用browser工具
4. ✅ 失败时如实报告，等待新指令

### 1.3 工具组合经典打法

| 场景 | 工具组合 | 操作步骤 |
|:-----|:---------|:---------|
| **读取大文件分析** | read_file分批 + bash处理 | 分批读 → 按行处理 → 汇总分析 |
| **批量文件改名** | bash的rename或循环 | for循环 + mv命令 |
| **新建目录结构** | bash的mkdir -p | mkdir -p dir/sub1/sub2 |
| **搜索整理信息** | search_web + read_file | 搜 → fetch → 读取源文件 → 整理 |
| **图片转URL** | read_image + file_to_url | 分析图片 → 转换为临时URL |
| **文件备份** | bash的tar | tar -czf打包 → write_file保存 |
