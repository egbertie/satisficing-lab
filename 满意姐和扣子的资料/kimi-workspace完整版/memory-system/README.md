# 记忆系统 V1.0 (实际环境适配版)

> 基于《Kimi Claw记忆系统部署v1.0》PDF文档，针对当前OpenClaw实际环境进行适配部署

## 一、可行性评估

### 原方案核心设计
- **三层架构**: 短期记忆(上下文) + 长期记忆(向量库) + 静态知识库
- **技术栈**: ChromaDB + BGE-M3嵌入模型 + Ollama本地服务
- **自动化**: 会话归档 + 知识自动索引 + 记忆召回

### 实际环境适配
| 原方案 | 实际环境 | 适配策略 |
|--------|----------|----------|
| `claw memory` 命令 | **不存在** | 改用Python脚本 + OpenClaw原生能力 |
| BGE-M3嵌入模型 | **未安装**(需torch 2GB+) | **暂不部署**，改用关键词+元数据检索 |
| Ollama服务 | **未安装** | **暂不部署**，纯本地文件系统方案 |
| 40GB云存储 | 实际40GB磁盘，已用83% | 精简目录结构，控制存储增长 |
| ChromaDB | **已安装** | 保留作为未来向量检索基础 |

### 双经济评估
- **Token经济学**: 本地处理为主，零API调用，Token可持续 ✅
- **效益经济学**: 直接解决"记不住"痛点，创始人5分钟内可用 ✅

## 三、核心能力

### 1. 会话归档 (解决"聊完就忘")
每次切换话题前执行归档，提取关键决策点保存到 `memory/YYYY-MM-DD_话题.md`

### 2. 记忆检索 (解决"想不起来")
支持按关键词、日期、项目搜索所有归档记忆

### 3. 项目隔离
每个项目独立目录，避免信息混杂

## 四、使用方式

### 归档当前会话
```bash
python3 ~/.openclaw/workspace/memory-system/scripts/archive_session.py \
  --topic "合伙人决策V1.6讨论" \
  --key-decisions "确定12类型案例库结构;确定五维罗盘训练方案"
```

### 搜索历史记忆
```bash
# 关键词搜索
python3 ~/.openclaw/workspace/memory-system/scripts/search_memory.py \
  --query "合伙人冲突"

# 按日期范围
python3 ~/.openclaw/workspace/memory-system/scripts/search_memory.py \
  --query "案例库" --from-date 2026-04-01 --to-date 2026-04-20
```

### 手动整理知识库
将重要文件放入 `knowledge/` 目录，系统自动维护索引

## 五、用户配合指南 (最佳效果)

### 日常习惯 (必须)
1. **话题切换时归档**: 完成一个话题、准备 `/new` 前，告知我"归档当前会话"
2. **命名规范**: 提供简短话题名，如"合伙人V1.6"而非"那个东西"
3. **关键决策确认**: 主动指出"这个决定很重要"，我会优先记录

### 每周维护 (建议)
1. **周日**: 浏览 `memory/` 目录，确认本周归档完整
2. **检索测试**: 随机搜索一个旧话题，验证能否召回

### 长期优化 (可选)
- 当磁盘空间充裕时，可安装 `sentence-transformers` 启用向量语义检索
- 当前关键词检索已能满足80%需求

## 六、限制说明

| 限制 | 原因 | 影响 |
|------|------|------|
| 无语义向量检索 | sentence_transformers未安装 | 只能关键词匹配，不能"意思相近"搜索 |
| 无自动触发 | OpenClaw无PreCompact钩子 | 需手动执行归档 |
| 单实例存储 | 无云端同步 | 仅本机可用，需自行备份 |
