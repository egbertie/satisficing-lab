## 一、能力边界 (S1)

**输入**: 用户的TODO相关指令（创建、更新、追踪、提醒、归档）  
**输出**: 结构化的TODO记录、状态报告、执行提醒  
**自动化集成**: Cron定时检查 + 事件触发  

**明确边界**:
- 🔄 管理单个TODO的全生命周期
- 🔄 分类、优先级、截止时间管理
- 🔄 自动提醒和状态追踪
- 🔄 批量操作和归档
- ❌ 不负责实际执行（仅追踪）
- ❌ 不替代项目管理系统（轻量级）

### 2.1 TODO数据结构

```json
{

  "description": "详细描述",

    {"type": "overdue", "sent": false}
```

### 2.2 五路图腾对齐机制

每个TODO任务需对齐五路图腾之一：

| 图腾 | 对齐场景 | 判断标准 |
|------|----------|----------|
| **刘禹锡** | 关系维护、信任建立 | 涉及人、关系、合作 |
| **司马贺** | 理性决策、满意解 | 需要分析、权衡、决策 |
| **观自在** | 应变调整、感知洞察 | 需要灵活应对变化 |
| **孔子** | 伦理判断、价值观 | 涉及道德、原则、底线 |
| **六祖慧能** | 顿悟突破、创新 | 需要突破、灵感、顿悟 |

### 2.3 核心功能

#### 功能1: 创建TODO
- 解析用户自然语言输入
- 自动提取：标题、截止时间、优先级、分类
- 分配图腾对齐
- 保存到存储

#### 功能2: 更新TODO
- 状态变更（pending → in_progress → completed）
- 属性修改（截止时间、优先级、描述）
- 批量更新

#### 功能3: 追踪与提醒
- 每日扫描即将到期任务
- 自动发送提醒（24h前、2h前、逾期）
- 生成每日/每周TODO报告

#### 功能4: 查询与筛选
- 按状态、优先级、分类、图腾筛选
- 模糊搜索标题和描述
- 时间范围查询

#### 功能5: 归档与统计
- 自动归档已完成任务（30天后）
- 生成完成率统计
- 五路图腾任务分布分析

## 五、准确性验证 (S5)

### 5.1 自检机制

```python
# 每次操作后自动验证
def validate_todo(todo):
    errors = []
    
    # S1: 必填字段检查
    required = ['id', 'title', 'status', 'priority', 'created_at']
    for field in required:
        if field not in todo:
            errors.append(f"Missing required field: {field}")
    
    # S2: 状态有效性检查
    valid_statuses = ['pending', 'in_progress', 'completed', 'cancelled', 'archived']
    if todo.get('status') not in valid_statuses:
        errors.append(f"Invalid status: {todo.get('status')}")
    
    # S3: 时间逻辑检查
    if todo.get('completed_at') and todo.get('created_at'):
        if todo['completed_at'] < todo['created_at']:
            errors.append("completed_at cannot be earlier than created_at")
    
    # S4: 图腾对齐检查
    valid_totems = ['刘禹锡', '司马贺', '观自在', '孔子', '六祖慧能']
    if todo.get('totem_alignment') not in valid_totems:
        errors.append(f"Invalid totem: {todo.get('totem_alignment')}")
    
    return len(errors) == 0, errors
```

### 5.2 质量检查报告

每次操作后输出检查报告：
- 🔄 数据完整性验证
- 🔄 时间逻辑验证  
- 🔄 图腾对齐验证
- 🔄 重复检测

## 六、局限标注 (S6)

### 6.1 明确局限

1. **存储局限**: 本地JSON存储，无数据库事务保障
2. **并发局限**: 不支持多会话同时修改同一任务
3. **提醒局限**: 依赖Cron执行，可能有分钟级延迟
4. **理解局限**: 自然语言解析基于关键词，复杂语义可能误解析
5. **集成局限**: 不直接与外部系统（飞书/企微）同步

### 6.2 失败场景

| 场景 | 行为 | 回滚策略 |
|------|------|----------|
| 文件写入失败 | 重试3次，失败后报错 | 保持原文件不变 |
| ID冲突 | 重新生成ID | 自动解决 |
| 解析失败 | 请求用户确认 | 不创建任务 |
| 磁盘空间不足 | 提示清理归档文件 | 暂停新任务创建 |

## 深度洞察 (L1-L5) 【2026-03-31闭环升级新增】

### L1: 表面现象

TODO管理系统实现了：
- 全生命周期管理（创建/更新/追踪/提醒/归档）
- 五路图腾对齐机制
- 自然语言解析
- S5/S7验证通过

**但实际使用情况**:
- 当前活跃任务仅1个（P1任务）
- 大量历史任务未录入系统
- 提醒功能未实际触发过

### L2: 模式识别

**成功模式**:
- 架构设计完整（TodoManager类）
- 五路图腾对齐有特色
- 验证机制完善

**异常模式**:
1. **用而不足**: 系统存在但使用率低
2. **录入滞后**: 任务完成后才录入，而非创建时录入
3. **提醒失效**: 提醒功能从未触发（cron未配置）

### L3: 根因分析（深挖到认知/人性）

**为什么用而不足？**
- 满意妞习惯用文件记录而非系统录入
- "先做事后记录"的旧习惯
- 系统录入 perceived as overhead（额外负担）

**为什么提醒失效？**
- 配置cron需要额外步骤
- 没有"配置≠完成"的意识
- 测试验证环节缺失

**根因**: 
- 工具完美主义：追求系统设计完美，而非实际使用
- 习惯性绕过：面对紧急任务，直接执行而非先录入
- 验证缺失：没有定期检查系统是否真正运行

### L4: 系统关联

**与立即执行文化的冲突**:
- 立即执行要求"确认后立即开始"
- 但TODO系统要求"先录入再执行"
- 冲突导致绕过系统

**与负熵原则的关联**:
- TODO系统本应减少混乱
- 但实际增加了步骤（录入+执行）
- 需要降低使用门槛

### L5: 未来指导（可执行原则）

**核心原则**: "执行即录入，录入即执行"

**可执行方案**:
1. **零摩擦录入**: 一句话创建TODO，无需复杂参数
2. **自动录入**: 每次用户指派任务，自动创建TODO
3. **提醒Cron配置**: 必须完成8步验证（不是配置完就算完成）
4. **使用率检查**: 每周检查TODO数量，低于5个则预警

**内化到工作流**:
```python
# 用户说"做XX" → 立即创建TODO
def on_user_task(title):
    todo_id = todo_manager.create(title, priority="P1")
    print(f"已创建TODO: {todo_id}")
    execute_task(title)  # 然后执行
```

**改进措施**:
- 简化创建命令: `todo.create("标题")` 而非复杂参数
- 自动优先级推断: 根据关键词自动设置P0/P1/P2
- 每日TODO数量报告: 强制关注使用率
