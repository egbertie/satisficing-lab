## 二、工具化路径

### 2.1 CLI工具命令设计

```bash
# 初始化案例库
case-repo init

# 添加新案例
case-repo add --file case_data.json
case-repo add --interactive

# 搜索案例
case-repo search --keyword "股权代持"
case-repo search --industry "AI芯片"
case-repo search --stage "A轮"

# 生成复盘报告
case-repo report --case-id CASE-001
case-repo report --case-id CASE-001 --template detailed

# 合伙人匹配评估
case-repo match --profile partner_profile.json
case-repo match --interactive

# 导出到飞书
case-repo export --case-id CASE-001 --format feishu
case-repo export --all --format markdown

# 版本控制
case-repo git --commit "添加张雪案例"
case-repo git --log
case-repo git --diff HEAD~1
```

## 三、流程化方案（SOP）

### SOP-001：案例入库流程

**触发条件**: 新案例需要入库

**执行步骤**:
```
Step 1: 数据采集（T+0）
├── 收集案例素材（报道、访谈、文档）
├── 验证信息可信度
└── 确认信源等级（A/B/C）

Step 2: 结构化输入（T+1）
├── 填写JSON模板
├── 关键决策点提取（≥3个）
├── 风险信号识别（≥3个）
└── 可迁移经验总结（≥2条）

Step 3: 质量审核（T+2）
├── 审核员检查数据完整性
├── 核实关键信息准确性
├── 确认理论映射正确性
└── 批准入库或退回修改

Step 4: 入库发布（T+3）
├── 执行 case-repo add
├── 生成复盘报告
├── 导出飞书文档
└── 通知相关方
```

**质量检查点**:
- 决策点必须有"当时情境-选择-逻辑-结果"
- 风险信号必须有"预警级别-应对措施"
- 可迁移经验必须有"适用/不适用场景"
- 信源等级必须明确（A=一手，B=二手，C=三手）

---

### SOP-002：复盘报告生成流程

**触发条件**: 案例入库后自动生成

**执行步骤**:
```
Step 1: 数据加载
├── 从数据库读取案例数据
├── 验证数据完整性
└── 加载Jinja2模板

Step 2: 内容生成
├── 执行摘要（自动提取关键信息）
├── 决策链重构（格式化决策点）
├── 风险模式识别（分类风险信号）
├── 可迁移经验（格式化经验教训）
└── 理论映射（自动匹配理论）

Step 3: 人工审核（15分钟）
├── 检查逻辑连贯性
├── 补充细节信息
├── 优化表达方式
└── 确认无误后发布

Step 4: 多格式输出
├── 生成Markdown文件
├── 导出飞书文档
├── 保存版本历史（Git）
└── 更新案例库索引
```

## 四、闭环机制

### 4.1 案例质量闭环

**指标**:
- 入库案例数量（目标：每月≥2个）
- 数据完整率（目标：≥95%）
- 审核通过率（目标：≥80%）

**频率**: 每月统计

**改进**:
- 完整率<90% → 优化输入模板
- 通过率<70% → 加强培训

---

### 4.2 复盘报告质量闭环

**指标**:
- 生成时间（目标：≤5分钟/份）
- 人工编辑率（目标：≤20%）
- 用户满意度（目标：≥4.5/5.0）

**频率**: 每份报告后

**改进**:
- 编辑率>50% → 优化模板
- 满意度<4.0 → 人工介入改进

---

### 4.3 检索效果闭环

**指标**:
- 检索准确率（目标：≥80%）
- 用户找到所需案例的比例（目标：≥90%）

**频率**: 每季度测试

**改进**:
- 准确率<70% → 优化知识图谱
- 考虑引入用户反馈机制
