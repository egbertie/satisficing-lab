## 二、版本使用规则

### 2.1 基础规则（通用）

| 场景 | 推荐版本 | 原因 |
|:--|:--|:--|
| **首次接触 / cold email 附件** | 精简版（默认） | 专家时间宝贵，8 分钟内读完，降低决策门槛 |
| **已表达兴趣 / 预约 30 分钟通话** | 精简版 + 第 04 篇完整版 | 先给精简版建立全貌，通话前再给完整版做深度准备 |
| **已预约 1 小时以上深度面谈** | 完整版 | 长时间面谈才需要 4.4 万字背景支撑 |
| **微信/飞书随手转发** | 精简版 | 移动端阅读，字数必须克制 |

### 2.2 多轮沟通规则（V1.1新增）

| 沟通轮次 | 推荐版本 | 说明 |
|:---------|:---------|:-----|
| **第一轮（首次接触）** | `2026-04-18-第二轮/` 精简版 | 使用最新版本，展示V2.2机制化能力 |
| **第二轮（跟进/深度）** | 根据第一轮反馈选择 | 如专家已读第一轮，可补充完整版 |
| **历史版本查阅** | `2026-04-12-第一轮/` | 仅用于对比，不主动发送 |

### 2.3 版本选择决策树

```
首次接触专家？
├─ 是 → 发送 2026-04-18-第二轮/精简版
│
└─ 否（已沟通过）→ 专家是否要求更多细节？
    ├─ 是 → 发送 2026-04-18-第二轮/完整版（如存在）或补充特定文档
    └─ 否 → 保持精简版，更新进展即可
```

## 三、精简版与完整版核心差异

| 维度 | 精简版 | 完整版 |
|:--|:--|:--|
| 总字数 | ~1.2 万字 | ~4.4 万字 |
| 单篇阅读时间 | 6–10 分钟 | 20–35 分钟 |
| 案例细节 | 保留 1–2 个核心案例 | 保留全部案例 + 数据 |
| 理论铺陈 | 只留结论和一句话映射 | 保留学术来源 + 推导过程 |
| 执行细节 | 只列里程碑和关键数据 | 保留全部脚本、工具、Git 提交号 |
| V2.2机制 | ✅ 包含 | （第二轮完整版待补充） |
| 错误案例库 | ✅ 包含 | （第二轮完整版待补充） |

## 五、发送流程 SOP

```
步骤 1: 确认专家类型（学者/实战派/投资人）
    ↓
步骤 2: 选择版本轮次（默认第二轮 2026-04-18）
    ↓
步骤 3: 选择版本类型（默认精简版）
    ↓
步骤 4: 以 PDF 或 Markdown 发送（优先 PDF，防止格式错乱）
    ↓
步骤 5: 72 小时内无回复，追加一条 50 字跟进
    ↓
步骤 6: 确认面谈后，再补发完整版（如需）
    ↓
步骤 7: 记录专家反馈，更新到下一轮版本
```

## 六、禁用行为清单

**⚠️ 绝对禁止**：
- ❌ 同时发送精简版和完整版（造成认知负担）
- ❌ 在未经预约的情况下首发完整版（转化率 plummet）
- ❌ 修改文件名中的序号（导致版本混乱）
- ❌ 将第一轮和第二轮版本混发（造成混淆）
- ❌ 不阅读文档就直接转发（无法回答专家问题）

**⚠️ 谨慎使用**：
- ⚠️ 完整版仅在专家明确要求或深度面谈前发送
- ⚠️ 第一轮版本仅用于历史对比，不主动发送
