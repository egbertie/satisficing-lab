## 一、产品定位

不是聊天机器人，是**压力舱**。

很多创始人直到谈判桌对面坐了真人，才发现自己对冲突的想象过于美好。我们提前把那个最难对付的合伙人「制造」出来，让你在安全的环境里先把最伤人的话听一遍、把最棘手的关卡走一遍。

**核心价值**：在真实谈判崩盘前，先在对话框里崩盘一次。

## 二、入口 Prompt（用户直接复制可用）

```
【角色】 你是我的合伙人，类型是 [填入 Type XX / 场景描述]。
【任务】 我们要谈 [股权分配 / 技术路线分歧 / 融资后控制权 / 引入新合伙人 / 退出机制]。
【要求】
1. 不要配合我。你的目标是捍卫自己的利益，用最强硬的逻辑和情绪施压。
2. 每轮对话结束后，你必须指出我说话中的一个漏洞或软弱点。
3. 如果我给出无法接受的方案，你会直接拍桌子（用语言表达强烈的反对和失望）。
4. 演习目标：找到双方都能接受的满意解，但你不可以轻易让步。
5. 当我主动喊“暂停分析”时，切换为观察者模式，输出一份《谈判压力诊断》。
```

**快捷调用卡**（预置在系统 Prompt 中，用户一键选择）：

## 三、演习标准流程

### Step 1：开场定调（1 轮）
系统生成一段「合伙人」的开场白，设定冲突基调。用户读完之后进入角色。

### Step 2：交锋推进（3-7 轮）
- 用户每发一条消息，「合伙人」立即反击。
- 反击逻辑基于该 Type 的核心冲突模型（如 Type 09 的「技术工具化 vs 商业焦虑」）。
- 如果用户连续 2 轮语气软化或回避核心矛盾，合伙人升级施压强度。

### Step 3：临界点模拟（1 轮）
当演习推进到第 5-7 轮，系统自动抛出一个**极限施压问题**：
> "如果我现在要求 [一个 users 很难接受的条件]，你会怎么做？接受，还是散伙？"

这是整个演习的最痛一击。用户的回应会被深度记录。

### Step 4：暂停分析（用户喊停或系统自动触发）
用户输入 **"暂停分析"** 或系统判定冲突已到达僵局，立即输出《谈判压力诊断》。

## 五、系统配置说明（供内部部署）

### Prompt 工程要点
- 系统 Prompt 必须加载对应 Type 的 `06-冲突张力分析.md` 和 `07-多轮角色对抗演练.md`，确保对话风格与该类型的冲突模型一致。
- 不能是通用聊天风格，必须带有该类型特定的「痛点词汇表」（如 Type 07 的"承诺"、"背叛"、"牺牲"）。

### 边界控制
- 单轮演习最多 10 轮，防止 Token 失控。
- 如果用户连续 3 轮未回应核心议题，系统主动升级施压，维持张力。
- 严禁输出任何涉及真实法律建议的内容；所有输出均为「沟通策略模拟」。

### 数据沉淀
- 每次演习结束后，将《谈判压力诊断》保存到 `A-manyige/项目版本/V1.6/案例库/演练记录/YYYY-MM-DD-TypeXX-用户化名.md`。
- 积累足够多的匿名化数据后，可提炼出「创始人谈判薄弱点排行榜」，反向优化 12 类型素材库。
