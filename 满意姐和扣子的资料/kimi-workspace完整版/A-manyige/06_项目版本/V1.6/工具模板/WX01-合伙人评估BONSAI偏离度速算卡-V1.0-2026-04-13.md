> **来源**: 微信学术快报 · BONSAI 思想（默认配置感知贝叶斯优化）
> **版本**: V1.0

> **规则**: 先定基准，再算偏离，最后对标 ρ

## 第二步：候选人偏离度打分（Deviation Score）

针对上述勾选的每一项，评估候选人的偏离程度：

| 偏离等级 | 描述 | 得分 |
|:--|:--|:--:|
| **完美匹配** | 候选人完全符合该项描述 | 0 |
| **轻微偏离** | 候选人略有差异，但差异可被规则或时间弥补 | 1 |
| **中度偏离** | 候选人与基准有明显差异，需要额外机制（如对赌、培训、岗位调整）才能弥合 | 2 |
| **重度偏离** | 候选人在该项上与基准冲突，且难以通过规则或时间改变 | 3 |

## 第三步：设定你的可容忍代价上限 ρ (Rho)

ρ 不是对候选人的宽容，而是你对"偏离结果"愿意支付的最大代价。

| ρ 等级 | 含义 | 适用场景 |
|:--|:--|:--|
| **ρ = 3** | 零容忍。任何单项偏离 ≥ 1 都直接否决。 | 你只有一次翻身机会（第三次再创业 / 高龄创始人） |
| **ρ = 6** | 小步试错。总偏离 ≤ 6 且单项偏离 ≤ 2 可接受。 | 你有 12–18 个月窗口期，资金相对充裕 |
| **ρ = 9** | 战略性包容。总偏离 ≤ 9，但单项偏离不得超过 2。 | 早期探索阶段，需要快速凑齐团队验证模式 |
| **ρ = ∞** | 无基准，看感觉。 | ⚠️ 强烈不建议，等同于取消满意解边界 |

## 第四步：30 秒决策

```
IF 最大单维偏离 > 2    →  🔴 红灯：一票否决，无论总分多少
ELSE IF 总偏离分 Σ > ρ  →  🟡 黄灯：回退到"额外机制设计"（对赌/培训/试用期）
ELSE                   →  🟢 绿灯：进入正式合伙人宪章谈判
```

## 五、满意解提示

> 💠 **司马贺**: "不要寻找完美合伙人，寻找'足够好、可被规则约束'的搭档。"
> 🛡️ **观自在**: "偏离本身不是风险，对偏离的盲目容忍才是。"

**记住**: BONSAI 的核心是"最小必要偏离"。每一次偏离都应有理由、有代价上限、有补丁机制。
