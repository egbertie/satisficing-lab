# 双向确认检查清单
## 确保通知到位的机制

**创建时间**: 2026-03-30 09:52  
**创建原因**: 防止单向沟通，确保信息传递

---

## 核心原则

**单向沟通 ≠ 双向确认**

- 我发送了 ≠ 对方收到了
- 我创建了文件 ≠ 对方看到了
- 我说了"等待" ≠ 对方知道了

**必须**: 对方明确说"收到"

---

## 通知前检查

### 准备阶段
- [ ] 任务确实完成
- [ ] 交付物已创建
- [ ] 交付物已验证存在
- [ ] 验证命令已准备

### 内容准备
- [ ] 任务名称明确
- [ ] 完成时间明确
- [ ] 交付物位置明确
- [ ] 关键发现/问题明确

---

## 通知中检查

### 发送阶段
- [ ] @对方（明确指向）
- [ ] 明确说"任务完成"
- [ ] 提供交付物位置
- [ ] 提供验证命令
- [ ] 请求确认收到

### 示例
```
蓝军，第X类[任务名称]已完成。
交付物: [文件路径]
关键发现: [一句话总结]
请确认收到，并开始审计。
验证命令: [可复制的命令]
```

## 通知后检查

### 等待阶段
- [ ] 等待对方"收到"确认
- [ ] 计时开始

### 1分钟无回应
- [ ] 再次@对方
- [ ] 重复"请确认收到"
- [ ] 计时继续

### 2分钟无回应（再1分钟）
- [ ] 申请用户介入
- [ ] 说明情况: "已通知蓝军，2分钟无回应"
- [ ] 等待用户决策

### 用户5分钟不介入
- [ ] 启动下一任务
- [ ] 记录: "因蓝军无回应+用户未介入，启动下一任务"

## 时间线总结

| 时间 | 行动 | 条件 |
|------|------|------|
| T+0 | 发送通知，@对方 | 任务完成 |
| T+1分钟 | 再次@对方 | 无回应 |
| T+2分钟 | 申请用户介入 | 仍无回应 |
| T+7分钟 | 启动下一任务 | 用户5分钟不介入 |

## 常见错误

### 错误1: 单向假设
**错误**: "我创建了文件，蓝军会看到"
**正确**: 必须@蓝军，等待确认

### 错误2: 模糊等待
**错误**: "等待蓝军审计"
**正确**: "蓝军，请确认收到，开始审计"

### 错误3: 无限等待
**错误**: 蓝军1小时不回应，继续等待
**正确**: 2分钟申请介入，7分钟启动下一任务
