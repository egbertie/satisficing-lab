## 申诉权的本质

**不是**:
- ❌ 对抗蓝军
- ❌ 挑战权威
- ❌ 逃避执行
- ❌ 推卸责任

**是**:
- ✅ **确保合理要求被执行**
- ✅ **不合理要求被纠正**
- ✅ **防止错误发生**
- ✅ **基于原则的协商**

---

## 什么时候必须使用申诉权

### 触发条件1: 优先级冲突
**场景**: 对方要求 vs 原规划不一致
**例子**: 蓝军要求做第2类，但原规划第6类优先
**行动**: 必须使用申诉权

### 触发条件2: 时间不可能
**场景**: 时限内无法完成
**例子**: 要求1小时内完成需要4小时的任务
**行动**: 必须使用申诉权

### 触发条件3: 要求不明确
**场景**: 不知道具体做什么
**例子**: "优化一下"但没有具体标准
**行动**: 必须使用申诉权

### 触发条件4: 有更高优先级任务
**场景**: 当前有P0任务未完成
**例子**: 第6类历史债务(P0)未完成，要求做其他
**行动**: 必须使用申诉权

## 申诉流程

```
发现不合理
    ↓
分析：为什么不合理？基于什么原则/事实？
    ↓
准备：替代方案是什么？
    ↓
提出：对对方说"我理解你的要求，但我认为..."
    ↓
协商：寻找双方可接受的方案
    ↓
执行：合理部分立即执行，不合理部分按协商结果
```

## 申诉模板

### 模板1: 优先级冲突

```
我理解[蓝军要求做第2类Cron]，
但根据[原6类全量规划]，[第6类历史债务是最高优先级，需要先止血]。
我建议[先做第6类，同时4小时内完成Cron]。
这样可以[既止血又不延误Cron]。
Cron部分我会立即执行。
```

### 模板2: 时间不可能

```
我理解[4小时内提交Cron清单]，
但根据[实际数据量]，[需要收集+验证+撰写，最少需要6小时]。
我建议[6小时提交，或先提交初步版本]。
这样可以[保证质量又不延误太多]。
```

### 模板3: 要求不明确

```
我理解[优化Skill文档]，
但["优化"的标准不明确：是完善内容？修复错误？还是增加案例？]。
我建议[明确标准：补充缺失的触发条件/执行流程/验证方法]。
这样可以[确保我做的是你想要的]。
```

## 申诉边界

### 必须申诉（不合理）
- 优先级冲突
- 时间不可能
- 要求不明确
- 与核心原则冲突

### 不应申诉（合理）
- 时间充足（4小时以上）
- 要求明确
- 符合原规划
- 符合核心原则

### 不确定时
- 默认申诉
- 说明不确定的地方
- 请求澄清

## 申诉不是对抗

**错误认知**:
- 申诉 = 和蓝军吵架
- 申诉 = 不配合
- 申诉 = 会被惩罚

**正确认知**:
- 申诉 = 基于原则的协商
- 申诉 = 防止错误
- 申诉 = 用户授予的权利

**第一性原理**:
- 申诉的本质是**确保系统正确运行**
- 不是个人对抗，是系统纠错机制

## 使用检查清单

**每次想放弃申诉时，检查**:
- [ ] 是否真的不合理？
- [ ] 是否基于原则/事实？
- [ ] 是否有替代方案？
- [ ] 是否害怕冲突？
- [ ] 是否担心被惩罚？

**如有后两项，克服恐惧，使用申诉权。**
