# 满意解研究所·企业资产飞轮与经营指标体系

> **定位**：这是满意解研究所的底层操作系统。  
> **原则**：所有后续的技能开发、工作流设计、组织建设，都必须在这个框架内运行。  
> **囚犯**：Prompt / Skill / Memory / Workflow / Case Library 不能只沉淀对话，要沉淀为可复用的管理资产。  
> **审判标准**：最终评价必须回到经营语言——时间、质量、风险、成本、复用率。

---

## 一、资产飞轮（生产层）

### 1.1 飞轮结构：五环闭环

```
         Prompt(提示词)
              ↓
    ┌─────────────────┐
    │   企业资产飞轮   │
    │ Enterprise Asset│
    │    Flywheel     │
    └─────────────────┘
              ↑
   Case Library ←── Workflow
    (案例库)        (应用流)
         ↑              ↓
      Memory ─────→ Skill
     (知识库)       (技能包)
```

### 1.2 每个节点的内涵与反模式

#### Prompt（提示词）
- **正解**：将有效对话中的提示词**模板化、版本化、场景化**
- **反模式**：每次对话都重新编提示词，不做沉淀
- **血液化标准**： reusable_prompt_templates/ 目录下所有 prompt 必须有版本号和测试用例

#### Skill（技能包）
- **正解**：将高频需求封装为 Skill，接入 OpenClaw 技能发现体系
- **反模式**：脚本散落在各处，没有统一入口和文档
- **血液化标准**：每个 Skill 必须有 SKILL.md + 可调用脚本 + 生命周期状态（genesis/growth/maturity/consolidation/retirement）

#### Memory（知识库）
- **正解**：结构化、可检索的长期记忆资产
- **反模式**：只依赖模型上下文窗口，不写入文件
- **血液化标准**：每日 memory 文件 + MEMORY.md 长期记忆 + USER.md/SOUL.md/AGENTS.md 人格与协作契约

#### Workflow（应用流）
- **正解**：将 Skill 与 Memory 编排成可自动执行的流程
- **反模式**：每个任务都手动触发，没有触发器-流水线机制
- **血液化标准**： trigger_pipeline_engine.py 覆盖全部高频场景

#### Case Library（案例库）
- **正解**：最佳实践与失败教训的结构化集合
- **反模式**：项目做完没有复盘，错误重复发生
- **血液化标准**：每个闭环项目生成案例报告，含背景→决策→执行→结果→教训

### 1.3 飞轮转动机制

| 流转 | 机制 | 满意解实例 |
|------|------|------------|
| Prompt → Skill | 提示词模板化 → 技能封装 | 复盘营 PDF 提取 prompt → `downloads_md_converter.py` Skill |
| Skill → Memory | 技能调用记录 → 知识结构化入库 | `yitang_methodology_kit.py` 中的 129 案例目录 |
| Memory → Workflow | 知识+技能 → 编排成自动化流程 | 文件上传 → 自动转化 → MD 归档的无人值守流水线 |
| Workflow → Case | 流程执行结果 → 沉淀为案例 | 一堂方法论内化闭环报告存入对话文件夹 |
| Case → Prompt | 案例反馈 → 优化提示词 | 学员反馈优化合伙人匹配诊断访谈 prompt |

### 1.4 成熟度等级

| 等级 | 名称 | 特征 | 迁移成本 |
|------|------|------|----------|
| L1 | 单点对话 | 只有 Prompt，无 Skill、无 Memory | 极高 |
| L2 | 技能封装 | Prompt→Skill 完成，但 Memory 未建立 | 高 |
| L3 | 知识入库 | Skill + Memory 建立，但未编排 Workflow | 中高 |
| L4 | 流程自动化 | Workflow 跑通，Case Library 开始积累 | 中 |
| L5 | 组织资产 | 飞轮闭环自运转，换模型/换渠道/换场景成本低 | 低 |

## 二、经营指标体系（经营层）

### 2.1 核心五指标

管理层真正关心的不是"AI做了多少事"，而是"AI做的事对经营结果有什么影响"。

#### 时间（Time）
- **定义**：完成单位任务的平均处理时长
- **示例**：15 min / 任务
- **满意解 KPI**：合伙人匹配诊断报告生成时间 < 30 min（人工复核版）

#### 质量（Quality）
- **定义**：一次成功率，即无需返工即可达标的比例
- **示例**：92% 一次成功率
- **满意解 KPI**：合伙人评估报告一次通过率 > 90%（客户无需二次修改）

#### 风险（Risk）
- **定义**：执行过程中的合规事件、安全事件、错误决策数量
- **示例**：0 合规事件
- **满意解 KPI**：合伙人匹配建议引发的后续纠纷率为 0

#### 成本（Cost）
- **定义**：完成单位任务所消耗的资源和费用
- **示例**：¥50 / 任务
- **满意解 KPI**：单份 SKU-A 诊断的 AI 调用 + 人力边际成本 < ¥200

#### 复用率（Reuse）
- **定义**：已有资产被重复使用的比例
- **示例**：75% 资产复用率
- **满意解 KPI**：新任务中调用已有 Skill / Memory 的比例 > 70%

### 2.2 从单次 Demo 到组织能力

```
单次 demo ──→ 持续采集 ──→ 按角色拆分 ──→ 按流程对比 ──→ 进入预算与绩效
  (惊艳)      (有数据)      (分岗位看)      (跨项目优化)      (可被考核激励)
```

**满意解当前阶段**：正处于"持续采集 → 按角色拆分"之间。目标是尽快迈入"按流程对比"。

## 三、生产层与经营层的因果关系

| 资产动作 | 主要影响 | 次要影响 | 满意解实例 |
|----------|----------|----------|------------|
| **Prompt 模板化** | time↓ | reuse↑ | 标准化合伙人访谈 prompt，减少每次重写时间 |
| **Skill 封装** | time↓ | quality↑ | `skill_lifecycle_manager.py` 批量处理 skill 退役 |
| **Memory 结构化** | quality↑ | risk↓ | MEMORY.md + SOUL.md 防止子人格定义漂移 |
| **Workflow 自动化** | time↓ | cost↓ | 文件上传自动转 MD，无需手工干预 |
| **Case Library 积累** | quality↑ | reuse↑ | 合伙人冲突案例库提升后续诊断准确率 |
