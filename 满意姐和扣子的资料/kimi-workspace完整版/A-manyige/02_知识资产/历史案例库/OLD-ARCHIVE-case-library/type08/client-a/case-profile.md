# Type 8: 创始人与合伙人关系定位决策
## Client A - 案例模拟档案

---

## 一、客户数字替身档案

| 维度 | 内容 |
|------|------|
| **姓名** | 陈浩然（化名） |
| **年龄** | 36岁 |
| **项目** | 企业级SaaS |
| **团队规模** | 30人 |
| **合伙人结构** | 陈浩然(CEO,50%) + 联合创始人3人(各15%) + 期权池5% |

### 核心痛点：权责不清
- **决策混乱**：4个创始人都是"联合创始人"，谁说了算？
- **会议低效**：每个决策都要4人同意，经常"3票赞成1票反对"陷入僵局
- **责任推诿**：项目失败时"这不是我的责任"
- **退出困境**：一位联合创始人想退出，但其他人不同意回购价格

## 二、RACI权责矩阵

### 关键决策RACI定义

| 决策事项 | CEO(R) | CTO(R) | COO(R) | CPO(R) | 备注 |
|----------|--------|--------|--------|--------|------|
| 产品方向 | A | C | I | R | CPO主导，CEO批准 |
| 技术架构 | A | R | I | C | CTO主导，CEO批准 |
| 融资决策 | R | C | C | I | CEO主导，全体知情 |
| 核心招聘 | A | C | R | C | COO执行，CEO批准 |
| 预算分配 | R | C | C | C | CEO主导 |
| 股权调整 | R | C | C | C | 需董事会通过 |

**图例**: R=负责执行 | A=最终批准 | C=必须咨询 | I=知情

## 三、决策工具输出

### 工具1: 合伙人角色宪章

```
《联合创始人角色宪章》
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【陈浩然 - CEO】
- 核心职责：战略方向、融资、对外关系、最终决策
- 专属权力：预算>50万的最终审批权、核心人员任免
- 必须咨询：股权变动、产品重大调整、技术路线变更

【李明 - CTO】
- 核心职责：技术战略、研发团队管理、技术债务控制
- 专属权力：技术选型、技术团队招聘、技术预算内支出
- 必须咨询：产品功能优先级、非技术团队的技术需求

【王芳 - COO】
- 核心职责：运营效率、流程优化、跨部门协调
- 专属权力：运营预算支配、流程制度制定
- 必须咨询：涉及多部门的运营决策

【张伟 - CPO】
- 核心职责：产品愿景、用户体验、产品团队管理
- 专属权力：产品功能定义、产品设计决策
- 必须咨询：技术可行性、商业可行性

【冲突解决机制】
- 第1级：直接沟通（涉及双方）
- 第2级：CEO调解（涉及三方）
- 第3级：全体合伙人会议（涉及四方或战略级）
```

### 工具2: 决策升级机制

| 决策级别 | 金额/影响 | 决策机制 | 时限 |
|----------|-----------|----------|------|
| L1日常 | <5万 | 负责合伙人独立决定 | 即时 |
| L2常规 | 5-50万 | 负责合伙人决定，知会其他合伙人 | 24h内 |
| L3重要 | 50-200万 | 相关合伙人协商，CEO批准 | 3天内 |
| L4战略 | >200万或方向性 | 全体合伙人会议，多数决 | 1周内 |
| L5根本性 | 股权/商业模式/退出 | 全体一致同意 | 协商确定 |
