# Type 9: 创始人与技术合伙人关系决策
## Client C - 技术合伙人技术锁死场景

---

## 一、客户数字替身档案

| 维度 | 内容 |
|------|------|
| **姓名** | 老马（55岁，传统行业老板） |
| **身份** | 跨界科技，技术完全依赖合伙人 |
| **技术合伙人** | 小高（天才程序员，35%股权） |
| **现状** | 小高是唯一能懂代码的人，开始要挟 |

### 核心痛点
1. **技术锁死**: 代码只有小高能懂，没有文档
2. **权力失衡**: 小高要求涨股到51%，否则不干了
3. **代际鸿沟**: 老马不懂技术，无法判断小高说的是真是假

---

## 二、躯体信号档案

**老马的躯体语言**:
- 与小高开技术会：点头，假装听懂 → 心虚
- 独处时：翻阅技术书籍，上网搜索 → 焦虑
- 与小高谈判时：出汗，声音提高 → 被威胁的恐惧

**小高的躯体语言**:
- 与老马对话：自信，甚至傲慢 → 技术优势感
- 提要求时：身体前倾，眼神直视 → 攻击性
- 被质疑时：冷笑，说"你不懂" → 轻视

**关键信号**:
> 小高说："没有我，这公司就是一堆废代码。"

**解读**: 技术合伙人利用信息不对称要挟创始人。

---

## 三、合伙人冲突诊断

### 权力地图

```
老马（创始人/CEO）
├── 商业：✅ 控制
├── 融资：✅ 控制
├── 客户：✅ 控制
└── 技术：❌ 被小高锁死
    └── 代码：只有小高能懂
    └── 架构：没有文档
    └── 部署：只有小高会操作
```

### PFI评分

| 维度 | 老马-小高 | 危机阈值 |
|------|-----------|----------|
| **价值观契合** | 🟡 50 | - |
| **信任基础** | 🔴 20 | <20 |
| **权力平衡** | 🔴 30:70 | - |
| **信息透明** | 🔴 0 | - |

---

## 四、干预方案

### 第一步：技术解耦（紧急）

**立即执行**:
- 聘请外部技术顾问（老马的人）
- 要求小高：
  1. 代码注释
  2. 技术文档
  3. 部署手册
  4. 知识转移培训

**话术**:
"小高，投资人要求我们提供技术文档，这是标准流程。"

### 第二步：制衡建立

**引入技术VP**:
- 招聘新CTO（老马信任的人）
- 小高转任首席架构师（虚职）
- 逐步移交技术控制权

**准备Plan B**:
- 外部技术团队评估重构成本
- 如小高离职，多久能恢复
- 技术备份

### 第三步：股权谈判

**底线**: 小高不能控股

**谈判方案**:
```
小高要求：51%控股
老马回应：
├── 加薪：年薪翻倍
├── 分红：利润20%分红
├── 期权：4年兑现，每年5%
└── 底线：股权不超过40%

交换条件：
├── 小高提供完整技术文档
├── 小高培训新CTO
└── 小高承诺3年不离职
```

## 五、压力测试

### 场景1: 小高拒绝提供文档
**触发**: 小高说"代码就是我的文档"  
**应对**:
- 冻结股权变动
- 启动外部重构评估
- 考虑法律手段（职务侵占）

### 场景2: 小高突然离职
**触发**: 小高拿着代码去竞争对手  
**应对**:
- 竞业限制启动
- 报警（窃取商业机密）
- 紧急技术重构

### 场景3: 老马被迫接受51%
**触发**: 老马不懂技术，被迫妥协  
**应对**:
- 这是红线，不能妥协
- 宁愿公司死掉，不能失去控制权
- 引入新投资人，稀释小高

---

## 六、决策建议

### 核心问题：老马能否拿回技术控制权？

**建议**: **坚决解耦，不妥协**:

1. 短期（1个月）：要求文档+外部顾问介入
2. 中期（3个月）：招聘新CTO，小高转虚职
3. 长期（6个月）：技术控制权转移，小高可选择留下或退出

### 躯体信号监测

**观察老马与小高下次谈判**:
- 老马：是否坚定 vs 软弱
- 小高：是否合作 vs 要挟

**评估**:
- 老马坚定+小高合作 → 可解决
- 老马软弱 → 必须外部支持（律师/顾问）
- 小高强硬要挟 → 准备分手
