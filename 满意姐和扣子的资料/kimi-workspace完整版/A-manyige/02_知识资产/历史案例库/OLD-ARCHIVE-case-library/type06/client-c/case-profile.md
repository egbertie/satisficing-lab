# Type 6: 项目产品成型打磨期合伙人韧性决策
## Client C - 产品失败边缘场景

---

## 一、客户数字替身档案

| 维度 | 内容 |
|------|------|
| **姓名** | 王工程师 |
| **身份** | 技术极客创始人，产品上线6个月 |
| **产品** | AI硬件（智能音箱+健康监测）|
| **现状** | 销量惨淡（月销100台），现金流断裂 |
| **合伙人** | CTO小李（技术宅）+ 销售合伙人老张（想撤资） |

### 核心痛点
1. **技术完美主义**: 产品功能堆叠，用户不懂用
2. **市场验证失败**: 假设的需求不存在
3. **合伙人内耗**: 技术 vs 销售的口水战

## 二、躯体信号档案

**王工程师的躯体语言**:
- 提及产品：眼睛发亮，语速加快 → 技术热爱
- 提及销量：声音降低，摸鼻子 → 心虚
- 与老张争吵：脸红，手指戳桌子 → 防御性攻击

**关键信号**:
> 王工程师每天工作16小时，但拒绝看用户反馈数据。

**解读**: 用战术勤奋（加班）掩盖战略懒惰（面对失败）。

## 三、合伙人冲突诊断

### 冲突焦点

**王工程师（技术）**:
- "产品没问题，是销售没本事"
- "只要再加这个功能，用户就会买单"
- "给我3个月，我做出颠覆性功能"

**老张（销售）**:
- "产品根本没人要，别浪费钱了"
- "我拉来的客户都说太贵/太复杂"
- "我要撤资，你们继续做梦"

**小李（CTO）**:
- "两边都有道理，我听王总的"
- （内心：其实我也不知道怎么办）

### PFI评分

| 维度 | 王-老张 | 危机阈值 |
|------|---------|----------|
| **价值观契合** | 🔴 20 | <30 |
| **目标一致性** | 🔴 10 | <20 |
| **信任基础** | 🔴 20 | <20 |
| **沟通效率** | 🔴 10 | <30 |

## 四、干预方案

### 第一步：暂停开发（止血）

**立即停止**:
- 新功能开发
- 硬件改版
- 市场推广

**立即开始**:
- 用户深度访谈（至少30个真实用户）
- 产品使用数据分析
- 竞品拆解

### 第二步：面对现实

**数据呈现**（给王工程师看）:
```
残酷真相
├── 用户留存率：5%（行业平均40%）
├── NPS评分：-20（极度不推荐）
├── 退货率：30%
└── 用户反馈Top3：
    1. 不会用（60%）
    2. 太贵（50%）
    3. 不需要这些功能（40%）
```

### 第三步：决策分叉

**选项A: Pivot（转型）**
- 基于现有技术，换场景（B端而不是C端）
- 与老张谈判：再给3个月验证新方向

**选项B: Persevere（坚持）**
- 大刀阔斧砍功能，降低价格
- 老张撤资，王工程师自筹/找新投资

**选项C: 放弃**
- 清算，各自散伙
- 王工程师找份工作，积累经验再创业

## 五、压力测试

### 场景1: 老张强制撤资
**触发**: 老张起诉，要求回购股权  
**应对**:
- 协商分期回购
- 找新投资人接盘
- 最坏：公司清算

### 场景2: 王工程师拒绝面对现实
**触发**: 坚持继续开发，否认失败  
**应对**:
- 董事会强制干预
- 心理咨询
- 考虑CEO替换

### 场景3: 小李站队老张
**触发**: 技术合伙人也失去信心  
**应对**:
- 紧急挽留（股权+情感）
- 技术备份
- 寻找替代CTO

---

## 六、决策建议

### 核心问题：王工程师能否放下骄傲？

**建议**: **强迫面对现实**，期限2周：

1. 王工程师必须完成30个用户深度访谈
2. 基于数据，重新评估产品方向
3. 如果数据支持Pivot → 制定转型计划
4. 如果数据不支持 → 考虑放弃

### 躯体信号监测

**观察王工程师看用户反馈时**:
- 表情：认真 vs 不屑
- 反应：记录 vs 辩解
- 后续：行动 vs 继续原路线

**评估**:
- 认真+记录+行动 → 可救，支持
- 不屑+辩解+原地踏步 → 建议放弃
