# Type 3: 项目升级期（从1到100）合伙人关系决策
## Client A - 案例模拟档案

---

## 一、客户数字替身档案

| 维度 | 内容 |
|------|------|
| **姓名** | 周志强（化名） |
| **年龄** | 41岁 |
| **项目** | 工业物联网平台 |
| **当前阶段** | 从1到100升级期（已验证PMF，年营收5000万→目标5亿） |
| **团队规模** | 80人→计划扩张到300人 |
| **合伙人结构** | 周志强(CEO,45%) + 技术合伙人(CTO,20%) + 销售合伙人(CRO,15%) + 投资人(20%) |

### 核心痛点
- **能力Gap暴露**：技术合伙人从"全能工程师"变成"需要管50人团队的CTO"，不适应
- **股权争议**：CTO认为早期贡献被低估，要求从20%增至30%
- **决策冲突**：从"拍脑袋"到"需要数据支撑"，合伙人之间方法论冲突
- **文化稀释**：新员工大量涌入，早期"兄弟文化"面临崩塌

## 三、决策工具输出

### 工具1: 0-1 vs 1-100 能力Gap矩阵

| 角色 | 0-1阶段要求 | 1-100阶段要求 | Gap评估 |
|------|------------|--------------|---------|
| CTO | 全栈开发、快速迭代 | 团队管理、技术战略、跨部门协作 | 🔴 严重Gap |
| CRO | 亲自跑客户、搞定大单 | 销售体系建设、团队培养、流程标准化 | 🟡 中度Gap |
| CEO | 方向把控、资源协调 | 组织设计、资本运作、战略升级 | 🟡 中度Gap |

**决策选项**：
1. 升级CTO能力（培训+教练）
2. 引入新任CTO，原CTO转架构师
3. 原CTO退出，股权回购

### 工具2: 股权动态调整方案

```
《股权激励调整框架》
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【当前状态】
- CTO: 20%（静态持有）
- 诉求: 增至30%

【调整方案 - 业绩对赌模式】
- 基础股权: 保持20%
- 业绩股权: 最高可增持至30%
  ├─ 团队规模扩展到100人 → +2%
  ├─ 技术架构支撑日活100万 → +3%
  ├─ 培养2名核心技术Leader → +2%
  └─ 技术预算控制在营收15%以内 → +3%

【时间周期】
- 对赌期: 18个月
- 解锁节奏: 每6个月评估一次

【退出机制】
- 未达成目标: 维持20%，无惩罚
- 主动退出: 按最近一轮估值80%回购
```

## 四、72小时压力测试

**场景**: CTO提出"要么增股，要么离职"最后通牒

**Day 1**: 深度诊断
- 与CTO一对一：了解真实诉求（不仅是钱，还有尊重/认可）
- 与CRO沟通：评估CTO替代成本
- 投资人沟通：了解对CTO离开的容忍度

**Day 2**: 方案设计
- 三套方案：A)增股对赌 B)角色转换 C)和平分手
- 沙盘推演：每种方案的后果预测

**Day 3**: 决策执行
- 选定方案
- 与CTO关键对话
- 团队沟通（防止消息失控）
