## 一、客户数字替身档案

| 维度 | 内容 |
|------|------|
| **姓名** | 李明（化名） |
| **项目** | B2B工业品电商平台 |
| **当前阶段** | 从1到100，但选择"慢速增长"路径 |
| **与Client A差异** | Client A是能力Gap导致冲突，Client B是理念分歧 |

### 合伙人理念冲突
| 合伙人 | 观点 | 立场 |
|--------|------|------|
| **李明(CEO)** | "先盈利，再扩张" | 保守派 |
| **CTO** | "技术领先才能赢" | 技术理想派 |
| **CRO** | "必须快速抢占市场" | 激进派 |
| **投资人** | "3年IPO或被收购" | 退出驱动 |

### 独特痛点
- **没有对错，只有选择**：每种理念都有道理
- **决策疲劳**：每天都在争论方向
- **关系磨损**：从"战友"变成"对手"

## 二、决策工具输出

### 满意解决策框架应用

```
《理念分歧的满意解处理》
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【第一步：明确约束条件】
- 现金流：可支撑18个月
- 市场窗口：竞争对手正在融资
- 团队状态：可支撑20%扩张，无法支撑100%

【第二步：生成备选方案】
方案A: 李明方案 - 维持现状，追求盈利
方案B: CTO方案 - 加大技术投入，延迟盈利
方案C: CRO方案 - 激进扩张，融资补血
方案D: 混合方案 - 小步快跑，边盈利边扩张

【第三步：满意解评估】
| 方案 | 盈利时间 | 技术领先 | 市场份额 | 风险 | 综合 |
|------|----------|----------|----------|------|------|
| A | ★★★★★ | ★★☆☆☆ | ★★☆☆☆ | ★★★★☆ | 70分 |
| B | ★★☆☆☆ | ★★★★★ | ★★★☆☆ | ★★★☆☆ | 65分 |
| C | ★☆☆☆☆ | ★★★☆☆ | ★★★★★ | ★★☆☆☆ | 55分 |

【第四步：满意解并非最优解】
- 没有让任何一方完全满意
- 但都在可接受范围内
- 关键是：各方都同意"这是当下最好的选择"
```

### 理念分歧的合伙人契约

```
《理念共存协议》
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【承认差异】
- 我们承认对战略方向有不同看法
- 这些分歧源于对公司的关心，而非个人恩怨
- 分歧本身不是问题，如何处理才是

【决策机制】
- 当分歧发生时，使用满意解决策框架
- 时间盒：最多讨论3天必须决策
- 最终决策权：CEO，但需听取所有意见

【复盘机制】
- 每季度回顾：当时的决策是否正确？
- 如果是错误的，共同承担，不相互指责
- 调整方向，而非调整人

【退出预案】
- 如果某合伙人的理念长期被否决，可选择退出
- 退出机制：按最近一轮估值回购股权
```
