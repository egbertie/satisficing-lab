## Metadata

## Description
蓝军实时拦截系统（Blue-Army-Real-Time-Interceptor）是一个基于5标准化建设的AI响应质量拦截与审计系统。通过分层审计、智能抽样、结果缓存和模型降级策略，实现对AI输出的实时质量把控，同时大幅降低Token消耗（目标节省85-90%）。

## Trigger Conditions
- 当主控AI生成响应需要质量审计时
- 当需要实时拦截潜在问题输出时
- 当需要分层审计策略（L1/L2/L3）时
- 当需要优化Token消耗的场景

## Token Optimization Configuration

### 分层审计策略
| 层级 | Token预算 | 审计深度 | 适用场景 |
|------|----------|----------|----------|
| L1轻量 | 100 tokens | 基础语法、敏感词检测 | 低风险、短文本 |
| L2标准 | 500 tokens | 逻辑一致性、事实核查 | 中风险、常规文本 |
| L3深度 | 1000 tokens | 全面审计、多维度分析 | 高风险、长文本 |

### 抽样策略
- **随机抽样比例**: 30%
- **异常触发**: 检测到高风险关键词时100%审计
- **结果缓存**: 相似请求复用审计结果（基于向量相似度≥0.85）

### 模型降级策略
- **审计模型**: GPT-3.5-turbo（低成本执行审计）
- **主响应模型**: GPT-4（保持输出质量）
- **降级触发**: Token预算紧张时，审计可进一步降级至本地规则引擎

### Token节省目标
- **原始消耗**: ~40,000 tokens/日
- **优化后目标**: ~4,000-6,000 tokens/日
- **节省率**: 85-90%

## 5-Standard Implementation (S1-S7)

### S1: 全局考虑 (Global Consideration)

#### 人员 (People)
- **主控AI**: 生成原始响应
- **蓝军AI**: 执行分层审计（本系统）
- **最终用户**: 接收经过审计的输出

#### 事务 (Process)
```
请求拦截 → 分层决策 → 蓝军审计 → 质量评分 → 修正/放行 → 输出
```

#### 资源 (Resources)
- **计算资源**: CPU/内存用于本地缓存和规则匹配
- **Token预算**: 优化后6,000 tokens/日
- **存储资源**: 审计日志和缓存（预估1GB/月）

#### 环境 (Environment)
- **实时性要求**: 最大延迟<500ms
- **抽样率**: 30%随机 + 异常触发
- **缓存命中率**: 目标>60%

#### 外部依赖 (External)
- **GPT-3.5 API**: 审计执行
- **缓存存储**: 本地SQLite/Redis
- **向量相似度**: 本地embedding计算

#### 边界条件 (Boundaries)
- **最大延迟**: <500ms（P99）
- **最低通过率**: ≥95%（非拦截率）
- **熔断机制**: 连续失败>5次时自动降级

```python
def auto_tier_selection(risk_score: float, text_length: int, 
                        cache_hit: bool) -> str:
    """
    自动选择审计层级
    
    Args:
        risk_score: 风险评分 (0-100)
        text_length: 文本长度
        cache_hit: 缓存是否命中
    
    Returns:
        tier: "L1" | "L2" | "L3" | "SKIP"
    """
    if cache_hit:
        return "SKIP"  # 复用缓存结果
    
    if risk_score < 30 and text_length < 200:
        return "L1"
    elif risk_score < 70 and text_length < 1000:
        return "L2"
    else:
        return "L3"
```

```python
class CircuitBreaker:
    """熔断器实现"""
    
    def __init__(self, threshold=5, recovery_time=60):
        self.failure_count = 0
        self.threshold = threshold
        self.state = "CLOSED"  # CLOSED/OPEN/HALF_OPEN
        self.recovery_time = recovery_time
    
    def record_failure(self):
        self.failure_count += 1
        if self.failure_count >= self.threshold:
            self.state = "OPEN"

        if self.state == "HALF_OPEN":
```

```python
class FalsePositiveTracker:
    """误报率追踪器"""
    
    def __init__(self):
        self.total_blocks = 0
        self.user_overrides = 0  # 用户手动放行的拦截
```

## Limitations & Future Work

### 当前局限
1. **抽样审计遗漏**: 30%抽样率意味着70%请求未深度审计
2. **GPT-3.5精度**: 审计模型精度低于主响应模型
3. **缓存复用风险**: 相似请求可能因上下文差异产生误判
4. **实时性代价**: 延迟限制可能影响审计深度

### 未来优化方向
1. **自适应抽样**: 基于历史准确率动态调整抽样率
2. **多模型投票**: 集成多个轻量模型提高审计准确性
3. **增量审计**: 仅审计变化部分，减少Token消耗
