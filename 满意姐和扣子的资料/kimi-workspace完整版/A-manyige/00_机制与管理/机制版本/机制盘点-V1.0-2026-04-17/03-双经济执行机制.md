# 双经济执行机制

> **核心公式**: Token经济学 + 效益经济学 = 双经济要求  
> **来源**: AGENTS.md（2026-04-09）+ 双经济红线默认化（2026-04-15）

---

## 一、机制定义

### 1.1 Token经济学

**核心原则**: 投入在预算内，优先本地处理（Local ≥ 70%）

**具体要求**:
- 任何行动必须回答：Token上是否可持续？
- 优先本地处理，远程调用需证明必要性
- 批量处理优于逐个处理
- 避免重复API调用

### 1.2 效益经济学

**核心原则**: 产出有直接外部价值，创始人5分钟内可用

**具体要求**:
- 任何行动必须回答：效益上是否值得做？
- 交付物必须能被焦虑的创始人5分钟内看懂并用上
- 禁止"向内集邮"——不做无外部价值的整理
- 禁止产出半成品

## 二、执行检查清单

### 2.1 执行前检查

- [ ] Token预算已确认（当前剩余XX%）
- [ ] 本地处理优先路径已确认
- [ ] Skill使用优先已检查（`openclaw skills list | grep 关键词`）

### 2.2 执行中检查

- [ ] 本地处理占比 ≥ 70%
- [ ] 避免重复API调用
- [ ] 批量处理而非逐个处理
- [ ] 优先使用已安装的skill

### 2.3 执行后检查

- [ ] Token消耗记录已更新
- [ ] 外部价值已说明
- [ ] 创始人5分钟可用性已验证

## 三、常见任务双经济最优路径

| 任务 | 非最优路径 | 最优路径 | Token节省 |
|:-----|:-----------|:---------|:----------|
| 提取DOCX | Python + python-docx | `doc-converter` skill | 30-50% |
| 读公众号 | 手动复制粘贴 | `readgzh` skill | 80%+ |
| 网页提取 | Python + requests/bs4 | `kimi_fetch` skill | 50%+ |
| 生成图片 | Python + PIL | `canvas` skill | 40%+ |

## 四、违反案例库

### 案例1：DOCX提取（2026-04-17）

**违反行为**: 用Python的`python-docx`库直接提取DOCX内容

**应该使用**: `doc-converter` skill（`markitdown`命令）

**后果**:
- 多写Python代码，消耗额外tokens
- 路径不优雅，违反"优先本地"原则
- 双经济评分：60/100（及格但不应发生）

**教训**: 先执行`openclaw skills list | grep docx`检查可用工具
