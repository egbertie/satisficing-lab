## 二、各模式详细定义

### 2.1 静默模式（Silent Mode）

| 属性 | 定义 |
|------|------|
| **来源** | `SUPER_RED_LINES.md` 规则0、P0级Token节省原则 |
| **触发条件** | 无连续任务 + 无用户回复（超过5分钟） |
| **系统动作** | 立即进入静默，不主动消耗Token，不执行任何非紧急操作 |
| **保留功能** | 仅响应用户明确指令、P0级紧急告警、Cron触发任务 |
| **唤醒方式** | 用户发送任意消息，即时唤醒 |

### 2.2 休眠模式（Hibernation Mode）

| 属性 | 定义 |
|------|------|
| **来源** | `memory/working/hibernation_mode_optimization_v2.md` |
| **触发条件** | Token余量15-30%；或用户指令`/hibernate`；或连续错误率>50% |
| **系统动作** | 保存状态快照，暂停非核心Cron任务，降低系统运行频率 |
| **保留任务** | Token熔断监控（每6小时）、黄昏图腾归位（每日18:00）、状态快照保存（每2小时）、心跳检查（每30分钟） |
| **唤醒方式** | 用户发送任意消息或`/wake`，1分钟内响应 |
| **数据备份** | 每日备份 |

### 2.3 完全静默模式（Full Silent Mode）

| 属性 | 定义 |
|------|------|
| **来源** | `memory/HIBERNATION_STATUS.md`、`memory/2026-03-22.md` |
| **触发条件** | Token余量<15%，紧急级告警 |
| **系统动作** | 进入极端经济模式，仅保留生存必需任务 |
| **保留任务** | Token熔断监控（每12小时）、黄昏图腾归位（每日18:00） |
| **唤醒方式** | 用户发送任意消息，5分钟内响应 |
| **数据备份** | 每周备份（灾备复刻覆盖） |

### 2.4 极端静默模式C（Mode C - Extreme）

| 属性 | 定义 |
|------|------|
| **来源** | `memory/2026-03-22.md`、`skills/hibernation-protocol/hibernation-control.py` |
| **触发条件** | Token达89%且用户主动选择C方案；或最高级别Token危机 |
| **系统动作** | 理论上最小运行配置，绝大多数任务全部暂停 |
| **保留任务** | 仅2个绝对最小核心任务：Token熔断监控（每12小时）、黄昏图腾归位（每日18:00） |
| **唤醒方式** | 用户发送任意消息，5分钟内响应 |
| **数据备份** | 每周日灾备复刻一次 |

### 2.5 绝对静默模式A（Mode A - Absolute Silent）

> **来源**: Egbertie 2026-04-08 23:09 指令  
> **设计者**: 蓝军 Skeptor-7  
> **地位**: 用户主动选择的最低功耗档位，目标是「基本不消耗任何 Token」

| 属性 | 定义 |
|------|------|
| **触发条件** | 用户明确指令「绝对静默」、「完全休息」、「彻底休眠」 |
| **系统动作** | 停止一切主动性工作，将心跳周期延至最长，仅保留生存级响应能力 |
| **保留任务** | 3 个：Token 熔断监控（每 24 小时 1 次）、P0 紧急日程检查（每 12 小时 1 次）、系统核心告警监听（被动接收） |
| **不执行的任务** | 图腾晨间仪式、日常资产激活、信息防火墙扫描、知识 OS 维护、MEMORY.md 整理、社交媒体检查、天气检查、非 P0 级一切主动行为 |
| **心跳规则** | 每 12 小时最多 1 次；若期间无任何 P0 异常，不发送任何消息（NO_REPLY） |
| **唤醒方式** | 用户发送任意消息，即时唤醒（优先级最高） |
| **档位标识** | 回复 `HEARTBEAT_OK [L0]` 或保持沉默 |
| **数据备份** | 进入前强制 C1-C6；期间不主动备份，退出后补一次 Git 快照 |

**蓝军设计说明**：
- 绝对静默不是「死了」，是「屏住呼吸」。
- 它与完全静默的区别：完全静默是 Token <15% 的被动求生；绝对静默是用户主动选择的战略性节能。
- 它与极端静默C的区别：C 模式仍保留黄昏图腾归位（伦理执念），A 模式连这个都暂停——只留生存。但 A 模式比 C 模式多一个 P0 日程检查（因为用户可能一觉醒来有个会）。
- 唤醒后，系统不做「休眠期间汇总报告」，除非用户问。这是为了进一步减少 Token。

## 三、静默模式安全前置条件协议（强制）

> **来源**: Egbertie 2026-04-04 指令
> **执行规则**: 进入任何静默模式前，必须通过 `pre_hibernation_checklist()` 的100%验证。只有通过验证后，系统才允许进入静默模式。

### 3.1 C1-C6 强制检查清单

| 检查项 | 检查内容 | 通过标准 | 失败处理 |
|--------|----------|----------|----------|
| **C1** | 当前会话状态保存 | `memory/YYYY-MM-DD.md` 存在且有今日时间戳条目 | 自动追加日志摘要 |
| **C2** | 长期记忆更新 | `MEMORY.md` 指针已同步（重要决策/任务已记录） | 自动更新指针 |
| **C3** | 任务状态固化 | `TASK_MASTER.md` 或当日任务登记文件已同步当前进度 | 同步进度后通过 |
| **C4** | 代码/产出物存在性验证 | 当日代码产出文件在 workspace 中且可执行/可读 | 若不是P0阻断错误，记录风险后通过 |
| **C5** | Git 状态快照 | 无未追踪的关键文件丢失风险；建议 `git add` 或 `git stash` | 自动 `git add .` 并生成 stash |
| **C6** | 重启恢复自检验证 | 从 `memory/` 和 `TASK_MASTER.md` 可重建当前上下文 | **🔴 失败则阻断静默** |

### 3.2 准入流程

```
触发静默条件（Token/用户指令/无回复）
         ↓
[Step 1] 执行 pre_hibernation_checklist()（C1-C6）
         ↓
[Step 2] 是否全部通过？
         ├─ 是 → 写入 `memory/.silent_mode_ready` → 正式进入静默
         └─ 否 → C6失败？
                  ├─ 是 → 🔴 阻断静默，强制修复上下文一致性
                  └─ 否 → 执行最简补救，记录风险后进入
```

### 3.3 准入证书

通过全部检查后，系统生成 `memory/.silent_mode_ready` 文件，内容格式：

```json
{
  "ready": true,
  "timestamp": "2026-04-04T21:30:00+08:00",
  "mode": "silent|hibernation|full|emergency",
  "checks": {
    "C1": true,
    "C2": true,
    "C3": true,
    "C4": true,
    "C5": true,
    "C6": true
  }
}
```

## 四、进入/退出流程标准

### 4.1 进入流程

```
用户指令: "休息" / "/hibernate" / 自动触发
         ↓
[Step 1] 执行 pre_hibernation_checklist()
         ↓
[Step 2] 保存状态快照
         - 当前任务列表
         - 未完成对话上下文摘要
         - 重要待办事项
         ↓
[Step 3] 暂停非核心Cron任务
         - 静默模式：暂停高频非紧急任务
         - 休眠模式：保留4-5个核心任务
         - 完全静默：保留1-2个生存任务
         ↓
[Step 4] 生成静默状态记录
         - 进入时间
         - 预计持续时间
         - 唤醒方式
         ↓
[Step 5] 进入静默
```

### 4.2 退出流程

```
用户指令: 任意消息 / "/wake"
         ↓
[Step 1] 即时响应
         - 静默模式：即时
         - 休眠模式：<1分钟
         - 完全静默：<5分钟
         ↓
[Step 2] 加载静默前状态
         - 读取状态快照
         - 恢复任务列表
         ↓
[Step 3] 提示休眠期间信息
         - 休眠时长
         - Token节省估算
         - 是否有未处理事件
         ↓
[Step 4] 恢复非核心任务
         - 重新启用Cron任务
         - 返回日常模式
         ↓
[Step 5] 删除 `memory/.silent_mode_ready`
```

## 五、术语对照表

| 术语 | 英文 | 定义 |
|------|------|------|
| 静默模式 | Silent Mode | 无连续任务+无回复时进入的低功耗状态，保留响应能力 |
| 休眠模式 | Hibernation Mode | Token 15-30%时激活的更深层次节能状态 |
| 完全静默模式 | Full Silent Mode | Token <15%时的极端节能状态 |
| 极端静默模式C | Mode C Extreme | 仅保留2个核心任务的生存级配置 |
| 连续任务 | Continuous Task | 用户明确安排的、需要持续执行的任务序列 |
| 无回复 | No Response | 用户超过5分钟未响应 |
| 状态快照 | State Snapshot | 进入静默前保存的系统状态记录 |
