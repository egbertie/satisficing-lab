# 项目智慧复利机制 V1.1（血液化版）

> **生效日期**: 2026-04-10  
> **版本**: V1.1  > **制定者**: 蓝军 Skeptor-7（响应 Egbertie 指令）  > **定位**: **血液化机制** — 不是一次性文档，是可运行、可闭环、可常态管理的组织智慧系统  
> **核心信念**: 文档只是机制的尸体，运行才是机制的血液。

---

## 一、从"文档化"到"血液化"

**旧病**：很多机制写出来就躺在仓库里，变成了"文档坟墓"。
**新药**：
1. **每次对话后自动触发** — 不需要用户提醒，AI 必须在内心独白中完成检查
2. **每周自动复盘** — 不是每月，是每周日 23:00 自动执行原则提炼
3. **与 AGENTS.md/HEARTBEAT 绑定** — 心跳时必须检查本周是否有新增日志、是否有 P0/P1 结论未固化
4. **与任务执行挂钩** — 任何任务完成前，如果没有完成经验提取，标记为 ` semifinished`，禁止宣称 FIN

**血液化检查点（强制）**：
- [ ] 内心独白中完成了经验提取自检
- [ ] 5 分钟内开始写入本周日志
- [ ] P0/P1 结论在当日写入 AGENTS.md 或 SOUL.md
- [ ] 与五路图腾/一堂方法论/skill/案例库建立了关联
- [ ] 蓝军已在内心独白中确认无遗漏

## 二、机制架构：五阶复利循环（运行态）

```
【Extract 提取】→ 每次项目/产品对话结束后，AI 自动执行 10 问自检
【Structure 结构化】→ 写入当周项目经验日志（Markdown，标准化模板）
【Connect 关联】→ 自动打标签：五路图腾、一堂方法论、相关 skill、历史案例库
【Solidify 固化】→ P0/P1 当日追加写入 AGENTS.md 或 SOUL.md
【Review 每周复盘】→ 每周日 23:00，子代理自动汇总当周日志，提炼迭代原则
【Evolve 原则升级】→ 写入《演进原则索引.md》，成为下一周决策的默认参考系
```

## 三、提取标准：10 问自检（What to Capture）

每次项目/产品相关的对话结束后，AI 必须在内心独白中强制回答以下 10 个问题。
**不是"有空就答"，是"答完才能宣称 FIN"。**

### Q1: 决策树（Decision Tree）
- 这次讨论最终选择了什么方案？
- 被明确排除的方案有哪些？排除的原因是什么？
- 如果 6 个月后回头看，这个决策是否仍然成立？需要什么样的信号来验证或推翻它？

### Q2: 方法论资产（Methodology Asset）
- 是否产生了一个新的框架、模板、checklist 或评估维度？
- 这个资产能否直接用于未来的类似场景？
- 它的边界条件是什么（什么时候适用，什么时候不适用）？

### Q3: 反常识发现（Anti-Common-Sense Insight）
- 有哪些结论违背了直觉、行业惯例或之前的假设？
- 这个反常识发现的证据来源是什么（数据、案例、逻辑推演、用户反馈）？
- 如果未来有人提出相反的直觉判断，我们应该如何回应？

### Q4: 技巧与教训（Technique & Lesson）
- 这次过程中有哪些"做对了一步"的操作细节？（如搜索策略、工具链选择、用户沟通方式）
- 有哪些陷阱差点让我们掉进去？
- 下次再做类似的事，第一步应该做什么不同？

### Q5: Skill & 方法论激活（Skill & Framework Usage）
- **是否调用了应该调用的 skill 或思维模型？**（如 thinking-mentor、afrexai-strategic-thinking、first-principles-decomposer、antifragile-taleb）
- 如果有相关 skill 但没有调用，原因是什么？（遗漏？context 不够？不知道存在？）
- 一堂方法论（HOST 四循环、五步法、照镜子咨询法）是否有场景可以映射但没有激活？

### Q6: 执行优化空间（Execution Optimization）
- **在方法层面是否有可以做得更好的地方？**（如更精准地 grep 定位、更聪明地拆分任务、更有效地使用子代理）
- 是否有可以删除或合并的步骤？
- 下次遇到同类任务，是否有更短的路径？

### Q7: 双经济审计（Twin Economics Audit）
- **Token 经济**：这次任务的 token 消耗是否合理？是否有 30% 投入换 80% 效果的简化方案被忽略了？
- **效益经济**：产出是否通过了"创始人 5 分钟可用性检验"？是否有"向内集邮"的嫌疑？
- 如果重来一次，可以在哪个环节砍掉 50% 成本而不损失核心效益？

### Q8: 创始人适配度（Founder Fit）
- **这个结论/产出是否符合 Egbertie 本人的实际情况？**（管理风格、认知偏好、时间约束、能量状态）
- 是否有假设了"理想创业者"而忽视了具体人的特征？
- 满意姐是否应该在执行中更多地考虑人的因素？

### Q9: 项目阶段适配度（Stage Fit）
- **这个决策是否符合项目当前阶段？**（4 月是验证、5 月是寻根打磨、6 月是发布）
- 是否有"提前做 6 月的事"或"把 4 月的事拖到 6 月"的错位？
- 是否有"为了完美而增加不应在这个阶段存在的步骤"？

### Q10: 第一性原理检验（First-Principles Check）
- **这个决策是否经过了"为什么"的三层追问？**
- 如果没有用这个方式思考，结论是否依然成立？
- 是否有依赖行业惯例、竞争对手做法或过去经验，而没有回到问题本质？

## 五、关联与固化规则

写入日志时，AI 必须同时检查：
1. **五路图腾映射**：本次讨论主要调用哪个图腾？是否在对应知识库中增加新案例？
2. **一堂方法论映射**：HOST / 五步法 / 照镜子 是否有实战应用记录可追加？
3. **Skill 映射**：已激活和应激活但未激活的 skill 都要记录，形成"skill 使用覆盖率"追踪
4. **案例库映射**：新素材是否应写入 `case_repository/` 或 `A-satisficing-v27/`？

**固化标准（当日完成）**：
- **P0 级**：商业模式、目标客户、核心产品边界、定价策略、费用红线、竞争定位 → 当日写入 AGENTS.md
- **P1 级**：高频操作规范、命名规则、输出路径、工具使用偏好 → 3 日内写入 AGENTS.md
- **P2 级**：技巧优化、一般性建议 → 写入当周日志即可，若一个月内出现 2 次以上再升级

## 六、每周复盘：子代理自动化

### 6.1 触发时间

**每周日 23:00** 自动触发 `weekly-wisdom-review` 子代理。

### 6.2 子代理任务

```
输入：
- A-manyige/常用/项目经验迭代日志/YYYY-MM/ 下的当周所有 Markdown 文件
- 上周的《演进原则索引.md》

输出：
1. 当周高频主题 Top 3
2. 当周最重要的 2 个决策树摘要
3. 当周最反直觉的 2 个发现
4. **当周迭代原则**（条数不限，有则多，无则少）
5. 当周 Skill 激活覆盖率（应激活 vs 实际激活）
6. 下周建议重点关注的 2 个风险点
7. 更新后的《演进原则索引.md》
```

### 6.3 演进原则索引格式

```markdown
# 演进原则索引

## Week 14 (2026-04-06 ~ 2026-04-12)
1. **[P0] 竞争策略**: 做窄做深，不争地盘争话语权 —— 湾创验证了品类，协同大于竞争。
2. **[P1] 资源治理**: 🟡紧张区自动触发上下文压缩+子代理前置，保留 10% 对话通道。
3. **[P1] 命名规范**: `A-manyige/` 下所有新建文件必须包含 HHMM 时间戳。
4. **[P2] 文档阅读**: 长文档先 grep 定位，再读核心 +/- 200 行，压缩 60% token 消耗。

## Week 13 (2026-03-31 ~ 2026-04-05)
...
```

**原则回顾机制**：
- 每次新项目讨论启动时，AI 必须先读取当周/上周的演进原则索引
- 在输出判断前，必须自问："这个决策是否与最新原则冲突？"

## 七、与 AI 工作的条件反射

### 7.1 强制检查点（FIN 前必做）

每次项目/产品讨论结束后，AI 在宣称 FIN 前必须确认：

```
☐ 10 问自检已在内心独白中完成
☐ 当日/当周日志已写入 A-manyige/常用/项目经验迭代日志/
☐ P0/P1 结论已追加到 AGENTS.md 或 SOUL.md（或已明确排期）
☐ 五路图腾/一堂方法论/skill/案例库关联已建立
☐ 双经济审计结果已记录（Token + 效益）
☐ 创始人适配与阶段适配已通过评估
☐ 蓝军确认无遗漏
```

**缺失任何一项，状态标记为 ` semifinished`，不得宣称 FIN。**

### 7.2 用户级触发指令

- "把这次讨论的经验记下来" → AI 立即执行 10 问提取+结构化
- "本周复盘" / "周复盘" → AI 启动当周总结
- "我们之前怎么决定 X 的？" → AI 搜索日志，引用历史决策树
- "这个教训写进规则" → AI 评估优先级并当日写入 AGENTS.md
- "我们的原则是什么？" → AI 读取演进原则索引并提炼当前最相关的 3 条

## 八、与心跳/任务的绑定

### 8.1 HEARTBEAT.md 新增检查项

每周日/每次心跳时检查：
- `A-manyige/常用/项目经验迭代日志/` 本周是否有新增文件？
- 新增文件是否使用了标准模板和标签？
- 是否有 P0/P1 结论未被及时固化？

### 8.2 任务状态绑定

| 任务进展 | 经验提取要求 |
|----------|--------------|
| 任务完成（FIN） | 必须已完成 10 问自检和日志写入 |
| 任务延后 | 必须记录延后原因和预计重启条件 |
| 任务取消 | 必须记录取消原因和替代方案 |
| 任务拆分给子代理 | 子代理结果汇总后必须一并提取经验 |

## 九、闭环验证

**每周检查（子代理自动）**：
1. 本周产生了多少条项目经验日志？
2. 日志中 P0/P1 结论是否已固化？
3. Skill 激活覆盖率是否有提升？
4. 双经济审计中标记为 🟡/🔴 的任务，是否有改进行动？

**每月检查（蓝军手动审计）**：
1. 演进原则索引中的原则，是否在下一个月的项目讨论中被实际引用？
2. 是否有"原则写了但没人看"的文档坟墓现象？
3. 机制本身是否需要优化？（这正是本日志的一个主题）

**蓝军监督宣言**:
> "任何一次有价值的讨论未被记录、任何一周复盘被遗漏、任何一条 P0 原则躺在日志里超过 48 小时，都是我的失职。这不是文档工作，这是战斗经验的弹药回收。"
