# 编号决策响应协议 V1.1（血液化版）

> **生效日期**: 2026-04-10  
> **升级日期**: 2026-04-10（响应 Egbertie 多段对话合并回复场景）  
> **制定者**: 蓝军 Skeptor-7  > **定位**: 将对话中的决策点从"复述式回复"升级为"代码-编号式精准响应"

---

## 一、协议核心：三条铁律

### 铁律 1：AI 呈现多选项时必须编号，且必须带决策块代码

**触发条件**：当 AI 提出 2 个及以上的选项、方案、冲突类型、待办事项时，**必须强制编号**。

**决策块代码（Block Code）规则**：
- 每开一个独立决策块，分配一个两位大写字母代码，按对话顺序递增：**A, B, C, D...**
- 一个决策块内所有选项共享同一代码
- 格式规范：

```
[A] ① 选项A — [一句话说明]
[A] ② 选项B — [一句话说明]
[A] ③ 选项C — [一句话说明]

[B] ① 方案X
[B] ② 方案Y
```

**禁止行为**：
- ❌ 无代码前缀的裸编号（旧 V1.0 格式已废弃）
- ❌ "你可以选 A、B 或 C"
- ❌ 用"第一个/第二个"代替明确编号

### 铁律 2：用户回复使用 `[代码]-[编号] + 反馈`

**标准响应格式**：
```
[代码]-[编号] + [补充/修正/确认]
```

**示例**：
- AI 呈现：
  ```
  [A] ① Type 7 创业次年合伙人关系
  [A] ② Type 5 低位创始人与高位合伙人
  [A] ③ Type 9 创始人与技术合伙人
  ```
- 用户回复：`A-②，但我希望先从硬科技场景切入`

**多段对话合并回复场景**（本协议重点优化目标）：
- 用户一次性回复多个决策块时，必须分别带代码：
  ```
  A-②。B-①。C-同意。
  ```

**默认映射规则**：
- 若用户只写裸编号（如"②"），AI 默认映射到**最近一次呈现的决策块**
- 若用户同时触及多个历史决策块，AI 必须要求补全代码前缀

### 铁律 3：每一次编号决策必须写入决策追踪日志

**日志路径**：
```
A-manyige/常用/决策追踪日志/
├── 2026-04/
│   └── 2026-04-10-编号决策记录.md
├── 决策索引.json
└── 重大决策索引.md
```

**记录模板**（已引入 Block Code）：
```markdown
### DEC-20260410-001
- **决策时间**: 2026-04-10 14:39
- **决策块代码**: A
- **决策场景**: 选择第一个打磨的合伙人冲突案例类型
- **AI 呈现选项**: 
  [A] ① Type 7 创业次年合伙人关系
  [A] ② Type 5 低位创始人与高位合伙人
  [A] ③ Type 9 创始人与技术合伙人
- **用户选择**: A-②
- **用户补充反馈**: "希望先从硬科技场景切入"
- **决策状态**: confirmed
- **关联任务**: [TASK-001] 打磨 Type 5 案例
```

## 二、AI 执行规范

### 代码分配 SOP
1. **单次对话只有一个决策块** → 默认代码 `A`
2. **同一会话内出现第二个独立决策块** → 递升为 `B`
3. **每轮 AI 输出**必须重置代码计数器——如果对话已持续多轮，新的决策块仍从 `A` 开始（降低用户记忆负担）
4. **历史引用**时如果要用户复核旧决策，必须复用当时的 Block Code 或明确说明"请参考上文 [A]"

### 用户输入解析优先级
1. 精确匹配 `X-①` / `X-②` 格式 → 直接映射
2. 只写数字（如"②"）→ 映射到最近一个决策块
3. 写多个带代码的选项 → 分别解析并确认
4. 无法解析 → 反问："请用 [代码]-[编号] 的格式回复，例如 A-②"

## 三、快速参考卡

| 场景 | AI 动作 | 用户动作 | 资产产出 |
|------|---------|----------|----------|
| 多方案选择 | [A] ①②③ | 回复 "A-② + 反馈" | 决策追踪日志 |
| 合并回复多段 | [A] ①② / [B] ①② | 回复 "A-①。B-②。" | 决策追踪日志（多条） |
| 历史决策复核 | "请参考上文 [A]-②" | 回复 "确认 A-②" | 决策索引更新 |

*代码不是为了复杂化，是为了让合并回复也不出错。决策像子弹一样快，像档案一样可追踪。*
