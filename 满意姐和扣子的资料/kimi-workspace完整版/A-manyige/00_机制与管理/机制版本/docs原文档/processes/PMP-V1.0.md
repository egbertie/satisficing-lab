## 阶段详解

### 阶段0: 前置确认 (10分钟)

**目标**: 确认文件基本信息，排除重复/无效文件

**检查清单**:
- [ ] 告知文件名、UUID、大小、类型
- [ ] 判定文件性质（确认适用PMP流程）
- [ ] 检测重复文件（文件名+大小+内容哈希）
- [ ] 检查文件完整性（段落数统计）
- [ ] 确认上一文件已闭环

**输出物**:
```
文件信息卡片:
- 文件名: xxx.docx
- UUID: xxx
- 大小: xxx bytes
- 段落数: xxx
- 类型: 程序类
- 重复状态: 新文件/重复版本
```

**决策点**:
- 重复文件 → 标记跳过
- 文件损坏 → 报告异常
- 类型不符 → 转WEP流程

---

### 阶段1: 质量门控 (20分钟) ⭐新增

**目标**: 前置可行性评估，避免无效投入

**检查清单**:

**1.1 可行性评估**
- [ ] 文件内容是否可解析
- [ ] 是否包含可实施组件
- [ ] 技术栈是否匹配当前环境

**1.2 风险评估**
- [ ] 复杂度评估（段落数/组件数）
- [ ] 依赖外部资源评估
- [ ] 技术债务风险

**1.3 资源估算**
- [ ] 预估组件数量
- [ ] 预估实施时间
- [ ] 确定P0/P1/P2范围

**输出物**:
```
质量门控报告:
- 可行性: ✅通过 / ❌不通过
- 风险等级: 🟢低 / 🟡中 / 🔴高
- 预估组件: P0(x), P1(x), P2(x)
- 建议时间: xxx分钟
- 决策: 继续/降级/跳过
```

**不通过处理**:
- 可行性不通过 → 标记跳过，记录原因
- 风险过高 → 与用户确认是否继续
- 资源不足 → 拆解为多个子任务

---

### 阶段2: 深度洞察 (30分钟)

**目标**: 全文扫描，识别组件，理论映射

**检查清单**:
- [ ] 全文深度扫描（100%段落，无遗漏）
- [ ] 关键词统计与聚类
- [ ] 结构分析（章节/组件识别）
- [ ] 理论框架映射
- [ ] 技术债务识别

**输出物**:
```
深度洞察报告:
- 总段落数: xxx
- 识别组件: xx个
  - P0: xx个
  - P1: xx个
  - P2: xx个
- 理论映射: xxx
- 技术债务: xxx
```

**禁止事项**:
- ❌ 速度导向（只扫描部分段落）
- ❌ 跳过边界检查
- ❌ 理论引用缺失

---

### 阶段3: 实施设计 (20分钟) ⭐新增

**目标**: 明确实施范围，制定实施计划

**检查清单**:
- [ ] P0组件完整实施范围确认
- [ ] P1组件核心功能范围确认
- [ ] P2组件框架实现范围确认
- [ ] 依赖关系梳理
- [ ] 回退机制设计

**分层实施标准**:

| 优先级 | 实施深度 | 交付标准 | 时间预算 |
|--------|----------|----------|----------|
| **P0** | 完整实施 | 代码+单元测试+验证 | 60分钟 |
| **P1** | 核心功能 | 关键功能实现+基础验证 | 40分钟 |
| **P2** | 框架实现 | 代码框架+注释+迭代条件 | 20分钟 |

**输出物**:
```
实施设计文档:
- P0组件清单: [xxx, xxx]
  - 每个组件的实施范围
  - 验收标准
- P1组件清单: [xxx, xxx]
  - 核心功能点
- P2组件清单: [xxx, xxx]
  - 框架结构
- 依赖关系图
- 回退触发条件
```

---

### 阶段4: 分层实施 (动态时间)

**目标**: 按计划实施组件，支持回退

**检查清单**:

**4.1 P0组件实施**
- [ ] 完整代码实现
- [ ] 单元测试编写
- [ ] 功能验证通过

**4.2 P1组件实施**
- [ ] 核心功能实现
- [ ] 基础功能验证

**4.3 P2组件实施**
- [ ] 代码框架搭建
- [ ] 详细注释
- [ ] 迭代条件记录

**回退机制**:
- 发现设计问题 → 回退到阶段3
- 发现需求问题 → 回退到阶段2
- 发现不可行 → 回退到阶段1（标记降级）

**输出物**:
```
实施成果:
- 代码文件: xxx.py (xxx bytes)
- 配置文件: xxx.yaml
- 测试用例: xxx个（P0组件）
- 迭代条件: xxx.md
```

---

### 阶段5: 验证闭环 (20分钟)

**目标**: 质量验证，确保交付物可用

**检查清单**:

**5.1 功能验证**
- [ ] P0组件单元测试通过
- [ ] 集成测试通过
- [ ] 边界条件测试

**5.2 蓝军审计**
- [ ] 代码审查
- [ ] 文档审查
- [ ] 置信度评定

**5.3 修复闭环**
- [ ] 问题修复
- [ ] 回归测试
- [ ] 最终确认

**输出物**:
```
验证报告:
- 测试通过率: xx%
- 发现问题: xx个
- 修复情况: xx/xx
- 蓝军评定: 🟢通过 / 🟡有条件通过 / 🔴不通过
- 置信度: 🟢高
```

---

### 阶段6: 归档固化 (10分钟)

**目标**: 完整记录，更新Memory，Git提交

**检查清单**:
- [ ] 闭环报告生成
- [ ] 技术迭代条件记录
- [ ] Memory追加
- [ ] Git提交

**输出物**:
```
归档清单:
- [ ] 闭环报告: A-manyige/汇报/xxx.md
- [ ] 迭代条件: xxx/docs/技术迭代条件记录.md
- [ ] Memory: memory/2026-04-04.md
- [ ] Git: commit推送
```

## 关键特性

### 1. 质量门控前置
- 阶段1设置可行性评估
- 避免在不可行文件上浪费时间
- 资源估算指导后续投入

### 2. 分层实施机制
- P0/P1/P2差异化实施深度
- 时间预算动态分配
- 确保核心价值优先交付

### 3. 回退机制
- 阶段4可回退到阶段3/2/1
- 发现问题及时纠正
- 降低返工成本

### 4. 双质量门控
- 前置: 阶段1可行性评估
- 后置: 阶段5功能验证
- 全程质量保障

| 维度 | 旧流程 | PMP-V1.0 (优化后) |
|------|--------|-------------------|
| 质量门控 | 后置(阶段5) | 前置(阶段1)+后置(阶段5) |
