## 一、"七化"定义与区别

| 术语 | 定义 | 关键特征 | 典型产出物 |
|:-----|:-----|:---------|:-----------|
| **固化** | 将临时做法转变为永久规则 | 文档化、位置固定、可检索 | 规则文档、目录结构 |
| **内化** | 将外部知识转化为内部能力 | 理解→应用→创新 | 知识映射、工具模板 |
| **标准化** | 统一格式、流程、质量标准 | 可复制、可检查、可改进 | SOP、检查清单 |
| **体系化** | 建立层级关联和依赖关系 | 网状结构、相互引用 | 知识图谱、框架图 |
| **机制化** | 设计自动触发和自我维持的系统 | 触发器、反馈环、责任制 | 自动化脚本、cron任务 |
| **血液化** | 融入日常决策和行为的直觉反应 | 无需提醒、条件反射 | 速查卡、决策树 |
| **系统化** | 整合为有机整体，产生涌现价值 | 1+1>2、自组织 | 平台、生态系统 |
| **闭环** | 有始有终、可验证、可复盘 | 起点→过程→终点→反馈→改进 | 完成报告、审计日志 |

## 三、"七化"执行检查清单

### 3.1 每次任务完成后自检

```markdown
- [ ] **固化**: 产出物是否已归档到固定位置？
- [ ] **内化**: 是否提取了可复用的方法论？
- [ ] **标准化**: 格式是否符合规范？
- [ ] **体系化**: 是否关联了相关知识/文档？
- [ ] **机制化**: 是否需要设立自动化触发？
- [ ] **血液化**: 是否有速查卡/决策工具？
- [ ] **系统化**: 是否考虑了整体影响？
- [ ] **闭环**: 是否有完成报告和未完成任务清单？
```

### 3.2 机制文档新建流程

1. **触发**: 用户提出"固化/机制化/血液化"等要求
2. **检索**: 检查`docs/`下是否已有类似机制
3. **整合**: 如有碎片，合并升级；如无，新建
4. **索引**: 更新本文档，确保新机制被收录
5. **Git锁定**: 提交并记录版本号
6. **同步**: 重要机制写入`AGENTS.md`或`SOUL.md`
