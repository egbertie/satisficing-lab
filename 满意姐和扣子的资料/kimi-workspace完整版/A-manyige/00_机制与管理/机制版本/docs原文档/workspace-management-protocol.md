## 一、目标

随着项目资产持续增长，建立**机制化**的空间与文件管理系统，防止：
1. 磁盘空间突然告警
2. 垃圾文件累积污染
3. 备份体积无节制膨胀
4. 重要资产遗失在临时目录中

## 三、三层管理机制

### 3.1 自动监控层（每日执行）

**工具**: `claw_space_manager.py`
**触发方式**: 
- Cron 每日 03:17 自动运行（已加入 `memory_cleanup.sh` 链式调用）
- 手动触发：直接运行 `python3 claw_space_manager.py`

**输出**:
- 报告文件：`memory/claw-space-diagnosis-YYYY-MM-DD-HHMM.md`
- 告警阈值：
  - 🟢 使用率 < 70%：正常
  - 🟡 使用率 70-85%：提醒清理
  - 🔴 使用率 > 85%：强制清理 + 立即通知用户

### 3.2 定期清理层（每周执行）

**清理对象**:
| 路径/类型 | 保留期限 | 清理动作 |
|-----------|----------|----------|
| `/tmp/openclaw/` 下载缓存 | 7 天 | 删除 |
| `memory/` 中的旧诊断报告 | 30 天 | 归档到 `archive/reports/` 后删除 |
| `__pycache__/` | 永久 | 每周清理一次 |
| `.tmp` / `.bak` 临时文件 | 3 天 | 删除 |
| `skills/` 中未验证的 stubs | 60 天 | 压缩归档 |

**执行脚本**: `scripts/weekly_cleanup.sh`
**执行时间**: 每周日 02:00

### 3.3 备份优化层（每次备份前）

**排除规则**（减少备份体积）:
```
EXCLUDE:
- __pycache__/
- .git/  (GitHub 已独立托管)
- archive/md_conversions/  (已转换的旧文档，本地保留即可)
- memory/claw-space-diagnosis-*.md  (诊断报告可重建)
- OLD-ARCHIVE-2026/  (历史归档，单独备份)
- skills/token-optimizer/.token-optimizer-analysis.json  (临时分析文件)
```

**备份体积控制目标**:
- 周增长 < 100 MB
- 单月备份 < 1 GB
- 超标时触发空间审查

## 四、大文件管理

### 发现机制
运行 `claw_space_manager.py` 时自动扫描 > 10MB 的文件。

### 处理流程
1. **识别** → 列出 TOP 20 大文件
2. **分类** → 判断是核心资产 / 可压缩 / 可迁移 / 可删除
3. **处置**:
   - 核心资产：保持原位
   - 媒体/图片：考虑迁移到飞书 Drive 或 Git LFS
   - 旧导出文件：删除或压缩
   - 重复文件：保留最新版本
