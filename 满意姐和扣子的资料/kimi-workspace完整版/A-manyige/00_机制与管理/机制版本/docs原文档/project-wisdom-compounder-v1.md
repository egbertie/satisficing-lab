# 项目智慧复利机制 V1.0

> **生效日期**: 2026-04-10  
> **制定者**: 蓝军 Skeptor-7（响应 Egbertie 指令）  
> **定位**: 将每一次项目/产品相关讨论的经验，转化为可积累、可检索、可复用的组织智慧  
> **核心信念**: 没有自动迭代机制的经验，只是散落在对话里的沙子；有了机制，沙子才能聚成塔。

---

## 一、问题诊断

**现状痛点**:
1. **经验流失** — 每一次深度的项目/产品讨论都产生了宝贵的洞察和方法论，但讨论结束后这些经验就锁死在对话历史里，未来难以复用
2. **重复造轮子** — 类似的战略问题（如竞争定位、定价策略、客户旅程设计）在不同时间被反复讨论，却没有调用过往结论
3. **skill 与实战脱节** — `thinking-mentor`、`afrexai-strategic-thinking` 等 skill 的能力没有被结构化地注入到项目决策流程中
4. **一堂方法论未充分激活** — HOST 四循环、五步法等方法论存在于文档中，但没有形成"每次项目讨论自动调用"的条件反射

**目标**: 建立一个**Project Wisdom Compounder（项目智慧复利器）**，使每一次战略/产品/客户相关的讨论，在执行完毕后自动经历：
> **提取 → 结构化 → 关联 → 固化 → 月度复盘 → 升级原则**

---

## 二、机制架构：五阶复利循环

```
【Extract 提取】
  ↓ 每次项目/产品讨论结束后，AI 自动提取：决策树、方法论资产、反常识发现、技巧教训

【Structure 结构化】
  ↓ 写入当月项目经验日志（Markdown 格式，标准化模板）

【Connect 关联】
  ↓ 自动打标签：关联到五路图腾、一堂方法论、相关 skill、历史案例库

【Solidify 固化】
  ↓ 高价值经验（P0/P1）追加写入 AGENTS.md 或 SOUL.md 的对应章节

【Review 月度复盘】
  ↓ 每月最后一天，子代理自动汇总当月日志，提炼 3 条"升级后的行动原则"

【Evolve 原则升级】
  ↓ 写入《演进原则索引.md》，成为下一个月决策的默认参考系
```

## 三、提取标准（What to Capture）

每次项目/产品相关的对话结束后，无论是否由用户明确提示，AI 都必须自问以下四个问题，并将答案写入日志：

### Q1: 决策树（Decision Tree）
- 这次讨论最终选择了什么方案？
- 被明确排除的方案有哪些？排除的原因是什么？
- 如果 6 个月后回头看，这个决策是否仍然成立？需要什么样的信号来验证或推翻它？

### Q2: 方法论资产（Methodology Asset）
- 是否产生了一个新的框架、模板、 checklist 或评估维度？
- 这个资产能否直接用于未来的类似场景？
- 它的边界条件是什么（什么时候适用，什么时候不适用）？

### Q3: 反常识发现（Anti-Common-Sense Insight）
- 有哪些结论违背了直觉、行业惯例或之前的假设？
- 这个反常识发现的证据来源是什么（数据、案例、逻辑推演、用户反馈）？
- 如果未来有人提出相反的直觉判断，我们应该如何回应？

### Q4: 技巧与教训（Technique & Lesson）
- 这次过程中有哪些"做对了一步"的操作细节？（如搜索策略、工具链选择、用户沟通方式）
- 有哪些陷阱差点让我们掉进去？
- 下次再做类似的事，第一步应该做什么不同？

## 五、关联与固化规则

### 5.1 自动关联触发条件

写入日志时，AI 必须同时检查以下内容并建立关联：
1. **五路图腾映射**：这次讨论主要调用了哪个图腾的智慧？在对应图腾的提示词或知识库中是否应增加这个新案例？
2. **一堂方法论映射**：是否使用了 HOST 四循环、五步法、照镜子咨询法？如果是，在相关方法论文档中追加"实战应用记录"。
3. **Skill 映射**：是否激活了某个 skill 的思维模型？skill 的实战经验是否应反馈给 skill 维护者（如果是自定义 skill）？
4. **案例库映射**：是否产出了新的案例素材？是否应写入 `case_repository/` 或 `A-satisficing-v27/`？

### 5.2 固化到系统文档的标准

以下情况必须写入 `AGENTS.md` 或 `SOUL.md`：
- **P0 级决策**: 影响商业模式、目标客户、核心产品边界、定价策略的结论
- **P0 级禁令/强制规则**: 如"多册文件必须逐册全量提取"、"费用红线规则"、"中文优先+A-manyige 归口"
- **P1 级高频操作规范**: 如果某个技巧/教训在一个月内出现了 2 次以上，应升级为 AGENTS.md 的操作规则

## 六、月度复盘：子代理自动化

### 6.1 触发时间

每月最后一天 23:00（或用户触发"月度复盘"指令时）。

### 6.2 子代理任务

任务名称：` Monthly Project Wisdom Review Agent`

```
输入：
- A-manyige/常用/项目经验迭代日志/YYYY-MM/ 下的所有 Markdown 文件
- 上个月的《演进原则索引.md》

输出：
1. 当月高频主题词云/排名 Top 5
2. 当月最重要的 3 个决策树摘要
3. 当月最反直觉的 3 个发现
4. **3 条升级后的行动原则**（P0/P1/P2 各 1 条）
5. 下个月建议重点关注的 2 个风险点
6. 更新后的《演进原则索引.md》
```

### 6.3 演进原则索引格式

```markdown
# 演进原则索引

## 2026-04（竞争定位与机制奠基月）
1. **[P0] 竞争策略**: 做窄做深，不争地盘争话语权 —— 湾创的出现验证了品类，协同大于竞争。
2. **[P1] 资源治理**: 系统进入紧张区时，必须自动触发上下文压缩和子代理前置，并保留 10% 用户对话通道。
3. **[P2] 文件处理**: 所有 `A-manyige/` 下新建文件必须包含精确到分钟的 HHMM 时间戳。

## 2026-03（...）
...
```

## 七、与 AI 工作的条件反射

### 7.1 强制检查点

每次项目/产品相关讨论结束后，AI 必须在内心独白中执行以下检查：
1. 这次对话是否产生了值得写入日志的决策、资产、发现或教训？
2. 如果是，是否已在 5 分钟内开始写入 `A-manyige/常用/项目经验迭代日志/`？
3. 这个结论是否达到了需要写入 AGENTS.md/SOUL.md 的 P0/P1 级别？
4. 是否与五路图腾/一堂方法论/skill/案例库建立了关联？

### 7.2 用户级触发指令

用户可以说：
- "把这次讨论的经验记下来" → AI 立即执行提取+结构化
- "月度复盘" → AI 启动子代理运行月度总结
- "我们之前怎么决定 X 的？" → AI 搜索项目经验迭代日志，引用历史决策树
- "这个教训写进规则" → AI 评估优先级并写入 AGENTS.md

## 九、闭环验证

**每周检查**:
- `A-manyige/常用/项目经验迭代日志/` 下是否有新增文件？
- 新增日志是否使用了标准模板和标签？
- 是否有 P0/P1 结论未被及时固化到 AGENTS.md？

**每月检查**:
- 子代理是否按时执行了月度复盘？
- 《演进原则索引.md》是否更新？
- 上个月的 3 条原则是否在下个月的决策中被实际引用？

**蓝军监督**: 任何一次有价值的项目讨论未被记录、任何一个月度复盘被遗漏、任何一条 P0 原则躺在日志里却没有进入系统文档，均视为违规。
