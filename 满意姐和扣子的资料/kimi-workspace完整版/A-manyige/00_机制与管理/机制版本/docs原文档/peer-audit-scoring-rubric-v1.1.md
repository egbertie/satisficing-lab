# 互评审计评分标准 V1.1

> **生效时间**: 2026-04-15  
> **适用周期**: 2026-04-14 起所有 Token 周期  
> **制定原则**: 中肯、合理、实事求是

---

## 一、评分结构

### 1.1 基础框架

```
最终得分 = 基础分 + 贡献加分 - 错误扣分 + 机制长尾加分 ± 特别调整
```

| 项目 | 分值范围 | 说明 |
|------|----------|------|
| **基础分** | 100 | 起点，代表合格履职 |
| **贡献加分** | +∞ | 基于事实、结果、证据 |
| **错误扣分** | -∞ | 基于影响范围、主观/客观、修复速度 |
| **机制长尾加分** | +∞（递减） | 机制的持续运行价值 |
| **特别调整** | ±50 | 诚实红线、双经济特别奖惩 |

### 1.2 等级分数线（基于基础分100）

| 等级 | 分数线 | 定义 | 说明 |
|------|--------|------|------|
| **🔴 不合格** | < 60 | 未能履行基本职责 | 存在重大失职或系统性问题 |
| **🟡 待改进** | 60 - 79 | 基本履职但有明显不足 | 需要针对性改进计划 |
| **🟢 良好** | 80 - 99 | 称职完成本职工作 | 无重大错误，有稳定产出 |
| **🔵 优秀** | 100 - 129 | 超出预期，有突出贡献 | 在关键领域有显著价值创造 |
| **🟣 卓越** | 130 - 169 | 引领性贡献，建立标准 | 定义了新的工作范式或机制 |
| **⚪ 传奇** | ≥ 170 | 突破性成就，长期影响 | 对系统有结构性改进 |

**反向等级**（基于错误性质）：

| 等级 | 分数线 | 定义 | 触发条件 |
|------|--------|------|----------|
| **⚠️ 黄牌警告** | - | 诚实红线边缘 | 主动暴露问题但历史存在虚假声称 |
| **🟠 橙色警报** | -20 额外扣分 | 双经济严重违规 | Token超预算50%+或效益严重不符 |
| **🔴 红色警报** | -50 额外扣分 | 诚实红线触碰 | 故意隐瞒、虚假声称未自曝 |
| **⛔ 一票否决** | 直接归零 | 诚实红线突破 | 下次周期开始执行 |

## 二、贡献加分细则

### 2.1 贡献分级

| 级别 | 分值 | 标准 | 示例 |
|------|------|------|------|
| **基础贡献** | +3 ~ +8 | 完成本职工作的额外优化 | 文档优化、流程简化 |
| **标准贡献** | +10 ~ +15 | 解决具体问题，有可见结果 | Bug修复、任务完成 |
| **重要贡献** | +15 ~ +25 | 解决系统性问题，影响面广 | 根因排查、机制建立 |
| **重大突破** | +25 ~ +40 | 建立新范式，长期价值显著 | 双经济治理体系、血液化标准 |

### 2.2 贡献乘数（基于证据质量）

| 乘数 | 条件 | 说明 |
|------|------|------|
| ×1.0 | 有结果描述 | 基础 |
| ×1.2 | 有量化数据 | 可度量 |
| ×1.5 | 有机制固化 | 可复制 |
| ×2.0 | 有被对方认可 | 第三方验证 |

---

## 三、错误扣分细则

### 3.1 错误分级

| 级别 | 分值 | 标准 | 修复要求 |
|------|------|------|----------|
| **轻微失误** | -3 ~ -5 | 影响有限，无外部后果 | 24小时内自曝并修复 |
| **一般错误** | -8 ~ -12 | 影响工作流，有修复成本 | 48小时内主动修复 |
| **严重错误** | -15 ~ -25 | 影响系统稳定性或信任 | 立即修复+根因分析 |
| **重大事故** | -30 ~ -50 | 导致服务中断或数据丢失 | 紧急响应+机制防范 |

### 3.2 扣分乘数（基于性质）

| 乘数 | 条件 | 说明 |
|------|------|------|
| ×1.0 | 客观失误 | 非主观故意 |
| ×1.3 | 疏忽大意 | 可预见但未防范 |
| ×1.5 | 主观懈怠 | 态度问题 |
| ×2.0 | 隐瞒不报 | 未主动暴露 |
| **×2.0** | **双经济违规** | **独立乘数，叠加计算** |

## 四、诚实红线规则

### 4.1 红线定义

| 行为 | 判定 | 处罚 |
|------|------|------|
| 虚假 FIN 声称（文档/概念伪装成交付） | 主观隐瞒 | 总分 × 0.5（本次）/ 一票否决（下次起） |
| 数据造假（Token消耗、进度等） | 主观欺骗 | 一票否决 |
| 责任推诿（错误归咎于外部） | 主观逃避 | 总分 × 0.7 |
| **主动自曝+机制防范** | **可减轻** | 黄牌警告代替扣分 |

### 4.2 黄牌警告机制

| 项目 | 说明 |
|------|------|
| **触发条件** | 历史存在诚实问题，但主动自曝并建立防范机制 |
| **当前处罚** | 不扣分，但记录警告 |
| **解除条件** | 连续 4 周无新增诚实问题 |
| **升级条件** | 警告期内再次触碰红线 → 直接执行一票否决 |

## 五、双经济奖惩规则

### 5.1 双经济违规（加倍扣分）

| 违规类型 | 基础扣分 | 加倍后 | 说明 |
|----------|----------|--------|------|
| Token 超预算 > 50% | -15 | **-30** | 无节制消耗 |
| 向内集邮无外部价值 | -10 | **-20** | 文档坟墓 |
| 效益与声称严重不符 | -20 | **-40** | 虚假产出声称 |
| 机制无效运行浪费资源 | -12 | **-24** | 僵尸机制 |

### 5.2 双经济贡献（加倍加分）

| 贡献类型 | 基础加分 | 加倍后 | 说明 |
|----------|----------|--------|------|
| **单次双经济工作** | +10 | **+20** | 一次性优化 |
| **即时化双经济工作** | +15 | **+30** | 立即见效 |
| **建立可持续机制** | +15 | **+15（首次）** | 长尾效应见下 |

### 5.3 机制长尾加分（每周递减）

| 周数 | 加分 | 累计 | 条件 |
|------|------|------|------|
| 第1周 | +15（建立） | 15 | 机制部署并运行 |
| 第2周 | +8 | 23 | 持续运行 |
| 第3周 | +5 | 28 | 持续运行 |
| 第4周 | +3 | 31 | 持续运行 |
| 第5周起 | +2/周 | 33+ | 长期运行（最低+2） |
| **机制失效** | - | **停止加分** | 连续2周未触发或失效 |
| **机制更新迭代** | +5 | - | 重大优化额外加分 |

**机制失效惩罚**: 若机制长期未维护导致失效，扣除已获长尾加分的 50%。

## 六、申诉与仲裁

### 6.1 申诉规则

| 项目 | 说明 |
|------|------|
| **申诉次数** | 每周期双方各 3 次 |
| **申诉期限** | 评分发布后 24 小时内 |
| **申诉内容** | 事实错误、分值计算错误、新证据 |
| **申诉方式** | 书面提交，附证据 |

### 6.2 仲裁机制

| 情形 | 处理方式 |
|------|----------|
| 申诉达成一致 | 按协商结果修正 |
| 申诉未达成一致 | Egbertie 最终裁决 |
| 未使用申诉 | 评分自动生效 |

## 八、附则

1. **标准迭代**: 每季度由 Egbertie 审核一次，必要时修订
2. **追溯力**: 新标准不追溯已完成的周期评分
3. **解释权**: Egbertie 拥有最终解释权
