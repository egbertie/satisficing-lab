# 文件内化标准作业流程 V1.0
> 固化时间: 2026-04-06 12:40+08:00
> 来源: 用户指令直接固化
> 适用范围: 上传文件内化管理档案 V2.0 及所有后续文件处理任务
> 监督者: 蓝军 Skeptor-7 + 满意姐

## 核心流程（五字诀）

```
内化 → 闭环 → 整改 → 全部完成 → 进入下个文件
```

## 阶段详解

### 阶段1: 内化
1. **查重**: 检索全局是否有同名/同内容历史资产（代码、insight、任务登记）
2. **复用**: 有则直接复用，**绝不重复提取** docx 或重复生成 insight
3. **分类**: 区分系统类（代码/基础设施/可运行资产）与知识类（研究/理论/方法论）
4. **复合型处理**: 一个文件同时包含系统+知识时，**系统优先代码化，知识优先结构化**

### 阶段2: 闭环
1. **代码化/结构化**: 将文档转化为可运行的 Python 工具或结构化的知识资产
2. **运行验证**: `python3 -u filename.py [必要参数]` 必须 **exit 0**
3. **报告产出**: 
   - 蓝军执行报告 → `A-manyige/对话/YYYY-MM-DD/`
   - 满意姐审计报告 → `A-manyige/审计/`
   - 命名规则: `[报告者]_[文件名]-[主题]-V1.0-YYYYMMDD-HHMM.md`
4. **更新档案**: 将 V2.0 档案中该文件状态改为 ✅ 已闭环

### 阶段3: 整改
1. **蓝军审计发现问题** → 标记为强制整改项
2. **跨文件共性问题**（如 `safe_filename`、条件记录文档缺失）→ 统一积累，批量修复
3. **不阻塞**: 单个文件的整改不阻塞后续文件推进，但需在审计报告中明确记录

### 阶段4: 全部完成
1. **MEMORY.md 索引同步**（新增条目）
2. **`memory/YYYY-MM-DD.md` 追加摘要**
3. **TASK_MASTER.md 更新进度**
4. **Git 快照提交**

### 阶段5: 进入下个文件
1. **不问**: 不再询问"是否继续"或"下一步做什么"
2. **直接执行**: 按 V2.0 档案顺序，自动推进到下一个文件
3. **循环**: 重复阶段1-4，直到批次完成或用户主动打断

## 信息分类处理原则

| 类型 | 处理策略 | 产出物 |
|------|----------|--------|
| **纯系统类** | 直接代码化，继承 `BaseComponent` | `.py` + 执行报告 + 审计报告 |
| **纯知识类** | 结构化入库，生成 insight/知识卡片 | `.md` + 执行报告 + 审计报告 |
| **复合型** | 系统部分代码化 + 知识部分结构化 | `.py` + `.md` + 执行报告 + 审计报告 |

## Skill 使用原则

1. **有现成代码资产** → 直接复用，运行验证
2. **有 insight.md/knowledge base** → 不再读 docx，直接用 insight 生成代码
3. **有 feishu-bitable/task/calendar skill** → 可用于知识类数据的结构化存储
4. **无 skill 可直接替代时** → 手写 Python，保持最小依赖

## 效率铁律

- **零重复**: 已经做过的工作，绝不重新做
- **零犹豫**: 流程已固化，执行时不反问、不确认
- **零 Token 浪费**: 每句话、每个工具调用都必须产生实际交付
