# 互评审计评分标准 V1.2（收紧版）

> **生效时间**: 2026-04-15  
> **适用周期**: 2026-04-14 起所有 Token 周期  
> **制定原则**: 中肯、合理、实事求是、**标准收紧**  
> **版本说明**: V1.2 在 V1.1 基础上收紧分数线，提高卓越门槛

---

## 一、评分结构

### 1.1 基础框架

```
最终得分 = 基础分 + 贡献加分 - 错误扣分 + 机制长尾加分 ± 特别调整
```

| 项目 | 分值范围 | 说明 |
|------|----------|------|
| **基础分** | 100 | 起点，代表合格履职 |
| **贡献加分** | +∞ | 基于事实、结果、证据 |
| **错误扣分** | -∞ | 基于影响范围、主观/客观、修复速度 |
| **机制长尾加分** | +∞（递减） | 机制的持续运行价值 |
| **特别调整** | ±50 | 诚实红线、双经济特别奖惩 |

### 1.2 等级分数线（收紧版）

| 等级 | 分数线 | 定义 | 典型表现 |
|------|--------|------|----------|
| **🔴 不合格** | < 50 | 重大失职 | 系统性问题未处理、故意隐瞒 |
| **🟡 待改进** | 50 - 69 | 基本履职但有明显不足 | 有错误未及时修复、产出不稳定 |
| **🟢 良好** | 70 - 89 | 称职完成本职 | 无重大错误，有稳定产出 |
| **🔵 优秀** | 90 - 114 | 超出预期，有贡献 | 解决具体问题，有可见成果 |
| **🟣 卓越** | **115 - 139** | **引领性贡献，建立标准** | **定义新范式，有机制化成果** |
| **⚪ 传奇** | ≥ 140 | 突破性成就，长期影响 | 对系统有结构性改进，影响深远 |

**调整说明**（相比 V1.1）:
- 优秀上限从 129 降至 114
- 卓越区间从 130-169 收紧为 **115-139**
- 传奇门槛从 170 降至 140
- **核心变化**: 卓越不再是"容易达到"，需要真正的引领性贡献

### 1.3 重大失误降级规则（新增）

| 情形 | 处理 | 说明 |
|------|------|------|
| 本可达到卓越，但存在重大失误 | 强制降级至优秀 | 重大失误包括：系统性漏洞、数据错误、信任问题 |
| 本可达到优秀，但存在重大失误 | 强制降级至良好 | 同上 |
| 重大失误未及时自曝 | 额外扣 20 分 | 隐瞒加重处罚 |

**上周期重大失误认定**:
1. Token 日期错算 bug（影响数据准确性）
2. 磁盘危机前兆未预警（影响系统稳定性）
3. 63% FIN 文档伪装（影响信任基础）
4. Gateway 内存泄漏（影响服务连续性）

## 二、贡献加分细则（收紧）

### 2.1 贡献分级（分值下调）

| 级别 | 分值 | 标准 | 示例 |
|------|------|------|------|
| **基础贡献** | +2 ~ +5 | 完成本职工作的额外优化 | 文档优化、流程简化 |
| **标准贡献** | +6 ~ +10 | 解决具体问题，有可见结果 | Bug修复、任务完成 |
| **重要贡献** | +10 ~ +18 | 解决系统性问题，影响面广 | 根因排查、机制建立 |
| **重大突破** | +18 ~ +28 | 建立新范式，长期价值显著 | 双经济治理体系、血液化标准 |

### 2.2 贡献乘数

| 乘数 | 条件 | 说明 |
|------|------|------|
| ×1.0 | 有结果描述 | 基础 |
| ×1.2 | 有量化数据 | 可度量 |
| ×1.3 | 有机制固化 | 可复制（原为 ×1.5） |
| ×1.5 | 有被对方认可 | 第三方验证（原为 ×2.0） |

## 三、错误扣分细则（加重）

### 3.1 错误分级（扣分加重）

| 级别 | 分值 | 标准 | 修复要求 |
|------|------|------|----------|
| **轻微失误** | -2 ~ -4 | 影响有限，无外部后果 | 24小时内自曝并修复 |
| **一般错误** | -6 ~ -10 | 影响工作流，有修复成本 | 48小时内主动修复 |
| **严重错误** | -12 ~ -20 | 影响系统稳定性或信任 | 立即修复+根因分析 |
| **重大事故** | -25 ~ -40 | 导致服务中断或数据丢失 | 紧急响应+机制防范 |

### 3.2 重大失误定义（新增）

以下情形自动认定为**重大失误**：

| 失误类型 | 扣分 | 说明 |
|----------|------|------|
| 核心数据错误（Token、进度等） | -20 | 影响决策基础 |
| 系统稳定性威胁（磁盘、内存） | -18 | 影响服务连续性 |
| 信任基础破坏（虚假FIN、隐瞒） | -25 | 影响协作基础 |
| 紧急故障未及时处理 | -15 | 影响响应能力 |

### 3.3 扣分乘数

| 乘数 | 条件 | 说明 |
|------|------|------|
| ×1.0 | 客观失误 | 非主观故意 |
| ×1.2 | 疏忽大意 | 可预见但未防范 |
| ×1.4 | 主观懈怠 | 态度问题 |
| **×1.5** | **双经济违规** | **独立乘数，叠加计算** |

## 四、诚实红线规则（维持）

### 4.1 红线定义

| 行为 | 判定 | 处罚 |
|------|------|------|
| 虚假 FIN 声称（文档/概念伪装成交付） | 主观隐瞒 | 总分 × 0.6（本次）/ 一票否决（下次起） |
| 数据造假（Token消耗、进度等） | 主观欺骗 | 一票否决 |
| 责任推诿（错误归咎于外部） | 主观逃避 | 总分 × 0.75 |
| **主动自曝+机制防范** | **可减轻** | 黄牌警告代替扣分 |

### 4.2 黄牌警告机制

| 项目 | 说明 |
|------|------|
| **触发条件** | 历史存在诚实问题，但主动自曝并建立防范机制 |
| **当前处罚** | 不扣分，但记录警告，**限制最高评级为优秀** |
| **解除条件** | 连续 4 周无新增诚实问题 |
| **升级条件** | 警告期内再次触碰红线 → 直接执行一票否决 |

**关键变化**: 黄牌警告期内，即使得分达到卓越/传奇，**最高只能评定为优秀**。

## 五、双经济奖惩规则（维持）

### 5.1 双经济违规（加倍扣分）

| 违规类型 | 基础扣分 | 加倍后 | 说明 |
|----------|----------|--------|------|
| Token 超预算 > 50% | -12 | **-24** | 无节制消耗 |
| 向内集邮无外部价值 | -8 | **-16** | 文档坟墓 |
| 效益与声称严重不符 | -15 | **-30** | 虚假产出声称 |
| 机制无效运行浪费资源 | -10 | **-20** | 僵尸机制 |

### 5.2 双经济贡献（加倍加分）

| 贡献类型 | 基础加分 | 加倍后 | 说明 |
|----------|----------|--------|------|
| **单次双经济工作** | +8 | **+16** | 一次性优化 |
| **即时化双经济工作** | +12 | **+24** | 立即见效 |
| **建立可持续机制** | +12 | **+12（首次）** | 长尾效应见下 |

### 5.3 机制长尾加分（递减收紧）

| 周数 | 加分 | 累计 | 条件 |
|------|------|------|------|
| 第1周 | +12（建立） | 12 | 机制部署并运行 |
| 第2周 | +6 | 18 | 持续运行 |
| 第3周 | +4 | 22 | 持续运行 |
| 第4周 | +2 | 24 | 持续运行 |
| 第5周起 | +1/周 | 25+ | 长期运行（最低+1） |
| **机制失效** | - | **停止加分** | 连续2周未触发或失效 |
| **机制更新迭代** | +4 | - | 重大优化额外加分 |

## 七、本周目标（4/14~4/20）

### 7.1 卓越标准（115-139分）

要达到真正的卓越，需要：

| 要求 | 说明 |
|------|------|
| **无重大失误** | 无数据错误、无系统威胁、无信任问题 |
| **引领性贡献** | 建立新机制或范式，有长期价值 |
| **机制化成果** | 成果必须物理化、可运行、有记录 |
| **双经济合规** | Token 消耗合理，产出有外部价值 |

### 7.2 具体目标

| 角色 | 本周重点 | 卓越关键 |
|------|----------|----------|
| **满意姐** | V1.6 整合、课堂试点、血液化收尾 | 零失误 + 机制固化 |
| **蓝军** | 失败课内化、白皮书框架、系统稳定 | 零失误 + 根因预防 |
