## 二、机制核心：12 步标准舞步

已固化的标准流程如下：

| 步骤 | 名称 | 关键动作 |
|------|------|---------|
| 1 | 触发接收 | 确认文件下载/存储，失败即标记缺失 |
| 2 | 去重与版本裁决 | 全库检索已有版本，轻量旧版优先，避免重复加工 |
| 3 | 本地格式转换 | PDF→pypdf、DOCX→python-docx、图片→Tesseract OCR、链接→kimi_fetch；**本地免费优先，付费须经确认** |
| 4 | 结构化存储 | 原始资料按来源归口，`A-manyige/素材库/{来源}/` |
| 5 | 深度洞察 | 三层挖掘：说了什么 → 底层逻辑 → 对满意解的价值 |
| 6 | 内化映射 | 外部概念 ↔ 满意解知识体系对照改写 |
| 7 | 血液化输出 | 产出至少 1 项可战场直接使用的弹药（SOP/制度/话术/案例/产品嵌入） |
| 8 | 生成子文档 | 每份源资料产出 1 份血液化 MD |
| 9 | 汇总报告 | 跨资料综合报告，必须同步到当日对话文件夹 |
| 10 | 任务清单同步 | `TASK_MASTER.md` 登记状态 |
| 11 | 记忆固化 | `memory/YYYY-MM-DD.md` + `MEMORY.md` 双写 |
| 12 | Git 快照 + 静默前置检查 | C1-C6 逐项通过，附 Git 哈希 |

## 三、质量红线（蓝军监督）

机制生效的前提是 6 条红线：

1. **R1 去重检查**: 漏检导致重复加工 → 任务 FAILED
2. **R2 双经济优先**: 未经确认使用付费 API → 费用问责
3. **R3 血液化检验**: 仅有摘要/笔记而无可复用弹药 → 任务 FAILED
4. **R4 报告同步**: 未同步到对话文件夹 → 任务 FAILED
5. **R5 任务登记**: TASK_MASTER 未更新 → 机制断链 FAILED
6. **R6 灾备回溯**: Git 哈希未写入 memory → 任务 FAILED
