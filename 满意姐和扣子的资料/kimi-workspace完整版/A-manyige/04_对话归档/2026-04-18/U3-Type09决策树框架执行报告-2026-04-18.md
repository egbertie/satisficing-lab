## 📚 Type09背景回顾

**类型名称**: Type09 创始人与技术合伙人  
**核心冲突**: 创始人（商业背景）与技术合伙人（技术背景）之间的沟通失效、期望错位、价值评估分歧  
**典型场景**:
- 技术合伙人认为"技术是最重要的"，商业是"简单的"
- 创始人认为技术合伙人"不懂市场"，产品方向错误
- 技术交付延期，创始人焦虑，技术合伙人委屈
- 股权分配争议：技术价值如何量化？

**课堂试点优先级**: Type09是试点类型之一（与Type02、Type07并列）

## 🔍 决策节点详解

### 节点一：双方是否愿意继续合作？

**评估问题**:
1. "如果有一个'魔法按钮'可以瞬间解决所有问题，您愿意按吗？"
2. "抛开所有困难，您认为对方的能力对公司的价值是什么？"
3. "如果明天对方提出退出，您的第一反应是'松了一口气'还是'焦虑'？"

**决策标准**:
| 双方意愿 | 建议路径 | 预期成功率 |
|:---------|:---------|:----------:|
| 双方均愿意 | 信任修复路径 | 70-85% |
| 一方愿意一方犹豫 | 信任修复路径（需先解决意愿问题） | 50-60% |
| 一方愿意一方拒绝 | 有序退出路径 | 80-90% |
| 双方均拒绝 | 有序退出路径 | 90%+ |

### 节点二：核心分歧识别（信任修复路径）

#### 分歧A：技术方向

**症状**:
- 创始人："技术方向错了，市场不需要"
- 技术合伙人："技术是最前沿的，商业不懂"

**决策树**:
```
技术方向分歧
    │
    ├─ 是否有客户验证数据？
    │   ├─ 有 ──→ 数据说话，技术合伙人调整
    │   └─ 无 ──→ 快速MVP验证（2-4周）
    │
    ├─ 是否引入第三方技术顾问？
    │   ├─ 是 ──→ 顾问评估+双方共同接受
    │   └─ 否 ──→ 技术合伙人主导，创始人承担风险
    │
    └─ 决策权归属
        ├─ 创始人主导（技术合伙人服从或退出）
        ├─ 技术合伙人主导（创始人承担风险）
        └─ 共同决策（需设定分歧解决机制）
```

#### 分歧B：交付节奏

**症状**:
- 创始人："承诺的时间永远达不到"
- 技术合伙人："技术不确定性被低估了"

**决策树**:
```
交付节奏分歧
    │
    ├─ 延期原因分析
    │   ├─ 技术难度低估 ──→ 重新评估时间表
    │   ├─ 资源不足 ──→ 增加资源或调整范围
    │   ├─ 需求变更频繁 ──→ 冻结需求机制
    │   └─ 执行力问题 ──→ 项目管理培训或换人
    │
    ├─ 新时间表设定
    │   ├─ 激进方案（缩短30%，风险高）
    │   ├─ 保守方案（延长50%，稳妥）
    │   └─ 分阶段方案（MVP+迭代）
    │
    └─ 延期补偿机制
        ├─ 股权调整（延期→股权稀释）
        ├─ 薪资调整（延期→薪资降低）
        └─ 对赌协议（达成→奖励，未达成→惩罚）
```

#### 分歧C：股权分配

**症状**:
- 创始人："技术合伙人要得太多了"
- 技术合伙人："我的技术价值被低估了"

**决策树**:
```
股权分配分歧
    │
    ├─ 技术价值量化
    │   ├─ 技术独特性（1-5分）
    │   ├─ 技术替代成本（招募同水平工程师的成本）
    │   ├─ 技术商业价值（对收入的贡献）
    │   └─ 技术时间价值（提前上市带来的价值）
    │
    ├─ 股权结构选项
    │   ├─ 固定股权（一次性确定）
    │   ├─ 分期兑现（Vesting，4年）
    │   ├─ 里程碑兑现（达成技术目标→兑现股权）
    │   └─ 动态调整（每年根据贡献重新评估）
    │
    └─ 股权争议解决
        ├─ 第三方估值（技术估值机构）
        ├─ 模拟清算（如果明天公司卖掉，技术值多少）
        └─ 长期对赌（3年后根据实际贡献调整）
```

#### 分歧D：沟通模式

**症状**:
- "我说东他说西"、"我谈市场他谈技术"、"完全不在一个频道"

**决策树**:
```
沟通模式分歧
    │
    ├─ 建立"双语翻译"机制
    │   ├─ 技术→商业翻译（技术合伙人学习商业语言）
    │   ├─ 商业→技术翻译（创始人学习技术语言）
    │   └─ 引入翻译者（产品经理做桥梁）
    │
    ├─ 沟通规范设定
    │   ├─ 每周固定沟通时间（不可取消）
    │   ├─ 议题提前48小时共享（准备充分）
    │   ├─ 决策模板统一（用同一套框架讨论）
    │   └─ 情绪管理规则（冲突升级时的暂停机制）
    │
    └─ 沟通失效处理
        ├─ 轻度：工作坊调解（1-2次）
        ├─ 中度：引入外部教练（4-8周）
        └─ 重度：决策权重新分配或退出
```

### 节点三：有序退出路径详解

#### 退出时机决策

| 时机 | 优缺点 | 适用情况 |
|:-----|:-------|:---------|
| **技术交付节点后** | 优：技术交付完成，交接清晰；劣：技术合伙人可能不配合 | 技术合伙人理性、关系尚可 |
| **融资节点前** | 优：投资人介入前解决，估值不受损；劣：时间压力 | 急需融资、关系已破裂 |
| **紧急退出** | 优：快速止损；劣：补偿成本高、交接混乱 | 技术合伙人严重失职/违规 |

#### 退出方式决策

| 方式 | 适用情况 | 成本 | 风险 |
|:-----|:---------|:----:|:----:|
| **股权回购** | 创始人有资金、技术合伙人愿意退出 | 高（现金支出） | 低（彻底分离） |
| **股权转期权** | 技术合伙人仍愿意贡献但不想全职 | 中（分期成本） | 中（仍有绑定） |
| **引入新CTO** | 需要技术合伙人继续过渡 | 低（薪资调整） | 高（权力斗争） |
