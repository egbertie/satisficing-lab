## 一、产品概述

### 1.1 产品定位

本系统是满意解研究所 V1.6 版本的**系统类配套产品**，与知识类产品（12类型案例库）形成完整解决方案：

```
知识产品（案例库） + 系统产品（测评自动化） = 可交付的客户价值
```

### 1.2 核心功能

| 功能模块 | 说明 | 交付物 |
|:---------|:-----|:-------|
| 问卷采集 | 飞书问卷自动记录 | 多维表格数据 |
| 智能评分 | 5维度成熟度评估 | 0-100分总分 |
| 风险匹配 | 12类型案例库映射 | 风险预警 |
| 报告生成 | 自动化分析文档 | Markdown/PDF |
| 持续监测 | Cron定时轮询 | 实时报告 |

### 1.3 产品形态

- **部署方式**: 本地脚本 + 飞书生态
- **交付格式**: Markdown报告 + PDF报告
- **适用场景**: 客户课前测评/课后跟踪/自我诊断

## 二、系统架构

### 2.1 技术栈

```
前端层: 飞书问卷表单
数据层: 飞书多维表格

输出层: Markdown → PDF
调度层: Linux Cron
```

### 2.2 数据流

```
[用户填写飞书问卷]

         ↓
[PDF转换]
         ↓

         ↓
[客户收到完整报告]
```

### 3.3 案例库匹配算法

```python
# 12类型案例库映射
CASE_TYPE_MAPPING = {
    "Type01": {"name": "股权分配冲突", "keywords": ["股权", "分配", "出资", "比例"]},
    "Type02": {"name": "决策权争夺", "keywords": ["决策", "投票", "控制权", "一言堂"]},
    "Type03": {"name": "价值观冲突", "keywords": ["价值观", "愿景", "理念", "分歧"]},
    "Type04": {"name": "责任推诿", "keywords": ["责任", "推诿", "担当", "逃避"]},
    "Type05": {"name": "利益冲突", "keywords": ["利益", "关联交易", "私心", "侵占"]},
    "Type06": {"name": "信任崩塌", "keywords": ["信任", "隐瞒", "欺骗", "背叛"]},
    "Type07": {"name": "沟通障碍", "keywords": ["沟通", "沉默", "冷战", "误解"]},
    "Type08": {"name": "退出机制缺失", "keywords": ["退出", "散伙", "分手", "机制"]},
    "Type09": {"name": "能力不匹配", "keywords": ["能力", "贡献", "付出", "不对等"]},
    "Type10": {"name": "资源争夺", "keywords": ["资源", "争夺", "客户", "渠道"]},
    "Type11": {"name": "外部干预", "keywords": ["家人", "朋友", "外部", "干预"]},
    "Type12": {"name": "声誉危机", "keywords": ["声誉", "品牌", "危机", "公关"]},
}

# 匹配逻辑
def match_case_types(assessment_data, top_n=3):
    matches = []
    for type_id, type_info in CASE_TYPE_MAPPING.items():
        relevance_score = 0
        # 关键词匹配
        for keyword in type_info["keywords"]:
            if keyword in str(assessment_data.values()):
                relevance_score += 10
        # 字段加权
        if type_id == "Type01" and assessment_data.get("equity_cognition", 0) < 50:
            relevance_score += 20
        elif type_id == "Type07" and assessment_data.get("communication_frequency", 0) < 50:
            relevance_score += 20
        # ... 其他类型判断
        if relevance_score > 0:
            matches.append({"type_id": type_id, "name": type_info["name"], "relevance": relevance_score})
    return sorted(matches, key=lambda x: x["relevance"], reverse=True)[:top_n]
```

## 四、部署实施指南（可复刻）

### 4.1 前置条件

| 条件 | 要求 | 检查命令 |
|:-----|:-----|:---------|
| Python3 | >= 3.8 | `python3 --version` |
| 飞书账号 | 已认证 | 登录飞书确认 |
| 多维表格 | 已创建 | 确认表格Token |
| Cron服务 | 运行中 | `sudo systemctl status cron` |
| 磁盘空间 | > 100MB | `df -h` |

### 4.2 部署步骤

#### 步骤1: 飞书端配置（用户操作）

1. **创建问卷表单**
   - 登录飞书 → 工作台 → 问卷
   - 创建「合伙人决策成熟度测评」问卷
   - 设置问题对应5维度评分字段

2. **绑定多维表格**
   - 问卷设置 → 数据存储 → 绑定多维表格
   - 记录表格Token和Table ID

3. **测试数据录入**
   - 填写测试问卷
   - 确认数据自动同步到多维表格

#### 步骤2: 服务端部署

```bash
# 1. 克隆/进入工作目录
cd /root/.openclaw/workspace

# 2. 确认文件结构
ls -la scripts/partner_assessment_v1.py
ls -la scripts/maturity_scoring_algorithm.py

# 3. 配置Cron定时任务
sudo crontab -e
# 粘贴以下内容：
*/5 * * * * cd /root/.openclaw/workspace && /usr/bin/python3 scripts/partner_assessment_v1.py >> /tmp/assessment_cron.log 2>&1
0 * * * * cd /root/.openclaw/workspace && /usr/bin/python3 scripts/pdf_report_generator.py >> /tmp/pdf_gen_cron.log 2>&1

# 4. 创建报告目录
mkdir -p reports/assessments/pdf

# 5. 测试运行
python3 scripts/partner_assessment_v1.py

# 6. 查看结果
ls -la reports/assessments/
cat reports/assessments/*.md
```

#### 步骤3: 验证部署

```bash
# 运行端到端测试
python3 scripts/test_end_to_end.py

# 预期输出: 5/5 PASS
```

### 4.3 配置文件说明

| 文件 | 路径 | 用途 |
|:-----|:-----|:-----|
| 主配置 | 脚本内硬编码 | APP_TOKEN, TABLE_ID |
| 状态文件 | `/tmp/partner_assessment_state.json` | 已处理记录追踪 |
| 日志文件 | `/tmp/assessment_cron.log` | 执行日志 |
| 报告目录 | `reports/assessments/` | Markdown报告 |
| PDF目录 | `reports/assessments/pdf/` | PDF报告 |

### 4.4 故障排查

| 现象 | 原因 | 解决方案 |
|:-----|:-----|:---------|
| 无报告生成 | Cron未启动 | `sudo systemctl start cron` |
| 评分异常 | 字段映射错误 | 检查问卷字段名与代码一致 |
| PDF未生成 | md-to-pdf未安装 | 使用占位符或安装CLI |
| 重复处理 | 状态文件丢失 | 检查`/tmp/partner_assessment_state.json` |
