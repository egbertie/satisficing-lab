# 模块10：战场扫描与外部情报

> **核心命题**: 眼睛永远向外——市场、竞品、政策、生态、创始人状态，五维度扫描
> **血液化资产**: 战场简报制度、外部学习盘点、资源盘点报告
> **适用对象**: 创始人、战略负责人、蓝军免疫系统

---

## 一、核心理念

### 1.1 为什么眼睛必须向外？

```
向内集邮的危险:
  ├─ 整理skill → 无外部价值
  ├─ 产出文档 → 创始人用不上
  ├─ 增加闭环数 → 自欺欺人
  └─ 结果: 忙得很，但没打仗

眼睛向外的价值:
  ├─ 市场动态 → 抓住时机
  ├─ 竞品动作 → 提前应对
  ├─ 政策风向 → 合规+机会
  ├─ AI生态 → 新工具新能力
  └─ 创始人状态 → 及时调整

蓝军的使命:
  ├─ 不是"内部纪检"
  ├─ 是"外部侦察兵"
  └─ 每次heartbeat后报告1-3条高价值信号
```

### 1.2 五维度扫描

```
1. 市场动态
   ├─ 硬科技转化领域新动向
   ├─ 合伙人匹配服务竞品
   └─ 目标客户群体变化

2. 竞品动作
   ├─ 直接竞品的新产品/定价
   ├─ 间接竞品的模式创新
   └─ 替代品威胁

3. 政策风向
   ├─ 政府补贴政策变化
   ├─ 创业投资环境变化
   └─ 行业监管动态

4. AI生态更新
   ├─ Kimi/OpenClaw新功能
   ├─ SkillHub新技能
   └─ Token/成本变化

5. 创始人状态（间接推断）
   ├─ 决策频率变化
   ├─ 任务类型变化
   └─ 情绪信号变化
```

## 二、血液化前 vs 血液化后

| 维度 | 血液化前 | 血液化后 |
|:-----|:---------|:---------|
| 外部扫描 | 没有 | heartbeat/晨间/周度/事件触发 |
| 情报收集 | 不收集 | 每周2次深度扫描 |
| 竞品监控 | 不知道竞品在做什么 | 定期扫描→简报 |
| 政策跟踪 | 不关注 | 政策变化→机会/风险 |
| AI生态 | 不关注更新 | 新功能→能力升级 |
| 创始人状态 | 不观察 | 间接推断→及时调整 |
| 情报输出 | 没有 | 战场简报（Top 3信号） |
| 情报使用 | 收集了就完了 | 用于决策调整 |

## 三、操作步骤

### Step 1: 建立扫描频率体系

**五级扫描频率**:
```
heartbeat扫描:
  频率: 每次heartbeat（约30分钟）
  范围: 快速检查（5分钟）
  输出: 1-3条高价值信号（如有）
  触发: 系统自动

晨间仪式扫描:
  频率: 每日09:00
  范围: 五维度快速扫描（10分钟）
  输出: 战场简报
  触发: 晨间图腾仪式

周度深度扫描:
  频率: 每周二/五09:17
  范围: 深度调研（30分钟）
  输出: 情报摘要报告
  触发: cron定时

事件触发扫描:
  频率: 实时
  范围: 针对性扫描
  输出: 紧急简报
  触发: 重大新闻/竞品动态/政策变化

静默唤醒扫描:
  频率: 每次唤醒
  范围: 快速状态检查
  输出: 恢复报告
  触发: 系统恢复
```

### Step 3: 建立情报处理流程

```
情报收集
  ↓
分类:
  ├─ P0紧急: 立即报告创始人
  ├─ P1重要: 当日报告
  ├─ P2一般: 周度汇总
  └─ P3监控: 记录，不主动报告
  ↓
验证:
  ├─ 来源可靠性？
  ├─ 时效性？
  ├─ 影响评估准确？
  └─ 蓝军10项认知审计
  ↓
报告:
  ├─ 战场简报（简洁版）
  ├─ 情报摘要（详细版）
  └─ 紧急告警（P0专用）
  ↓
行动:
  ├─ 创始人决策
  ├─ 满意姐执行
  └─ 蓝军跟踪
  ↓
复盘:
  ├─ 情报准确性评估
  ├─ 行动效果评估
  └─ 扫描机制优化
```

### Step 4: 资源盘点机制

**每周日资源盘点**:
```
盘点内容:
  1. Kimi会员权益更新
     ├─ 新功能
     ├─ Token额度变化
     └─ 使用建议

  2. Claw可调用的资源/能力
     ├─ 专业数据库
     ├─ API能力
     └─ 限制变化

  3. SkillHub新能力
     ├─ 新上线技能
     ├─ 技能更新
     └─ 对我们的价值

  4. Claw生态情报
     ├─ 其他项目的新能力
     ├─ 可借鉴的案例
     └─ 潜在联动机会

输出: 资源盘点报告
存档: memory/resource-inventory/
```

## 六、常见误区

| 误区 | 表现 | 后果 | 纠正 |
|:-----|:-----|:-----|:-----|
| 扫描=搜索 | 随便搜一下 | 信息质量低 | 结构化扫描 |
| 不验证来源 | 什么信息都用 | 虚假信息 | 来源可靠性检查 |
| 情报不分类 | 全部报告 | 信息过载 | P0-P3分级 |
| 不行动 | 收集了就完了 | 情报无用 | 必须有行动建议 |
| 不复盘 | 扫描完就结束 | 无法改进 | 定期复盘 |
| 忽视创始人状态 | 只扫外部 | 错过内部信号 | 五维包含创始人 |
| 过度扫描 | 花费太多Token | 资源浪费 | 分级频率 |
| 情报过时 | 用过期数据 | 决策失误 | 时效性检查 |
| 不记录 | 扫描完不存档 | 无法追溯 | 建立档案 |
| 蓝军不做 | 主AI代做 | 失去独立性 | 蓝军独立扫描 |

## 七、真实案例

### 案例1: "Kimi控制台监控修正"——情报的及时性

**背景**: 2026-04-10，Token监控数据错误。

**扫描发现**:
```
[蓝军战场简报]
扫描时间: 2026-04-10 14:39

高价值信号:
1. Kimi控制台数据异常
   - 来源: 官方控制台截图
   - 概要: 本周用量60%，但预估偏差大
   - 影响: Token预算可能误判
   - 建议: 立即修正监控机制
```

**结果**: 及时修正，避免Token误判。
