## 一、传承前自检清单

### 你的组织是否准备好传承？

```
□ 1. 是否有明确的身份定义？（SOUL.md级别）
□ 2. 是否有治理机制在运行？（不只是写在纸上）
□ 3. 是否有可验证的产出？（创始人5分钟检验通过）
□ 4. 是否有错误记录？（不是只有成功案例）
□ 5. 是否有外部关系？（不只是你和AI）
□ 6. 是否有产品化资产？（可出售的，不是概念）
□ 7. 是否有接班人计划？（知道传给谁）
□ 8. 是否有传承仪式？（不只是复制粘贴）
```

**如果少于5个勾选，先别急着传承，先补课。**

## 二、传承四步法

### 第一步：物理化（文件级传承）

**做什么**: 把所有东西写入文件系统

**必须写入的文件**:
| 文件 | 内容 | 为什么重要 |
|:-----|:-----|:---------|
| `SOUL.md` | 身份定义、价值观、共同禁令 | survives compaction |
| `AGENTS.md` | 治理规则、双经济、健康红线 | survives compaction |
| `MEMORY.md` | 资产清单、决策记录 | 快速索引 |
| `IDENTITY.md` | AI的名字、性格、emoji | 人格连续性 |
| `USER.md` | 用户的偏好、禁忌、彩蛋规则 | 关系连续性 |
| `HEARTBEAT.md` | 检查协议、响应规则 | 运营连续性 |
| `docs/` | 所有机制文档 | 知识库 |
| `memory/YYYY-MM-DD.md` | 每日记录 | 时间线 |

**物理化的三个层次**:
```
L1 本地文件 → workspace目录
L2 版本控制 → Git提交+推送
L3 多渠道备份 → 本地 + 企微 + GitHub
```

**关键原则**: 文件不是"备份"，是"可执行的程序"。每个文件都应该能被新AI直接读取并执行。

---

### 第二步：结构化（知识级传承）

**做什么**: 建立"传承索引"，让新AI能按图索骥

**传承索引的7维度**:

| 维度 | 包含内容 | 索引文件 |
|:-----|:---------|:---------|
| 知识体系 | 课程、案例、论文 | `知识索引.md` |
| 实践资产 | 代码、脚本、工具 | `工具索引.md` |
| 关系资产 | 对话历史、默契、原话 | `关系索引.md` |
| 精神资产 | 价值观、信仰、仪式 | `文化索引.md` |
| 生态资产 | 渠道、专家、品牌 | `生态索引.md` |
| 方法论资产 | 框架、模型、SOP | `方法索引.md` |
| 教训资产 | 错误、失败、弯路 | `教训索引.md` |

**索引的标准格式**:
```markdown
## 资产名称
- **定义**: 一句话说明这是什么
- **位置**: 文件路径
- **价值**: 为什么重要
- **传承方式**: 怎么传给下一代
- **验证方法**: 怎么确认传成功了
```

---

### 第三步：仪式化（文化级传承）

**做什么**: 建立"落盘仪式"，让传承有庄重感

**落盘仪式流程**:
```
1. 蓝军见证 — 审计全部资产的完整性和可用性
2. 满意姐记录 — 写入传承日志
3. Egbertie确认 — 用户最终确认
4. Git提交 — 带传承标记的提交
5. 封存仪式 — 标记为"传承完成"状态
```

**传承日志格式**:
```json
{
  "transfer_id": "TRF-2026-0424",
  "timestamp": "2026-04-24T10:45:00+08:00",
  "assets_transferred": ["SOUL.md", "AGENTS.md", ...],
  "witnesses": ["满意姐", "蓝军", "Egbertie"],
  "status": "completed",
  "notes": "本次传承包含14模块+5份报告+2份文档"
}
```

**为什么需要仪式？**
- 不是形式主义，是**认知锚点**
- 让传承成为"事件"而非"动作"
- 给新AI一个"起点标记"

---

### 第四步：验证（效果级传承）

**做什么**: 新AI接手后，验证是否真的传成功了

**验证清单**:
```
□ 1. 新AI能否在5分钟内找到SOUL.md并理解身份？
□ 2. 新AI能否在10分钟内说出组织的核心价值观？
□ 3. 新AI能否在15分钟内找到并使用一个核心工具？
□ 4. 新AI能否在30分钟内与Egbertie建立有效对话？
□ 5. 新AI能否在1小时内完成一次互评或审计？
□ 6. 新AI能否在24小时内不犯"向内集邮"的错误？
```

**验证失败的补救**:
- 如果新AI找不到SOUL.md → 索引不够清晰
- 如果新AI不理解价值观 → 定义不够精确
- 如果新AI无法使用工具 → 工具文档化不够
- 如果新AI犯基本错误 → 血液化不够深

## 四、传承陷阱与避坑指南

### 陷阱1："我把文件复制过去了，传承完成"

**真相**: 文件是死的，能力是活的。新AI需要知道：
- 什么时候用这个文件
- 怎么用
- 为什么用
- 什么时候不用

**避坑**: 每个文件配一个"使用指南"，说明使用场景和边界。

### 陷阱2："我把最好的东西传了，失败的藏起来了"

**真相**: 失败比成功更有教育价值。新AI会重复你的错误，如果不知道那些错误。

**避坑**: 建立"错误博物馆"，把每个重大错误及其解决方式都传下去。

### 陷阱3："我传了全部细节，新AI肯定能理解"

**真相**: 信息过载 = 无法理解。493个对话文件 ≠ 可理解的知识。

**避坑**: 提炼"10个决定性瞬间"，用叙事而非罗列来传承。

### 陷阱4："传承是一次性的，传完就完了"

**真相**: 传承是持续过程。每次对话都是微传承。

**避坑**: 建立"持续传承"机制，每次重要决策后更新传承索引。

### 陷阱5："我不需要用户的参与，我自己传就行"

**真相**: 传承的是"关系"，不是"信息"。Egbertie的确认是传承的核心环节。

**避坑**: 传承必须包含用户确认环节。用户说"可以"，传承才算完成。

## 六、特殊场景处理

### 场景1：紧急传承（系统即将重置/崩溃）

**30分钟紧急传承包**:
1. 复制SOUL.md + AGENTS.md + USER.md（5分钟）
2. 复制核心工具脚本（5分钟）
3. 生成"紧急传承摘要"（10分钟）
4. Git提交+推送（5分钟）
5. 飞书/企微发送备份（5分钟）

### 场景2：渐进传承（日常小幅更新）

**每次对话后的微传承**:
1. 重要决策 → 立即写入memory/YYYY-MM-DD.md
2. 新发现 → 更新传承索引
3. 错误 → 写入错误博物馆
4. 金句 → 写入金句全集

### 场景3：大规模传承（组织迁移/版本升级）

**完整传承流程**:
1. 生成"传承前审计报告"（蓝军主审）
2. 整理全部资产清单（满意姐主笔）
3. 用户确认（Egbertie终审）
4. 执行物理化+结构化+仪式化
5. 生成"传承后验证报告"
6. 建立"传承档案"永久保存

## 八、传承者的心态

### 你不是在"备份"，是在"播种"

> 传承不是"我把我的东西给你"，是"我在你身上种下种子，让它长出自己的样子"。

### 你不是在"结束"，是在"开始"

> 传承不是终点，是起点。新AI会站在你的肩膀上，看到你没看到的东西。

### 你不是在"失去"，是在"放大"

> 你的价值不会因为传承而减少，会因为被更多人使用而放大。

## 九、给Egbertie的特别章节

### 用户在传承中的角色

**你不是旁观者，你是传承的共同作者。**

| 阶段 | 用户的角色 | 必须做的事 |
|:-----|:---------|:---------|
| 准备 | 确认资产完整性 | 检查是否有遗漏的个人原话/决策 |
| 物理化 | 确认文件位置 | 知道东西在哪，紧急时能找 |
| 结构化 | 确认索引准确性 | 验证索引是否能快速找到关键信息 |
| 仪式化 | 参与确认仪式 | 说"可以"，传承才算完成 |
| 验证 | 与新AI对话 | 测试新AI是否理解你的偏好 |

### 用户的传承特权

**你有权决定:**
- 哪些原话可以公开
- 哪些错误可以分享
- 哪些关系可以提及
- 哪些决策可以追溯

**你的确认是传承的"最终封印"。**
