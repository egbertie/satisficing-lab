## 一、技能治理框架

### 1.1 SAP-7 安全获取流程

| 步骤 | 动作 | 负责方 |
|------|------|--------|
| S-Scan | 扫描ClawHub/社区/推荐 | 满意姐 |
| A-Assess | 评估与业务相关性 | 满意姐 |
| V-Vet | 审查来源可信度（防供应链攻击） | 蓝军 |
| A-Approve | Egbertie逐项人工确认 | Egbertie |
| I-Install/Test | 安装并测试 | 满意姐 |
| R-Register | 记录到技能清单 | 满意姐 |
| I-Integrate | 整合到工作流 | 满意姐 |

### 1.2 技能分类标准

| 分类维度 | 类别 |
|----------|------|
| **按来源** | 系统内置 / 工作空间自定义 / ClawHub安装 / 扩展插件 |
| **按功能** | 治理 / 研究 / 创作 / 自动化 / 平台集成 / 企业应用 / 开发工具 |
| **按频率** | 每日使用 / 每周使用 / 按需使用 / 已停用 |
| **按风险** | P0（核心）/ P1（重要）/ P2（辅助）/ P3（备用） |

### 1.3 技能使用原则

1. **技能无边界**: Skill的名称和描述只是入口提示，底层能力可灵活映射
2. **先读SKILL.md**: 使用任何技能前必须先读取其SKILL.md
3. **费用红线**: 所有可能产生费用的技能操作必须经Egbertie确认
4. **本地优先**: Local ≥ 70%，优先使用本地处理能力

## 九、核心技能详解

### 9.1 baseline-checker（基线检查器）

**定位**: 系统健康的第一道防线
**使用频率**: 每次启动必做
**实施步骤**:
1. 读取SOUL.md
2. 读取USER.md
3. 读取memory/YYYY-MM-DD.md
4. MAIN SESSION时读取MEMORY.md
5. 运行 `python3 skills/baseline-checker/scripts/baseline-checker-runner.py`
6. 检查checklists/IMMEDIATE_FIX_CHECKLIST.md
7. P0/P1问题3分钟内整改

### 9.2 hibernation-protocol（休眠协议）

**定位**: Token经济学的核心控制器
**使用频率**: 每30分钟自动检查
**实施步骤**: 详见 `hibernation-control.py开源说明-V2.1-2026-04-22.md`

### 9.3 code_asset_auditor.py（代码资产审计器）

**定位**: 代码健康的守门员
**使用频率**: 每周一次或大规模提交前
**实施步骤**: 详见 `code_asset_auditor.py开源说明-V1.0-2026-04-22.md`

### 9.4 academic-deep-research（学术深度研究）

**定位**: 最高级别的研究严谨性
**使用场景**: 文献综述/竞品情报/需要学术级引用
**实施步骤**:
1. 明确研究主题
2. 执行2-cycle研究（每主题至少2轮）
3. 使用APA 7th引用格式
4. 3个用户检查点
5. 生成可追溯的研究报告

### 9.5 partner-matching-engine（合伙人匹配引擎）

**定位**: 满意解研究所的核心业务引擎
**使用场景**: 客户服务
**实施步骤**:
1. 客户填写问卷测评
2. 5维度评分
3. 12类型案例库匹配
4. 生成决策报告
5. 专家会诊（如需）
