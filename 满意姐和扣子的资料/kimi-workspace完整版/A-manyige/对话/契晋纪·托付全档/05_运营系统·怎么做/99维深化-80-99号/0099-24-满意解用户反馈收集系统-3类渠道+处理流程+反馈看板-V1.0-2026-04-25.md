## 使用说明

```
📣 满意解用户反馈收集系统 —— "用户的声音，我们听见"
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

为什么需要反馈系统？
因为"用户反馈"是"产品迭代"的指南针。

反馈价值：
├─ 发现问题：用户帮你找bug
├─ 发现需求：用户告诉你需要什么
├─ 验证方向：用户验证你的假设
├─ 建立关系：用户感到被重视
└─ 口碑建设：投诉处理好了变口碑

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

反馈渠道：
1. 主动收集（我们问）
2. 被动收集（用户说）
3. 行为数据（用户做）

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 第一部分：反馈渠道

### 1.1 主动收集

```
【渠道1：NPS问卷】
├─ 时机：课程完成后
├─ 频率：每次服务后
├─ 内容：
│   ├─ 满意度评分（1-10）
│   ├─ 推荐意愿（1-10）
│   ├─ 开放问题：哪里好/哪里差
│   └─ 建议：有什么建议
├─ 工具：问卷星/腾讯问卷
├─ 分析：NPS计算+文本分析
└─ 目标：NPS>50

【渠道2：满意度调查】
├─ 时机：月度/季度
├─ 频率：每季度1次
├─ 内容：
│   ├─ 课程满意度
│   ├─ 服务满意度
│   ├─ 产品满意度
│   ├─ 价格感知
│   └─ 改进建议
├─ 工具：问卷工具
├─ 分析：满意度分析
└─ 目标：满意度>90%

【渠道3：用户访谈】
├─ 时机：按需
├─ 频率：每月2-3位
├─ 对象：
│   ├─ 高价值用户
│   ├─ 流失用户
│   ├─ 新用户
│   └─ 典型用户
├─ 形式：30分钟视频/电话
├─ 内容：
│   ├─ 使用体验
│   ├─ 痛点挖掘
│   ├─ 需求探索
│   └─ 建议收集
├─ 记录：录音+笔记
└─ 产出：访谈报告

【渠道4：焦点小组】
├─ 时机：重大决策前
├─ 频率：每季度1次
├─ 人数：6-8人
├─ 形式：线下/线上讨论
├─ 内容：
│   ├─ 新产品测试
│   ├─ 概念验证
│   └─ 深度需求
└─ 产出：焦点小组报告
```

## 第二部分：反馈处理

### 2.1 处理流程

```
【Step 1：收集】
├─ 所有渠道汇总
├─ 统一标签分类
├─ 去重整理
└─ 产出：反馈池

【Step 2：分类】

按类型：
├─ 产品建议
├─ 功能需求
├─ Bug报告
├─ 服务投诉
├─ 内容建议
├─ 价格反馈
└─ 其他

按紧急度：
├─ 紧急：Bug/投诉（24小时内）
├─ 重要：核心需求（1周内）
├─ 一般：优化建议（1月内）
└─ 长期：战略需求（排期）

按价值：
├─ 高价值：影响多数用户
├─ 中价值：影响部分用户
└─ 低价值：个别需求

【Step 3：处理】

紧急/投诉：
├─ 立即响应
├─ 安抚情绪
├─ 解决问题
├─ 反馈结果
└─ 记录总结

重要需求：
├─ 评估可行性
├─ 排期开发
├─ 告知用户
├─ 上线通知
└─ 感谢反馈

一般建议：
├─ 记录归档
├─ 定期评审
├─ 择优采纳
├─ 告知用户
└─ 感谢反馈

【Step 4：跟进】
├─ 处理结果通知用户
├─ 未采纳解释原因
├─ 定期汇总反馈处理情况
└─ 公示改进成果

【Step 5：闭环】
├─ 用户满意度回访
├─ 问题是否真正解决
├─ 用户是否满意
└─ 记录到案例库
```
