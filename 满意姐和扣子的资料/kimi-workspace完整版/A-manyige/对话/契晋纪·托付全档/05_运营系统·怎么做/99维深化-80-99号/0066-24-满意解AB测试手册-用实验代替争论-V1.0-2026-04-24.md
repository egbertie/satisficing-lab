## 一、A/B测试基础

### 什么是A/B测试？

> 简单来说：
> 你有一群人，分成两组。
> A组看版本A，B组看版本B。
> 看哪组表现更好。
> 
> 就像试吃：
> 给一半人尝A口味，一半人尝B口味。
> 看哪个更多人喜欢。

### 什么时候用A/B测试？

| 场景 | 示例 |
|:-----|:-----|
| **页面优化** | 首页设计、按钮颜色、文案 |
| **流程优化** | 注册流程、购买流程 |
| **定价测试** | 不同价格点的转化 |
| **内容测试** | 标题、配图、内容形式 |
| **功能测试** | 新功能是否值得上线 |
| **算法测试** | 推荐算法的效果 |

## 二、实验设计

### 实验设计模板

```
实验名称：[清晰描述]

假设：
"如果我们[改变X]，
 那么[指标Y]会[提升/下降Z]，
 因为[原因]。"

示例：
"如果我们把'立即报名'按钮从蓝色改成橙色，
 那么点击率会提升15%，
 因为橙色更醒目，与品牌色对比更强。"

变量：
- 对照组（A）：当前版本
- 实验组（B）：新版本

指标：
- 主要指标：点击率
- 次要指标：转化率、页面停留时间
- 守护指标：退款率（确保没有负面影响）

样本量：
- 每组至少[计算值]人
- 统计功效：80%
- 显著性水平：95%

运行时间：
- 最少[计算值]天
- 覆盖完整业务周期

成功标准：
- 点击率提升>10%
- 统计显著（p<0.05）
```

```python
# 简单版：用在线计算器
```

## 三、实验执行

### 执行清单

```
□ 实验设计完成
□ 技术实现准备
□ 数据追踪确认
□ 样本分配随机化
□ 实验启动
□ 每日监控
□ 实验结束
□ 数据分析
□ 结果汇报
□ 决策执行
```

### 常见错误

| 错误 | 说明 | 避免方法 |
|:-----|:-----|:---------|
| **样本污染** | 用户同时看到A和B | 确保用户只看到一个版本 |
| **过早停止** | 看到效果就停止 | 运行到预定时间 |
| **多重比较** | 同时测太多变量 | 一次只测一个变量 |
| **选择偏差** | 非随机分配 | 确保随机化 |
| **忽略负向** | 只看正向指标 | 同时监控守护指标 |

```
【主要指标】
- A组：[基准值]
- B组：[实验值]
- 提升：[相对提升%]
- 统计显著性：p=[值]

【次要指标】

【守护指标】
- 退款率：A组[X]% vs B组[X]%

【结论】
[是否采纳实验版本]

【下一步】
```

## 五、实验文化

### 实验日历

```
每周实验例会（周五下午）

议程：
1. 本周实验回顾（15分钟）
   - 哪些实验结束了？结果如何？
   
2. 下周实验计划（15分钟）
   - 哪些实验要启动？
   - 资源分配
   
3. 实验经验分享（15分钟）
   - 成功案例
   - 失败教训
   
4. 新想法 brainstorm（15分钟）
   - 任何人可以提出实验想法
   - 快速评估可行性
```

```
在办公室设置"实验墙"：

- 实验A：测试XX（预计X月X日结束）
- 实验B：测试XX（预计X月X日结束）

【本周结果】
- 实验C：成功！点击率+15%
- 实验D：失败。原因：样本不足

【月度冠军】
- 最佳实验：XX（影响最大）

- 最佳执行：XX（最严谨）
```
