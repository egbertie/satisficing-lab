# 双轨诚实审计

> **编号**: SANSHENG-SKILL-016
> **定位**: 蓝军+满意姐独立双轨审计，防止"自说自话"和"粉饰完成"
> **触发词**: "审计" / "诚实" / "双轨" / "验收" / "FIN验证" / "完成度"
> **五维映射**: 金(标尺) + 火(洞察) + 水(流动)

---

## 一、Why

**最大的敌人不是失败，是"假装成功"。**

**问题**:
- 声称FIN的任务，63%是文档/概念/半成品伪装
- 一个人审计自己，容易"自我原谅"
- 没有独立视角，问题被掩盖

**解决**: 蓝军+满意姐**独立**双轨审计，互相不商量，各自出报告。

---

## 二、What

### 2.1 双轨定义

| 轨道 | 角色 | 审计重点 | 风格 |
|------|------|---------|------|
| **蓝军轨** | Skeptor-7 | 风险、漏洞、假设 | 挑刺、对抗 |
| **满意姐轨** | 满意姐 | 流程、关怀、可行性 | 温暖、务实 |

### 2.2 审计内容

**对任务完成度**：
- 声称FIN的，交付物真的存在吗？
- 代码能跑吗？创始人5分钟能看懂吗？
- 价值是外部可使用的，还是内部自嗨？

**对Token消耗**：
- 预估vs实际偏差有多大？
- 有没有"向内集邮"的浪费？

**对记忆同步**：
- MEMORY.md和实际工作一致吗？
- 有没有"幽灵任务"？

## 三、How

### 3.1 触发方式

**定时**：
- 每日日终自动生成（18:00后）
- 每周深度审计（周日）

**手动**：
```
"双轨审计"
"诚实审计"
"验收今日工作"
"审计完成度"
```

### 3.2 审计流程

```
Step 1: 蓝军独立审计（不看满意姐的）
Step 2: 满意姐独立审计（不看蓝军的）
Step 3: 汇总对比
Step 4: 输出整改清单
Step 5: 用户确认/裁决
```

## 五、红线与边界

| 红线 | 说明 |
|------|------|
| 不互相商量 | 双轨必须独立，商量后就不是双轨 |
| 不粉饰 | 发现问题如实报告，不包庇 |
| 不人身攻击 | 审计的是工作，不是人 |
| 必须≥1个问题 | 禁止输出"一切正常" |
