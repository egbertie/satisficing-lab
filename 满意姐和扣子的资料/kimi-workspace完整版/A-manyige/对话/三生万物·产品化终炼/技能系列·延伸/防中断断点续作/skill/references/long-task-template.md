# 长任务分段执行模板库

## 模板A: 标准进度追踪文件

```markdown
# {任务名称} - 进度追踪
# 启动时间: YYYY-MM-DD HH:MM
# 防中断: ✅ 已启用
# 保存路径: {本文件路径}

## 任务总览

- **目标**: {一句话描述任务目标}
- **总单元数**: N
- **预估总时间**: XX 分钟
- **已消耗Token**: 待更新
- **最后更新时间**: YYYY-MM-DD HH:MM

## 单元清单

| 编号 | 单元名称 | 预估时间 | 状态 | 交付物 | 实际耗时 |
|------|----------|----------|------|--------|----------|
| U1 | {名称} | X分钟 | ⬜ 待执行 | {文件路径} | - |
| U2 | {名称} | X分钟 | ⬜ 待执行 | {文件路径} | - |
| U3 | {名称} | X分钟 | ⬜ 待执行 | {文件路径} | - |
| ... | ... | ... | ... | ... | ... |

## 执行日志

### [YYYY-MM-DD HH:MM] 任务启动
- 防中断措施已声明
- 进度追踪文件已创建
- 单元清单已确认

### [YYYY-MM-DD HH:MM] U1 完成
- 交付物: {文件路径}
- 实际耗时: X分钟
- Token消耗: ~X万
- 备注: {如有问题或异常}

## 断点恢复记录

| 时间 | 断点位置 | 中断原因 | 恢复验证 | 恢复人 |
|------|----------|----------|----------|--------|
| YYYY-MM-DD HH:MM | U{n}完成后 | Token耗尽/网络/用户暂停 | ✅ 交付物完整 | {谁恢复的} |

## 双经济检查记录

| 检查点 | Token可持续? | 效益值得? | 行动 |
|--------|-------------|-----------|------|
| U1后 | ✅/❌ | ✅/❌ | 继续/熔断/复盘 |
| U2后 | ✅/❌ | ✅/❌ | 继续/熔断/复盘 |
```

## 模板B: 防中断措施声明（对话开头使用）

```
---
**防中断措施已启动** 🛡️

本任务已标记为 **P{X}-长任务**，分段执行。
- 总单元数: {N}
- 预估时间: {XX} 分钟
- 进度追踪: {文件路径}

每完成一个单元将立即汇报进度并保存。
如需暂停，随时告知，断点将精确记录。
---
```

## 模板C: 单元完成汇报

```
✅ [U{n}] 完成 — {单元名称}
━━━━━━━━━━━━━━━━━━━━
📊 总体进度: {n}/{N} ({百分比}%)
⏱️ 本单元耗时: {X} 分钟
💾 交付物:
  - {文件1}
  - {文件2}
🔄 下一单元: [U{n+1}] {名称}（预计{X}分钟）
💰 Token状态: 剩余约{X}%（可持续）
```

## 模板E: 双经济熔断报告

```
⚠️ 双经济检查触发熔断
━━━━━━━━━━━━━━━━━━━━
触发单元: [U{n}]
熔断原因:
  - Token预估: 剩余{X}%，不足以完成剩余{N-n}个单元
  - 或: 已完成部分缺乏可直接使用的外部价值

已保存:
  - 进度追踪文件: {路径}
  - 已完成交付物: {清单}

建议:
  [A] 申请更多Token配额后继续
  [B] 缩减任务范围，聚焦高价值单元
  [C] 暂停任务，后续恢复
```

## 模板G: 多技能并行任务追踪

当同时执行多个技能的系列建设时，使用矩阵视图：

```markdown
# 技能系列建设总览 - YYYY-MM-DD

| 技能名 | 优先级 | 状态 | 当前单元 | 进度 | 阻塞项 |
|--------|--------|------|----------|------|--------|
| skill-a | P0 | 🟢 进行中 | U2 | 2/5 | 无 |
| skill-b | P0 | ⬜ 待启动 | - | 0/4 | 等待skill-a完成U2 |
| skill-c | P1 | ⬜ 待启动 | - | 0/6 | 无 |

## 依赖关系
- skill-b 依赖 skill-a 的 references/ 完成
```
