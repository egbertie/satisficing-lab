# 编号决策协议

> **编号**: SANSHENG-SKILL-017
> **定位**: 让每个决策有编号、有选项、有记录、有追溯链
> **触发词**: "决策" / "选哪个" / "编号" / "DEC-" / "选项" / "A-①" / "B-②"
> **五维映射**: 金(标尺) + 土(根基) + 火(洞察)

---

## 一、Why

**"我们之前决定过什么？"**

**问题**:
- 决策没有记录，事后争议
- 选项太多，用户决策疲劳
- 改了决策但不知道改了什么、为什么改

**解决**: 编号决策协议 — 每个决策有编号、有选项、有记录、有追溯链。

---

## 二、What

### 2.1 选项编号规则

**呈现2个及以上选项时必须编号**：

```
[A] ① 选项A — [说明]
[A] ② 选项B — [说明]
```

**多段对话合并回复**：
```
[A] ① 选项A — [说明]
[B] ② 选项B — [说明]
```

### 2.2 用户最小响应

```
A-② + [反馈]
```

### 2.3 决策存档

**编号格式**: `DEC-XXX`

```
[DEC-042] 决策存档
━━━━━━━━━━━━━━━━━━━━
决策时间: YYYY-MM-DD HH:MM
决策主题: {主题}

[选项]
① {描述} — [未选]
② {描述} — ✅ [已选]

[用户响应原文] "A-② + [反馈]"

[影响评估]
直接影响: {描述}
后续任务: {列表}
关联决策: {DEC-XXX}
━━━━━━━━━━━━━━━━━━━━
```

---

## 三、How

### 3.1 触发方式

**呈现选项时**:
```
[A] ① 立即启动
[A] ② 分阶段启动
[A] ③ 推迟一周
```

**用户选择后**:
```
确认：A-②，对吗？
→ 用户: "对" → 分配DEC编号 → 存档
```

### 3.2 决策调整

**修改历史决策必须走调整流程**：
```
原决策: DEC-042
原选择: ② → ①
调整原因: {说明}
影响处理: {已执行的变更}
```

## 五、红线与边界

| 红线 | 说明 |
|------|------|
| 不编号不给选项 | 2个以上选项必须编号 |
| 不存档不做决策 | 用户选择后必须存档 |
| 不改历史不留痕 | 修改决策必须记录调整原因 |
| 选项不超过5个 | 超过5个=没有聚焦 |
