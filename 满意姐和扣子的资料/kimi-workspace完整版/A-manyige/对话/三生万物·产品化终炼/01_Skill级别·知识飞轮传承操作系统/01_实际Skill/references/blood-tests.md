# 血液化检验标准 · KICL闭环质量检查

## 什么是血液化？

```
归档 = 文件从A搬到B
摘要 = 把1000字压缩成100字
洞察 = 提取底层方法论
映射 = 外部知识→满意解框架
血液化 = 知识变成"可执行的行动"或"可直接用的弹药"
```

## 血液化五级检验

| 级别 | 名称 | 检验标准 | 示例 |
|:-----|:-----|:---------|:-----|
| L0 | 归档 | 文件物理落盘，命名规范 | `案例库-Type07-2026-04-25.md` |
| L1 | 摘要 | 有1页以内的核心摘要 | "本文讨论了X在Y情境下的应用" |
| L2 | 洞察 | 提取了底层方法论/模式 | "X方法的核心是A→B→C三步" |
| L3 | 映射 | 与现有框架建立了连接 | "对应五维决策体系的'金'维度" |
| L4 | 血液化 | 可转化为直接可用的产出 | SOP片段/话术/诊断问题/技能定义 |

**只有达到L4，才算真正的"入库"完成。**

## L4血液化产出类型

| 类型 | 定义 | 检验问题 |
|:-----|:-----|:---------|
| **SOP片段** | 可直接嵌入现有流程的步骤 | "这个步骤能否直接替换现有流程中的某一步？" |
| **客户话术** | Egbertie可以直接对客户说的话 | "Egbertie能否在下次客户沟通中直接使用？" |
| **诊断问题** | 用于评估/诊断的新问题 | "这个问题能否直接加入现有问卷？" |
| **课程大纲补充** | 可加入教育系列的新模块 | "能否作为现有课程的扩充章节？" |
| **弹药库条目** | 金句/数据/案例片段 | "能否在下次报告中直接引用？" |
| **技能定义** | 可复用的能力单元 | "能否写成Skill.md供其他AI调用？" |
| **飞轮燃料** | 能启动新行动的知识 | "能否催生一个新任务/新飞轮？" |

## KICL 12步质量检查表

```
□ Step 1: 触发接收 — 接收日志已记录（1句话）
□ Step 2: 去重检查 — 去重结论已输出
□ Step 3: 本地转换 — 本地免费优先，没用付费API
□ Step 4: 结构化存储 — 物理落盘，命名规范
□ Step 5: 深度洞察 — 3个问题已回答 + 四维度拆解
□ Step 6: 内化映射 — 与现有框架建立了≥1条连接
□ Step 7: 血液化 — 至少1项L4产出（能"直接用"）
□ Step 8: 子文档 — 整合Step 5-7的完整MD
□ Step 9: 汇总报告 — 1页纸总结同步到对话文件夹
□ Step 10: 任务清单 — TASK_MASTER.md已更新
□ Step 11: 记忆固化 — memory已追加 + MEMORY.md已同步
□ Step 12: Git 快照 — 已commit，hash已记录

□ 蓝军自检: 血液化成果是否真的能"直接用"？
□ 修正记录: 本次处理有什么经验教训？
□ 飞轮检查: 这次处理催生了什么新行动？
```

## 血液化失败常见模式

| 失败模式 | 表现 | 修正 |
|:---------|:-----|:-----|
| " superficial映射" | "A像B"的表层对照 | 必须回答"怎么用" |
| "文档坟墓" | 处理完放着不用 | 每次处理完问"下一步行动是什么" |
| "完成虚荣" | "我处理了10份！" | 追求深度>数量，1份×100% > 10份×10% |
| "闭环缺失" | 缺了任务/记忆/Git步骤 | 12步必须全部走完 |
