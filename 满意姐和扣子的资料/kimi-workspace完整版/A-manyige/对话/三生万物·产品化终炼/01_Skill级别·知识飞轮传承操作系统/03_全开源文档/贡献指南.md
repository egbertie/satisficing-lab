# 贡献指南

> **用途**: 教你如何参与三生万物体系的开源贡献
> **适用**: 任何想改进、扩展、适配本体系的人

---

## 一、贡献类型

### 1. 报告问题（Bug Report）

发现体系中的错误、遗漏、或不适用的场景：
- 具体描述问题
- 说明你的场景（L1/L2/L3/L4？什么行业？）
- 建议的修正方向

### 2. 改进文档（Documentation）

发现文档不够清晰、有歧义、或缺少示例：
- 指出具体段落
- 提供改进建议或重写版本
- 说明改进后对谁更有帮助

### 3. 扩展方案（Feature Extension）

发现现有方案覆盖不到的场景：
- 描述新场景
- 说明为什么现有方案不适用
- 提供初步设计思路

### 4. 适配案例（Case Study）

在真实场景中应用本体系，并记录结果：
- 你的场景描述
- 使用的方案（A/B/C/D）
- 时间线和关键节点
- 成功经验和失败教训
- 量化指标（新人上手时间、复用率等）

### 5. 翻译与本地化（Localization）

将体系翻译成其他语言，或适配特定文化背景：
- 目标语言/文化
- 翻译样本
- 文化适配建议

---

## 二、贡献流程

```
1. 阅读本指南
2. 确认你的贡献类型
3. 准备贡献内容
4. 通过满意解研究所渠道提交
5. 等待审核（蓝军审计 + 满意姐评估）
6. 根据反馈修正
7. 合并到主版本
8. 更新版本历史
```

---

## 三、审核标准

### 蓝军审计（批判性验证）
- [ ] 是否有逻辑漏洞？
- [ ] 是否与现有体系冲突？
- [ ] 是否有未考虑的边界情况？
- [ ] 是否满足"创始人5分钟可用性检验"？

### 满意姐评估（效益验证）
- [ ] 对现有用户有负面影响吗？
- [ ] 是否增加不必要的复杂度？
- [ ] 是否真正解决了一个真实问题？
- [ ] Token消耗是否合理？

### Egbertie裁决（战略验证）
- [ ] 是否符合满意解研究所的品牌定位？
- [ ] 是否有利于长期发展？
- [ ] 资源投入是否值得？

- **优先使用权**: 新版本优先体验
