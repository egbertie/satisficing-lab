## 一、理论根基：为什么是「技能系列」

### 1.1 从「知识资产」到「技能产品」的跃迁

满意解研究所历经数月沉淀，已形成近百万字的知识资产（奔月计划、大学课程、案例库、科研论文集等）。但知识资产如果仅停留在文档层面，就无法直接为用户创造价值。

**技能（Skill）是知识资产的「活化形态」**:
- 知识资产是「原料」—— 需要用户自己加工
- 技能是「成品」—— 开箱即用，直接嵌入工作流
- 技能系列是「产品矩阵」—— 覆盖用户全场景需求

### 1.2 三生万物的哲学映射

| 产品层级 | 哲学概念 | 对应形态 | 关系 |
|----------|----------|----------|------|
| **底层** | 道生一 | 五维决策体系 | 一切技能的根基 |
| **中层** | 一生二 | 决策教练服务 / 知识产品 | 体系的外化 |
| **上层** | 二生三 | 技能系列·延伸 | 产品的原子化 |
| **应用** | 三生万物 | 用户场景组合使用 | 价值最大化 |

> 从「道」（五维决策）到「万物」（具体场景的技能应用），每一层都是对上一层的细化与延伸。

## 二、总体思路：技能系列的构建逻辑

### 2.1 三大构建原则

**原则一：双经济驱动**
- **Token经济学**: 每个技能的设计必须考虑调用成本，优先本地处理，减少重复计算
- **效益经济学**: 每个技能必须回答——创始人5分钟内能否看懂并受益？

**原则二：防中断优先**
- 所有技能必须内置防中断断点续作机制（参考「防中断断点续作」技能）
- 长任务自动分段，短任务快速闭环
- 进度追踪可视化，状态恢复无摩擦

**原则三：五维决策嵌入**
- 每个技能的核心判断必须嵌入五维决策视角（土金水木火）
- 不是装饰，是强制检查点

### 2.2 技能分层架构

```
┌─────────────────────────────────────────┐
│         应用层：场景化技能组合              │
│   （用户按需调用，灵活组合）               │
├─────────────────────────────────────────┤
│         产品层：独立技能产品                │
│   （每个技能=一个独立产品，四类文档配套）    │
├─────────────────────────────────────────┤
│         基础层：核心能力支撑                │
│   （五维决策/防中断/双经济/知识管理）       │
├─────────────────────────────────────────┤
│         底座层：满意解研究所IP               │
│   （奔月计划/案例库/大学课程/科研论文）      │
└─────────────────────────────────────────┘
```

### 2.3 技能生命周期管理

每个技能从创建到退役，遵循7阶段生命周期：

| 阶段 | 动作 | 输出物 |
|------|------|--------|
| **发现** | 从工作历史中识别技能化机会 | 潜力技能评估报告 |
| **设计** | 按SKILL.md规范设计技能结构 | SKILL.md + references/ + scripts/ |
| **配套** | 创建四类配套文档 | 使用说明/全开源/微信传播/实操指引 |
| **验证** | 实际场景测试，收集反馈 | 测试报告 |
| **发布** | 打包为.skill文件，注册到技能中心 | .skill文件 + 注册记录 |
| **运营** | 监控调用频率，收集用户反馈 | 使用数据 |
| **迭代** | 根据反馈优化，版本升级 | 更新日志 |

## 五、组合使用：1+1>2的场景

### 5.1 典型组合场景

**场景一：合伙人冲突咨询**
```
合伙人冲突案例库（诊断）
    ↓
双轨诚实审计（验证判断）
    ↓
编号决策协议（给出明确建议）
    ↓
五维决策工作坊（深度介入）
```

**场景二：新合伙人筛选**
```
问卷测评自动化（初步评估）
    ↓
合伙人冲突案例库（预判风险类型）
    ↓
奔月计划战略导航（长期匹配度）
    ↓
五维决策工作坊（共同决策）
```

**场景三：知识产品创作**
```
知识内化引擎（吸收外部方法论）
    ↓
大学课程生成器（结构化输出）
    ↓
晨报日报生成器（日常内容维护）
    ↓
奔月计划战略导航（品牌一致性校验）
```

**场景四：内部治理**
```
防中断断点续作（保障长任务执行）
    ↓
双轨诚实审计（定期质量检查）
    ↓
编号决策协议（关键决策记录）
    ↓
晨报日报生成器（信息同步）
```

### 5.2 组合使用原则

1. **诊断先行**: 任何行动前先诊断（案例库/问卷）
2. **审计跟进**: 重大判断后必须审计（双轨审计）
3. **决策留痕**: 关键选择必须编号记录（编号决策）
4. **防断保底**: 长任务必须启动防中断（断点续作）

## 七、质量标准与验收规范

### 7.1 每个技能的必备配套

每个技能必须包含以下四类文档：

```
{技能名}/
├── skill/                          # 实际技能文件夹
│   ├── SKILL.md                    # 技能主文件（触发+流程+输出）
│   ├── references/                 # 参考文档
│   └── scripts/                    # 可执行脚本（如有）
├── 使用说明与实操指引/              # 用户手册
│   ├── 快速入门.md
│   ├── 场景示例.md
│   └── 常见问题.md
├── 全开源文档/                     # 开源版本（去敏感信息）
│   └── {技能名}-开源版.md
└── 微信传播文档/                   # 社交媒体版本
    ├── 朋友圈文案.md
    ├── 公众号文章.md
    └── 小红书笔记.md
```

### 7.2 验收检查清单

- [ ] SKILL.md 通过 package_skill.py 验证
- [ ] 触发词覆盖用户常用表达
- [ ] 五维决策视角至少嵌入一处
- [ ] 配套文档四类齐全
- [ ] 开源版无敏感信息
- [ ] 微信传播版有吸引力
- [ ] 蓝军审计通过（至少发现1个问题）
