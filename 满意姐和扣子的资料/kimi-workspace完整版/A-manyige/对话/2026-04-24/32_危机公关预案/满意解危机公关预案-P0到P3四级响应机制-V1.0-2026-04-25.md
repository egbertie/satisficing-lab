## 第一部分：危机分级标准

### P0级：生死存亡危机

```
【定义】
可能直接导致公司倒闭、创始人入狱、品牌毁灭的事件

【触发条件】
├─ 创始人重大法律问题（刑事犯罪）
├─ 产品导致用户严重损失（如投资亏损百万）
├─ 数据泄露（用户隐私大规模泄露）
├─ 资金链断裂（无法支付员工/供应商）
├─ 核心团队集体离职
└─ 监管机构强制关停

【响应时间】
├─ 0-2小时：内部紧急会议
├─ 2-4小时：律师+公关顾问到位
├─ 4-8小时：初步声明
└─ 24小时内：全面应对方案

【响应团队】
├─ 总指挥：Egbertie
├─ 法律：外部律师
├─ 公关：外部公关顾问
├─ 执行：全部团队
└─ 决策：创始人+律师+投资人（如有）

【应对原则】
├─ 保命优先（法律风险）
├─ 真诚认错（不要狡辩）
├─ 立即行动（不是"将"要怎么做，是"已"做了什么）
└─ 接受结果（哪怕公司倒闭，也要体面）
```

---

### P1级：重大损害危机

```
【定义】
品牌严重受损，可能导致大量用户流失、收入下降

【触发条件】
├─ 创始人个人负面新闻（道德问题、争议言论）
├─ 产品质量问题（课程内容错误、误导用户）
├─ 服务失败（承诺未兑现、用户投诉集中爆发）
├─ 重大数据错误（测评系统bug导致错误诊断）
├─ 合作伙伴违约（代理商欺诈、联名方丑闻）
├─ 媒体负面报道（主流媒体报道负面）
└─ 社交媒体大规模负面传播（微博热搜、知乎热榜）

【响应时间】
├─ 0-4小时：内部确认事实
├─ 4-8小时：制定回应策略
├─ 8-24小时：对外发声
└─ 72小时内：跟进处理

【响应团队】
├─ 总指挥：Egbertie
├─ 内容：满意姐（起草声明）
├─ 审核：蓝军（风险评估）
├─ 执行：运营团队
└─ 外部支持：律师（如需）、公关顾问（如需）

【应对原则】
├─ 速度第一（黄金4小时内响应）
├─ 真诚透明（不隐瞒、不甩锅）
├─ 承担责任（是我们的错就认）
├─ 给出方案（不是只有道歉，有补救措施）
└─ 持续跟进（不是发完声明就结束）
```

### P2级：中度影响危机

```
【定义】
局部负面传播，影响特定群体或渠道

【触发条件】
├─ KOL/大V负面评价
├─ 用户集体投诉（10-50人）
├─ 社群内部争议
├─ 单个产品退货/退款潮
├─ 员工离职引发质疑（1-2人）
├─ 小媒体负面报道
└─ 竞争对手恶意攻击

【响应时间】
├─ 0-8小时：确认事实
├─ 8-24小时：内部回应
├─ 24-48小时：如有必要，对外回应
└─ 1周内：问题闭环

【响应团队】
├─ 负责人：运营负责人
├─ 内容：满意姐
├─ 审核：蓝军
└─ 决策：Egbertie

【应对原则】
├─ 快速确认（不要拖延）
├─ 私下沟通（能私了不公开）
├─ 具体问题具体解决
├─ 记录归档（防止复发）
└─ 低调处理（不要小事化大）
```

### P3级：轻微波动

```
【定义】
个别投诉、吐槽，影响范围小

【触发条件】
├─ 单个用户投诉
├─ 社交媒体吐槽（非大V）
├─ 知乎/小红书负面笔记（低流量）
├─ 退款申请
├─ 课程差评
└─ 客服态度投诉

【响应时间】
├─ 0-24小时：响应用户
├─ 24-48小时：解决问题
└─ 1周内：回访确认

【响应团队】
├─ 负责人：客服/运营
├─ 升级：如用户不满升级，转P2处理
└─ 决策：Egbertie（如涉及原则问题）

【应对原则】
├─ 快速响应（24小时内回复）
├─ 同理心（先理解用户情绪）
├─ 解决导向（不是辩解，是解决）
├─ 超出预期（给用户惊喜）
└─ 记录反馈（用于产品改进）
```


### 2.2 危机响应团队激活

```
【P0/P1响应】

0-2小时：紧急会议
├─ 召集人：Egbertie
├─ 参会人：创始人+律师+公关顾问+核心团队
├─ 议题：
│   1. 事实确认（到底发生了什么）
│   2. 影响评估（最坏情况是什么）
│   3. 法律风险（有没有法律责任）
│   4. 公关策略（怎么说、什么时候说）
│   5. 行动计划（谁做什么、什么时候完成）
└─ 产出：危机应对方案V1.0

2-4小时：分工执行
├─ 法律组：律师评估法律风险、准备法律文件
├─ 公关组：起草声明、联系媒体、监控舆情
├─ 运营组：联系受影响用户、处理退款/补偿
├─ 技术组：修复技术问题、保护数据
└─ 决策组：Egbertie最终决策

4-8小时：对外发声
├─ 发布官方声明（官网/公众号/社交媒体）
├─ 联系核心媒体（解释情况、争取理解）
├─ 联系KOL（如果有负面评价，沟通澄清）
└─ 监控舆情（持续跟踪传播情况）

8-24小时：持续跟进
├─ 更新声明（如有新进展）
├─ 回应质疑（针对具体问题回应）
├─ 执行补救（补偿、退款、整改）
└─ 内部复盘（记录过程、总结经验）
```

## 第三部分：典型危机场景预案

### 场景1：创始人负面新闻

```
【触发】
Egbertie个人负面新闻（如争议言论、道德质疑）

【分级】
通常P1（除非涉及刑事犯罪→P0）

【应对】
Step 1: 确认事实
├─ 新闻是否属实？
├─ 是事实/误解/恶意造谣？
└─ 影响范围多大？

Step 2: 制定策略
├─ 如果是事实：真诚道歉+说明改进
├─ 如果是误解：澄清事实+提供证据
└─ 如果是造谣：法律手段+公开澄清

Step 3: 执行
├─ 创始人个人声明（如果是个人问题）
├─ 公司声明（如果是公司相关问题）
├─ 暂停创始人公开活动（如有必要）
├─ 加强其他IP（满意姐/蓝军）的曝光
└─ 监控舆情，持续回应

【预防】
├─ 创始人社交媒体内容审核（蓝军预审）
├─ 创始人公开场合发言准备（提前准备Q&A）
├─ 创始人个人品牌建设（正面内容积累）
└─ 创始人危机培训（如何回应负面问题）
```

### 场景2：产品质量问题

```
【触发】
用户反馈课程内容错误/测评系统bug/工具包无效

【分级】
P2（个别问题）→ P1（批量问题）

【应对】
Step 1: 确认问题
├─ 是个别情况还是系统性问题？
├─ 影响多少用户？
└─ 问题严重程度？

Step 2: 立即修复
├─ 技术问题：立即修复bug
├─ 内容问题：立即更正+向用户说明
└─ 产品问题：暂停销售+召回/退款

Step 3: 用户补偿
├─ 受影响用户：退款/补偿/赠送课程
├─ 公开说明：承认问题+改进措施
└─ 预防措施：建立质量检查流程

【预防】
├─ 内容三审：满意姐初审+蓝军复审+Egbertie终审
├─ 技术测试：上线前全面测试
├─ 用户反馈：建立快速响应机制
└─ 质量监控：定期用户满意度调查
```

### 场景3：用户集体投诉

```
【触发】
10+用户同时投诉（如退款难、服务差、承诺不兑现）

【分级】
P2（10-50人）→ P1（50+人）

【应对】
Step 1: 快速响应
├─ 24小时内发布声明
├─ 承认问题（如果是我们的错）
└─ 说明解决方案

Step 2: 分类处理
├─ 合理投诉：立即解决+补偿
├─ 不合理投诉：耐心解释+提供证据
└─ 恶意投诉：保留法律权利

Step 3: 补救措施
├─ 退款：简化流程，快速处理
├─ 补偿：赠送课程/优惠券/服务
├─ 改进：根据投诉优化产品/流程
└─ 反馈：向用户通报改进结果

【预防】
├─ 服务标准：明确服务承诺（SLA）
├─ 投诉渠道：畅通的投诉入口
├─ 响应机制：24小时内响应
└─ 预警机制：投诉量异常时自动预警
```

### 场景4：竞争对手恶意攻击

```
【触发】
竞品发布对比文章、恶意评论、挖角客户

【分级】
P2（通常）→ P1（大规模攻击）

【应对】
Step 1: 评估影响
├─ 攻击内容是否属实？
├─ 传播范围多大？
└─ 用户反应如何？

Step 2: 策略选择
├─ 如果攻击不实：发布澄清+保留法律权利
├─ 如果攻击属实：承认+改进
└─ 如果恶意造谣：法律手段+公开回应

Step 3: 回应原则
├─ 不点名攻击对手（保持风度）
├─ 强调自身优势（差异化价值）
├─ 提供证据（数据/案例/用户证言）
└─ 邀请体验（让用户自己判断）

【示例回应】
"我们注意到市场上有一些关于满意解的质疑。
满意解专注'合伙人决策'，这是我们唯一做的事。
我们相信，用户的真实反馈是最好的证明。
欢迎体验我们的免费测评，自己判断。"

【预防】
├─ 正面内容积累（案例库/用户证言）
├─ 用户关系维护（高满意度降低被挖角风险）
├─ 法律准备（知识产权/商业秘密保护）
└─ 舆情监测（及时发现负面信息）
```

```
├─ 准备法律文件
├─ 应对监管调查

Step 3: 公关应对
├─ 发布声明（承认问题+补救措施）
├─ 向用户道歉+补偿
├─ 第三方安全审计
└─ 持续更新进展

【预防】
├─ 数据加密：用户数据加密存储
├─ 权限管理：最小权限原则
├─ 定期审计：每季度安全审计
├─ 应急预案：数据泄露响应流程
└─ 用户授权：明确告知数据使用范围
```

## 第四部分：危机后修复

### 4.1 声誉修复计划

```
【危机后30天修复计划】

Week 1：善后
├─ 完成所有受影响用户的补偿
├─ 完成技术/产品整改
├─ 发布整改报告
└─ 监控舆情（确保负面不再扩散）

Week 2：沟通
├─ 向核心用户/合作伙伴单独沟通
├─ 向媒体提供最新进展
├─ 在社群回应用户关切
└─ 收集用户反馈（用于改进）

Week 3：展示
├─ 发布正面内容（案例/用户成功故事）
├─ 展示整改成果（数据/证据）
├─ 邀请第三方背书（审计报告/专家评价）

├─ 时间是最好的修复剂（不急于洗白）
```
