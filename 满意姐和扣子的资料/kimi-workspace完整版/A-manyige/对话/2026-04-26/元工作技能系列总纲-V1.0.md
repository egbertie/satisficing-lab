## 系列哲学

> **不是向内集邮，是向外输出。**
> **不是完善体系，是创始人5分钟可用。**
> **不是记录经验，是铸造可复用的工作协议。**

这个系列中的每一个技能，都源自一个真实问题：
- Token耗尽在中途 → `dual-economy-auditor`
- 63%的FIN是伪装 → `fin-honesty-validator`
- 创始人看不懂代码 → `founder-5min-usability`
- "我以为你懂了"导致的返工 → `lean-communication`
- 输出"一切正常"的幻觉 → `rapid-cognitive-audit`
- 被技能名字限制 creativity → `skill-cross-pollinator`
- 重启后不知道走到哪了 → `checkpoint-archivist`
- 复杂任务无从下手 → `task-decomposition-artisan`
- 记忆断层导致决策偏差 → `memory-sync-protocol`
- "我们之前决定过什么？" → `decision-checkpoint`

## 技能组合工作流

### 工作流A: 长任务执行（从启动到完成）

```
1. 任务拆解 → task-decomposition-artisan（拆成Unit）
2. 双经济审计 → dual-economy-auditor（每个Unit前检查）
3. 精益沟通 → lean-communication（意图契约+约束）
4. 防中断保护 → task-resumption-guard（进度追踪）
5. 断点存档 → checkpoint-archivist（中断时保存）
6. 记忆同步 → memory-sync-protocol（恢复时自检）
7. FIN验证 → fin-honesty-validator（完成后验收）
8. 5分钟检验 → founder-5min-usability（可用性确认）
```

### 工作流B: 决策支持（从问题到选择）

```
1. 认知审计 → rapid-cognitive-audit（问题本身的偏差）
2. 技能映射 → skill-cross-pollinator（找相关技能）
3. 双经济审计 → dual-economy-auditor（选项成本）
4. 决策存档 → decision-checkpoint（编号+记录）
5. 蓝军验证 → blue-team-verification（重大决策全量审计）
```

### 工作流C: 日常会话（启动→工作→结束）

```
启动: memory-sync-protocol（C1-C6自检）
  ↓
工作: task-decomposition + dual-economy + lean-communication
  ↓
中断: checkpoint-archivist（30秒存档）
  ↓
恢复: memory-sync-protocol + checkpoint恢复
  ↓
结束: fin-honesty-validator（当日产出验收）
```

## 使用优先级

**最高优先级**（每次交互默认激活）：
1. `dual-economy-auditor` — 所有行动的经济约束
2. `lean-communication` — 所有输出的沟通规范
3. `rapid-cognitive-audit` — 所有判断的偏差检查

**高优先级**（任务级激活）：
4. `task-decomposition-artisan` — 复杂任务拆解
5. `memory-sync-protocol` — 会话启动/恢复
6. `fin-honesty-validator` — 产出验收

**按需激活**（场景触发）：
7. `founder-5min-usability` / `23_创始人5分钟可用性检验` — 交付物可用性检验
8. `checkpoint-archivist` / `27_断点存档工程师` — 中断存档
9. `decision-checkpoint` / `30_决策断点存档` — 选项呈现与记录
10. `skill-cross-pollinator` / `26_技能跨界映射师` — 技能创新使用
11. `ai-partner-maturity` / `31_AI伙伴成熟度训练系统` — 新AI初始化
