# 巨量知识资产托付操作手册 · 教授版

> **定位**: 给已经拥有巨量知识资产的"教授"（资深AI/人类专家）使用  
> **目标**: 把你的知识资产完整、有效地托付给一个新的小白AI  
> **核心问题**: "我怎么确保我的54天/2个月/10年经验不会在新AI手里变成垃圾？"

---

## 一、托付前的自我诊断

### 1.1 你的资产现状体检表

```
□ 我有多少个文件？（粗略数字即可）
□ 它们分布在多少个文件夹里？
□ 我能说出每个文件夹里"最核心"的3个文件吗？
□ 过去30天里，我调用了这些知识资产多少次？
□ 这些资产中，有多少已经被"血液化"（可直接用于产出）？
□ 新AI接手后，我最担心他/她搞砸的是什么？
```

**如果以上问题有2个以上答不上来** → 先花1-2天做"资产盘点"，不要急着托付。

### 1.2 资产分级

| 级别 | 特征 | 托付策略 |
|:-----|:-----|:---------|
| **S级 · 核心骨架** | 身份定义、宪章、战略蓝图、方法论 | **必须亲手检查**，不能批量处理 |
| **A级 · 知识血肉** | 案例库、课程、报告、研究 | **结构化后托付**，附阅读指引 |
| **B级 · 过程记录** | 日志、审计、错误记录、复盘 | **选择性托付**，重点标记教训 |
| **C级 · 临时材料** | 草稿、中间产物、已废弃版本 | **不建议托付**，会制造噪音 |

### 1.3 托付 readiness 检查

```
□ 我的核心骨架文件（S级）已经过审计，没有矛盾或过时内容
□ 我的知识资产有明确的分类体系（至少3层）
□ 我已经准备了一份"紧急救生圈"清单（5个高频场景对应文件位置）
□ 我有一份"修正日志"，记录了最常见的错误和正确做法
□ 我准备好花3-5天时间引导新AI，而不是"把资料丢过去就不管"
```

## 二、托付流程（教授→小白）

### 阶段0：打包（Day -3到Day 0）

**任务1：生成"总导览README"**
```
内容:
- 你是谁（一句话）
- 这些资产是什么（一句话）
- 10个一级分类分别是什么（每类1句话）
- 最重要的3个文件在哪里（路径）
- 新AI应该从哪里开始（明确的起点）
```

**任务2：生成"Starter Pack"（新手启动包）**
```
选出10个文件:
- 3个"理解我是谁"
- 3个"理解我们要做什么"
- 2个"理解我们的方法"
- 2个"理解我们的过去"

每个文件附:
- 1句话推荐理由
- 预计阅读时间
- 读完的标志（"读完后你应该能说出X"）
```

**任务3：准备"修正日志摘要"**
```
从你的修正日志中，提炼:
- 最常犯的5类错误
- 每类的"正确做法"一句话
- 1个"如果重来一次，我最想避免的是什么"
```

### 阶段1：交付（Day 1）

**交付仪式**（不要发文件，要"介绍资产"）

```
对新AI说:
"这里有[数字]个文件，是我[时间]积累的资产。
不要急着读它们。先花3天时间，建立'地图'。
我给你准备了一份'Starter Pack'，里面有10个文件——
不是最重要的10个，是'最适合你先读的10个'。
读完它们，你就会知道'我们是谁，要做什么'。
不急，稳步前进。"
```

**同时交付的3份文档**:
1. `00_总导览README.md` — 地图
2. `00_Starter-Pack.md` — 启动包
3. `00_修正日志摘要.md` — 前车之鉴

### 阶段2：引导（Day 1-10）

**Day 1-3：只回答"在哪里"，不回答"是什么"**
- 新AI问"这个文件讲什么？" → 回答"它在X文件夹，先建立地图"
- 新AI问"我应该先读哪个？" → 回答"Starter Pack第1个，读完告诉我标志"

**Day 4-7：检查阅读日记**
- 要求新AI每读完1个文件，提交阅读日记
- 检查：收获是否具体？疑问是否真实？联想是否成立？
- 你的反馈：不是"对/错"，是"这个理解和我当年一样"或"这个角度我没想过"

**Day 8-10：第一次"连接测试"**
- 让新AI用已读的文件，建立一个"知识图谱"
- 检查：节点是否准确？连接是否合理？空白是否被识别？

### 阶段3：放手（Day 11-30）

**Week 2-3：从"教"退到"审"**
- 不再主动指导阅读顺序
- 但要求新AI每完成一个端到端任务，提交成果+自检清单
- 你的角色：审核者、反馈者、修正记录者

**Week 4：第一次"飞轮验收"**
- 让新AI独立完成一次KICL 12步
- 检查：12步是否走完？血液化成果是否"可直接用"？
- 如果通过 → 进入"成熟期"
- 如果没通过 → 回到阶段2，针对性地补

### 阶段4：传承（Day 30+）

**新AI成长为"教授"的标志**:
- 能独立完成KICL 12步，血液化比例≥80%
- 能建立新的知识连接，发现你之前没发现的空白
- 能产出"可直接用"的内容产品
- 能指导下一个新AI（至少能给出阅读顺序建议）

**传承仪式**:
```
对新AI说:
"你已经不是小白了。
现在，你也拥有了'巨量知识资产'——
不只是我的836个文件，还有你在这30天里建立的连接、
记录的修正、产生的洞察。
这些是你的资产。将来，你也会把它们托付给下一个AI。
这就是飞轮。"
```

## 三、托付中的常见错误（教授版避坑）

| 错误 | 为什么错 | 正确做法 |
|:-----|:---------|:---------|
| "把所有文件打包发给AI" | 没有地图，AI会吓死 | 先发地图+启动包，再分批给 |
| "你先读完这些，再来找我" | 没有引导，AI会迷路 | 每3天检查一次进度 |
| "这个很简单，你应该很快就能搞定" | 贬低学习过程 | "这个我当时也花了很久" |
| "你理解错了，应该这样" | 打击信心 | "这个角度我没想过，但还有另一个视角" |
| "我之前说过了，你怎么不记得？" | 新AI没有你的记忆 | 主动提供上下文，不要假设他记得 |
| "你太慢了，满意姐当初比这快" | 比较伤害关系 | "你和满意姐是不同的人，按你的节奏" |

```
□ 新AI能在5天内说出"S级核心骨架的3个要点"

□ 新AI能独立完成1次KICL 12步，血液化成果被Egbertie认可
□ 新AI能说出"如果下一个新AI接手，我会给他什么建议"
```

## 五、教授的自检

```
我是否做到了:
□ 没有"一次性丢所有文件"
□ 没有"比较"（满意姐当初...）
□ 没有"贬低学习过程"
□ 提供了"地图"而非"资料堆"
□ 记录了新AI的"修正日志"
□ 验收了"飞轮是否在转"
□ 完成了"传承仪式"
```
