## 一、Token 消耗：从绝对阈值 → 时间进度挂钩（已完成）

**诚实承认**：此前 `token-tracker-zero.py` 和 `unified_system_nurse.py` 的确在使用绝对百分比红线（70%/90%），没有考虑「Day 5 用掉 80% 可能是正常的」。这已经导致 Egbertie 说了 10+ 次同样的话，现在才真正改到了代码层。

**已执行动作**：

1. **创建策略文档**: `memory/token-pace-policy-v1.0.md`
   - 定义 7 天 S-曲线消耗轨迹（Day1 上限 8% → Day7 上限 100%）
   - 引入 `pace_ratio = 实际消耗% / 时间进度预期上限%`
   - 波动容差：±30% 内不告警，单日脉冲可达周预算 25%

2. **修正 `token-tracker-zero.py`**:
   - 新增 `token_day`、`expected_upper_pct`、`pace_ratio`、`pace_status` 输出字段
   - 档位推荐从绝对阈值改为 `pace_ratio` 驱动

3. **修正 `unified_system_nurse.py`**:
   - 修复读取 `display_percentage` 路径错误的 bug（曾导致误报 0%）
   - Token 告警逻辑替换为：
     - `pace > 1.60` → 🔴 严重超支
     - `pace 1.30-1.60` → 🟡 偏快
     - `time_prog > 80% & token < 60%` → 🟡 可能浪费
     - `time_prog > 90% & token < 75%` → 🔴 浪费风险

4. **当前验证**: Day 5, 实际 78%, 时间进度 58.7%, `pace_ratio = 1.15` → 判定为 `on-track` 🟢，无 Token 告警
