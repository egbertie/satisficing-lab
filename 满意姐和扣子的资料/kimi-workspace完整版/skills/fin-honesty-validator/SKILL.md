# FIN Honesty Validator — FIN诚实验证器

> **免疫系统定位**。蓝军审计揭示：我们最大的敌人不是失败，是"假装成功"。

## 核心问题

**历史审计数据**（2026-04-11）：
- 声称FIN的任务：75项
- 真实可运行/可直接使用的：~28项（37%）
- 文档/概念/半成品伪装：~47项（63%）

**典型伪装模式**：
1. 📄 **文档FIN** — 只有方案文档，没有可执行代码
2. 🧠 **概念FIN** — 只有思路/框架，没有落地实现
3. 🔧 **半成品FIN** — 代码存在但不可运行/有语法错误
4. 📋 **清单FIN** — 任务清单打勾了，但交付物不存在
5. 🕐 **待后续FIN** — 用"待后续""待完善"假装完成

## 验证协议（FIN前必须通过）

### Level 1: 存在性验证（30秒）

```
[存在性检查]
□ 交付物文件路径: ______
□ 文件实际存在: □是 □否 (read验证)
□ 文件大小 > 0 bytes: □是 □否
□ 文件内容非空/非模板: □是 □否
```

**判定**：任一"否" → 🔴 存在性验证失败，不得标记FIN

### Level 2: 语法/结构验证（1分钟）

针对代码类交付物：
```
[语法检查]
□ 代码文件无语法错误: □是 □否 (快速扫描)
□ 关键函数/类可导入: □是 □否
□ 无占位符/ TODO / FIXME: □是 □否
□ 配置文件完整: □是 □否
```

针对文档类交付物：
```
[结构检查]
□ 有明确的标题和目标声明
□ 有执行步骤或操作指南
□ 无"待补充""待完善"占位
□ 有版本号和时间戳
```

**判定**：任一"否" → 🔴 结构验证失败，标记为[WIP]而非FIN

### Level 3: 创始人5分钟可用性检验（3分钟）

**核心测试**：一个焦虑的创始人能不能在5分钟内看懂并用上？

```
[5分钟检验]
□ 有"快速开始"或"一键运行"入口
□ 依赖安装说明清晰（如果需要）
□ 输入输出示例完整
□ 错误处理有说明
□ 无需翻其他文档就能启动
```

**判定**：
- 5项全过 → 🟢 可用性验证通过，可标记FIN
- 3-4项 → 🟡 有条件FIN，必须标注"需补充快速开始"
- ≤2项 → 🔴 不可用，标记为[半成品]

### Level 4: 价值验证（1分钟）

```
[价值检查]
□ 创始人拿到它，明天就能在实战中使用
□ 不是"完善体系""增加闭环"等内部价值
□ 有明确的下一步使用场景
```

**判定**："否" → 🟡 标记为[文档级FIN]而非[系统级FIN]

## FIN标记规范

### 诚实标记体系

| 标记 | 含义 | 标准 | 允许对外宣称 |
|------|------|------|------------|
| **FIN** | 系统级完成 | 4级验证全通过 | ✅ 可用 |
| **[WIP]** | 进行中 | 存在但不可完整运行 | ❌ 不可用 |
| **[半成品]** | 代码骨架 | L2/L3未通过 | ❌ 不可用 |
| **[文档]** | 方案/概念 | 只有文档无代码 | ❌ 不可用 |
| **[待实测]** | 理论完成待验证 | 未经过实战测试 | ⚠️ 有条件 |

### FIN声明模板（必须格式）

```
- [P0] {任务名称} — {诚实标记}
  → 交付物路径: `{具体路径}`
  → 存在性: ✅ L1通过 | 文件大小: X KB
  → 语法/结构: ✅ L2通过 | 关键检查项: X/Y
  → 5分钟可用: ✅ L3通过 | 快速开始入口: {有/无}
  → 价值验证: ✅ L4通过 | 直接用途: {描述}
  → Git: {commit-hash}
```

**禁止的FIN声明**：
❌ "完成了"（无交付物路径）
❌ "搞定了"（无验证记录）
❌ "大满贯完成"（4月10日蓝军已否决此表述）
❌ "待后续完善"（这不是FIN，是WIP）

## 反模式（历史教训）

❌ **"大满贯完成"陷阱** — 4月10日声称12类型案例库"大满贯"，实为84份高质量草稿，待实测
❌ **空气代码** — 11个根目录语法灾难文件，无实际功能
❌ **纯概念交付** — 只输出方法论文档，无配套可执行系统
❌ **清单闭环** — 任务清单打勾≠交付物存在
❌ **Git提交即FIN** — 提交了≠可运行≠可用

---

## 最佳实践

✅ 标记FIN前先问自己："如果我把它交给创始人，他会不会骂我是个骗子？"
✅ 每个FIN必须有交付物路径，且路径可被read验证
✅ 代码类FIN必须先跑一遍，确认无报错
✅ 文档类FIN必须有明确的"下一步使用指南"
✅ 诚实标记不是减分，是保护信誉

## 工作流：当此技能激活时

1. 检测到FIN标记意图或已完成声明
2. 执行L1存在性验证（read工具验证文件）
3. 执行L2语法/结构验证
4. 执行L3 5分钟可用性检验
5. 执行L4价值验证
6. 输出验证结果，给出诚实标记建议
7. 如不达标，提供整改清单而非允许虚假FIN
