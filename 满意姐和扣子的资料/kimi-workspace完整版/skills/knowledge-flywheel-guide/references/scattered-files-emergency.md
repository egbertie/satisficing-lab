# 散乱文件应急处理手册·知识飞轮传承

> **编号**: SSW-075（新增）
> **定位**: 当输入不标准时的应急操作指南
> **目标**: 收到100个散乱文件也能启动传承
> **版本**: V1.0
> **日期**: 2026-04-25

---

## 一、问题定义

**标准输入**：
- 压缩包 + 导览 + 索引 + 验收标准 + P0/P1/P2标记

**非标准输入**（常见情况）：
- 散乱文件集合（没有索引）
- 口头描述 + 少量文档
- 压缩包 + 基本指引（缺优先级标记）
- 历史聊天记录/邮件往来

**当前系统问题**：
- 对标准输入：✅ 非常适合
- 对基本指引：⚠️ 部分适合
- 对散乱文件：❌ 不适合（容易迷失）
- 对口头描述：❌ 不适合（缺乏锚点）

**本手册解决**：如何在非标准输入下启动传承。

## 二、散乱文件处理流程（7步法）

### Step 1：收集（10分钟）

**目标**：把所有文件放进一个文件夹

```
□ 创建文件夹：/传承输入/原始文件/
□ 把所有收到的文件复制进去
□ 不要整理、不要重命名、不要筛选
□ 统计总数：___个文件
```

**如果文件 > 100个**：
- 先粗略分类（按文件类型：文档/图片/代码/数据）
- 每类创建一个子文件夹
- 不要细分类，粗略分即可

### Step 2：扫描（20分钟）

**目标**：快速了解每个文件是什么

```
对每个文件，记录：
| 文件名 | 类型 | 一眼看过去是关于什么的 | 大小 | 修改时间 |
|:-------|:-----|:------------------------|:-----|:---------|
| | | | | |
```

**快速判断方法**：
- 看文件名（是否包含"指南""手册""报告""总结"等关键词）
- 看文件类型（.md/.pdf/.docx通常是知识文件）
- 看文件大小（太大的可能是原始数据，不是知识）
- 看修改时间（最新的可能是当前状态，最旧的是历史）

### Step 3：识别核心（15分钟）

**目标**：找出"如果只有3个文件能传，是哪3个"

**识别方法**：

```
对每个文件问：
1. "如果承者没有这个文件，能启动吗？"
   → 不能 = 可能是核心
   
2. "这个文件被其他文件引用/依赖吗？"
   → 被引用最多 = 可能是核心
   
3. "这个文件的标题看起来像'总结'还是'细节'？"
   → 总结 = 可能是核心
   → 细节 = 可能是补充
   
4. "这个文件是'是什么'还是'怎么做'？"
   → 是什么 = 可能是框架
   → 怎么做 = 可能是执行
```

**输出**：标记3-5个"核心候选文件"

### Step 4：构建最小索引（15分钟）

**目标**：创建一个临时传承清单

```markdown
# 临时传承清单（自动生成）

## 核心层（先读这些）
| 序号 | 文件名 | 类型 | 为什么核心 | 预计阅读时间 |
|:-----|:-------|:-----|:-----------|:-------------|
| 1 | | | | |
| 2 | | | | |
| 3 | | | | |

## 支撑层（核心层读完再读）
| 序号 | 文件名 | 类型 | 支撑哪个核心文件 | 预计阅读时间 |
|:-----|:-------|:-----|:-----------------|:-------------|
| 1 | | | | |

## 背景层（有时间再读）
| 序号 | 文件名 | 类型 | 背景信息 | 预计阅读时间 |
|:-----|:-------|:-----|:---------|:-------------|
| 1 | | | | |

## 待分类（暂时不确定）
| 序号 | 文件名 | 类型 | 快速判断 | 预计阅读时间 |
|:-----|:-------|:-----|:---------|:-------------|
| 1 | | | | |
```

### Step 5：提取阅读指引（20分钟）

**目标**：为核心文件补充"阅读指引"

**每个核心文件头部添加**：

```markdown
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 阅读指引（自动生成）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
来源: [散乱文件集合]
优先级: 🔴 P0（推断）
阅读时间: 约___分钟（根据文件长度估算）
前置要求: 无（如果是第1个核心文件）
核心产出: 读完后你应该能______（根据文件标题推断）
验证方法: 读完后请尝试______（根据文件内容推断）
困惑信号: 如果读到这里卡住了，说明你可能需要______
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### Step 6：启动传承（10分钟）

**目标**：按最小可用版本启动

```
□ 把"临时传承清单"发给承者
□ 告诉承者："这是临时清单，优先级是我推断的，可能不准确"
□ 约定第1次对账时间（3天内）
□ 告诉承者："第1次对账时，我们一起修正优先级"
□ 承者从核心层第1个文件开始读
```

### Step 7：首轮对账修正（第1次对账）

**目标**：根据承者反馈修正索引

```
承者反馈：
□ "这个文件我读不懂，因为它引用了我没见过的概念"
  → 说明这个文件有"隐藏的前置要求"
  → 找到被引用的概念在哪个文件→移到核心层
  
□ "这个文件很简单，我5分钟就读完了"
  → 可能是P2或P3，降级
  
□ "这个文件和我之前读的有矛盾"
  → 🔴困惑信号，立即处理
  
□ "我不知道这个文件和整体的关系"
  → 需要补充"关联说明"

传者修正：
□ 根据反馈调整P0/P1/P2
□ 补充缺失的"前置要求"
□ 标注文件间的关联
□ 更新"临时传承清单"为"正式传承清单"
```

## 三、口头描述应急处理

### 场景

传者只有口头描述，没有文档：
- "我把我的经验跟你说一遍…"
- "这个很简单，你听我说…"
- "我脑子里有，但从来没写过…"

### 处理流程

```
Step 1: 录音/记录（传者说话时）
  → 承者实时记录要点
  → 用"传者操作手册"中的模板引导传者表达

Step 2: 即时整理（传者说完后30分钟内）
  → 把口头内容整理成"文档"
  → 用"隐性知识表达模板"格式化
  → 发给传者确认："这是我的理解，对吗？"

Step 3: 传者确认（24小时内）
  → 传者修正理解偏差
  → 补充遗漏的点
  → 确认："这个文档能代表我的意思"

Step 4: 纳入传承
  → 把确认后的文档加入"传承清单"
  → 标记为P0（因为是核心隐性知识）
  → 继续标准传承流程
```

### 引导传者表达的提问模板

```
"您刚才说的______，能不能具体举个例子？"
"如果您遇到一个新手，他在这里会犯什么错？"
"您是怎么判断______的？能说出3个判断标准吗？"
"如果情况变成______，您的做法会不同吗？"
"您有没有遇到过'例外情况'？当时怎么处理的？"
```

## 四、系统上限管理（>100个文件）

### 问题

当前系统设计上限约100个文件。超过后会：
- 承者信息过载
- 优先级混乱
- 迷失在文件堆里

### 解决方案：分层索引

```
第1层：总索引（1个文件）
  → 只列10个一级分类
  → 每个分类指向一个"分类索引"
  
第2层：分类索引（10个文件）
  → 每个分类列10个核心文件
  → 每个文件指向具体内容
  
第3层：具体内容（N个文件）
  → 承者按索引逐层深入
  → 每次只打开1个文件
```

**关键规则**：
- 承者永远从"总索引"开始
- 承者一次只打开1个文件
- 承者读完当前文件后，必须回到索引选下一个
- 绝不直接打开"具体内容"层

### 如果文件 > 500个

**启动"目录树模式"**：
```
1. 按主题分10个大类
2. 每个大类下分5个子类
3. 每个子类下列出核心文件
4. 生成"可折叠目录树"（Markdown格式）
5. 承者像浏览文件夹一样浏览
```
