> **编号**: SSW-074（新增）
> **定位**: 传承的"质量控制系统"——确保传了≠白传
> **目标**: 让传承从"给出去"变成"验证接住"
> **版本**: V1.0
> **日期**: 2026-04-25

## 一、传承闭环的核心问题

```
传者以为："我把东西给你了" = "传承完成"
承者以为："我收到了东西" = "传承完成"

但真正的传承是：
"承者能在不看传者的情况下，做出和传者类似的判断"

当前系统缺什么？
❌ 没有"握手机制"——双方不知道对方进度
❌ 没有"成功标准"——不知道完成了没
❌ 没有"反馈回路"——错了不知道哪里错
❌ 没有"质量追溯"——失败了不知道怪谁
```

**本体系解决以上全部问题。**

## 二、传承握手机制

### 2.1 握手清单（每轮对账使用）

**传承启动握手（Day 0）**

```markdown
# 传承启动握手

## 传者确认
□ 我已完成传者准备度自检（7问）
□ 我已标记P0/P1/P2/P3优先级
□ 我已表达隐性知识（至少1项）
□ 我已估算时间投入
□ 我已准备传承清单
□ 我已约定双周对账时间

## 承者确认
□ 我收到了传承清单
□ 我确认P0/P1/P2标记清晰
□ 我确认有阅读指引
□ 我已创建阅读日志
□ 我确认知道困惑信号触发方式
□ 我确认双周对账时间

## 双方共同确认
□ 传承目标已明确（1句话）
□ 验收日期已约定
□ 验收标准已共识
□ 紧急联系方式已交换

## 握手完成
传者签名: ______ 日期: ______
承者签名: ______ 日期: ______
```

### 2.2 双周对账握手

**每轮对账的标准流程**：

```
Step 1: 承者汇报（10分钟）
  □ 我读了哪些文件？
  □ 我理解了多少？（自评1-5分）
  □ 我有哪些困惑？（标记🔴🟡🟢）
  □ 我尝试了哪些验证？（理解三问结果）

Step 2: 传者检查（10分钟）
  □ 承者的理解是否与我的意图一致？
  □ 承者的困惑是否合理？（还是承者理解偏了？）
  □ 我是否需要修正表达？（不是承者的问题，是我的问题）
  □ 我是否有新的隐性知识要补充？

Step 3: 共同决策（10分钟）
  □ 下一轮阅读计划（读什么、读到什么程度）
  □ 新增/调整P0/P1/P2
  □ 约定下次对账时间
  □ 是否需要额外资源（模板、例子、工具）

Step 4: 记录（5分钟）
  □ 双方更新"传承清单"状态
  □ 承者更新"阅读日志"
  □ 传者记录"修正点"（下次传承要改进的地方）
```

### 2.3 紧急握手（异常时）

**触发条件**：
- 承者连续2轮对账没有进展
- 传者发现承者理解严重偏差
- 承者发现传者内容有矛盾/错误
- 任一方需要暂停传承

**紧急握手流程**：
```
1. 发现问题方发起"紧急握手信号"
2. 双方24小时内安排紧急对账
3. 不用等双周，立即对账
4. 问题分类：
   - 传端问题（表达不清/内容错误）→ 传者修正
   - 承端问题（理解偏差/执行困难）→ 承者重读+传者辅助
   - 系统问题（内容矛盾/缺失）→ 双方共同解决
5. 记录问题根因，更新传承文件
```

## 三、传承成功标准

### 3.1 三层验证模型

```
第一层：信息传递（有没有收到）
  ↓ 验证通过
第二层：理解达成（有没有看懂）
  ↓ 验证通过
第三层：能力迁移（能不能做到）
  ↓ 验证通过
  = 传承成功
```

**关键规则**：
- 不能跳过层级！
- 第一层没通过，不进入第二层
- 第二层没通过，不进入第三层
- 每一层有明确的通过标准

### 3.2 第一层验证：信息传递

**验证问题**：承者收到了什么？

| 检查项 | 验证方法 | 通过标准 |
|:-------|:---------|:---------|
| 收到传承清单 | 承者展示清单 | 清单完整，有P0/P1/P2标记 |
| 收到所有P0文件 | 承者展示文件 | 文件可打开，内容可读 |
| 知道阅读顺序 | 承者口头说明 | 能说出"先读X，再读Y" |
| 知道验证方法 | 承者口头说明 | 能说出"我怎么知道自己懂了" |

**验证方式**：
- 承者向传者展示清单和文件
- 承者口头说明阅读计划
- 如果说不出来→第一层未通过→回到"传者操作手册"重新交付

### 3.3 第二层验证：理解达成

**验证问题**：承者看懂了多少？

| 检查项 | 验证方法 | 通过标准 |
|:-------|:---------|:---------|
| 能用自己的话解释P0 | 反向教学 | 传者认可"理解一致" |
| 能举出例子 | 举例测试 | 例子合理，不是背诵原文 |
| 能指出困惑 | 困惑信号检查 | 承者诚实说出"这里我不懂" |
| 能关联其他知识 | 关联测试 | 能说出"这个和X的关系是…" |

**验证方式**：
- **反向教学**：承者给传者讲一遍，传者判断理解程度
- **举例测试**：承者举例子，传者评估例子质量
- **困惑检查**：查看承者的"困惑信号"记录

**通过标准**：
- 反向教学：传者评分≥4/5
- 举例测试：例子与传者的预期一致
- 困惑信号：🔴全部解决，🟡部分解决

### 3.4 第三层验证：能力迁移

**验证问题**：承者能做到吗？

| 检查项 | 验证方法 | 通过标准 |
|:-------|:---------|:---------|
| 能独立执行核心任务 | 任务测试 | 不看文件，完成核心任务 |
| 能处理边缘案例 | 极端场景测试 | 用传者的判断逻辑处理新情况 |
| 能发现传者的遗漏 | 反哺测试 | 承者指出"这里传者漏了…" |
| 能教别人 | 教学测试 | 承者能教会第三方 |

**验证方式**：
- **任务测试**：给真实任务，承者独立完成
- **极端场景**：给"传者没教过的情况"，看承者判断
- **反哺测试**：承者提出改进建议
- **教学测试**：承者教另一个人，看教学成果

**通过标准**：
- 任务测试结果与传者预期差异≤20%
- 极端场景处理合理（不求最优，但求方向对）
- 反哺建议有价值（传者认可）
- 教学成果可接受（第三方能理解）

## 五、传承质量追溯

### 5.1 追溯机制

**如果传承失败了，怎么查原因？**

```
第一步：看验收报告
  → 哪一层没通过？

第二步：看对账记录
  → 哪一轮对账出了问题？

第三步：看困惑信号
  → 承者在哪里卡住了？

第四步：看传者记录
  → 传者是否及时修正？

第五步：看双方自检
  → 传者自检是否通过？承者自检是否通过？
```

### 5.2 责任判定（不是为了追责，是为了改进）

| 失败原因 | 判断标准 | 改进方向 |
|:---------|:---------|:---------|
| **传端表达问题** | 承者困惑合理，传者表达不清 | 优化传者操作手册 |
| **传端遗漏问题** | 承者发现传者没传的关键知识 | 优化核心知识萃取法 |
| **传端优先级问题** | P0标记错误，承者先读了不重要的 | 优化优先级标记工具 |
| **承端理解问题** | 传者表达清晰，承者理解偏差 | 优化承者辅助机制 |
| **承端执行问题** | 理解到位，但执行不到位 | 增加执行训练环节 |
| **承端态度问题** | 承者没有认真读/没有验证 | 强化承者自检清单 |
| **系统问题** | 双方都没问题，但系统设计有缺陷 | 优化闭环验证体系 |

## 六、适配性设计

### 6.1 不同规模的适配

| 规模 | 传承时长 | 对账频率 | 验证方式 | 文档化程度 |
|:-----|:---------|:---------|:---------|:-----------|
| **L1个人**（1对1） | 21天 | 双周1次 | 口头反向教学 | 简版清单 |
| **L2团队**（1对多） | 45天 | 每周1次 | 任务测试 | 标准版 |
| **L3组织**（多对多） | 90天 | 每周1次 | 极端场景+反哺 | 完整版 |
| **L4生态**（跨组织） | 180天+ | 双周1次+月度回顾 | 全面验收+教学测试 | 定制版 |

### 6.2 不同行业的适配

| 行业 | 核心验证点 | 特殊要求 |
|:-----|:-----------|:---------|
| **法律** | 案例判断一致性 | 引注验证、判例有效性 |
| **咨询** | 方法论应用 | 客户场景适配、保密要求 |
| **制造** | 工艺参数执行 | 安全标准、质量一致性 |
| **医疗** | 诊断判断 | 循证依据、伦理审查 |
| **金融** | 风险评估 | 合规要求、模型验证 |

### 6.3 人类-AI混合传承

| 场景 | 传者 | 承者 | 特殊机制 |
|:-----|:-----|:-----|:---------|
| 人传人 | 人类专家 | 人类新人 | 面对面+师徒制 |
| 人传AI | 人类专家 | AI助手 | 提示词+对账+自动化验证 |
| AI传AI | 老AI | 新AI | 知识迁移+一致性校验 |
| AI传人 | AI系统 | 人类用户 | 解释性输出+交互验证 |

## 七、最小可用版本（MVP）

**如果只有1天时间建立闭环验证**：

```
Step 1: 打印"传承启动握手清单"（5分钟）
Step 2: 双方填写并签名（10分钟）
Step 3: 约定验收日期和标准（5分钟）
Step 4: 约定第1次双周对账时间（5分钟）
Step 5: 承者创建"阅读日志"（5分钟）
Step 6: 承者开始读第1个P0（剩余时间）

完成以上，闭环验证的基础就建立了。
```

**如果没有时间做完整验收**：

```
最小验证（10分钟）：
1. 承者口头解释核心知识（3分钟）
2. 传者判断理解是否一致（3分钟）
3. 如果一致→通过；如果不一致→立即修正（4分钟）

这个最小验证每轮对账都做，就是最简单的闭环。
```
