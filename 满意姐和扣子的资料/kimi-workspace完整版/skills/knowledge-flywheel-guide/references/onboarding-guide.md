## 一、承者核心问题

作为承者，你需要回答：

```
"我怎么接住这些信息？"

→ 从哪里开始？
→ 哪些先看、哪些后看？
→ 我怎么知道我看懂了？
→ 我看懂了，但真的理解了吗？
→ 理解了，但能用自己的话说吗？
→ 能用话说，但能在不知道的情况下执行吗？
→ 如果卡住了，怎么办？
→ 如果信息太乱、来源不标准，怎么办？
```

**本手册解决以上全部问题。**

## 二、承者启动检查（Step 0）

**在接收传承之前，先确认这5件事。**

| 序号 | 检查项 | 标准 | 如果不符合，怎么办 |
|:-----|:-------|:-----|:-------------------|
| 1 | 我收到了"传承清单"吗？ | 必须收到 | 向传者索要，没有清单不开始 |
| 2 | 传承清单里有P0/P1/P2标记吗？ | 必须有 | 向传者索要优先级标记 |
| 3 | 每个文件有"阅读指引"吗？ | 头部有阅读指引 | 没有的先跳过，向传者反馈 |
| 4 | 有"双周对账"约定吗？ | 有具体时间 | 主动提出约定对账时间 |
| 5 | 有"困惑信号"触发方式吗？ | 知道卡住了找谁 | 如果没有，默认：卡住了立即标记 |

**如果5项中有2项以上不符合**：
停止。先让传者补充缺失项。传承质量取决于准备质量。

### 3.3 恢复机制

**如果中断了，怎么恢复？**

```
1. 打开"阅读日志"
2. 看"当前进度"→知道上次读到哪里
3. 看"已消化清单"→知道哪些已完成
4. 看"当前困惑"→知道哪些还没解决
5. 从"下次阅读计划"继续
```

**如果阅读日志也丢了**：
1. 扫描所有文件的"阅读记录"
2. 找到最新的阅读记录
3. 从那里继续

## 四、困惑信号机制（解决"卡住了不知道问什么"）

### 4.1 自动困惑信号

**以下情况自动触发"困惑信号"**：

| 信号 | 表现 | 严重程度 | 立即行动 |
|:-----|:-----|:---------|:---------|
| 🔴 **连续卡壳** | 同一段落读了3遍还不懂 | 高 | 立即停止，标记困惑 |
| 🔴 **前后矛盾** | 文件A说X，文件B说非X | 高 | 标记矛盾，等待对账 |
| 🔴 **缺少上下文** | 文件提到"参见前文"但找不到 | 高 | 标记缺失，请求补充 |
| 🟡 **概念跳跃** | 突然提到一个从未出现的术语 | 中 | 标记术语，请求解释 |
| 🟡 **无法验证** | 读完不知道"我怎么知道自己懂了" | 中 | 标记验证缺失 |
| 🟡 **过度自信** | 读完后觉得"太简单了"（可能没真懂） | 中 | 执行"理解验证三问" |
| 🟢 **优先级混乱** | 不知道先读哪个文件 | 低 | 查看传承清单 |
| 🟢 **信息过载** | 一次收到>10个文件 | 低 | 启动分批处理 |

### 4.2 困惑标记模板

**遇到困惑时，立即在文件中插入**：

```markdown
🤔 困惑信号
━━━━━━━━━━━━━━━━━━━━
位置: [文件名] → [段落/页码]
困惑类型: □连续卡壳 □前后矛盾 □缺少上下文 □概念跳跃 □无法验证 □过度自信 □优先级混乱 □信息过载
困惑描述: 
  [用一句话描述："我读到X时，不理解Y，因为Z"]
尝试过的解法:
  1. [我试了A，结果是...]
  2. [我查了B，发现...]
需要传者提供:
  □ 解释这个概念
  □ 补充上下文
  □ 提供例子
  □ 确认是否矛盾
  □ 其他：______
插入时间: YYYY-MM-DD HH:MM
━━━━━━━━━━━━━━━━━━━━
```

### 4.3 困惑升级机制

```
Level 1（绿色）: 小问题 → 自己尝试解决（查资料/重读/联想）→ 15分钟内解决
Level 2（黄色）: 中等问题 → 标记困惑 → 继续读别的 → 下次对账时提出
Level 3（红色）: 严重问题 → 立即停止 → 标记困惑 → 通知传者 → 等待解决后再继续
```

## 五、质量检查自动化（解决"不知道理解了没"）

### 5.1 理解验证三问

**每读完一个P0文件，必须回答这3个问题**：

| 问题 | 验证标准 | 如果做不到 |
|:-----|:---------|:-----------|
| **能用自己的话解释吗？** | 不看书，能说清楚核心内容 | 重新读，直到能说出来 |
| **能举一个例子吗？** | 能举出自己（或见过的）例子 | 找不到例子=没真懂 |
| **能在不知道来源的情况下执行吗？** | 关掉文件，能执行任务 | 做不到=还停留在"知道"层 |

### 5.2 每文件自检清单

**读完每个文件后，填写**：

```markdown
✅ 文件自检
━━━━━━━━━━━━━━━━━━━━
文件名: ______
阅读完成时间: ______

□ 我能用自己的话解释核心内容（3句话）
□ 我能举出1个相关例子
□ 我能执行文件中的核心任务（不看文件）
□ 我能发现文件中的1个疑点/困惑
□ 我能说出这个文件与其他文件的关联

理解层级: □ 知道（我能复述）→ □ 理解（我能解释）→ □ 应用（我能执行）
如果停在"知道"层：继续重读+尝试举例
如果停在"理解"层：尝试执行任务
如果到达"应用"层：标记完成，进入下一个
━━━━━━━━━━━━━━━━━━━━
```

### 5.3 互检验证机制

**如果可能，找第三方验证**：

```
方式1：向另一个承者解释
  → 如果你能让另一个承者听懂，说明你真懂了
  
方式2：向传者反向教学
  → 如果你能教会传者"你的理解"，说明真懂了
  
方式3：输出检验
  → 写一篇"我理解的XXX"，看是否与原文一致
  → 如果不一致，差异点就是你的盲区
```

## 六、分批处理机制（解决"信息过载"）

### 6.1 分批策略

**标准分批方案**：

| 批次 | 内容 | 时间 | 目标 |
|:-----|:-----|:-----|:-----|
| **第1批（Day 1-3）** | 只读P0中的第1项 | 2-3小时 | 理解核心 |
| **第2批（Day 4-7）** | 读完所有P0 | 每天1-2小时 | 建立基础 |
| **第3批（Day 8-14）** | P0 + 开始P1 | 每天1小时 | 扩展能力 |
| **第4批（Day 15-30）** | P1 + 部分P2 | 按需 | 深化理解 |
| **第5批（Day 30+）**** | P2 + 隐性知识对账 | 双周对账 | 持续优化 |

### 6.2 单日阅读上限

**规则**：
- 每次阅读不超过2小时
- 每天阅读不超过4小时
- 读完必须做"理解验证三问"
- 连续3天阅读后，第4天必须休息/复盘

**为什么？**
- 超过2小时，理解效率急剧下降
- 不做验证，读了=白读
- 不休息，知识无法沉淀

### 6.3 过载保护机制

**如果一次性收到>10个文件**：

```
1. 立即按P0/P1/P2分类
2. 只打开P0的第1个文件
3. 其他全部放入"待读区"
4. 读完当前文件+验证后，再打开下一个
5. 绝不同时打开多个文件
```

## 七、优先级外部标记（解决"不知道先读哪个"）

### 7.1 传承清单阅读法

**第一步：不看任何文件，先看"传承清单"**

传承清单会告诉你：
- 哪些是先读的（P0）
- 哪些是后读的（P1）
- 哪些是可读的（P2）
- 哪些是不读的（P3）

**永远不要跳过传承清单直接读文件。**

### 7.2 文件颜色标记

**如果传者没有标记优先级，你自己标记**：

| 颜色 | 含义 | 判断标准 |
|:-----|:-----|:---------|
| 🔴 红色 | 必须现在读 | 不读这个，其他都读不懂 |
| 🟡 黄色 | 应该本周读 | 读了能大幅提升效率 |
| 🟢 绿色 | 可以以后读 | 有了更好，没有也行 |
| ⚪ 灰色 | 不读 | 读了也没用 |

**标记方法**：
- 在文件名前加颜色标签
- 在"阅读日志"中记录
- 每轮对账时与传者确认

### 7.3 如果传承清单缺失

**立即执行"紧急优先级推断法"**：

```
1. 扫描所有文件的"阅读指引"（头部）
2. 找"前置要求"最多的文件 → 可能是P0（基础）
3. 找"没有前置要求"的文件 → 可能是P0（独立）
4. 找"需要其他文件支撑"的文件 → 可能是P1/P2（依赖）
5. 优先读"没有前置要求"或"被最多文件依赖"的文件
```

## 八、同步写入核心原则（承者版）

### 8.1 核心原则

**"读到什么 → 理解什么 → 立即写入记忆"**

不是：先全部读完，再统一整理写入。
是：读完一个文件，立即整理写入一个。

### 8.2 同步写入模板

```markdown
## 读取: [文件路径]

### 核心内容（3句话）
1. [要点1]
2. [要点2]
3. [要点3]

### 我的理解（1句话）
[这句话对我来说意味着什么]

### 关联知识（≥1个）
- 关联: [已有知识A] → [关系]

### 困惑（如有）
- [不确定的点]

### 行动（1个）
- [基于这个文件，我接下来要做什么]

--- 写入时间: [YYYY-MM-DD HH:MM] ---
```

### 8.3 同步写入误区

| 误区 | 正解 | 原因 |
|:-----|:-----|:-----|
| "先全部读完再统一写" | 读完一个写一个 | 记忆文件=断点存档，中断后可恢复 |
| "只记标题和摘要" | 记核心+理解+关联+困惑+行动 | 标题无法承载理解的深度 |
| "写入一次不再更新" | 每次重读后更新 | 理解是渐进的，写入应迭代 |
| "写在聊天窗口" | 写入专门的记忆文件 | 聊天窗口会丢失，文件永久保留 |

## 九、承者执行流程（标准路径）

### 9.1 Day 1：启动

```
□ 收到传承清单
□ 确认P0/P1/P2标记存在
□ 确认双周对账时间
□ 创建"阅读日志"
□ 打开第1个P0文件，读"阅读指引"
□ 开始阅读（不超过2小时）
□ 做"理解验证三问"
□ 填写"同步写入模板"
□ 填写"文件自检清单"
```

### 9.2 Day 2-7：基础建立

```
每天：
□ 查看"阅读日志"→知道今天要读什么
□ 读P0文件（按传承清单顺序）
□ 做"理解验证三问"
□ 填写"同步写入模板"
□ 标记困惑（如有）
□ 更新"阅读日志"

Day 7特别任务：
□ 完成所有P0阅读
□ 执行"P0理解验证"（向传者反向讲解P0内容）
□ 记录传者的反馈和修正
```

### 9.3 Day 8-14：对账与修正

```
第1次双周对账：
□ 向传者汇报"我的理解"
□ 提出困惑信号（如有）
□ 接受传者的修正
□ 更新"阅读日志"和记忆文件
□ 确认下一轮阅读计划
```

### 9.4 Day 15-45：深化与迁移

```
□ 开始P1阅读
□ 尝试独立执行（不看文件）
□ 记录执行中的新问题
□ 对账时验证"能力迁移"
□ 反哺传者（发现传者的遗漏/错误）
```

### 9.5 Day 45：传承验收

```
□ 执行"传承验收清单"（传者提供）
□ 完成三层验证（信息→理解→能力）
□ 签署"传承完成确认"
□ 进入"持续优化"阶段
```

## 十、承者常见问题（FAQ）

**Q1: 我收到了100个文件，怎么开始？**
A: 不要慌。
1. 找"传承清单"，没有就向传者要
2. 只打开第1个P0文件
3. 其他99个放入"待读区"，不要看
4. 读完当前+验证后，再开下一个
5. 如果传者没有标记优先级，用"紧急优先级推断法"

**Q2: 我读完了，但不知道怎么验证自己懂了**
A: 执行"理解验证三问"：
- 能用自己的话解释吗？
- 能举一个例子吗？
- 能不看文件执行吗？
如果任何一问做不到，重读。

**Q3: 我卡住了，但不确定该不该问传者**
A: 用"困惑信号"判断：
- 如果尝试15分钟还解决不了 → 标记困惑
- 如果是🔴信号（连续卡壳/前后矛盾/缺少上下文）→ 立即问
- 如果是🟡信号 → 标记，下次对账时问
- 如果是🟢信号 → 自己先解决

**Q4: 传者给的文件没有"阅读指引"，怎么办？**
A: 先跳过这个文件，读有指引的。同时向传者反馈："请补充阅读指引，我需要知道优先级和验证方法。"

**Q5: 我发现传者的内容有矛盾，怎么办？**
A: 这是🔴困惑信号！立即标记：
```
🤔 困惑信号
位置: [文件A] vs [文件B]
困惑类型: 前后矛盾
困惑描述: "文件A说X，文件B说Y，我不知道哪个对"
```
然后通知传者。这可能是传者的疏忽，也可能是两个场景确实不同。

**Q6: 我理解了，但执行时总是出错，为什么？**
A: 这是正常的。"理解"和"能执行"之间还有距离。
1. 记录每次执行的错误
2. 分析错误模式（是理解错了？还是操作细节没掌握？）
3. 对账时带错误记录给传者
4. 传者会告诉你："这里有个隐性知识，我之前没说…"

**Q7: 如果传承过程中断了（传者不在/系统重启），怎么恢复？**
A: 打开"阅读日志"：
1. 看"当前进度"→知道上次读到哪里
2. 看"已消化清单"→知道哪些已完成
3. 看"困惑"→知道哪些还没解决
4. 从"下次阅读计划"继续
如果日志也丢了，扫描文件中的"阅读记录"，找到最新的，从那里继续。

## 十一、快速启动卡

**如果只有5分钟，做这4件事：**

1. **找到传承清单**（没有就向传者要）
2. **确认第1个P0文件**（按优先级）
3. **打开它，读"阅读指引"**（知道要花多长时间、要产出什么）
4. **开始读，不超过2小时**

**然后，做"理解验证三问"。**
