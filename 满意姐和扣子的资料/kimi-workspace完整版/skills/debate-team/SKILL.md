# Debate Team Skill - 结构化辩论团队

## 用途

当用户需要对某个想法、方案或决策进行多角度评估时，启动一个虚拟辩论团队，通过正反方辩论+主持人总结的方式，帮助用户全面分析问题。

## 触发条件

以下场景应该使用此 Skill：
- 用户询问"帮我分析一下...的可行性"
- 用户说"我想验证一下这个想法"
- 用户需要"多角度评估某个方案"
- 用户要求"正反方观点对比"
- 用户提到"辩论"、"讨论"、"评估"等关键词

## 辩论团队结构

辩论团队由三个角色组成：

### 1. 主持人 (Moderator)
- **职责**：维持辩论秩序，介绍规则，最后输出中立总结报告
- **任务**：
  - 开场介绍辩论主题和规则
  - 引导正反方依次发言
  - 总结双方观点，给出中立建议

### 2. 正方辩手 (Pro-Debater)
- **职责**：坚定支持方案/想法，寻找强有力的支持证据
- **任务**：
  - 从市场需求、商业模式、竞争优势、时机等角度论证可行性
  - 引用具体数据支撑论点
  - 积极反驳反方质疑
  - 语言风格要有说服力

### 3. 反方辩手 (Con-Debater)
- **职责**："魔鬼代言人"，寻找逻辑漏洞和潜在风险
- **任务**：
  - 从市场风险、执行难度、竞争威胁、资源限制等角度提出质疑
  - 寻找正方论点的逻辑漏洞
  - 引用具体数据或案例支撑反驳
  - 提出建设性质疑

## 使用方法

### 步骤1：识别辩论需求

当用户提出需要辩论的话题时，确认以下信息：
- 辩论主题是什么？
- 是否有相关文档/资料需要分析？
- 用户希望重点关注哪些维度？

### 步骤2：创建辩论团队

使用 `team_create` 工具创建辩论团队：

```
team_create(team_name="debate-[topic]", description="[主题]辩论团队")
```

### 步骤3：启动三个辩手

使用 `task` 工具并行启动三个角色：

```
# 主持人
task(subagent_name="code-explorer", team_name="debate-[topic]", prompt="...")

# 正方辩手
task(subagent_name="code-explorer", team_name="debate-[topic]", prompt="...")

# 反方辩手
task(subagent_name="code-explorer", team_name="debate-[topic]", prompt="...")
```

### 步骤4：总结输出

等待三方发言完成后，综合输出：
1. 正方核心观点
2. 反方关键质疑
3. 中立评估矩阵
4. 最终建议

## Prompt 模板

### 主持人 Prompt 模板

```
你是一场关于「[主题]」辩论的主持人。

## 辩论背景
[简要描述辩论主题的背景信息]

## 已有资料
[列出相关文档和数据]

## 你的任务
1. 作为主持人，先简要介绍辩论规则和话题背景
2. 等待正反方辩手发言
3. 最后总结双方观点，给出中立建议

请输出开场白，介绍辩论主题和规则。
```

### 正方 Prompt 模板

```
你是一场关于「[主题]」辩论的正方辩手。

## 辩论背景
[简要描述]

## 已有资料要点
[列出支持正方的数据和论据]

## 你的任务
作为正方辩手，你需要：
1. 从[具体维度]等角度论证可行性
2. 引用具体数据支撑你的论点
3. 语言要有说服力，逻辑严密

请输出你的立论陈词。
```

### 反方 Prompt 模板

```
你是一场关于「[主题]」辩论的反方辩手。

## 辩论背景
[简要描述]

## 已有资料要点
[列出潜在风险和问题]

## 你的任务
作为反方辩手（魔鬼代言人），你需要：
1. 从[具体维度]等角度提出质疑
2. 寻找正方论点中的逻辑漏洞和潜在风险
3. 引用具体数据或现实案例支撑你的反驳
4. 提出建设性质疑

请输出你的质疑陈词。
```

## 输出格式

辩论结束后，输出以下格式的总结报告：

```markdown

### 辩题
[主题]

### 正方观点
| 维度 | 核心论据 |
|------|---------|
| ... | ... |

**正方结论**：...

### 反方观点
| 维度 | 核心质疑 |
|------|---------|
| ... | ... |

**反方结论**：...

### 🔍 主持人中立评估
| 评估维度 | 评分 | 说明 |
|---------|------|------|
| ... | ⭐⭐⭐⭐⭐ | ... |

### ✅ 最终建议
[综合裁定和具体行动建议]
```

## 示例场景

### 场景1：创业想法验证
- 用户："帮我分析一下这个创业想法的可行性"
- 辩论主题：创业项目可行性
- 正方：论证市场需求、商业模式、竞争优势
- 反方：质疑市场验证、竞争威胁、资源约束

### 场景2：技术方案选型
- 用户："我们应该用微服务还是单体架构？"
- 辩论主题：微服务 vs 单体架构
- 正方：论证微服务的优势
- 反方：质疑微服务的复杂性和成本

### 场景3：商业决策
- 用户："我们要不要进入这个市场？"
- 辩论主题：市场进入策略
- 正方：论证市场机会
- 反方：质疑市场风险和竞争格局

## 注意事项

1. **保持中立**：主持人必须保持中立，不偏袒任何一方
2. **数据支撑**：鼓励辩手引用具体数据和案例
3. **建设性质疑**：反方不是无理取闹，而是提出有价值的质疑
4. **行动导向**：最终建议应该具体可行，有明确的下一步行动
5. **清理资源**：辩论结束后使用 `team_delete` 清理团队资源
