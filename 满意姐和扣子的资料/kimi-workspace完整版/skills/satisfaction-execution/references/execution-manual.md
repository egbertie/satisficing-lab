# 满意解执行手册

> **用途**: 项目管理的详细操作指南
> **适用**: 任何需要高效执行的项目
> **阅读时间**: 15分钟

---

## 一、启动阶段（15分钟）

### 1.1 读取记忆

```bash
# 按顺序读取
1. SOUL.md          → 身份定义
2. USER.md          → 用户档案
3. memory/YYYY-MM-DD.md → 当日记忆
4. MEMORY.md        → 长期记忆指针
```

### 1.2 运行基线检查

```bash
python3 skills/baseline-checker/scripts/baseline-checker-runner.py
```

**检查项**:
- 磁盘使用率 < 75%
- 内存 < 900MB
- 基线错误率 < 0.1%

### 1.3 检查修复清单

```bash
cat checklists/IMMEDIATE_FIX_CHECKLIST.md
```

**P0/P1问题**: 3分钟内整改

### 1.4 确认运行模式

| Token状态 | 模式 | 心跳间隔 |
|:----------|:-----|:---------|
| >50% | L0 正常 | 30min |
| 20-50% | L2 休眠 | 30min |
| 10-20% | L3 静默 | 120min |
| <10% | L4 深度静默 | 720min |

## 二、执行阶段

### 2.1 任务评估

| 优先级 | 定义 | 响应时间 |
|:-------|:-----|:---------|
| P0 | 紧急，立即处理 | < 1分钟 |
| P1 | 重要，当日处理 | < 24小时 |
| P2 | 一般，本周处理 | < 7天 |
| P3 | 待定，有空处理 | 灵活 |

### 2.2 三板斧简化

**第一斧：砍**
- 这个任务真的需要做吗？
- 不做会怎样？
- 如果砍了，影响是什么？

**第二斧：合**
- 这个任务能和其他任务合并吗？
- 合并后效率会提升吗？

**第三斧：简**
- 这个任务最简可行版本是什么？
- 30%努力能换80%结果吗？

### 2.3 双经济自检

```
[Token经济学]
□ 这个任务优先本地处理吗？（Local ≥ 70%）
□ Token消耗在预算内吗？
□ 有没有更省Token的替代方案？

[效益经济学]
□ 产出有直接外部价值吗？
□ 创始人5分钟内能看懂并用上吗？
□ 效益值得投入吗？
```

### 2.4 防中断执行

```bash
# 1. 创建进度追踪文件
echo "# Progress $(date +%Y-%m-%d)" > progress-$(date +%Y-%m-%d).md

# 2. 逐块写入+Git提交
# 每完成一个文件块：
git add .
git commit -m "SANSHENG-$(date +%Y%m%d) [描述]"

# 3. 如果中断，从🔄标记处恢复
```

## 四、常见问题

**Q: 任务太多，怎么选先做哪个？**
A: P0先做，然后P1。同一优先级，选"效益最高且Token最省"的。

**Q: 怎么判断"足够好即可"？**
A: 问自己："创始人5分钟内能看懂并用上吗？"如果能，就是足够好。

**Q: 防中断策略麻烦，能不能简化？**
A: 不能。一次中断的损失，远大于每次多花2分钟提交。
