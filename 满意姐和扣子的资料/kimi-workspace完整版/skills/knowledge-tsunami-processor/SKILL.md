# knowledge-tsunami-processor

> **中文名**: 知识海啸处理器
> **定位**: 海量散乱信息的智能导入、分类、萃取、质量转化一体化系统
> **目标**: 将杂乱无章的海量信息（1000+文件）转化为结构化、可传承的知识资产
> **版本**: V1.0
> **日期**: 2026-04-25

---

## 一、产品概述

### 1.1 解决什么问题

**场景**: 你收到了一个U盘/网盘/邮件，里面是一位资深专家70年的积累——
- 3000个案件文件
- 500份笔记
- 200个模板
- 100封重要邮件
- 50个录音文件
- 杂乱无章，没有索引，没有分类

**问题**: 怎么把这些转化为"可传承的知识资产"？

**传统做法**: 人工逐一整理 → 需要3-6个月 → 质量不稳定 → 传者等不起

**知识海啸处理器**: 5步自动化处理 → 7天完成 → 质量标准化 → 立即可传承

### 1.2 核心能力

| 能力 | 说明 | 输出 |
|:-----|:-----|:-----|
| **海啸导入** | 批量扫描1000+文件，自动识别类型和内容 | 初始索引（含元数据） |
| **智能分类** | 基于内容的自动分类，P0/P1/P2/P3自动标记 | 分类索引+优先级标记 |
| **核心萃取** | 从海量中提取≤5项核心知识+隐性知识 | 核心知识清单+隐性知识表达 |
| **质量转化** | 转化为三生万物级别质量 | 五维映射+双视角+阅读指引 |
| **输出打包** | 生成标准传承包 | 可直接交付给承者 |

### 1.3 适用对象

| 对象 | 场景 | 示例 |
|:-----|:-----|:-----|
| **资深律师** | 毕生案件+经验 | 梁主席70年积累 |
| **退休教授** | 讲义+论文+笔记 | 30年学术成果 |
| **企业创始人** | 商业计划+合同+邮件 | 20年创业资料 |
| **医生** | 病例+诊断+研究 | 40年临床积累 |
| **咨询师** | 项目报告+方法论+工具 | 15年项目经验 |

### 1.4 系统上限

| 指标 | 上限 | 说明 |
|:-----|:-----|:-----|
| **文件数量** | 10,000个 | 超过需分批处理 |
| **总容量** | 100GB | 超过需外部存储 |
| **处理时间** | 7天（自动）+ 3天（人工确认） | 纯自动约2-3天 |
| **输出质量** | 可直接进入传承流程 | 达到P0/P1/P2标准 |

## 二、五步处理流程

### Step 1: 海啸导入（Tsunami Ingest）

**输入**: 散乱文件集合（任意格式、任意结构）
**输出**: `01_初始索引.json` + `02_文件元数据.csv`

**执行**: `python3 scripts/tsunami-ingest.py --input /path/to/files --output ./tsunami-output/`

**功能**:
- 递归扫描所有文件
- 识别文件类型（文档/图片/音频/视频/代码/数据）
- 提取元数据（文件名、大小、修改时间、路径深度）
- 生成初始索引（按路径排序）
- 估算处理时间

### Step 2: 智能分类（Smart Triage）

**输入**: `01_初始索引.json`
**输出**: `03_分类索引.md` + `04_P0-P1-P2标记.json`

**执行**: `python3 scripts/smart-triage.py --input ./tsunami-output/01_初始索引.json --output ./tsunami-output/`

**功能**:
- 基于文件名关键词自动分类
- 基于文件路径推断层级关系
- 基于修改时间识别"活跃"vs"历史"文件
- 自动标记P0/P1/P2/P3
- 识别重复文件
- 生成"推荐阅读顺序"

### Step 3: 核心萃取（Core Extraction）

**输入**: `03_分类索引.md` + 原始文件
**输出**: `05_核心知识清单.md` + `06_隐性知识候选.md`

**执行**: `python3 scripts/core-extractor.py --input ./tsunami-output/ --output ./tsunami-output/`

**功能**:
- 分析P0文件的内容，提取核心概念
- 统计高频关键词（出现频率>5次的概念）
- 识别"被引用最多"的文件（可能是核心）
- 生成"核心知识候选清单"（供人工确认）
- 标记"可能包含隐性知识"的文件（如"经验""感觉""判断"等关键词）

### Step 4: 质量转化（Quality Transform）

**输入**: `05_核心知识清单.md` + 原始文件
**输出**: `07_质量转化包/`（含五维映射+双视角+阅读指引）

**执行**: `python3 scripts/quality-transform.py --input ./tsunami-output/ --output ./tsunami-output/07_质量转化包/`

**功能**:
- 为每个P0文件生成"阅读指引"（含优先级、前置要求、验证方法）
- 为每个核心知识生成"五维映射"（土/金/水/木/火）
- 生成"人类视角导览"（面向传者/承者）
- 生成"AI视角导览"（面向AI助手）
- 生成"传承清单"（P0/P1/P2阅读顺序）

### Step 5: 输出打包（Package Builder）

**输入**: `07_质量转化包/`
**输出**: `08_标准传承包/`（可直接交付）

**执行**: `python3 scripts/package-builder.py --input ./tsunami-output/07_质量转化包/ --output ./08_标准传承包/`

**功能**:
- 按标准结构重组文件
- 生成总索引（README）
- 生成导览总纲
- 生成检验清单
- 打包为`.zip`或保留为文件夹

## 四、快速启动

### 4.1 安装

```bash
# 1. 复制skill到workspace
cp -r skills/knowledge-tsunami-processor ~/.openclaw/workspace/skills/

# 2. 进入目录
cd ~/.openclaw/workspace/skills/knowledge-tsunami-processor

# 3. 安装依赖（如有）
pip3 install -r requirements.txt  # 如需Python依赖
```

### 4.2 使用（5步）

```bash
# Step 0: 准备输入文件夹
mkdir -p ./input/
cp -r /path/to/your/messy/files/* ./input/

# Step 1: 海啸导入
python3 scripts/tsunami-ingest.py --input ./input/ --output ./tsunami-output/

# Step 2: 智能分类
python3 scripts/smart-triage.py --input ./tsunami-output/01_初始索引.json --output ./tsunami-output/

# Step 3: 核心萃取
python3 scripts/core-extractor.py --input ./tsunami-output/ --output ./tsunami-output/

# Step 4: 质量转化
python3 scripts/quality-transform.py --input ./tsunami-output/ --output ./tsunami-output/07_质量转化包/

# Step 5: 输出打包
python3 scripts/package-builder.py --input ./tsunami-output/07_质量转化包/ --output ./08_标准传承包/
```

### 4.3 人工确认（关键！）

**自动处理完成后，必须人工确认**：

| 确认项 | 谁确认 | 时间 |
|:-------|:-------|:-----|
| P0/P1/P2标记是否准确 | 传者 | 2小时 |
| 核心知识清单是否完整 | 传者 | 1小时 |
| 隐性知识候选是否有效 | 传者 | 2小时 |
| 阅读指引是否合理 | 传者 | 1小时 |
| 五维映射是否恰当 | 传者+承者 | 1小时 |

**总计**: 约7小时人工确认 → 系统从"80%质量"提升到"95%质量"

## 五、关键设计原则

### 5.1 人机协同

**机器做**：
- 批量扫描和分类
- 统计和排序
- 格式转换和重组
- 生成模板化内容

**人做**：
- 确认P0/P1/P2（机器推荐，人决策）
- 表达隐性知识（机器识别候选，人填写模板）
- 验证质量（机器生成，人审核）
- 最终决策（机器辅助，人拍板）

### 5.2 渐进式处理

**不要一次性处理所有文件**：
- 第1轮：只处理P0（核心层）
- 第2轮：处理P1（支撑层）
- 第3轮：处理P2（背景层）
- 第4轮：处理隐性知识

**为什么？**
- 人一次只能确认20-30个文件
- 核心层确认后，承者可以开始读
- 支撑层可以在对账时逐步补充

### 5.3 质量兜底

**机器处理的上限**: 80%质量
**人工确认后**: 95%质量
**最终传承**: 需要双周对账+三层验证

**不要期望机器100%准确**。
机器的价值是"把3个月的工作压缩到7天"，不是"替代人的判断"。

## 七、常见问题

**Q1: 机器分类准确率多少？**
A: 约70-80%。文件名清晰的准确率更高，文件名混乱的准确率更低。人工确认是必须的。

**Q2: 1000个文件处理要多久？**
A: 机器处理约2-3天（自动运行），人工确认约7小时（分2-3天完成）。

**Q3: 如果文件是手写笔记/扫描件怎么办？**
A: 先使用OCR工具（如Tesseract）转化为文本，再使用海啸处理器。OCR不属于本skill范围。

**Q4: 处理过程中可以中断吗？**
A: 可以。每个Step都有持久化输出，中断后从当前Step继续。

**Q5: 输出质量能达到"创始人5分钟可用"吗？**
A: 经过人工确认后，可以。机器单独输出约80%质量，需要人工确认提升到95%。
