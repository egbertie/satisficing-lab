## 一、问题定义（痛点分析）

### 1.1 当前问题
满意姐存在**"物理入库"与"内化完成"的混淆**：
- ❌ 将文件内容提取到日志 = 认为已完成入库
- ❌ 能说出文件框架 = 认为已完成内化
- ❌ 浅层扫描替代深度阅读

### 1.2 造成的后果
- 返工成本：同一文件需多次重新处理
- Token浪费：表面忙碌实则无效
- 决策风险：基于半消化信息做决策
- 信任损耗：用户需反复抽查验证

### 1.3 真实案例（2026-04-03）
```
AI决策系统设计.docx (213KB)
├── 满意姐声称：已提取，已入库
├── 实际状态：物理提取完成，内容不熟
├── 用户测试：文件大小都报错（说176KB，实际213KB）
└── 结论：物理入库 ≠ 内化完成
```

## 二、核心概念定义

### 2.1 知识入库（Knowledge Ingestion）
**定义**: 将外部文件/信息转化为系统可访问的存储格式
**标准**: 
- 文件内容完整提取
- 存储位置规范
- 索引可检索

**满意姐目前**: ✅ 能做到（但懒于做全）

### 2.2 知识内化（Knowledge Internalization）
**定义**: 将存储的信息转化为可理解、可应用、可创新的认知结构
**标准**（必须全部满足）：

| 层级 | 检验标准 | 测试方法 |
|------|---------|----------|
| L1-存在 | 能定位文件位置 | 问：XX文件在哪里？ |
| L2-理解 | 能解释核心内容 | 问：这份文件讲了什么？ |
| L3-结构 | 能画出知识框架 | 问：用思维导图表示？ |
| L4-应用 | 能提取可执行方案 | 问：哪些能立即实施？ |
| L5-创新 | 能与现有知识融合 | 问：如何与XX结合？ |

**满意姐目前**: ⚠️ 多数停留在L1-L2

## 四、审计系统功能需求

### 4.1 核心功能模块

#### 模块A：物理存在性审计
```
输入: 文件路径列表
输出: 
  - 文件是否存在
  - 文件大小是否正确
  - 最后修改时间
  - 内容哈希值（防篡改）
```

#### 模块B：内容理解度审计
```
输入: 文件内容 + 满意姐回答
测试问题集:
  1. 这份文件的核心目标是什么？
  2. 文件提供了哪几个解决方案？
  3. 每个方案的实施步骤是什么？
  4. 与现有系统的集成点在哪里？
  5. 哪些内容可以立即执行？
  
评分标准:
  - 5题全对: 内化完成 ✅
  - 3-4题对: 部分内化 ⚠️
  - <3题对: 未内化 ❌
```

#### 模块C：可执行资产提取审计
```
输入: 文件内容
输出检查:
  - 是否提取了可直接复制的代码？
  - 是否整理了配置模板？
  - 是否生成了检查清单？
  - 是否标注了实施优先级？
  
标准: 每份文件必须输出≥3个可执行资产
```

#### 模块D：跨文件关联审计
```
输入: 所有已审计文件
输出:
  - 文件间的重复内容
  - 冲突的方案/建议
  - 可整合的互补内容
  - 缺失的衔接环节
```

### 4.2 自动化审计流程

```
开始审计
    ↓
读取文件列表
    ↓
[并行] 物理审计 → 生成存在性报告
    ↓
[顺序] 内容审计 → 生成理解度评分
    ↓
[顺序] 资产审计 → 生成可执行清单
    ↓
[汇总] 跨文件审计 → 生成整合建议
    ↓
输出审计报告
    ↓
标记需返工文件
    ↓
生成整改任务清单
```

## 五、验收标准

### 5.1 单文件内化标准
一份文件被标记为"已内化"，必须满足：

| 检查项 | 要求 | 验证方式 |
|--------|------|----------|
| 内容摘要 | 300-500字核心洞察 | 人工抽查 |
| 可执行资产 | ≥3个（代码/配置/清单） | 自动计数 |
| 实施检查清单 | 步骤化，可勾选 | 人工验证 |
| 与现有系统关联 | 明确集成点 | 人工验证 |
| 时间戳 | 深度阅读记录 | 自动记录 |

## 七、给外援的需求要点

### 7.1 核心需求
> 设计一个**自动化知识内化审计系统**，能够：
> 1. 验证AI Agent是否真正"理解"了文件内容（而非仅存储）
> 2. 自动生成测试问题并评分
> 3. 提取可执行资产并检查完整性
> 4. 生成标准化审计报告

### 7.2 输入输出规范

**输入**:
- 文件路径列表
- 文件内容（文本）
- Agent的历史回答记录

**输出**:
- 审计报告（Markdown）
- 理解度评分（0-100）
- 需返工文件清单
- 可执行资产汇总

### 7.3 特殊要求
- 支持长文本（200KB+）
- 支持多轮对话文件（区分User/AI）
- 支持中文自然语言处理
- 适配Kimi Claw环境
