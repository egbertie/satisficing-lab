# 自动化任务治理宪章 V1.0

> 生效日期: 2026-04-11  
> 触发原因: token 周报准点输出暴露系统性执行闭环缺陷  
> 核心原则: **无洞察，不输出**

---

## 一、问题诊断

### 1.1 表面问题
- `token-tracker-zero` 每周三 09:00 机械输出报告，内容为空洞数据罗列，无判断、无行动、无洞察
- 仪式感大于实质，浪费 token，增加决策噪音

### 1.2 系统问题
- **自动化任务缺乏「输出熔断」机制**：任何脚本默认都会输出，没有「不输出」的选项
- **cron 注册缺乏「洞察审查」关卡**：新任务只检查能否跑通，不检查无数据时是否应该静默
- **仪式感幻觉**：把「有报告」等同于「有工作」，把「有机制」等同于「有价值」
- **缺失反馈闭环**：报告生成后没有「谁看了？做了什么决策？」的追踪

### 1.3 根因
> 执行标准没有被内化到机制中。「无洞察，不输出」是口号，不是代码层面的强制约束。

## 二、核心宪章：自动化任务三定律

### 定律一：触发定律（Trigger Law）
> 任何周期性自动化任务必须有明确的触发条件，以及明确的跳过条件。

**强制要求**：
```python
def should_run() -> (bool, str):
    """返回 (是否运行, 原因)"""
    pass
```

**禁止模式**：
- ❌ 固定时间到点就运行
- ❌ 仅以"仪式感"或"习惯"为由运行

**必须回答的三个问题**：
1. 什么条件下必须运行？（触发条件）
2. 什么条件下必须跳过？（跳过条件）
3. 最近一次运行产生了什么可验证的价值？（价值追溯）

### 定律二：输出熔断定律（Output Fuse Law）
> 如果输出无法让焦虑的创始人在 5 分钟内做出不同决策，就不输出。

**强制要求**：
- 每个自动化报告必须有「洞察断言」段落
- 如果只有数据罗列没有判断，任务应当静默并只更新 tracker JSON
- 报告尾部必须有「建议行动」和「不行动的代价」

**熔断检查清单**（运行前自检）：
- [ ] 本次输出包含至少一个明确的判断或预警
- [ ] 本次输出能直接导向一个具体行动（或不行动的明确理由）
- [ ] 如果删掉本次输出，创始人是否会错过什么重要信息？
- [ ] 如果以上任何一条为否，任务应转为静默更新（no_report）

### 定律三：注册审查定律（Registration Review Law）
> 任何新 cron 或周期性任务必须经过「三定律审查」才能注册。

**审查流程**：
1. **提案**：填写 `docs/automation-task-proposal-YYYYMMDD.md`
2. **蓝军审查**：专门的对抗性角色检查该任务是否会导致仪式感幻觉
3. **试运行**：最多试运行 2 个周期
4. **转正**：试运行后评估「触发命中率」和「行动转化率」，达标后方可注册到 `cron/jobs.json`

**审查必答题**：
- 该任务的跳过条件是什么？
- 过去 7 天内，如果不运行该任务，会有什么损失？
- 该任务是否只是为了让某份清单"看起来更完整"？

## 四、执行标准内化

### 4.1 代码层面
所有自动化脚本入口必须包含：
```python
if __name__ == "__main__":
    should, reason = should_run()
    if not should:
        print(f"[静默跳过] {reason}")
        exit(0)
    # 继续执行...
```

### 4.2 文档层面
- `cron/jobs.json` 中每个任务必须附带 `docs/` 下的说明文档
- 文档中必须明确写出触发条件和跳过条件

### 4.3 审查层面
- 每月第一个周日由蓝军执行「仪式感幻觉扫描」，检查所有 cron 任务
- 连续两个周期触发命中率为 0 的任务，进入「待淘汰观察期」
- 连续四个周期无行动转化，强制下线

## 五、责任与追责

- **谁注册，谁负责**：提案人对该任务的长期价值负责
- **蓝军一票否决**：任何新任务若被蓝军判定为"仪式感大于实质"，不得注册
- **诚实审计**：自动化任务纳入每月诚实审计范围
