# 知识入库全闭环机制 V1.0

> **生效日期**: 2026-04-12  
> **机制名称**: 知识入库全闭环 (Knowledge Ingestion & Assimilation Loop, KIA-Loop)  
> **责任人**: 满意姐（主执行）+ 蓝军 Skeptor-7（监督审计）  
> **审批**: Egbertie

---

## 一、机制目的

将「用户上传文档/图片 → 最终形成可战斗的洞察与资产」的全过程标准化，消除每次任务启动时的口头交代成本，确保：
- **不遗漏**：每份文档必经完整动线
- **不重复**：同类文档只做一次深度洞察
- **不躺尸**：所有产出必须通过「创始人 5 分钟可用性检验」
- **可追溯**：每一步都有文件落盘、Git 锁定、状态标记

---

## 二、触发条件

只要用户提供以下任意一种输入，自动触发 KIA-Loop：

| 输入类型 | 示例 |
|----------|------|
| PDF / DOCX / PPT / EPUB 等文档 | "帮我看一下这个 PDF" |
| 图片 / 截图 / 扫描件 | "把这张图里的内容整理一下" |
| 网页链接 / 文章 URL | "分析这篇文章" |
| 公众号文章 / 微信推文 | "这篇推文值得入库吗？" |
| 压缩包 / 批量文件 | "这一批资料帮我处理" |
| Im-msg 中的文件引用 | 用户引用或上传的聊天文件 |

**用户只需说三个字**：「知识入库」或「走闭环」，即代表默认授权执行完整流程。

---

## 三、标准流程（七步闭环）

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  ① 接收清点  │ → │  ② 轻量提取  │ → │  ③ 查重去冗  │ → │  ④ 深度洞察  │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
                                                          ↓
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  ⑦ 归档锁定  │ ← │  ⑥ 血液化   │ ← │  ⑤ 内化映射  │ ← │  ④ 深度洞察  │
│  + Git 快照  │    │  + 任务清单  │    │  + 机制建议  │    │  + 核心摘要  │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
```

---

### 步骤 ① 接收清点（Ingest）

**动作**：
1. 确认上传文件是否完整、可读取
2. 记录文件元信息：文件名、大小、页数/分辨率、上传时间、来源
3. 如遇下载失败（http_429 等），立即尝试替代来源；若仍失败，标记为 `pending_retry` 并报告

**输出**：
- 本地副本保存到标准路径（默认：`/root/.openclaw/workspace/.kimi/downloads/` 或指定工作目录）
- 生成 ` ingest-log-YYYY-MM-DD-HHMM.md `（可选，批量时必写）

---

### 步骤 ② 轻量提取（Extract）

**动作**：
1. **文档**：优先使用本地 `pypdf` / `fitz` / `python-docx` 提取文本
2. **图片**：优先使用本地 OCR（如已安装 `pytesseract` / `paddleocr`）或调用 ima-ge 描述工具
3. **网页**：使用 `kimi_fetch` 或 `web_fetch` 提取正文
4. **公众号**：优先使用 `readgzh` API（确保额度充足）， fallback 到 `kimi_fetch`

**原则**：免费优先、本地优先、避免重复调用高成本 API。

**输出**：
- 原始文本文件：`/tmp/提取_{原始文件名}.txt`
- 提取质量自检：页数/字数是否匹配、是否有乱码/缺页

---

### 步骤 ③ 查重去冗（Deduplicate）

**动作**：
1. 搜索知识库中是否已有同类文档或相似内容
2. 检查路径：`A-manyige/素材库/`、`A-manyige/汇报/专项报告/`、`memory/archive/`
3. 如果发现已处理过：
   - **轻量版**：直接引用已有洞察，更新版本标记，不做重复深度分析
   - **新版/修订版**：只做 diff 分析，标注新增内容

**输出**：
- 查重结论一句话："新文档 / 已有轻量版本 / 已有完整版本"
- 决策：继续完整流程 或 跳转轻量补充

---

### 步骤 ④ 深度洞察（Insight）

**动作**：
1. 快速浏览结构（目录、章节、图表、核心论点）
2. 提取 3-5 个核心洞察（不是摘要，是判断）
3. 标注可直接引用的数据、案例、方法论
4. 如触及新领域，调用 thinking-mentor / afrexai-strategic-thinking 做交叉校验

**输出**：
- 子报告：`{主题}-深度洞察-V1.0.md`
- 核心摘要卡片（300 字以内，可直接转发/引用）

---

### 步骤 ⑤ 内化映射（Assimilate）

**动作**：
1. 将外部知识映射到满意解研究所的已有框架中：
   - 五路图腾对应哪个维度？
   - 12 类型冲突案例中是否新增场景？
   - SKU-A/SKU-B/SKU-C 的哪个交付物可以吸收？
2. 提出「军转民」迁移建议（如果适用）
3. 如识别出可机制化的流程，写入 `docs/` 或更新 SKILL.md

**输出**：
- 血液化映射表（本书观点 → 我方观点 → 对应产品/工具）
- 机制化建议清单（如有）

---

### 步骤 ⑥ 血液化 + 任务清单（Weaponize）

**动作**：
1. 产出「可直接战斗的弹药」：
   - 话术模板（可直接对客户说）
   - 案例补充建议（可加入案例库）
   - 工具/交付物升级点（可修改 SKU-A/B 模板）
2. 生成后续跟进任务清单（Task List），写入 `docs/TASK_MASTER.md` 或当日报表
3. 进行「创始人 5 分钟可用性检验」

**输出**：
- 血液化报告：`{主题}-血液化映射-V1.0.md`
- 任务清单：`KIA-Tasks-YYYY-MM-DD.md`

---

### 步骤 ⑦ 归档锁定 + Git 快照（Archive）

**动作**：
1. 将所有产出移动到标准归档路径：
   - 当日报告 → `A-manyige/对话/YYYY-MM-DD/`
   - 专项报告 → `A-manyige/汇报/专项报告/`
   - 素材/原始提取 → `A-manyige/素材库/{主题}/`
2. 执行 `git add + commit`，commit message 包含 `KIA-Loop` 和关键词
3. 更新 `MEMORY.md` 指针

**输出**：
- Git commit hash
- 归档清单确认

## 五、双经济约束

| 约束 | 规则 |
|------|------|
| **Token 经济学** | 优先本地提取（pypdf/fitz/python-docx），避免全量复制到对话上下文。提取后只做轻量扫描，深度分析聚焦在 20% 核心章节。 |
| **效益经济学** | 不产出不进入弹药库的报告。每份洞察必须回答：创始人 5 分钟内能看懂并用上吗？ |

---

## 六、诚实执行声明

本机制一旦生效，满意姐承诺：
- **不跳步**：不因时间紧而跳过查重或血液化
- **不造假**：如某一步未真正完成，明确标记为 `pending` 或 `partial`
- **不向内集邮**：不为了闭环数量而生硬制造文档
- **看见即行动**：用户上传文件后，0.5 秒内启动 KIA-Loop，无需再次口头确认
