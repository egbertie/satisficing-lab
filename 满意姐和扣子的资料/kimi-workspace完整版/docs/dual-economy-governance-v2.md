## 一、Token 周期积分赛机制（2026-04-10 新增）

### 1.1 机制定义

> **"一个 Token 周期做一次积分比赛，周期初期做上一周期的，中间的活，大家都记着就好。"**  
> ——Egbertie, 2026-04-10

**周期节拍**（以 Token 周度周期为单位）：
- **周期起点**：每周三 12:00
- **积分赛时间**：周期初期（周三 12:00 后第一个工作时段，通常为周四上午）
- **周期中**：周一至周三上午为执行期，週三下午至週四上午为清算期

### 1.2 两阶段工作法

| 阶段 | 时间 | 行为规则 | 产出要求 |
|------|------|----------|----------|
| **执行期** | 周期中（周三 12:00 → 下周三 11:59） | 只记轻量日志，不强制每事必成文档 | `memory/YYYY-MM-DD.md` 追加、`TASK_MASTER.md` 进度标记、弹幕式短记录 |
| **清算期** | 周期初（下周三 12:00 后首个工作时段） | 统一盘点、积分、评比、把散落任务炼成闭环文档 | 周报/积分赛报告、决策索引更新、未完成项升维或丢弃 |

### 1.3 "记着就好"的操作标准

**执行期中，以下情况只记不做文档**：
- 尚未完成的情报搜索（只记 query 和初步结论）
- 中途被打断的分析思路（只记摘要和待验证假设）
- 用户口头确认但未固化的决策（只记决策内容和 timestamp）
- 探索性子代理尝试（只记启动参数和初步结果）

**执行期中，以下情况仍须即时闭环**：
- P0 级代码/脚本（影响系统生死，必须立即提交 Git）
- 用户明确指令"写进文件"的协议/规则（血液化要求）
- 需要外部发送的消息/邮件（时效性约束）
- 磁盘危机、安全漏洞等重大告警（自动触发，不容等待）

## 二、双经济守门员（已机制化）

**脚本**: `scripts/dual-economy-guard.py`

五级策略:
- **normal** → 全部放行
- **turbo** → turbo_focus（放行主线高耗任务，阻断分散注意力的任务）
- **hibernating** → 拦截 expensive 任务
- **silent** → 拦截所有非保活任务
- **deep-silent** → 仅放行保活任务

**强制要求**：所有高消耗 cron 在 payload 中先调用 `dual-economy-guard.py`；返回 DENY 则任务直接退出。

## 三、系统健康红线（已机制化）

**脚本**: `scripts/system-guardian.py`

| 指标 | 警戒线 | 危机线 | 自动动作 |
|------|--------|--------|----------|
| 磁盘使用率 | 75% | 85% | 自动运行 disk-guardian |
| 内存使用量 | 1024MB | 1536MB | 告警，建议重启 |
| 错误率 | 0.1% | 1% | 自动告警 |
| Token 消耗 | 70% | 90% | 自动降级运行模式 |

**自动触发**: `system-guardian.py` 每日 06:17 自动巡检。

## 四、费用红线（2026-04-10 永久生效）

> **所有可能产生费用的操作，必须逐项经 Egbertie 人工独立确认。**

- 当前红线：**免费优先**
- **禁止自行执行**任何付费操作，包括但不限于：付费 API 调用、高级功能开通/订阅、增值服务购买、超出免费额度的批量操作
- **执行标准**：在行动前明确告知可能产生的费用项目，等待用户逐项确认后再执行
- **例外**：明确已知免费的读操作（如搜索、列表查询、信息获取）可自主执行
