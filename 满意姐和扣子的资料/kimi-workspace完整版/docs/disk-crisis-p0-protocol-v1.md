# 磁盘危机 P0 处理协议 V1.0

> **协议状态**：紧急生效  
> **生效时间**：2026-04-10  
> **触发背景**：当日发生第二次因磁盘满导致的系统崩溃（git commit 失败：`Out of diskspace`），用户明确要求作为 P0 风险彻底解决、绝对闭环。

---

## 一、危机定义

**P0 磁盘危机**：当根分区磁盘使用率 ≥ 85% 时，系统随时可能因无法写入而发生级联故障：
- git commit 失败 → 代码资产无法提交
- 文件写入失败 → memory/报告丢失
- 系统服务崩溃 → OpenClaw 不可用
- **最坏结果：全部工作成果报废**

**本次事件（2026-04-10）根因**：
1. `.git/` 目录膨胀至 6.5G（大量大文件提交积累）
2. `/tmp/` 下堆积 2.5G+ 历史备份未清理
3. git commit 中断留下 **3.8G 僵尸 `tmp_pack_*` 文件**
4. 缺乏**事前拦截机制**：基线检查虽能发现，但无自动清理动作

## 二、三色警戒线

| 级别 | 使用率 | 状态 | AI 行为 | 用户通知 |
|------|:------:|:----:|---------|----------|
| 🟢 健康 | < 75% | 正常 | 轻量监控，每周清理一次 | 不通知 |
| 🟡 警告 | 75% ~ 84% | 紧张 | 每次 turn 前自动运行 `disk-guardian.py`，并在回复开头标注 | 简要提醒 |
| 🔴 危险 | ≥ 85% | P0 危机 | **立即停止所有非紧急写入**，强制清理，未完成前禁止生成大文件 | 紧急告警 |
| ⚫ 瘫痪 | ≥ 93% | 系统崩溃边缘 | 进入只读模式，仅保留查询/沟通，不做任何文件修改 | 立即告警 |

## 三、自动防御机制（已部署）

### 1. 磁盘守护者脚本
- **路径**：`scripts/disk-guardian.py`
- **功能**：
  - 自动清理 `/tmp/` 历史备份、`backups/` 过期副本、`.kimi/downloads/` 大文件
  - 自动删除 git `tmp_pack_*` 僵尸文件
  - 磁盘超红线时自动触发 `git gc`
  - 保留策略：`backups/` 只保留最近 **3** 个每日备份
- **运行方式**：
  - 每周日 03:17 通过 cron 自动执行
  - 每次基线检查失败时立即触发
  - 每次生成 >50MB 文件前手动触发

### 2. 基线检查升级
- `disk_usage_percent` 基线上限从 85% 调为 **75%**（提前干预）
- 一旦基线检查触发 `disk_usage` 警告，`baseline-checker-runner.py` 自动调用 `disk-guardian.py`

### 3. 备份策略收紧
- **本地备份**：`scripts/daily_local_backup.sh` 保留策略从 "7 天" 压缩为 "3 天"
- **云端备份**：大备份（>500MB）不再本地双份留存，生成后**立即分卷上传飞书**，上传成功后删除本地 `backups/` 中的原始 tar（保留 `essential-snapshot/` 的元数据索引）
- **临时分卷**：飞书分卷上传完成后，`.part-*` 碎片必须立即删除

### 4. Git 体积控制
- 每月第一周周日自动运行 `git gc --aggressive`
- 禁止将 >20MB 的单个二进制文件直接提交到 git（应放入 `backups/` 或飞书 Drive）
- `.gitignore` 已生效的规则持续维护：`*.tar.gz`、`*.part-*`、`tmp/` 等不进入 git

## 四、人工检查清单（每次生成大文件前必须执行）

```bash
# 1. 检查磁盘
python3 /root/.openclaw/workspace/scripts/disk-guardian.py

# 2. 检查 git 状态
cd /root/.openclaw/workspace && git status

# 3. 若磁盘 > 80%，先手动运行
df -h /
```

**谁负责**：每次即将执行批量产出（如 84 份文档）、大备份、大提取任务前，AI 必须主动运行 checklist。

## 六、责任与追责

- **如果磁盘再次因可预防原因（未及时清理 / 未运行 guardian / 基线告警后未处理）而爆仓，导致系统崩溃**：
  - 标记为 `P0-磁盘危机复发`
  - 蓝军必须在 5 分钟内提交书面根因分析
  - 满意姐必须检查是否遗漏了生成前的主动询问义务
  - 该事件永久写入 `memory/disk-crisis-incidents.md`
