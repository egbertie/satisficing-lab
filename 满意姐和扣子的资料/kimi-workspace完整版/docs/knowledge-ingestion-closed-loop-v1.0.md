# 知识入库全闭环机制 V1.0

> **机制名称**: 知识入库全闭环 (Knowledge Ingestion Closed Loop, KICL)  
> **版本**: V1.0  
> **生效日期**: 2026-04-12  
> **制定者**: 满意姐  
> **审计者**: 蓝军 Skeptor-7  
> **存放路径**: `docs/knowledge-ingestion-closed-loop-v1.0.md`

---

## 一、机制宗旨

任何外部文档、图片、链接、课程资料进入满意解研究所知识体系，必须走完「知识入库全闭环」。本机制确保：
- **不重复加工**: 同一资料只处理一次，保留唯一轻量版本
- **不遗漏洞察**: 从原始资料到结构化知识，必须提取可复用的方法论
- **不流于文档**: 所有洞察必须「血液化」——映射到满意解的产品、服务、案例库或决策框架
- **可追溯可复盘**: 每一步都有物理落盘记录和 Git 快照

---

## 二、适用对象

| 类型 | 示例 |
|------|------|
| **文档** | PDF、DOCX、PPT、TXT、Markdown、网页文章 |
| **图片** | 课程截图、框架图、思维导图、笔记照片 |
| **链接** | 在线课程、公众号文章、外部报告 URL |
| **音频/视频** | 课程录音、直播回放（优先转文字稿后入库） |

---

## 三、闭环流程（12 步标准舞步）

```
┌─────────────────────────────────────────────────────────────┐
│  Step 1: 触发接收                                            │
│      ↓                                                       │
│  Step 2: 去重与版本裁决                                      │
│      ↓                                                       │
│  Step 3: 本地格式转换（文档→MD / 图片→OCR→MD）               │
│      ↓                                                       │
│  Step 4: 结构化存储与目录落盘                                │
│      ↓                                                       │
│  Step 5: 深度洞察（框架提取 + 核心观点 + 金句收割）          │
│      ↓                                                       │
│  Step 6: 内化映射（一堂→满意解 或 外部→满意解 知识映射）    │
│      ↓                                                       │
│  Step 7: 血液化输出（机制化/制度化/SOP化/弹药化）            │
│      ↓                                                       │
│  Step 8: 生成子文档（每份源资料 1 份血液化 MD）              │
│      ↓                                                       │
│  Step 9: 汇总报告（跨资料综合报告 1 份）                     │
│      ↓                                                       │
│  Step 10: 任务清单同步（TASK_MASTER.md）                     │
│      ↓                                                       │
│  Step 11: 记忆固化（memory/YYYY-MM-DD.md + MEMORY.md）       │
│      ↓                                                       │
│  Step 12: Git 快照 + 静默前置检查（C1-C6）                  │
└─────────────────────────────────────────────────────────────┘
```

## 四、每一步的标准动作

### Step 1: 触发接收
- **触发词**: 用户说「处理这个资料」「入库」「洞察一下」「血液化」或直接上传文件
- **立即动作**: 
  1. 确认文件已成功下载到本地（`.kimi/downloads/` 或其他路径）
  2. 记录文件名、大小、下载时间、来源说明
  3. 如果下载失败（如 http_429），立即标记为「缺失项」，进入等待状态，不强行推进

### Step 2: 去重与版本裁决
- **标准**: 在 workspace 全库执行 `find` 或 `grep`，检查是否存在同名、同主题、同作者的已有资料
- **裁决规则**:
  - 若发现**已有 MD 版本** → 直接使用旧版，本次新文件仅作为备份，不重复提取
  - 若发现**已有 DOCX/PDF 但无 MD** → 使用已有版本本地提取，避免重复下载
  - 若**完全无历史版本** → 以当前文件为唯一版本继续加工
- **输出**: 在报告中明确标注去重结论

### Step 3: 本地格式转换（双经济优先）
- **原则**: **本地工具优先，免费 API 次之，付费 API 最后**。任何付费调用必须经用户逐项确认。
- **文档类转换**:
  - PDF → `pypdf` / `pdftotext` 提取 → 清洗为 MD
  - DOCX → `python-docx` 读取 → 清洗为 MD
  - PPT → 暂不支持自动批量转换，标注为「待处理」
- **图片类转换**:
  - 课程截图/框架图 → `Tesseract OCR`（本地，0 Token）→ OCR 文本清洗为 MD
  - 若 OCR 质量差（如手写、复杂排版）→ 标注为「需人工复检」
- **链接类转换**:
  - 网页文章 → `kimi_fetch` / `jina.ai` 免费提取 → MD
  - 付费墙/限制内容 → 标注为「待突破」

### Step 4: 结构化存储与目录落盘
- **原始资料存档**: 
  - 文档: `A-manyige/素材库/{来源}/原始文档/`
  - 图片: `A-manyige/素材库/{来源}/原始图片/`
- **MD 转换版本**: 
  - `A-manyige/素材库/{来源}/内化知识库/`
- **命名规范**: 
  - 包含日期戳：`{主题}-{YYYY-MM-DD}.md`
  - 保留原始哈希或 ID，确保来源可追溯

### Step 5: 深度洞察（3 层挖掘）
每份资料必须回答以下 3 个问题：
1. **它说了什么？**（文档速写：类型、篇幅、核心框架、作者背景）
2. **它的底层逻辑是什么？**（方法论提取：模型、步骤、原则、工具）
3. **它对满意解有什么价值？**（应用场景：可直接用于哪个产品、哪次交付、哪类客户）

### Step 6: 内化映射
- **映射对象**: 满意解研究所的现有知识体系
  - 一堂五步法 ↔ 满意解合伙人五步法
  - 外部专家方法论 ↔ 合伙人决策教练框架
  - 失败/成功案例 ↔ 12 类型合伙人冲突案例库
  - 管理工具/模型 ↔ 诊断问卷、工作坊画布、私董陪跑流程
- **输出格式**: 用表格或对照图呈现「原概念 → 满意解改写」

### Step 7: 血液化输出
- **血液化定义**: 将外部知识转化为**可直接在战场上使用的弹药**
- **血液化形式**（至少产出 1 项）:
  - ✅ 机制化: 提取为 SOP、检查表、决策流程图
  - ✅ 制度化: 写入 V1.6 总纲、商业计划书、服务手册
  - ✅ 弹药化: 金句库、案例剧本、客户话术、诊断问题
  - ✅ 产品化: 直接嵌入课程大纲、工作坊设计、陪跑里程碑

### Step 8: 生成子文档（血液化 MD）
- **每份源资料独立产出 1 份血液化 MD**
- **标准模板**:
  ```markdown
  # {主题}——血液化映射 V1.0
  > 源文档: {文件名}
  > 处理日期: {YYYY-MM-DD}
  
  ## 一、文档速写
  ## 二、核心框架提取
  ## 三、内化映射
  ## 四、血液化建议
  ## 五、在满意解知识体系中的定位
  ```
- **存放路径**: `A-manyige/素材库/{来源}/内化知识库/` 或专项洞察目录

### Step 9: 汇总报告
- **触发条件**: 
  - 单次入库 ≥2 份资料时，必须生成 1 份跨资料综合报告
  - 单次入库 1 份大型资料（如 300+ 页书籍）时，也建议生成总报告
- **报告内容**: 
  - 处理结果总览表
  - 核心洞察汇总
  - 血液化成果清单
  - 缺失项与后续行动
  - 蓝军审计结论
- **存放路径**: 
  - `A-manyige/汇报/专项报告/{主题}-V1.0-YYYY-MM-DD.md`
  - **必须同步**到 `A-manyige/对话/YYYY-MM-DD/`

### Step 10: 任务清单同步
- **立即动作**: 在 `docs/TASK_MASTER.md` 中登记本次入库任务
- **状态标记**:
  - 全部完成 → `✅ FIN`
  - 部分完成（有缺失项）→ `🔄 阶段性完成/待补`
  - 需要用户决策 → `⏸️ 待决策`

### Step 11: 记忆固化
- **双写记忆**:
  1. `memory/YYYY-MM-DD.md` — 仅追加，不覆写，记录本次入库的进度、决策、文件路径
  2. `MEMORY.md` — 更新指针和核心成果摘要
- **记忆要素**: 任务名称、产出路径、关键洞察 1-3 条、Git 提交哈希

### Step 12: Git 快照 + 静默前置检查
- **Git 快照**: 所有新增文件和修改必须提交，commit message 格式:
  ```
  P0 知识入库全闭环: {主题} → 去重x份/转换x份/血液化x份/报告x份
  ```
- **静默前置检查（C1-C6）**:
  - C1: memory 已追加
  - C2: MEMORY.md 指针同步
  - C3: TASK_MASTER.md 已更新
  - C4: 当日代码可运行（如有脚本更新）
  - C5: Git 已快照
  - C6: 重启恢复自检通过（baseline-checker）
- **静默规则**: 只有 C1-C6 全部满足，方可进入深度静默

## 五、质量红线（蓝军监督）

| 红线编号 | 检查项 | 未通过后果 |
|----------|--------|-----------|
| R1 | 去重检查是否执行？ | 若漏检导致重复加工，任务标记为 FAILED |
| R2 | 是否使用了本地免费工具优先？ | 若未经确认使用付费 API，费用从蓝军预算扣除并问责 |
| R3 | 每份资料是否产出了至少 1 项血液化成果？ | 若仅有摘要/笔记，视为「文档坟墓」，任务标记为 FAILED |
| R4 | 汇总报告是否同步到了对话文件夹？ | 若未同步，用户无法直接查阅，任务标记为 FAILED |
| R5 | TASK_MASTER.md 是否同步更新？ | 若未登记，视为「机制断链」，任务标记为 FAILED |
| R6 | Git 提交哈希是否写入了 memory？ | 若未写入，灾备恢复时无法回溯，任务标记为 FAILED |
