## 高维度需求识别

### 需求1: 决策工作流引擎 (System Orchestration)

**问题场景**:
```
用户: "我在考虑一个合伙人候选人，帮我分析一下"

当前: 用户需要知道要调用哪些Skill:
- partner-matching-engine?
- case-repository查相似案例?
- totem-avatar让司马贺分析?
- theory-miner查满意解理论?
- 全部都要？顺序呢？
```

**期望**:
```
用户: "帮我分析这个合伙人候选人"
系统: 自动触发完整工作流
  1. 采集候选人背景 → project-intelligence
  2. 查相似案例 → case-repository
  3. 执行匹配算法 → partner-matching-engine
  4. 五图腾联合分析 → totem-avatar
  5. 生成综合报告 → 自动汇总
```

**外求建议**: **是**，需外求设计决策工作流引擎

---

### 需求2: 知识图谱与本体论 (Knowledge Graph)

**问题场景**:
- 案例、理论、专家、项目 之间是割裂的
- CASE-001是"AI芯片项目"，但partner-matching-engine不知道
- theory-miner提取的"满意解"理论与case-repository的案例没有关联

**期望**:
```
知识图谱节点:
- 案例: CASE-001 (AI芯片, 成功)
- 理论: SatisficingTheory (满意解)
- 专家: 司马贺 (满意解理论)
- 项目: 某AI芯片初创 (project-intelligence采集)

关系:
- CASE-001 → 应用了 → SatisficingTheory
- CASE-001 → 属于 → AI芯片行业
- 司马贺 → 是 → SatisficingTheory 的提出者
- 某AI芯片项目 → 类似 → CASE-001
```

**外求建议**: **是**，需外求设计知识图谱架构

---

### 需求3: 五图腾协同决策协议 (Totem Collaboration)

**问题场景**:
- 当前每个图腾独立响应
- 用户需要手动切换 `[激活司马贺]` → `[激活孔子]` → ...
- 没有五图腾共同会诊的机制

**期望**:
```
用户: "这个合伙人选择，五路图腾怎么看？"

系统: 
【五图腾联合会诊】
├─ 司马贺: 从满意解角度分析阈值设定...
├─ 刘禹锡: 从德馨角度评估根基...
├─ 观自在: 从洞察角度指出盲点...
├─ 孔子: 从五常角度评估伦理...
├─ 慧能: 从顿悟角度给出突破...
└─ 【综合结论】: 五图腾共识与分歧点
```

**外求建议**: **是**，需外求设计五图腾协同协议

## 立即建议的外求需求

### 建议1: 决策工作流引擎 (Decision Workflow Engine)

**范围**:
- 定义常见决策场景（合伙人选择、投资评估、战略决策等）
- 每个场景的标准工作流程（调用哪些Skill，顺序如何）
- 工作流编排DSL或配置
- 自动化执行引擎

**交付物**:
- `workflows/partner_selection.yaml` - 合伙人选择工作流
- `workflows/investment_evaluation.yaml` - 投资评估工作流
- `workflow_engine.py` - 工作流引擎
- 使用文档

---

### 建议2: 五图腾协同决策协议 (Totem Consensus Protocol)

**范围**:
- 五图腾如何对同一问题各自分析
- 如何汇总五方观点（共识/分歧/优先级）
- 冲突解决机制（观点不一致时如何处理）
- 协同输出格式

**交付物**:
- `consensus_protocol.md` - 协议规范
- `totem_council.py` - 五图腾议会实现
- 协同决策示例

---

### 建议3: 知识图谱架构 (Knowledge Graph Schema)

**范围**:
- 本体定义（案例、理论、专家、项目、概念等实体类型）
- 关系定义（应用、属于、提出、关联等）
- 图数据库存储方案（Neo4j或轻量级替代）
- 与现有Skill的集成接口

**交付物**:
- `knowledge_graph/schema.md` - 本体定义
- `knowledge_graph/models.py` - 数据模型
- 集成示例代码

## 结论

**从单个Skill建设，升级到系统整体架构设计。**

当前6个P0 Skill只是**点**，需要：
1. **线**: 工作流引擎（把点连成线）
2. **面**: 五图腾协同（核心差异化）
3. **体**: 知识图谱（长期竞争力）

**立即建议外求**: 
1. 决策工作流引擎 (P0)
2. 五图腾协同协议 (P0)
3. 知识图谱架构 (P1)

这样满意解研究所才能从"一堆工具"升级为"智能决策系统"。
