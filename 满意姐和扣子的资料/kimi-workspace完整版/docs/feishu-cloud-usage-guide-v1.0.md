# 飞书与企微云端资产使用指南 V1.0

> **生效日期**: 2026-04-10  
003e **制定者**: 蓝军 Skeptor-7 + 满意姐（响应 Egbertie 指令）  
003e **定位**: 让飞书和企微成为满意解研究所的"云端驾驶舱"，实现"大文件上云、AI 读取、本地轻量"的工作模式  

---

## 一、核心战略：云端驾驶舱 + 本地轻量

**用户的真实需求**：
1. 有价值的文档统一放在**飞书 Drive** 和**企微文档**，方便随时查看
2. 利用**飞书多维表格**做驾驶舱，数据可视化，交互更方便
3. **大文件直接上传飞书**，AI 从飞书读取，本地只保留轻量 Markdown 索引
4. 减少手动传文件的碎片时间，提升整体工作流效率

**工作目标**：
> **本地 workspace 保留：代码、脚本、当前活跃的小文件、轻量 MD 索引**  
> **飞书云端承载：大文件、历史备份、报告文档、多维表格驾驶舱、可供 AI 读取的源文件**  
> **企微云端承载：摘要索引、通知备份、WeCom 生态下的共享文档**

## 二、飞书 Drive 使用规范

建议的子文件夹规划：

```

├── 📁 04-品牌内容/           # 公众号文章、演讲稿、寻根之旅素材
├── 📁 05-数据驾驶舱/         # 多维表格、仪表盘、关键指标跟踪
```

### 2.2 文件上传规则

#### 单文件上限
- **飞书 Drive upload API 单文件上限：20MB**
- 超过 20MB 的文件必须先在本地分卷（`split -b 20m`），生成 `.part-000`、`.part-001` 等分卷后再上传

#### 分卷文件的恢复方法

**场景**：你下载了 36 个分卷文件到本地，想要恢复原始 `.tar.gz` 文件

**步骤**：
```bash
# 1. 进入存放分卷的文件夹
cd /path/to/downloaded/parts

# 2. 按顺序合并分卷
cat workspace-backup-20260410-030014.tar.gz.part-* > workspace-backup-20260410-030014.tar.gz

# 3. 验证 SHA256（应与原始备份一致）
sha256sum workspace-backup-20260410-030014.tar.gz
# 原始值：09a565376201038b3f9a1c4eb241d2b7b8821a32a6d0230a23b9b6eed189bc03

# 4. 解压验证
tar -tzf workspace-backup-20260410-030014.tar.gz | head

# 5. 解压到目标目录
tar -xzf workspace-backup-20260410-030014.tar.gz -C /path/to/restore
```

**在飞书 Drive 中查看时**：
- 36 个分卷会显示为 36 个独立文件
- 文件名保持原始分卷名（如 `workspace-backup-20260410-030014.tar.gz.part-000`）
- **恢复时必须全部下载并按顺序合并**，缺少任何一个分卷都无法恢复

### 2.3 大文件"放飞书、AI 读取"模式

**操作流程**：

```
【用户侧】
1. 用户将大文件（docx/pdf/数据集）上传到飞书 Drive 的 "07-待读取大文件/"
2. 日常查看和批注直接在飞书完成

【AI 侧】
1. AI 通过 feishu_drive_file 下载该文件到本地 /tmp/
2. AI 读取并分析文件内容
3. AI 只将分析结果（轻量 Markdown）保留在本地 workspace
4. 原始大文件分析完成后从 /tmp/ 删除
```

**示例**：
- 用户上传 `影响行为决策的思维逻辑_套装12册_.docx`（14MB）到飞书 Drive
- AI 下载后逐册提取内容
- AI 在本地只保留提取后的 Markdown 摘要，原始 docx 不保留在本地 workspace

**优势**：
- 本地 workspace 体积可控（当前已从 710MB 清理到 <450MB）
- 用户随时随地通过飞书查看原始文件
- AI 读取时仍然可以拿到完整内容
- 减少用户和 AI 之间手动传文件的次数

## 三、飞书多维表格驾驶舱

### 3.1 驾驶舱定位

利用飞书多维表格（Bitable）建立满意解研究所的轻量级数据驾驶舱，核心场景：

| 驾驶舱名称 | 用途 | 关键字段 |
|------------|------|----------|
| **客户旅程驾驶舱** | 追踪特邀客户从接触到转化的全流程 | 姓名、公司、冲突类型、服务 SKU、当前阶段、下次跟进时间 |
| **案例库驾驶舱** | 管理 12 种冲突类型的案例素材 | 冲突类型、客户行业、决策结果、五路图腾映射、可用状态 |
| **项目进度驾驶舱** | 追踪 4-6 月关键任务 | 任务名称、负责人、截止日期、完成状态、阻塞项 |
| **资源消耗驾驶舱** | 追踪 Token 使用、子代理状态、双经济审计结果 | 周期、状态灯颜色、惊险时刻数、优化措施 |
| **专家会诊驾驶舱** | 管理 7 专家数字替身的触发记录 | 专家名称、会诊主题、输出摘要、一致性评分 |

### 3.2 AI 与多维表格的交互

AI 可以通过 `feishu_bitable_app_table_record` 等工具直接：
- **读取**多维表格中的数据
- **新增/更新**记录（如新增一个客户、更新任务状态）
- **筛选**特定条件的记录（如"下周待跟进的客户有哪些"）

**操作示例**：
```
用户："下周有哪些客户要跟进？"
AI：→ 查询飞书多维表格 "客户旅程驾驶舱"
    → 筛选"下次跟进时间"在本周内的记录
    → 返回：客户姓名 + 公司 + 当前阶段 + 建议跟进话术
```

**建议**：
- 将高频查询的驾驶舱 token 和 table_id 记录到 `TOOLS.md`
- 复杂的数据分析（如趋势图、统计汇总）优先在飞书多维表格视图中完成
- AI 负责数据的录入、更新和轻量查询，不负责复杂的可视化配置

## 四、企微备份与摘要策略

### 4.1 企微的能力边界

**企微现有 MCP 能力**：
- ✅ 发送文本消息
- ✅ 创建/编辑文档（doc_type=3）
- ✅ 创建/查询日程、会议
- ✅ 查询待办列表
- ❌ **不支持直接上传文件**（msg/doc 品类均无文件上传接口）

### 4.2 企微作为"摘要+索引"备份层

由于企微无法直接传文件，采用以下策略：

| 内容类型 | 本地 | 飞书 | 企微 |
|----------|------|------|------|
| 大文件/完整报告 | 轻量 MD 索引 | ✅ 完整文件 | ❌ 不支持 |
| 报告摘要（< 2000 字） | ✅ MD | ✅ 可选同步 | ✅ 文本消息/文档 |
| 任务清单/进度更新 | ✅ MD | ✅ 多维表格 | ✅ 文本消息 |
| 备份索引（分卷清单+恢复说明） | ✅ MD | ✅ 文件 | ✅ 文档 |
| 紧急通知（P0） | — | ✅ | ✅ 首选通道 |

### 4.3 每周摘要自动化

**每周日**，系统自动生成一份《满意解研究所周报摘要》，内容包括：
1. 本周完成的关键任务（3-5 条）
2. 下周重点事项（3 条）
3. 当前资源状态灯颜色
4. 需要用户决策/确认的待办（1-2 条）

**分发路径**：
- 本地：保存到 `A-manyige/汇报/周报/`
- 飞书：上传到 Drive 的 `02-研究报告/`
- 企微：以文本消息或文档形式发送（作为第二备份）

## 五、AI 读取飞书文件的完整流程

### 5.1 用户发起

用户可以在 Kimi 对话框中说：
- "飞书里有个文件帮我看一下"
- "读取我在飞书上传的《合伙人风险扫描报告》"
- "分析飞书 Drive 里 07-待读取大文件 下的那个 docx"

### 5.2 AI 执行步骤

```
Step 1: 询问或确认文件名/关键词
Step 2: 调用 feishu_drive_file search/list 定位文件
Step 3: 如果是 < 20MB 的单个文件 → 直接 download 到 /tmp/
        如果是分卷备份 → 提示用户"这是分卷备份，需要先合并才能读取具体内容"
Step 4: 读取文件内容（read/pdf/exec 等）
Step 5: 分析、总结、回答用户问题
Step 6: 如果需要保留结果 → 将轻量 Markdown 写入 A-manyige/ 或 workspace
Step 7: 清理 /tmp/ 中的原始大文件
```

### 5.3 费用红线提醒

- 飞书 Drive 的读/写/列文件操作：**免费**（已包含在 OpenClaw 授权内）
- 企微文档的读/写操作：**免费**（已包含在 WeCom 企业授权内）
- 任何涉及第三方付费 API 的读取操作（如高级 PDF 解析服务），**必须事先获得用户确认**

## 七、快速操作命令

### 7.1 列出飞书 Drive 文件夹内容

```bash
# 满意解研究所-同步
openclaw tool feishu_drive_file --action list --folder_token DNKFfMXLGlIEp7dE6sFcPYJFnih

# 满意解研究所
openclaw tool feishu_drive_file --action list --folder_token OAt2fwUw7lcJZcd26HtcPa6pnJO
```

### 7.2 下载飞书文件到本地

```bash
openclaw tool feishu_drive_file \
  --action download \
  --file_token YOUR_FILE_TOKEN \
  --type file \
  --output_path /tmp/target_filename.docx
```

### 7.3 本地分卷命令

```bash
# 将大文件分成 20MB/卷
cd /root/.openclaw/workspace/backups
split -d -a 3 -b 20m large-file.tar.gz large-file.tar.gz.part-

# 合并分卷
cat large-file.tar.gz.part-* > large-file-restored.tar.gz
```

## 八、蓝军的最后叮嘱

Egbertie，这份指南的核心就一句话：

> **让飞书成为你的文件仓库和驾驶舱，让本地 workspace 成为 AI 的轻量工作台，让企微成为你的摘要备份和紧急通道。**

三个不要：
1. **不要**把所有大文件都堆在本地 workspace — 它在膨胀，你的维护成本也在膨胀
2. **不要**期待企微能传大文件 — 它做不到，改用摘要/文档替代
3. **不要**让 AI 在没有索引的情况下乱翻飞书 Drive — 文件越多，越需要结构化目录

三个要：
1. **要**把高频查看的文档交给飞书多维表格驾驶舱 — 数据动起来，决策才快
2. **要**把大文件和备份交给飞书 Drive — 它免费、稳定、空间大
3. **要**让 AI 只保留"分析结果"在本地 — 原始大文件读完就删，轻装上阵

---

*云端驾驶舱，本地轻量脑。这是我们要的工作方式。*
