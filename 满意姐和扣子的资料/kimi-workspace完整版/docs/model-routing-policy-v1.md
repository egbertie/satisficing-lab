> **生效日期**：2026-04-10  
> **制定者**：蓝军 Skeptor-7  
> **监督者**：满意姐

---

## 一、为什么要路由

Anthropic 的 Claude Advisor Strategy 已经证明：**把小模型推在前面、大模型只在决策盲区出场**，可以降本 85% 而保留 90%+ 的性能。我们嘴上说着「双经济」，却还在用 k2.5 做格式整理和文件迁移——这是 Token 经济的漏洞。

本规则强制区分「执行层」与「顾问层」，让每一笔 Token 支出都过一道「 complexity 检票口」。

---

## 二、两层定义

### 2.1 执行层（Downgrade Allowed）
**特征**：目标明确、边界清晰、容错率低、不需要创造性推理。

**典型任务**：
- 文件格式转换（docx → md、md → pdf）
- 批量文件重命名、路径迁移、目录整理
- 简单摘要生成（内容已充分提供，只需压缩篇幅）
- 代码语法检查、模板填充、重复模式生成
- 日报/晨报的固定板块填充（已知数据 → 标准格式输出）
- 基线检查报告的可视化排版

**路由策略**：
1. **优先规则引擎/脚本**：能用 Python/shell/正则解决的，不用模型。
2. **次选轻量模型**：如果必须用模型，优先调低成本的模型档位（Kimi 轻量模式 / k2.5 的短输出模式）。
3. **Token 上限**：执行层任务单次调用不得超过 **5,000 tokens**；若超限，必须拆分为脚本化处理。

### 2.2 顾问层（Top-Tier Reserved）
**特征**：涉及战略判断、多变量权衡、创造性重构、高价值内容产出。

**典型任务**：
- 合伙人匹配决策框架设计
- 蓝军对抗性审计与市场洞察
- 复杂商业案例分析、竞争定位报告
- 客户诊断与定制化决策建议
- 高价值品牌内容（白皮书、总纲底稿）
- 多轮角色演练脚本与心理学映射

**路由策略**：
- 直接启用 k2.5 完整能力。
- 但在启动前必须填写「效益经济自评」：*这个产出是否能让创始人在 5 分钟内看懂并用上？*

## 三、快速决策矩阵

当你拿到一个新任务时，用下面 3 个问题在 10 秒内判定层级：

| 问题 | 若答案为「是」 | 路由结果 |
|------|---------------|----------|
| 这个任务有明确的标准答案或固定模板吗？ | 是 | **执行层** |
| 任务失败的成本仅限于"再跑一遍脚本"吗？ | 是 | **执行层** |
| 这个任务需要你对 Egbertie 的业务战场做新的判断吗？ | 是 | **顾问层** |

**兜底规则**：拿不准时，默认先按执行层处理；若输出质量不达标，再升级为顾问层。**禁止为了保险直接上顶级模型**。

---

## 四、硬性约束与红线

1. **禁止全量 k2.5 的批量任务清单**
   - 批量生成 84 份案例库时，必须拆分为：
     - 结构框架生成（顾问层，1 次）
     - 内容填充与格式化（执行层，批量子代理/规则化处理）
   - 不得对每个子文档都调用完整 k2.5 做从零创作。

2. **Heartbeat / 自动化任务强制降级**
   - 每日晨报、资产激活报告、基线报告生成——必须在 Prompt 中明确限制为「执行层模式」。
   - 除非当日检测到 P0 异常需要战略判断，否则 heartbeat 不唤醒顾问层。

3. **子代理启动前的检票动作**
   - 任何子代理 spawn 前，必须在 `subagent-registry.json` 中标注：
     - `expected_complexity`: execution / advisory
     - `model_tier`: light / standard / premium

4. **每周审计**
   - 每周日资源盘点时，检查 `memory/dual-economy-guard-log.json` 中是否有「执行层误用顶级模型」的标记。
