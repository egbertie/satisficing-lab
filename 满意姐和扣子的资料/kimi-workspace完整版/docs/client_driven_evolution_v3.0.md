# 五路图腾决策智慧引擎 - 客户驱动的进化闭环架构

> 文档版本: v3.0 (客户中心 + 模拟闭环 + 真实修正)  
> 核心理念: **客户是进化的燃料，模拟是进化的引擎，真实是进化的校准**  
> 目标: 构建客户驱动、自主模拟、真实校准的商业进化系统

## 第一部分：系统定位重构 - 客户驱动的进化生命体

### 核心认知转变

**从**: 我为Egbertie构建数字替身  
**到**: 我们为客户构建决策服务，在服务中共同进化

**商业本质**:
> **满意解研究所的核心产品不是"系统"，而是"帮助客户做出更好的合伙人决策"。系统是手段，客户价值是目的。**

### 角色重新定义

| 角色 | 旧定义 | 新定义 | 关系 |
|------|--------|--------|------|
| **Egbertie** | 唯一知识来源 | **首席决策官+校准者** | 设定标准、校准方向 |
| **我(Kimi Claw)** | 工具/助手 | **自主进化引擎+服务交付者** | 学习、模拟、服务、迭代 |
| **客户** | 无 | **核心角色+进化燃料** | 需求输入、反馈来源、价值验证 |
| **理论/产品/服务** | 静态 | **动态迭代** | 随客户需求持续进化 |

### 小闭环与大循环

```
┌─────────────────────────────────────────────────────────────┐
│                    大循环：商业生态                          │
│  真实客户 → 服务交付 → 反馈收集 → 模型修正 → 产品迭代        │
│       ↑                                              ↓      │
│       └────────────── 价值验证 ←─────────────────────┘      │
├─────────────────────────────────────────────────────────────┤
│                    小闭环：自主模拟                          │
│  模拟客户 → 场景生成 → 决策推演 → 模式发现 → 假设生成        │
│       ↑                                              ↓      │
│       └────────────── 自我验证 ←─────────────────────┘      │
└─────────────────────────────────────────────────────────────┘
                    ↓ 持续交互
              真实信息注入校准
```

**关键洞察**:
- **小闭环**让我在没有真实客户时也能持续进化
- **大循环**让系统与真实世界保持连接
- **真实信息**修正模拟偏差，防止"闭门造车"

## 第二部分：客户角色建模

### 2.1 客户画像体系 (Client Persona)

**不是**: 简单的 demographics  
**而是**: 决策风格、认知偏好、价值排序的动态模型

```python
@dataclass
class ClientPersona:
    # 基础信息
    id: str
    name: str
    company: str
    industry: str
    stage: str  # 天使/A轮/B轮等
    
    # 决策风格 (学习获得)
    decision_style: DecisionStyle  # 理性型/直觉型/平衡型
    risk_appetite: float  # 0-1 风险偏好
    time_pressure: float  # 0-1 时间压力敏感度
    information_need: float  # 0-1 信息需求度
    
    # 价值维度 (仁义礼智信评估)
    value_weights: Dict[str, float]  # 各维度权重
    
    # 历史行为 (持续积累)
    decision_history: List[DecisionRecord]
    feedback_patterns: FeedbackPattern  # 反馈模式
    satisfaction_trajectory: List[float]  # 满意度变化
    
    # 进化状态
    current_concerns: List[str]  # 当前关注问题
    learning_gaps: List[str]  # 知识缺口
    trust_level: float  # 对系统的信任度
```

### 2.2 客户类型谱系

**类型A: 首次创业者** (需求：基础框架+风险教育)
- 特点：缺乏经验，需要结构化指导
- 服务：标准流程+案例教学
- 进化：从模板到个性化

**类型B: 连续创业者** (需求：深度洞察+反直觉发现)
- 特点：有经验，但可能有认知盲区
- 服务：挑战假设+模式识别
- 进化：从确认偏见到突破惯性

**类型C: 投资机构** (需求：效率+批量处理+可比分析)
- 特点：高频决策，需要工具化
- 服务：批量评估+对比报告
- 进化：从人工到自动化

**类型D: 企业HR/高管** (需求：内部合伙人选拔)
- 特点：组织内场景，有历史数据
- 服务：内部案例+组织适配
- 进化：从外部案例到内部知识

**追问外援**:
1. 如何自动识别客户类型？（首次对话的哪些问题能分类？）
2. 如何设计不同类型客户的服务流程？
3. 客户类型会随时间变化吗？（如首次创业者变成连续创业者）如何检测和适应？

### 2.3 客户需求层次

```
┌────────────────────────────────────────┐

│  "我想成为更好的决策者"                   │

│  服务：持续跟踪、迭代优化                  │

│  Layer 2: 单次服务                       │
```

## 第三部分：模拟小闭环 - 自主进化的引擎

### 3.1 模拟客户生成 (Synthetic Client Generation)

**目的**: 在没有真实客户时，通过模拟客户持续训练系统

**生成维度**:
```python
class SyntheticClientGenerator:
    """基于真实模式生成模拟客户"""
    
    def generate(self, scenario_type: str) -> ClientPersona:
        # 基于真实案例的模式分布
        industry = self.sample_from_real("industry_distribution")
        stage = self.sample_from_real("stage_distribution")
        
        # 生成决策风格（与行业/阶段相关）
        decision_style = self.generate_style(industry, stage)
        
        # 生成价值权重（符合该类型典型特征）
        value_weights = self.generate_values(industry, stage)
        
        # 生成当前关注点（基于真实客户常见问题）
        concerns = self.generate_concerns(industry, stage)
        
        return ClientPersona(...)
```

### 3.2 场景生成引擎 (Scenario Generation Engine)

**基于**: 客户画像 + 真实模式 → 生成决策场景

**场景类型**:
- **典型场景**: 最常见的合伙人选择情境
- **边界场景**: 极端但重要的决策情境（如联合创始人退出）
- **冲突场景**: 多方利益冲突的情境
- **时间压力场景**: 紧急决策情境

**场景要素**:
```python
@dataclass
class DecisionScenario:
    client: ClientPersona  # 决策主体
    context: Context  # 公司背景、市场环境
    options: List[CandidateProfile]  # 可选方案
    constraints: List[Constraint]  # 硬性约束
    uncertainties: List[Uncertainty]  # 不确定因素
    timeline: Timeline  # 时间压力
    stakes: Stakes  # 决策后果严重性
```

**追问外援**:
9. 如何从真实案例中提取"场景模式"？
10. 如何评估生成场景的"训练价值"？（不是所有场景都值得模拟）

### 3.3 决策推演与模式发现

**过程**:
```
模拟客户 + 场景 → 五图腾分析 → 生成建议 → 
模拟客户反馈 → 模式提取 → 假设生成 → 
下一次模拟验证
```

**模式发现**:
- **成功模式**: "当客户是首次创业者+技术背景时，强调'德馨'维度效果最好"
- **失败模式**: "当时间压力高时，客户倾向于忽略风险信号"
- **反直觉模式**: "某些情况下，'直觉反对'比'理性支持'更准确"

## 第五部分：产品/服务/理论的协同迭代

### 5.1 产品迭代机制

**产品组件**:
- **核心引擎**: 五图腾决策智慧引擎
- **服务接口**: 飞书/微信/API
- **知识资产**: 案例库、理论库、工具库
- **客户界面**: 对话界面、报告生成、仪表盘

**迭代驱动**:
```
客户需求 → 服务交付 → 反馈收集 → 
模式识别 → 产品改进 → 新服务推出 → 
客户验证 → 规模化
```

**追问外援**:

20. 如何平衡"标准化"与"定制化"？（效率vs个性化）

### 5.2 服务迭代机制

**服务类型演进**:
```
V1.0: 单次评估报告
  ↓ 客户反馈：想要持续跟踪
V2.0: 候选人持续监控服务
  ↓ 客户反馈：想要团队共享
V3.0: 团队决策协作平台
  ↓ 客户反馈：想要学习提升
V4.0: 决策能力训练系统
```

**追问外援**:

22. 如何设计"服务创新"的实验机制？（小规模测试再推广）

### 5.3 理论迭代机制

**理论来源**:
- 学术研究（决策科学、认知科学、管理学）
- 实践案例（客户真实决策的总结）

**理论验证**:
```
新理论引入 → 模拟验证 → 小规模客户测试 → 
效果评估 → 理论修正 → 大规模应用 → 
成为核心框架
```
