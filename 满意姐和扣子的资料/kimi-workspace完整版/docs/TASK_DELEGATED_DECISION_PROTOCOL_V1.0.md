# 任务代决策协议 V1.0
> Task Delegated Decision Protocol (TDDP) V1.0

**发布日期**: 2026-04-09  
**制定者**: Egbertie（指挥官）  
**执行者**: 蓝军 Skeptor-7 + 满意姐  
**状态**: ✅ 已固化并生效

---

## 一、核心定义

**任务代决策（Delegated Decision）**：当指挥官（Egbertie）发出"代决策执行"指令时，任务执行人被授予在特定任务范围内的临时决策权。但此类决策在未经指挥官人工复核前，状态为**"预决策"**（Pre-Decision），而非最终决策。

**完整决策**：只有当指挥官完成人工复核并签字（或默认追认）后，预决策才升级为**"完整决策"**（Closed Decision）。

---

## 二、触发条件

代决策权仅在以下情况生效：

1. 指挥官明确发出包含"代决策执行"关键词的指令；
2. 指令中明确指定了任务范围（如"决策科学包"、"P1整改项"、"专家矩阵补全"）；
3. 任务执行人已确认理解该范围，并与监督者达成一致。

**未触发时**：任何超出当前文件或当前明确指令范围的决策，必须先请示指挥官，不得自行决定。

---

## 三、执行流程（五步法）

```
[Step 1] 授权确认
         指挥官发出"代决策执行" → 执行人复述任务范围 → 监督者确认无异议

[Step 2] 单任务执行
         一次只处理一项任务，逐项推进，禁止并行跳跃

[Step 3] 实时记录
         每项代决策必须生成《代决策清单》，记录决策逻辑、理由、结果和预期效果

[Step 4] 监督闭环
         监督者（满意姐）完成监督报告 → 列出整改项 → 执行人完成全部整改
         只有整改全部完成后，才能视为"任务闭环"

[Step 5] 指挥官复核
         指挥官回来后统一复核 → 确认/调整/否决 → 标记为"完整决策"或"待修正"
```

---

## 四、代决策清单标准模板

每项代决策必须生成如下清单条目：

```markdown
| 序号 | 决策事项 | 决策内容 | 决策理由 | 预期效果 | 实际结果 | 标签 | 复核状态 |
|------|----------|----------|----------|----------|----------|------|----------|
| DD-001 | 处理顺序 | 从小到大排列 | 先建立正反馈 | 降低认知负荷 | 已完成第一本 | [DD] [P0] | 待复核 |
```

### 标签规范（强制）

- **[DD]** — Delegated Decision，代决策标识
- **[P0]/[P1]/[P2]/[P3]** — 优先级标签
- **[CLOSED]** — 已闭环（监督报告完成+整改清零）
- **[BLOCKED]** — 遇到阻塞，已转入待办
- **[APPROVED]** — 指挥官人工复核通过
- **[REVISED]** — 指挥官复核后要求调整
- **[REJECTED]** — 指挥官复核后否决

**只有同时带有 [DD] + [CLOSED] + [APPROVED] 的条目，才是完整的最终决策。**

---

## 五、单任务闭环标准

一个任务要进入"闭环"状态，必须同时满足：

- ✅ 任务范围内的核心产出物已完成（代码/文档/分析等）
- ✅ 产出物已通过基础验证（运行通过 / pytest通过 / 语法检查通过）
- ✅ 监督者（满意姐）已完成监督报告
- ✅ 监督报告中提出的所有整改项已全部完成
- ✅ 代决策清单已更新并存放至对话文件夹
- ✅ memory/YYYY-MM-DD.md 已追加本次任务摘要

**不满足以上任一条件，禁止进入下一个任务。**

---

## 六、监督报告要求

满意姐作为监督者，必须在每个任务结束后产出：

1. **执行诚实度评估**（是否如实汇报进度/缺陷）
2. **质量评分**（0-100分）
3. **CONDITIONAL_PASS / PASS / FAIL 结论**
4. **整改项清单**（如为 CONDITIONAL_PASS 或 FAIL）
5. **风险预警**（如有）

蓝军作为对抗性验证方，可选择性产出：

1. **蓝军审计摘要**（至少发现1个问题）
2. **硬否决意见**（如存在高危风险）

---

## 七、例外与待办处理

如果当前任务遇到以下情况之一：

- 必须指挥官介入才能继续（如涉及重大战略方向、金钱支出、对外承诺）
- 客观条件限制（如网络中断、文件损坏、外部API不可用）
- 处理过程出现异常（如pytest大面积失败、代码逻辑无法自洽、存在根本性歧义）

**执行标准**：

1. 在代决策清单中标记为 **[BLOCKED]**
2. 将任务详细状态、阻塞原因、已尝试的解决方案记录清楚
3. 将任务转入 `TASK_MASTER.md` 或当日 memory 中的"待办任务"栏目
4. **立即启动下一个任务**（前提是当前任务的核心阻塞原因已穷尽，无法在没有指挥官的情况下推进）
5. 指挥官回来后，**第一时间汇报所有 [BLOCKED] 项**，请求补充决策

## 九、执行示例

### 示例场景
指挥官："代决策执行决策科学包5本书的内化闭环。"

### 执行与记录
1. **蓝军决策**："按文件体积从小到大处理。"
2. **理由**：先处理轻量文件建立正反馈，避免大文件第一轮就消耗大量Token并可能超时。
3. **执行结果**：第一本《慢思考，快决策》闭环完成。
4. **监督报告**：满意姐审计通过，评分84/100，CONDITIONAL_PASS→整改后转为PASS。
5. **标签 更新**：该条目标记为 `[DD] [P0] [CLOSED]`，等待指挥官复核后升级为 `[APPROVED]`。
