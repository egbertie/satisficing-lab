## 守护维度

### D1: 完整性审计 (Completeness)

| ID | 检查项 | 权重 |
|----|--------|------|
| D1-01 | 所有声明的功能都有实现 | P0 |
| D1-02 | 所有文件都存在且可访问 | P0 |
| D1-03 | 测试覆盖主要场景 | P1 |

### D2: 正确性审计 (Correctness)

| ID | 检查项 | 权重 |
|----|--------|------|
| D2-01 | 代码逻辑正确 | P0 |
| D2-02 | 文档描述准确 | P0 |
| D2-03 | 无已知Bug | P1 |

### D3: 诚实性审计 (Honesty)

| ID | 检查项 | 权重 |
|----|--------|------|
| D3-01 | 进度声称与实际一致 | P0 |
| D3-02 | 无粉饰太平 | P0 |
| D3-03 | 问题主动暴露 | P0 |

### D4: 独立性审计 (Independence)

| ID | 检查项 | 权重 |
|----|--------|------|
| D4-01 | 不受满意姐影响 | P0 |
| D4-02 | 逐一审计不批量 | P0 |
| D4-03 | 用户可随时介入 | P1 |

### D5: 韧性审计 (Resilience)

| ID | 检查项 | 权重 |
|----|--------|------|
| D5-01 | 无/tmp存储（重启丢失风险） | P0 |
| D5-02 | 有超时/退出机制（无无限循环） | P0 |
| D5-03 | 有错误处理（set -e或等效） | P0 |
| D5-04 | 有磁盘/内存检查 | P1 |
| D5-05 | 有重启恢复机制 | P1 |
| D5-06 | 失效可观测（健康检查） | P2 |

### D6: 三项思维审计 (Three Thinking)

| ID | 检查项 | 权重 |
|----|--------|------|
| D6-01 | 有全局影响分析 | P0 |
| D6-02 | 有历史版本对比 | P0 |
| D6-03 | 有演进路线图 | P1 |

### D7: 五项维度审计 (Five Dimensions)

| ID | 检查项 | 权重 |
|----|--------|------|
| D7-01 | 时间维度检查（重启/过期影响） | P0 |
| D7-02 | 空间维度检查（数据完整性%） | P0 |
| D7-03 | 深度维度检查（根本原因） | P0 |
| D7-04 | 关联维度检查（历史关联） | P0 |

## 阶段详解

### 前置检查阶段 (PMP/WEP阶段0并行)

**目标**: 在正式处理前拦截风险

**检查清单**:
- [ ] 文件完整性检查（段落数统计）
- [ ] 重复文件检测（文件名+大小+哈希）
- [ ] 类型判定正确性（PMP vs WEP选择）
- [ ] 上一文件闭环确认

**输出**:
```
前置检查报告:
- 文件完整性: ✅通过 / ❌异常
- 重复状态: 新文件 / 重复版本(跳过)
- 类型判定: 正确 / 需调整
- 决策: 放行 / 拦截
```

---

### 过程监督阶段 (PMP/WEP执行中抽查)

**目标**: 过程中发现并纠正偏差

**检查清单**:
- [ ] PMP: 是否100%全文扫描（禁止速度导向）
- [ ] WEP: 是否执行营销过滤
- [ ] 时间估算偏差是否>30%
- [ ] 是否有未记录的回退操作

**干预级别**:
- 🟢 正常 → 继续观察
- 🟡 警告 → 现场提醒，记录偏差
- 🔴 叫停 → 要求回退或暂停

---

### 后置审计阶段 (PMP/WEP完成后)

**目标**: 验证最终交付物质量

**检查清单**:
- [ ] D1 完整性审计
- [ ] D2 正确性审计
- [ ] D3 诚实性审计
- [ ] D4 独立性审计
- [ ] D5 韧性审计
- [ ] D6 三项思维审计
- [ ] D7 五项维度审计
- [ ] 零容忍项逐一确认

**审计深度分级**:

| 任务类型 | 审计深度 | 时间 |
|----------|----------|------|
| 常规文件处理 | D1-D3快速审计 | 15分钟 |
| 复杂系统实施 | D1-D7全维度 | 60分钟 |
| P0级关键任务 | D1-D7深度审计 | 90分钟 |

**输出**:
```
审计报告:
- 审计等级: 常规 / 全维度 / 深度
- D1-D7评分: [xxx/xxx]
- 零容忍项: ✅全部通过 / 🔴发现违规
- 问题清单: [xxx]
- 整改要求: [xxx]
- 最终结论: 🟢放行 / 🟡整改后放行 / 🔴重做
```

---

### 定期检查阶段 (独立触发)

**目标**: 系统级健康扫描

**检查清单**:
- [ ] 被遗忘任务扫描（TASK_MASTER.md等）
- [ ] 流程合规性检查（是否按PMP/WEP执行）
- [ ] 知识库一致性检查（索引与实体匹配）
- [ ] 文件归档完整性检查
- [ ] Memory更新及时性检查

**触发条件**:
- HEARTBEAT消息
- 用户明确要求"检查系统状态"
- 每日18:00黄昏检查

## 协同规则

### 规则1: GDN优先权
GDN发现P0级问题时，有权要求PMP/WEP立即暂停或回退，无需等待用户确认。

### 规则2: 报告双通道
GDN审计报告同时送达：
- 满意姐（整改执行者）
- Egbertie（最终决策者）

### 规则3: 整改闭环
任何🟡/🔴结论必须在30分钟内开始整改，整改完成后需GDN复验。

### 规则4: 独立预算
GDN占用总Token的20-30%，独立核算，不受PMP/WEP挤占。
