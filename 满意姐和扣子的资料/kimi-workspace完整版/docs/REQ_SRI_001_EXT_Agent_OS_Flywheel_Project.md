## 一、我们是谁

### 1.1 组织简介

**名称**: 满意解研究所 (Satisficing Research Institute)  
**定位**: 硬科技转化的合伙人匹配决策教练  
**核心理念**:  Herbert Simon "满意解"理论 + 儒商哲学 + 商业直觉  
**服务对象**: 获得政府补贴或投资的初创期硬件企业家

### 1.2 创始人背景

**Egbertie**  
- 22年双系统深度体验（前11年大型商业银行 + 后11年中小企业创业）
- 6项专业认证：CBIIP商业直觉智能、CDAA数字资产分析、CFC、CFP、FAIAA、MSE
- 独特方法论：左脑风控 + 右脑直觉（感知力）综合决策

### 1.3 五路图腾决策体系

我们的核心方法论基于五个认知框架的具身化：

| 图腾 | 五行 | 核心精髓 | 决策视角 |
|------|------|---------|----------|
| **刘禹锡** | 土 | 斯是陋室，惟吾德馨 | 长期价值、根基评估 |
| **司马贺** | 金 | 不求最优，但求最适 | 边界分析、满意解算法 |
| **观自在** | 水 | 居方寸之地，以价值致远 | 直觉感知、定力判断 |
| **孔子** | 木 | 仁义礼智信 | 五常评估、伦理判断 |
| **六祖慧能** | 火 | 顿悟红莲，直指人心 | 创新突破、压力顿悟 |

### 1.4 当前发展阶段

- **阶段**: 商业筹划中，2026年3月25日官宣
- **首年目标**: 30个案例库
- **技术基础**: OpenClaw + Kimi 智能体平台

## 三、我们的痛点

### 3.1 核心问题（按优先级）

#### P0: 知识入库与内化断层
- 物理提取 ≠ 内化完成，返工率高
- 缺乏标准化的入库流程
- 内化质量无法验证

#### P0: Workflow完全缺失
- SOP无法数字化
- 执行标准依赖人工
- 流程无法复用和优化

#### P0: 指标体系空白
- 无时间/质量/风险/成本/复用率采集
- 工作成果无法用经营语言衡量
- 无法进入预算与绩效体系

#### P1: Memory碎片化
- 知识分散在各处
- 检索困难，找不到、用不了
- 缺乏知识图谱索引

#### P1: Skill管理混乱
- 技能缺乏统一入口
- 依赖关系不清晰
- 版本管理缺失

#### P2: Prompt零散
- 提示词缺乏模板化
- 五图腾System Prompt未标准化
- 复用率低

### 3.2 造成的后果

| 问题 | 后果 |
|------|------|
| 每次新项目 | 从零开始，重复造轮子 |
| Token消耗 | 大量浪费在重复探索 |
| 时间投入 | 1小时以上启动新任务 |
| 质量波动 | 依赖个人状态，标准不一 |
| 无法评估 | 不知道做得好不好 |
| 迁移困难 | 换模型/渠道需1周+ |

## 四、我们的目标

### 4.1 愿景

> 构建满意解研究所的**Agent OS操作系统**——一个自增强的资产生态系统，让每一份投入都产生复利积累，从创新项目变成组织能力。

### 4.2 战略对标

参考OpenClaw官方资产飞轮与指标体系，我们希望在以下维度达标：

**资产飞轮五节点**: Prompt → Skill → Memory → Workflow → Case Library（全闭环）

**经营指标五维度**: 时间、质量、风险、成本、复用率（全采集）

### 4.3 阶段性目标

#### 短期目标（1个月）
- 建立知识入库与内化标准入口（SOP数字化）
- 完成首批50个高质量资产入库
- 建立基础指标采集（时间+成本）
- 蓝军监督机制数字化

#### 中期目标（3个月）
- Workflow引擎上线（核心SOP数字化）
- Memory知识图谱建成
- 五维指标全采集
- 资产复用率达到40%
- 平均任务处理时间<30分钟

#### 长期目标（6个月）
- 完整的Agent OS操作系统
- 资产复用率>70%
- 平均任务处理时间<15分钟
- 换模型/渠道迁移成本<1天
- 进入预算与绩效体系

## 五、具体需求

### 5.1 系统架构需求

我们需要的系统包含三层：

```
┌─────────────────────────────────────────┐
│  【入口层】知识入库与内化系统            │
│  - 文件接收 → 物理入库 → 深度消化 → 内化验证  │
└─────────────────────────────────────────┘
                    │
                    ▼
┌─────────────────────────────────────────┐
│  【飞轮层】资产飞轮系统                  │
│  Prompt → Skill → Memory → Workflow → Case  │
│  (生产)  (编码)  (存储)   (流程)    (案例)  │
└─────────────────────────────────────────┘
                    │
                    ▼
┌─────────────────────────────────────────┐
│  【指标层】经营语言系统                  │
│  时间 / 质量 / 风险 / 成本 / 复用率        │
└─────────────────────────────────────────┘
```

### 5.2 功能模块需求

#### 模块A: 知识入库与内化系统（P0）

| 功能 | 描述 | 验收标准 |
|------|------|----------|
| 文件登记 | 自动提取元数据，分类标记 | 3分钟内完成登记 |
| 物理入库 | 内容提取+格式转换+3-2-1备份 | 完整备份，可检索 |
| 内化辅助 | 三遍阅读辅助，模板引导 | 辅助完成深度消化 |
| 质量验证 | 5题抽查，自动评分 | 80分通过，否则返工 |
| 蓝军审计 | 独立监督，违规记录 | 全流程可追溯 |

#### 模块B: Workflow引擎（P0）

| 功能 | 描述 | 验收标准 |
|------|------|----------|
| 流程模板库 | SOP数字化，可视化编辑 | 核心SOP全覆盖 |
| 工作流编排 | 多Skill串联，条件分支 | 复杂流程可编排 |
| 执行追踪 | 状态监控，日志记录 | 全流程可观测 |
| 异常处理 | 中断恢复，错误处理 | 容错率>95% |

#### 模块C: 指标采集系统（P0）

| 功能 | 描述 | 验收标准 |
|------|------|----------|
| 时间追踪 | 自动记录任务处理时长 | 精度到秒 |
| 质量评估 | 一次成功/返工标记 | 用户一键标记 |
| 风险监控 | 合规事件记录+告警 | 实时告警，0遗漏 |
| 成本核算 | Token消耗自动统计 | 精确到单次调用 |
| 复用统计 | 资产使用频次追踪 | 自动识别复用 |

#### 模块D: Memory知识图谱（P1）

| 功能 | 描述 | 验收标准 |

| 实体识别 | 自动识别人物/概念/关系 | 准确率>90% |
| 知识图谱 | 实体关系可视化 | 可探索的知识网络 |

## 七、约束与偏好

### 7.1 技术约束

- **平台**: 基于OpenClaw框架
- **模型**: 适配Kimi系列模型
- **部署**: 优先本地/私有部署
- **安全**: 数据不出境，敏感信息加密

### 7.2 协作偏好

- **沟通**: 飞书/微信，及时响应
- **文档**: Markdown格式，Git版本控制
- **进度**: 每周Review，每月里程碑
- **质量**: 蓝军Skeptor-7全程监督

### 7.3 特殊要求

1. **经营语言**: 所有功能最终要体现为时间/质量/风险/成本/复用率指标
2. **闭环设计**: 每个模块必须形成自增强闭环
3. **渐进交付**: 优先P0，再P1/P2，快速验证
4. **培训转移**: 交付时需提供完整培训，确保我们能自主运维
