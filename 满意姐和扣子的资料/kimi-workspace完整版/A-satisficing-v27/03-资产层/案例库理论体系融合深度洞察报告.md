## 第一部分：类型融合架构（12×44矩阵）

### 1.1 发现问题：两种分类体系的维度差异

| 维度 | 原有12类型 | 新增44类型 |
|------|-----------|-----------|
| **分类逻辑** | 按"创业阶段/场景" | 按"冲突本质/性质" |
| **颗粒度** | 粗（12个场景） | 细（44种子类型） |
| **理论基础** | 五路图腾+22年经验 | 法律+人性心理+全球比较 |
| **交付形态** | 案例脚本+评分卡 | 类型描述+预防方案 |
| **使用场景** | 课程教学+模拟训练 | 风险识别+预防指南 |

**洞察**: 两种体系不是替代关系，而是**正交矩阵关系**——每个场景类型都会涉及多种冲突类型，每种冲突类型会在多个场景中显现。

## 第二部分：哈佛商业评论标准对标

### 2.1 HBR案例标准解析

**哈佛商业评论(HBR)案例的5大标准**：

| 标准 | 要求 | 我们的现状 | 改进方向 |
|------|------|-----------|---------|
| **1. 决策焦点** | 案例必须围绕一个关键决策点 | 目前偏叙事 | 强化决策时刻 |
| **2. 信息密度** | 足够信息支持分析，但有信息缺口 | 信息较完整 | 故意保留信息缺口 |
| **3. 多重视角** | 呈现多方观点，无明确对错 | 有倾向性 | 增加反方观点 |
| **4. 理论锚定** | 明确链接管理理论 | 隐含理论 | 显性化理论框架 |
| **5. 教学笔记** | 包含教学目标、讨论问题、理论点 | 无 | 补充教学笔记 |

### 2.2 北大商业评论标准补充

**中国本土案例的3个特殊要求**：

| 要求 | 说明 | 我们的优势 |
|------|------|-----------|
| **1. 制度情境** | 需说明中国特定制度背景 | 22年中国经验 |
| **2. 关系网络** | 需呈现guanxi网络影响 | 社会资本理论 |
| **3. 演化视角** | 需呈现长期演化过程 | 五路图腾动态观 |

### 2.3 我们的案例标准（HBR+本土融合）

**案例结构（8要素）**：

```
案例标题（决策焦点+冲突类型+结果暗示）
├── 1. 摘要（200字：背景-冲突-决策-结果）
├── 2. 背景（行业-企业-人物-时间点）
├── 3. 冲突 escalation（按时间线呈现冲突升级）
├── 4. 决策时刻（关键决策点，信息不完全）
├── 5. 多方观点（创始人/合伙人/投资人/员工）
├── 6. 结果与后续（实际结果+后续发展）
├── 7. 理论框架（链接到五路图腾+冲突类型）
└── 8. 教学笔记（目标-问题-理论点-作业）
```

## 第三部分：案例库索引体系

### 3.1 五层索引架构

```
案例库索引（5层架构）
│
├─ Layer 1: 元数据索引（所有案例的DNA）
│   ├─ 案例ID（统一编码系统）
│   ├─ 场景类型（Type 1-12）
│   ├─ 冲突域（8大类）
│   ├─ 五路图腾锚点
│   └─ 行业/地域/时间标签
│
├─ Layer 2: 理论索引（理论到案例的映射）
│   ├─ 五路图腾理论 → 相关案例列表
│   ├─ 冲突类型 → 典型案例
│   ├─ 决策科学 → 应用场景
│   └─ 儒商哲学 → 伦理困境案例
│
├─ Layer 3: 教学索引（课程到案例的映射）
│   ├─ 课程模块 → 核心案例
│   ├─ 学习难度 → 案例分级
│   ├─ 训练目标 → 案例匹配
│   └─ 评估维度 → 案例覆盖
│
├─ Layer 4: 检索索引（快速查找）
│   ├─ 关键词索引
│   ├─ 相似案例推荐
│   ├─ 对比案例组合
│   └─ 更新提醒（案例后续发展）
│
└─ Layer 5: 数据索引（量化分析）
    ├─ PFI评分数据
    ├─ ECBM识别频率
    ├─ 冲突类型分布
    └─ 预测准确率反馈
```

### 3.2 案例ID编码系统

**编码格式**: `CASE-[TYPE]-[CONFLICT]-[REGION]-[YEAR]-[SEQ]`

示例: `CASE-T07-C11-CN-2024-001`
- T07 = Type 7 (创业次年)
- C11 = 冲突类型11 (承诺升级)
- CN = 中国
- 2024 = 案例年份
- 001 = 序列号

### 3.3 动态更新机制

| 更新类型 | 触发条件 | 更新内容 | 责任方 |
|---------|---------|---------|--------|
| **事实更新** | 案例有新进展 | 补充"后续发展"章节 | 蓝军 |
| **理论更新** | 新理论出现 | 更新"理论框架"章节 | 满意姐 |
| **教学更新** | 教学反馈 | 更新"教学笔记" | 课程团队 |
| **索引更新** | 新增案例 | 更新所有索引层级 | 系统自动 |

## 第四部分：工作流搭建

### 4.1 案例生产工作流（7步法）

```
Step 1: 案例发现（输入）
├─ 线上监测（新闻/诉讼/公告）
├─ 线下访谈（客户/学员/专家）
└─ 学员提交（实际遇到的问题）
    ↓
Step 2: 案例初筛（过滤）
├─ 是否符合12场景类型之一？
├─ 是否涉及8冲突域之一？
└─ 是否有教学价值？
    ↓
Step 3: 信息收集（调研）
├─ 公开信息检索（17引擎矩阵）
├─ 当事人访谈（如可能）
└─ 专家验证（数字替身审核）
    ↓
Step 4: 案例撰写（生产）
├─ 按8要素结构撰写
├─ 嵌入理论框架
└─ 设计教学笔记
    ↓
Step 5: 蓝军审计（质检）
├─ 事实准确性检查
├─ 理论一致性检查
└─ 伦理合规性检查
    ↓
Step 6: 案例入库（归档）
├─ 生成案例ID
├─ 更新所有索引
└─ 关联相关案例
    ↓
Step 7: 应用反馈（迭代）
├─ 教学中收集反馈
├─ 更新案例数据
└─ 优化理论模型
```

### 4.2 线上线下案例融合机制

| 类型 | 来源 | 处理方式 | 隐私保护 |
|------|------|---------|---------|
| **线上案例** | 公开报道/诉讼/公告 | 直接使用，标注来源 | 已公开 |
| **线下案例A** | 客户授权 | 脱敏处理后使用 | 签署授权书 |
| **线下案例B** | 客户未授权 | 仅用于内部分析 | 严格保密 |
| **合成案例** | 多案例特征组合 | 标注"合成案例" | 无隐私问题 |

**融合原则**: 
- 线上案例提供"广度"（多种类型）
- 线下案例提供"深度"（细节丰富）
- 合成案例提供"教学针对性"

## 第五部分：Skill创建建议

### 5.1 建议创建：case-library-manager Skill

**功能模块**:

```
case-library-manager Skill
│
├─ case search (案例搜索)
│   └─ 输入: 场景/冲突/理论/关键词
│   └─ 输出: 匹配案例列表
│
├─ case add (案例入库)
│   └─ 输入: 案例内容(支持多种格式)
│   └─ 处理: 自动提取元数据、生成分类、分配ID
│   └─ 输出: 入库确认
│
├─ case update (案例更新)
│   └─ 输入: 案例ID + 更新内容
│   └─ 处理: 版本控制、变更记录
│   └─ 输出: 更新确认
│
├─ case analyze (案例分析)
│   └─ 输入: 案例ID 或 案例内容
│   └─ 处理: PFI评分、ECBM识别、图腾校准
│   └─ 输出: 分析报告
│
└─ case generate (案例生成)
    └─ 输入: 类型 + 冲突 + 教学目标
    └─ 处理: 基于模板生成案例框架
    └─ 输出: 案例初稿
```

### 5.2 Skill使用示例

```bash
# 搜索案例
case-library search --type T07 --conflict C11 --region CN

# 添加案例
case-library add --file ./zhangxue_case.md --auto-classify

# 分析案例
case-library analyze --case CASE-T07-C11-CN-2024-001 --output report.md

# 生成教学案例
case-library generate --type T07 --conflict C11 --difficulty medium
```

## 第六部分：资产飞轮固化方案

### 6.1 什么是资产飞轮

**定义**: 每一个工作产出都自动转化为可复用资产，并驱动下一轮产出质量提升。

**飞轮结构**:

```
        ┌─────────────┐
        │   案例发现   │
        └──────┬──────┘
               ↓
        ┌─────────────┐
        │   深度研究   │ ← 理论提升
        └──────┬──────┘
               ↓
        ┌─────────────┐
        │   案例产出   │ → 入库为资产
        └──────┬──────┘
               ↓
        ┌─────────────┐
        │   教学应用   │ → 反馈数据
        └──────┬──────┘
               ↓
        ┌─────────────┐
        │   数据沉淀   │ → 优化理论
        └─────────────┘
               │
               └────────→ 回到"案例发现"
```

### 6.2 固化到日常工作

**满意姐每日工作流**:

| 时间段 | 工作内容 | 资产产出 |
|--------|---------|---------|
| 09:00-09:30 | 晨间图腾仪式 | 当日校准记录 |
| 09:30-10:30 | 案例监测（新闻/公告） | 候选案例清单 |
| 10:30-12:00 | 深度案例研究 | 案例初稿 |
| 14:00-16:00 | 客户咨询/模拟训练 | 案例应用数据 |
| 16:00-17:00 | 案例入库+索引更新 | 可复用资产 |
| 17:00-18:00 | 蓝军审计+复盘 | 改进建议 |

**蓝军每日工作流**:

| 时间段 | 工作内容 | 资产产出 |
|--------|---------|---------|
| 09:00-09:30 | 案例质量抽检 | 质检报告 |
| 09:30-11:00 | 事实核查+信源验证 | 验证记录 |
| 11:00-12:00 | 理论一致性检查 | 审计意见 |
| 14:00-15:00 | 伦理合规审查 | 合规报告 |

### 6.3 内化检查清单

**每日结束时的3个问题**:

1. **今天发现了什么值得入库的案例？**
   - 候选案例是否已记录到 inbox？
   - 是否已初步分类（Type/Conflict）？

2. **今天的研究产出了什么可复用资产？**
   - 案例框架？理论模型？工具模板？
   - 是否已归档到正确位置？

3. **今天的数据反馈了什么优化方向？**
   - 教学反馈？预测准确率？客户问题？
   - 是否已记录到改进日志？
