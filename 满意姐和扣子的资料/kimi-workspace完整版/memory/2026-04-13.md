## 2026-04-13 16:30 Gateway 内存根因排查重大进展

### 根因定位：sessions.json 中 Cron Session 状态膨胀

**排查路径**:
1. 排除传统泄漏：FD（40 个，17 socket）正常，无 native addon 大块内存（pmap 最大段 75MB）。
2. 发现高基线：Gateway 重启后 10 分钟即达 735MB，说明问题不在"缓慢泄漏"，而在**启动 Resident Set 过大**。
3. 锁定 `sessions.json`（`/root/.openclaw/agents/main/sessions/sessions.json`）：大小 **10.3MB**。
4. 拆解结构：85 个顶层条目中，**75 个是 `agent:main:cron:` session**。
5. Cron 占比：数量占 88.2%，JSON 大小贡献约 **93%（9.6MB）**。
6. 单个 cron session 元数据约 **187KB**（包含 system prompt 快照、skill snapshot、token 统计、上下文窗口 128K 配置）。

**根因结论**:
- 这不是传统意义的内存泄漏（悬空引用）。
- 这是 **state bloat（状态膨胀）**：大量已完成的一次性 cron session 元数据永久堆积在 `sessions.json` 中，Gateway 启动时必须将整个文件反序列化为 V8 heap 对象，导致常驻内存基线持续升高。
- **蓝军置信度**: 0.85（高）。

### 已部署的修复动作

**1. 清理脚本** `scripts/gateway-session-bloat-cleaner.sh`
- 策略：删除 `updatedAt` 超过 48 小时的 `agent:main:cron:` 条目。
- Dry-run 结果：可删除 **32 个过期 cron session**，释放 **2.39MB JSON**。
- 实际执行方式：集成到 `gateway-memory-guard.sh` 中，**仅在 Gateway restart 止血窗口期间执行清理**，确保无竞态风险。

**2. Guard 脚本升级** `scripts/gateway-memory-guard.sh`
- 在 `kill -TERM/KILL` 之后、`systemctl restart` 之前，自动调用 cleaner。
- 这意味着：每次 Gateway 因内存超阈值被重启时，都会自动"瘦身"，长期防止基线无限攀升。
