## 三、Skill 自建战略（2026-04-12 升级）

**核心理念**: 归档外部 Skill 只是第一步，最终目标是**整合优秀基因、剔除垃圾信息，自建核心 Skill**。

**参考文章**:
- [Kimi + MCP + Agent：智能体世界的进化论](https://mp.weixin.qq.com/s/GJ41aM1e2uWzTyJFxwZKHg) — 强调在 ACP/Agent 生态中，自建能力 > 过度依赖外部插件。

**策略阶梯**:
1. **归档**（Archive）: 将非核心/低频/未验证的 Skill 移入 `skills-archive/`
2. **合并**（Merge）: 将功能重叠的 Skill 内聚为 1 个能力更全的使命级 Skill
3. **自建**（Build）: 基于业务基因（合伙人匹配、五路图腾、满意解方法论），从零构建原生 Skill

**执行原则**:
- 外来 Skill 只留「能立刻调用」和「有启发价值」的两类
- 任何 Skill 进入 `skills/` 目录前必须通过 SAP-7 审查
- 自建 Skill 必须通过 `code_asset_auditor.py` 语法检查 + 至少一个端到端测试

## 四、使用协议

1. **SAP-7 流程适用**: 任何从这些站点引入的 skill/tool，仍需经过 Scan→Assess→Vet→Approve→Install→Test→Register→Integrate。
2. **费用红线**: 付费功能必须经 Egbertie 逐项确认。
3. **优先策略**: OpenClaw 原生 SkillHub (crawhub.ai) > 外部可集成平台 > 封闭平台参考。
