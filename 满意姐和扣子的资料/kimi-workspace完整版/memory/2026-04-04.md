## 🕗 20:00 补录 — 蓝军诊断 Kimi 超时问题

### 问题现象
Egbertie 报告：对话中再次出现 `Request timed out before a response was generated`，今日第二次发生，每次需重启 Gateway 才能恢复。

### 诊断结论
**根因不在本地，而在上游 Kimi 服务端 WebSocket 订阅流资源耗尽。**

### 证据链
| 来源 | 发现 |
|------|------|
| 本地系统状态 | CPU 0.01、内存 1.4G/7.8G、磁盘 37%、Gateway PID 152453 正常运行 |
| OpenClaw 日志 | `2026-04-04T19:50:29` 出现 `code=resource_exhausted message=connect stream failed` |
| ACP timeout | 本地 prompt timeout 为 1800000ms（30分钟），远未触达 |

### 为什么重启有效
重启 Gateway 会 **强制断开并重建 WebSocket 连接**，旧会话被服务端清理，新连接获得新的资源分配。

### 应急替代方案（无需重启）
```bash
kill -SIGUSR1 $(pgrep -f "openclaw-gateway")
```
Gateway 日志已确认支持 `SIGUSR1` 软重连，5 秒内恢复。

### 预防建议（待执行）
- 将 `agents.defaults.timeoutSeconds` 从 300 提升到 600，增加模型生成缓冲
- 已将 `resource_exhausted` 加入蓝军监控清单，单日出现 3 次以上即视为系统性上游不稳定
