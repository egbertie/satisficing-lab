# 任务闭环 FIN 新标准 V1.0

> 生效日期: 2026-04-12
> 来源: 满意姐独立审计报告 (2026-04-11) 整改要求
> 适用对象: 蓝军、满意姐及全部自动化 Agent

---

## 硬标准

任何任务要标记为 **FIN / ✅ / 完成**，必须满足以下**至少一条**：

| 标准编号 | 标准内容 | 示例 |
|----------|----------|------|
| **S1** | 有可运行的代码/脚本，并已通过基础验证（`py_compile`、`shellcheck`、`go build` 等） | `.py` 文件通过 `python3 -m py_compile` |
| **S2** | 有注册的 cron job 或自动化 pipeline，且已运行至少一次 | crontab 可见 + 日志存在 |
| **S3** | 有真实的 API 集成并通过了端到端测试 | 真实调用 + 记录响应 |

## 不满足标准的分类

- **半成品**：有产出但无运行代码/自动化/API
- **文档化完成**：产出为 Markdown、分析结论、目录结构、路线图
- **未启动** / **进行中** / **队列化**

## 禁止用词

- 禁止将 **半成品** 或 **文档化完成** 标记为 **FIN / ✅ / 完成**
- 禁止在 memory、TASK_MASTER、AGENTS.md 中用文字游戏掩盖未完成状态

## 守门脚本

- `code_asset_auditor.py`：每周日 03:17 自动扫描全仓库 `.py` 文件语法
- `daily_report_gatekeeper.py`：每日 09:00 检查日报/晨报缺失
- `deadline_watchdog.py`：每日 09:00 检查 P0-P1-P2 超期任务
- `file_processing_insight_enforcer.py`：每周一 09:17 检查文件闭环后是否产出 L1-L5 洞察
- `weekly_status_rollup.py`：每周一 09:30 自动汇总周报

## 违规后果

- 第一次违规：蓝军审计标记 + 立即修正状态标签
- 第二次违规：任务责任人降级（Token 配额减少）
- 连续三次：进入整顿模式，暂停一切非 P0 任务，直至整改通过

---
*本标准为硬性约束， override 一切先前的宽松 FIN 判定习惯。*
