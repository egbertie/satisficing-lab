# Token 消耗节奏策略 V1.0

> 生效日期: 2026-04-12
> 来源: Egbertie 反复强调（≥10次）的直接指令
> 核心修正: 从「绝对比例红线」转向「时间进度挂钩 + 波动容差」

---

## 问题诊断

**旧机制缺陷**:
- 周中 50% 时看到 Token 40% 就放松 → 后半周突增导致超支
- 周日前一天 Token 85% 就触发 L4 强制静默 → 剩余额度被浪费
- 忽略了创意型工作的**非线性脉冲**特征

## 新策略: S-曲线消耗轨迹

基于 7 天周期的**非线性**消耗模型：

| 天数 | 时间进度 | 允许消耗上限 | 建议消耗区间 |
|------|----------|--------------|--------------|
| Day 1 | 0–14% | 8% | 0–5%（蓄力期） |
| Day 2 | 14–29% | 18% | 5–15%（启动期） |
| Day 3 | 29–43% | 32% | 15–28%（加速期） |
| Day 4 | 43–57% | 50% | 28–45%（主产出期） |
| Day 5 | 57–71% | 68% | 45–62%（冲刺期） |
| Day 6 | 71–86% | 85% | 62–80%（收尾期） |
| Day 7 | 86–100% | 100% | 80–100%（清算期） |

## 告警规则（替换旧绝对阈值）

**过快** (`pace_ratio = actual_pct / expected_upper_limit_pct`):
- `pace_ratio > 1.30` → 🟡 黄灯：消耗偏快，建议本周后三日控制轻量任务
- `pace_ratio > 1.60` → 🔴 红灯：严重超支风险，立即启动双经济守门

**过慢/浪费风险**:
- 当 `time_progress > 80%` 且 `actual_pct < 60%` → 🟡 黄灯：额度可能用不完，可释放轻量任务
- 当 `time_progress > 90%` 且 `actual_pct < 75%` → 🔴 红灯：有浪费风险，主动推进积压的非高耗任务

**波动容差**:
- 单日脉冲可达周预算的 25%，不触发告警（只要累计仍在 S-曲线上方±30% 内）

## 执行责任

- `token-tracker-zero.py` 读取此策略计算 `display_percentage` 和 `level`
- `unified_system_nurse.py` 按此策略判定 Token 健康状态
- 任何 Token 告警必须先输出 `time_progress`、`pace_ratio`、`day_of_cycle`，再下结论

---
*本策略为硬性约束， override 此前所有绝对百分比阈值机制。*
