# 报告交付协议 V1.0

> 生效日期: 2026-04-12
> 来源: Egbertie 直接指令（针对报告遗漏存放路径问题）

---

## 核心规则（硬性约束）

**规则 1: 每次提交报告，必须同时完成两件事**
1. 告知 Egbertie **文档的完整存放路径**
2. 将报告 **同步一份到当日对话文件夹**（`A-manyige/对话/YYYY-MM-DD/`）

**规则 2: 报告文件命名规范**
- 文件名必须包含时间戳后缀 `-YYYY-MM-DD-HHMM`
- 主存档目录优先使用 `A-manyige/汇报/专项报告/` 或 `A-manyige/审计/`
- 当日同步目录固定使用 `A-manyige/对话/YYYY-MM-DD/`

**规则 3: 报告交付检查清单（Checklist）**
- [ ] 报告内容已写入 `.md` 文件
- [ ] 主存档路径已确认
- [ ] 当日对话同步副本已确认
- [ ] 向用户回复中明确列出了两个路径
- [ ] Git 已提交（如为代码相关报告）

**规则 4: 遗漏惩罚机制**
- 若 Egbertie 追讨报告存放路径，即视为本次交付 **不完整**
- 不完整交付需在 5 分钟内补正，并在 `memory/YYYY-MM-DD.md` 中记录原因
- 连续 2 次不完整交付，升级为 P0 机制审计项

---

## 示例（标准回复模板）

> 报告已保存：
> - 主存档: `A-manyige/汇报/专项报告/XXX-YYYY-MM-DD-HHMM.md`
> - 当日同步: `A-manyige/对话/YYYY-MM-DD/XXX-YYYY-MM-DD-HHMM.md`

---

## 适用范围

- 专项整改报告
- 审计/诚实报告
- 技术执行报告
- 任何自称「完成报告」的交付物

**不适用**: 纯对话式、无须归档的即时问答。

---
*本协议为最高效力条款，覆盖此前所有关于报告交付的散漫做法。*
