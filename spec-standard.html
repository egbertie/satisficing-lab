📋 产品说明书编写规范

满意解研究所 · V1.0 · 对标Reforge Product Brief + API Doc Standards

一、说明书体系

每个产品必须配套两份说明书：开发者说明书（内部维护） + 客户说明书（对外使用引导）。

A. 开发者说明书 · 十要素

#要素内容要求对标
1产品标识编号SP-XXX·文件名·器物代号·五族归属·形态·URLPIM元数据
2理论来源核心理论·学者·年份·关键论文/著作HBR引用标准
3翻书依据翻书索引编号·关键数据·样本量·准确率APA信效度
4阈值与公式评分公式·临界值·算法逻辑·边界条件Gartner方法透明
5理论限制适用场景·不适用场景·已知局限性APA局限性声明
6技术架构技术栈·存储方式·依赖·部署方式API文档标准
7逻辑流程输入→处理→输出·关键算法·错误处理UML流程图
8对外分类🟢公开/🟡门控/🔴内部/邀约PLM分类
9深度等级L1轻量/L2标准/L3深度HBR三级
10版本历史创建日期·修改记录·审核记录Git Changelog

B. 客户说明书 · 六要素

#要素内容要求
1这是什么一句话描述 + 一段话解释
2适合谁目标客户画像·适用场景·不适用场景
3如何使用步骤1-2-3·预计时间·所需准备
4你会得到什么输出结果·结果解读·分数含义
5理论基础（简明版）基于什么理论·准确性声明·局限性说明
6下一步根据结果推荐关联产品/深度服务

二、理论真实性审核清单

  • 每个论断是否可以追溯到具体学者和论文？
  • 关键数据（如91%准确率）是否有原文出处？
  • 阈值（如CI≥0.7）是否有方法论依据？
  • 产品适用场景是否与理论原情境一致？
  • 是否有"过度承诺"或"夸大疗效"的表述？
  • 信效度数据是否经过≥100样本验证？（内测期后补充）
