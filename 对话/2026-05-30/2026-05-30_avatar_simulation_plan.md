## 一、行业基准学习

### 1.1 合成客户替身的成熟度阶梯

| 级别 | 名称 | 特征 | 准确率 | 满意红当前 |
|:--:|------|------|:--:|:--:|
| L0 | 静态画像 | 文字描述的客户类型 | ~30% | ✅ 已完成 |
| L1 | 结构化画像 | 有字段/痛点/场景的结构化数据 | ~50% | ✅ 已完成 |
| L2 | 交互式替身 | 可通过提示交互，模拟客户反应 | ~65% | ❌ 未开始 |
| L3 | 数字孪生 | 基于真实行为数据的1:1复刻 | ~85% | ❌ 无条件 |
| L4 | 合成市场 | 多替身协作模拟市场行为 | ~75% | ❌ 未开始 |

### 1.2 最佳实践提取

来自Gartner + Bain + Stanford + synthetic-users研究:

1. **三部验证框架** (Beehive.ai):
   - Behavioral Realism: 替身是否像真人一样思考和反应?
   - Preference Realism: 替身的选择是否匹配真实消费者?
   - Predictive Realism: 替身能否预期真实世界结果?

2. **闭环数字孪生** (Siemens + Endeavor):
   - 制造数据 → 设计反馈 → 产品迭代 → 客户体验 → 制造数据
   - PLM(产品生命周期管理) + IoT数据 + 仿真技术

3. **合成用户研究关键原则** (Synthetic Users / Regal.ai):
   - LLM模拟客户侧 → AI Agent对话 → 自动评分 → 模式发现
   - 自动生成测试用例 → 每次迭代自动验证
   - 成本: 传统$1000s → 合成$0.01

## 四、核心洞察

### 三大维度共享一个根因: 无真实客户

但关键突破点在于: **在真实客户到来之前，客户替身可以作为模拟驱动源。**

```
当前:
  🏙️城市 ──推断──→ 👥客户 ──推断──→ 📦产品 ──未执行──→ 🌊知识

目标(L2模拟闭环):
  🏙️南山 ──模拟──→ 👥31替身 ──测试──→ 📦312产品 ──评分──→ 🌊消化管道
      ↑                                                              ↓
      └──────────────── 反馈驱动产品迭代 ───────────────────────┘
```

### 三重模拟的价值

| 价值 | 说明 |
|------|------|
| **测试覆盖率** | 312产品×31替身 = 9,672个潜在交互测试点 |
| **质量锚定** | 替身评分替代quality_score=100的虚假均质 |
| **管道激活** | 模拟数据驱动知识消化管道的首次真实运行 |
| **闭环验证** | 在数字环境下验证"城市→客户→产品→知识→反馈"全链路 |
| **优先级驱动** | 替身模拟结果指导真实客户的优先级 |

## 五、滚雪球方案设计

### Round 2 目标任务层次

```
Phase A: 替身升级 (L1→L2)
  ├─ A1: 31替身注入14个深度字段
  ├─ A2: 建立替身间连接(口碑·竞争·协同)
  ├─ A3: 替身质量差异化评分(替代60分均质)
  └─ A4: 替身分组(优先/标准/低优先)

Phase B: 模拟引擎搭建
  ├─ B1: 知识消化管道实体化(knowledge_pipeline)
  ├─ B2: 模拟任务定义: 每替身×每产品=评分+反馈
  ├─ B3: 驾驶舱增加"模拟启动"入口
  └─ B4: 模拟结果→entities_index写回链路

Phase C: 首次闭环
  ├─ C1: 选南山·5替身(硬科技/AI/半导体)·10精品产品
  ├─ C2: 执行首轮模拟→替身评分→产品改进建议
  ├─ C3: 模拟数据→知识消化管道→产出报告
  └─ C4: 验证"城市→替身→产品→管道→反馈"全链路

Phase D: 规模扩展
  ├─ D1: 31替身×312产品完整矩阵
  ├─ D2: 统一两套生命周期(LC-001~007)
  └─ D3: 模拟结果驱动产品迭代(version变更)
```
