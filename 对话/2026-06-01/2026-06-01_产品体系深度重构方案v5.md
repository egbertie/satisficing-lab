## 一、诚实盘点——当前产品体系的12个问题

### 1.1 数量失控
| 问题 | 数据 |
|------|:--:|
| 产品总数 | 315 |
| 已下架 | 76 (24%) |
| 归入知识库 | 67 (21%) |
| 精品 | 21 (7%) |
| 客户可见(L0+L1) | 31 (10%) |
| **客户实际需要接触的** | **约15个** |

**结论**: 315个产品中，客户真正需要的不超过15个。90%的产品属于内部资产和对客户无意义的噪声。

### 1.2 陈列不当
- product-catalog.html 显示全部315个产品，没有优先级和路径引导
- 品牌首页展示6个工具卡片，但缺乏"为什么A需要这个而不是B"的引导逻辑
- 产品之间没有形成"从A到B到C"的递进关系

### 1.3 版本混乱
- 多个产品存在不同版本（deep-chronicle v1→v4，blood-m1→m14，fw-m1→m12，sk-1→sk-30）
- 旧版本和新版本同时在线，客户可能使用废弃版本
- 无版本管理的生命周期标注

### 1.4 左脑/右脑区分不清
- 所有产品混在一起陈列，没有"我是偏逻辑分析的人"vs"我是偏直觉决策的人"的路径分流
- 这是最核心的差异化竞争力——**两翼驱动**——完全没有在产品体系中呈现

### 1.5 市场维度缺失
- 硬科技(激光雷达/AI)+新能源+医疗健康+AI机器人——不同产业的发展阶段完全不同
- 成熟期产业的需求 vs 初创期产业的需求完全相同吗？产品没有按产业适配

### 1.6 企业阶段缺失
- 初创期(0-1) vs 成长期(1-10) vs 成熟期(10-100)——企业的合伙人问题完全不同
- 当前所有产品对任何企业阶段都一样呈现

### 1.7 关系成熟度缺失
- 刚认识 vs 合作1年 vs 合作5年 vs 面临分手——合伙人关系的阶段完全不同
- 产品应该随着关系成熟度而变化

### 1.8 缺乏精品筛选标准
- Keep-Kill-Combine 框架已讨论但未在产品体系中可视化
- 客户看不到"哪些是精品，哪些还在打磨"

### 1.9 缺乏客户路径导航
- 整个网站没有"如果你是XXX，从哪里开始"的引导
- 全部依赖客户自己探索

### 1.10 内部产品和对外产品混淆
- HRV/扫描脚本/Cron——对内部运行的核心资产
- 这些不应该和对客户的产品放在同一个目录

### 1.11 代际混乱
- "扣子时代"→"满意姐时代"→"满意解研究所时代"三个时代的产物同时存在
- 不同时代的产品有不同的语言风格、设计标准、质量水平

### 1.12 HTML页面≠产品
- 200+ HTML页面 vs entities_index中315个产品——两组不同的数据
- 不是每个HTML页面都是"产品"（有些是内部工具，有些是历史归档）

## 二、向外学习——标杆实践

### 2.1 McKinsey解决方案架构
```
Insight (研究出版物)
  ├── Article (免费·吸引)
  ├── Report (留资·深度)
  └── Book (付费·权威)

Solution (解决方案)  
  ├── Diagnostic (诊断工具)
  ├── Benchmark (对标分析)
  └── Transformation (转型方案)

Capability Building (能力建设)
  ├── Academy (在线课程)
  ├── Workshop (工作坊)
  └── Certification (认证)
```
**借鉴**: 产品分层——不是按"产品类型"分，是按"客户价值深度"分

### 2.2 HubSpot飞轮模型
```
Attract (吸引) → Engage (交互) → Delight (愉悦)
    ↑                                    ↓
    └──────── 客户成为增长引擎 ──────────┘
```
**借鉴**: 每个阶段的客户看到不同的产品，产品之间存在"晋升"关系

### 2.3 Notion产品体系
```
Core (核心·免费)
  ├── Notes & Docs
  ├── Databases  
  └── Wikis

Premium (付费)
  ├── Unlimited AI
  ├── Advanced Permissions
  └── SSO
```
**借鉴**: 渐进式产品解锁——核心功能让人先进来，高级功能按需解锁

### 2.4 Design Thinking双钻模型
```
Discover → Define → Develop → Deliver
  (发散)    (收敛)    (发散)    (收敛)
```
**借鉴**: 左脑(收敛·分析)和右脑(发散·直觉)交替使用，不是二选一

## 三、核心设计——重构蓝图

### 3.1 核心理念

> **"每个创始人的问题相同——65%的失败源于合伙人冲突。**
> **但每个创始人的解决路径不同——有人需要逻辑分析，有人需要直觉觉醒，有人两者都需要。"**

### 3.2 产品分层（从315→5层金字塔）

```
        ┌─────────────┐
        │   🏆 精品  │  21个 (客户首选·已完成打磨)
        │   (Premium) │
        ├─────────────┤
        │  🌐 线上    │  151个 (可访问·持续迭代)
        │  (Online)   │
        ├─────────────┤
        │  📚 知识库  │  67个 (参考资料·归档内容)
        │  (Archive)  │
        ├─────────────┤
        │  🔧 内部    │  76个 (已下架·Cron·脚本)
        │  (Internal) │
        └─────────────┘
```

**客户每阶段只看到5个产品**，从精选中推荐，不展示知识库和内部资产。

### 3.3 左脑/右脑双翼路径（核心竞争力）

```
         🧠 左脑 (逻辑分析)            🧠 右脑 (直觉决策)
              │                              │
     ┌────────┴────────┐          ┌──────────┴──────────┐
     │ 五维自评(数据)  │          │ 五维自评(故事版)    │
     │ 雷达图(可视化)  │          │ 卡牌对局(角色扮演)  │
     │ 自检清单(结构化)│          │ 决策剧场(情景预演)  │
     │ 分割饼(量化)    │          │ 危机模拟(压力测试)  │
     │ 完整诊断(报告)  │          │ Pre-0(身体觉察)    │
     └─────────────────┘          └─────────────────────┘
              │                              │
              └──────────┬───────────────────┘
                         │
              ┌──────────┴──────────┐
              │   两翼驱动(平衡)     │
              │   退出指引·元合伙    │
              │   案例库·白皮书      │
              └─────────────────────┘
```

**核心差异化**: 不是"我们有左脑工具和右脑工具"，而是"我们教你如何在左右脑之间自由切换"。

### 3.4 五维路径矩阵（每个客户有独立路径）

| 维度 | 左脑路径 | 右脑路径 | 融合产品 |
|------|------|------|------|
| **时间轴**(土·刘禹锡) | 长期规划模板·里程碑管理 | 编年史·时间胶囊 | 雷达图(时间轴视图) |
| **可行域**(金·司马贺) | 分割饼·匹配引擎·提案书 | 卡牌·剧场·情景模拟 | 全面诊断 |
| **身心流**(水·水月观音) | HRV测量·客观压力指标 | Pre-0·身体觉察·口眼观 | 心理量表 |
| **信义观**(木·孔子) | 合伙人协议·退出指引·条款 | 四骑士·信任温度计 | 元合伙章程 |
| **直觉阈**(火·六祖慧能) | 决策日志·AI辅助分析 | 直觉训练·第一念练习 | 决策质量仪表盘 |

### 3.5 新增客户维度矩阵

#### 市场发展阶段
| 阶段 | 特征 | 推荐产品组合 |
|------|------|------|
| 🌅 启蒙期 | 新概念·新市场 | 五维自评+白皮书+行业报告 |
| 📈 扩张期 | 资本涌入·快速成长 | 匹配引擎+分割饼+卡牌对局 |
| 🏛️ 成熟期 | 稳定竞争·效率为王 | 退出指引+元合伙+完整诊断 |
| 🔄 转型期 | 技术颠覆·业务重塑 | 决策剧场+危机模拟+全面诊断 |

#### 企业成长阶段
| 阶段 | 特征 | 合伙人核心问题 | 推荐产品 |
|------|------|------|------|
| 💡 想法期 | 0→1，只有Idea | 找谁合伙？ | 五维自评+匹配引擎 |
| 🚀 初创期 | 1→10，PMF验证中 | 股权怎么分？ | 分割饼+卡牌对局+自检清单 |
| 🏢 扩张期 | 10→100，团队膨胀 | 信任还在吗？ | 四骑士+温度计+Pre-0 |
| 🏭 成熟期 | 100→N，多层管理 | 怎么退出？ | 退出指引+元合伙+完整诊断 |

#### 合伙人关系成熟度
| 阶段 | 特征 | 典型问题 | 推荐产品 |
|------|------|------|------|
| 🤝 蜜月期 | 刚认识·充满期待 | 怎么确定对方合适？ | 五维自评+雷达图 |
| ⚡ 磨合期 | 开始出现分歧 | 我们的分歧是正常的吗？ | 卡牌对局+四骑士 |
| 🧊 冰冻期 | 沟通减少·暗流涌动 | 说不出的不对劲 | 温度计+Pre-0+危机模拟 |
| 🔥 危机期 | 公开冲突·考虑分手 | 要不要散伙？ | 退出指引+完整诊断 |
| 🕊️ 重建期 | 分手后重新开始 | 怎么避免重蹈覆辙？ | 元合伙+案例库+白皮书 |

## 四、实施路线图

### 第一阶段: 数据层重构
1. entities_index 新增 `product_path_matrix` 字段（左脑/右脑×五维×市场×企业×关系 五维矩阵）
2. 每个产品标注：left_right(左/右/双), market_stage, company_stage, relationship_stage
3. 精品产品打标 `tier`: "premium"

### 第二阶段: 驾驶舱升级
1. 产品面板新增「左脑/右脑」切换视图
2. 新增「路径导航」面板——客户输入自己的情况 → 推荐产品组合
3. 客户旅程面板整合多维路径矩阵

### 第三阶段: 品牌首页优化
1. 英雄区增加「你是哪种决策者？」快速分诊
2. 产品展示区按左脑/右脑两列布局
3. 客户维度筛选项（市场/企业/关系）

### 第四阶段: product-catalog.html 重写
1. 精品产品优先展示
2. 多维筛选（左脑/右脑 + 市场阶段 + 企业阶段 + 关系阶段）
3. 隐藏知识库和内部资产（仅驾驶舱可见）
