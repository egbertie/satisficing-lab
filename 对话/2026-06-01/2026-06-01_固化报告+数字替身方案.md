## 数字替身·软件工程角色升级方案

### 一、问题诊断

当前"代码工程师"角色的问题：
- 职责边界模糊：一个人负责所有工程工作，导致代码修改缺少审核
- 没有分工：架构设计、代码实现、质量检查、部署管理混在一起
- 没有规范：改动后缺少回归验证、缺少版本审计

### 二、升级方案：将1个"代码工程师"拆分为5个专业角色

| 角色 | 职责 | 触发场景 |
|------|------|------|
| **软件架构师** | 系统设计·技术选型·架构决策·重构蓝图 | 重大改动前·架构讨论 |
| **前端工程师** | HTML/CSS/JS实现·响应式·交互 | 页面改动·驾驶舱增强 |
| **后端/数据工程师** | entities_index·Python脚本·Cron | 数据层改动·自动化 |
| **QA测试工程师** | 语法验证·链接检查·回归测试·性能 | 每次改动后 |
| **DevOps/发布经理** | 版本管理·部署·回滚·备份·监控 | 每次部署前 |

### 三、工程管理规范 (工程四步法)

```
任何系统改动必须经过四步：
① 软件架构师 审核设计方案
② 前端/数据工程师 实现改动
③ QA测试工程师 验证通过
④ DevOps发布经理 确认部署+验证+报告
```

违规处理：跳过任何一步的改动 → 自动回滚到最近的 stable tag

### 四、版本管理规范

| 规则 | 说明 |
|------|------|
| 大改前必打tag | `stable-YYYY-MM-DD-v{N}` |
| 改后必验证 | `dev.sh verify` 9项必须全通过 |
| 改后必有报告 | 同步到 `对话/YYYY-MM-DD/` |
| 上线必须确认 | 确认GitHub Pages CDN刷新完成 |

### 五、实施步骤

1. ✅ 固化当前版本为 `stable-2026-06-01-v13`
2. 升级数字替身：代码工程师 → 5专业角色
3. 后续每次改动：严格按工程四步法执行

### 六、关于AI Agent实施

- 主代理负责协调
- 关键改动由QA角色独立验证
