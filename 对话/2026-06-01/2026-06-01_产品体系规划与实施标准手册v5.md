### 1.2 产品形态分类（7种标准形态）

| 形态 | 缩写 | 定义 | 交付形式 | 典型产品 |
|------|:--:|------|------|------|
| **测评工具** | ASMT | 客户自评/自测获得个人化结果 | 在线问卷 → 即时报告 | 五维自评·温度计 |
| **交互工具** | INTR | 客户主动操作·互动中产生洞见 | 可交互Web页面 | 卡牌对局·决策剧场 |
| **诊断报告** | DIAG | 系统性评估输出可分享文档 | PDF/在线报告 | 化学报告·全面诊断 |
| **框架方法** | FRMW | 结构化思维框架或方法论 | 文章/白皮书/课程 | 五维框架·KKC框架 |
| **清单模板** | CHKL | 结构化自检或对照列表 | 在线清单/下载PDF | 决策前自检清单 |
| **案例研究** | CASE | 真实或模拟案例的深度分析 | 文章/在线页面 | 案例库·张学武案例 |
| **知识资产** | KNWL | 参考性内容·支持其他产品 | 文档/图谱/术语 | 白皮书·知识库 |

### 1.3 产品在不同形态之间的转化关系

一个核心内容可以产生多个形态产品：

```
同一个核心洞见 "65%的创业失败源于合伙人冲突"
  │
  ├── ASMT: 五维自评（测评工具）
  ├── INTR: 卡牌对局（交互工具）
  ├── DIAG: 化学报告（诊断报告）
  ├── FRMW: 五维决策框架白皮书（框架方法）
  ├── CHKL: 合伙人决策前自检清单（清单模板）
  ├── CASE: 真实案例·某硬科技团队（案例研究）
  └── KNWL: 决策方法论知识库（知识资产）
```

## 二、产品命名规范（标准）

### 2.1 命名原则

| 原则 | 说明 | 好案例 | 坏案例 |
|------|------|------|------|
| **可秒懂** | 客户3秒理解产品做什么 | 五维自评 | 综合决策辅助系统V2 |
| **可搜索** | 关键词在名称中 | 合伙人决策卡牌 | 卡牌 |
| **可区分** | 一眼区分于其他产品 | 决策剧场 / 危机模拟 | 决策工具A / 决策工具B |
| **可记住** | 朗朗上口·不拗口 | 分割饼 | 股权贡献量化分配工具 |
| **有画面** | 名称本身是隐喻 | 四骑士 / 温度计 | 合伙人关系评估工具 |

### 2.2 命名模式（5种标准模式）

#### 模式1: 数字+概念（创建认知锚点）
```
五维自评 · 五维雷达图 · 五维决策框架
十三种冲突类型学 · 四层诊断模型
```
**规则**: 数字→概念，让客户形成"五维=满意解"的品牌锚。

#### 模式2: 隐喻+功能（一眼知道做什么）
```
决策剧场 · 分割饼 · 关系温度计 · 四骑士
```
**规则**: 隐喻在前·功能在后，或隐喻即功能。

#### 模式3: 动词+对象（明确行动）
```
匹配引擎 · 退出指引 · 危机模拟
```
**规则**: 动词必须是客户会主动想做的动作。

#### 模式4: 场景+形式（触发共鸣）
```
合伙人决策前自检清单 · 30分钟轻咨询
```
**规则**: 场景必须精准匹配客户当前境遇。

#### 模式5: 深度+原著（学术背书）
```
深度·合伙人困境(Wasserman) · 深度·团队五障(Lencioni)
```
**规则**: "深度·"前缀 + 作者名，建立学术权威。

### 2.3 禁止的命名方式

| ❌ 禁止 | 原因 | 替代建议 |
|------|------|------|
| 技术术语 | 客户不理解 | 用隐喻替代 |
| 版本号在标题 | 显得不稳定 | 版本号放在metadata |
| 内部代号 | 客户完全不明白 | 对外用统一产品名 |
| 过长名称(>10字) | 记不住 | 精简到核心概念 |
| 拼音/英文混搭 | 不专业 | 纯中文或统一双语 |

### 2.4 命名检查清单
- [ ] 3秒能明白做什么？
- [ ] 能联想到一个画面？
- [ ] 和朋友介绍时不会尴尬？
- [ ] 在搜索引擎能找到？
- [ ] 不和现有产品混淆？

## 四、客户产品推荐标准

### 4.1 推荐逻辑（五维矩阵）

推荐一个产品给客户时，必须同时满足至少3个维度：

| 维度 | 权重 | 评估方法 |
|------|:--:|------|
| **客户阶段** | 30% | 发现→评估→尝试→深入→共契 |
| **左脑/右脑偏好** | 25% | 客户自评结果中的直觉阈vs可行域得分 |
| **关系成熟度** | 20% | 蜜月→磨合→冰冻→危机→重建 |
| **企业阶段** | 15% | 想法→初创→扩张→成熟 |
| **市场阶段** | 10% | 启蒙→扩张→成熟→转型 |

### 4.2 推荐规则引擎

**规则1: 永远从五维自评开始**
除非客户已完成自评，否则所有推荐路径的第一步必须是五维自评。

**规则2: 左脑型客户优先推荐结构化工具**
```
如果 可行域得分 > 直觉阈得分 > 20分差:
  推荐: 自检清单 → 分割饼 → 完整诊断 → 退出指引
```

**规则3: 右脑型客户优先推荐体验式工具**
```
如果 直觉阈得分 > 可行域得分 > 20分差:
  推荐: 卡牌对局 → 决策剧场 → Pre-0 → 危机模拟
```

**规则4: 平衡型客户推荐融合产品**
```
如果 |可行域-直觉阈| < 20分差:
  推荐: 五维雷达图 → 全面诊断 → 元合伙 → 案例库
```

**规则5: 危机期客户跳过轻量产品**
```
如果 关系阶段 = "危机期":
  推荐: 完整诊断 → 退出指引（跳过自评/卡牌/清单）
```

**规则6: 每个产品后必须有CTA**
```
CTA格式: "下一步: [推荐产品名]"
CTA规则: 上一条用完立即推荐下一条
```

### 4.3 推荐话术标准

| 场景 | 话术模板 |
|------|------|
| 新客户首次访问 | "65%的创业失败源于合伙人冲突。3分钟，先了解你的决策模式 → 五维自评" |
| 完成自评后 | "你的决策模式偏[左脑/右脑/平衡型]。基于你的情况，我们建议下一步试试[产品名]" |
| 使用一个产品后 | "你刚完成了[产品名]。90%的使用者在接下来选择了[产品名]" |
| 客户犹豫时 | "不需要一次决定。试一个，看看是否对你有帮助" |
| 危机场景 | "我们理解现在的情况很困难。你已经迈出了最难的一步——正视问题" |

## 六、产品审核标准（Keep-Kill-Combine 修改版）

### 6.1 评分维度

| 维度 | 权重 | 精品(≥80) | 线上(60-79) | 知识库(40-59) | 内部(<40) |
|------|:--:|------|------|------|------|
| 客户价值 | 30% | 直接解决客户核心痛点 | 对特定场景有用 | 参考价值 | 仅内部使用 |
| 完成度 | 25% | 完整可交付·无已知BUG | 功能完备·小问题 | 框架已齐·待完善 | 概念或草稿 |
| 设计规范 | 15% | 严格遵循VI标准 | 基本遵循VI | 部分遵循 | 未遵循 |
| 数据支撑 | 10% | 有真实数据或引用 | 有概念支撑 | 纯理论 | 无 |
| 更新频率 | 10% | 近30天更新过 | 近90天更新过 | 近180天更新过 | 超过180天 |
| 客户反馈 | 10% | 有正面反馈记录 | 无负面反馈 | 无反馈 | 无 |

### 6.2 决策类型

**Keep (保留·精品/线上)**: 评分≥60 → 继续迭代优化
**Kill (下架)**: 评分<40 或 重复度>70% → 归档为内部
**Combine (合并)**: 两个产品功能重合度>50% → 合并为一个
**Archive (归档)**: 历史版本·已被替代 → 移入知识库

## 七、同内容多形态转化标准

### 7.1 转化矩阵

对于同一个核心内容，按以下矩阵决定产出哪些形态产品：

```
            │ 左脑客户          │ 右脑客户
────────────┼───────────────────┼──────────────────
 发现阶段   │ ASMT(测评)        │ INTR(交互)
 评估阶段   │ DIAG(诊断)+CHKL   │ CASE(案例)+INTR
 尝试阶段   │ FRMW(框架)        │ INTR(交互)+ASMT
 深入阶段   │ DIAG(诊断)+CHKL   │ CASE(案例)+FRMW
 共契阶段   │ KNWL(知识)        │ CASE(案例)+INTR
```

### 7.2 转化示例：五维决策框架

| 形态 | 产品 | 客户获取方式 |
|------|------|------|
| ASMT | 五维自评(简版19题) | 品牌首页·免费·即时 |
| ASMT | 五维自评(完整版59题) | 深入阶段·预约获取 |
| DIAG | 五维雷达图 | 完成自评后即时生成 |
| FRMW | 五维决策框架白皮书 | 下载·留邮箱获取 |
| CHKL | 合伙人决策前自检清单 | 免费在线使用 |
| INTR | 决策剧场 | 线上交互体验 |
| CASE | 案例·某硬科技团队的合伙人危机 | 案例库浏览 |
| KNWL | 五维框架知识库条目 | 驾驶舱参考 |
