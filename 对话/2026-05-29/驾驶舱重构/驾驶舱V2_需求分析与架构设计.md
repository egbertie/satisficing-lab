> 版本: V2.0 | 时间: 2026-05-29 23:45 CST

### 1.2 飞书驾驶舱需要融合的内容

| 飞书模块 | 数据量 | 核心价值 | 融合方式 |
|----------|:------:|----------|----------|
| 任务决策驾驶舱 V1.7 | 1个主表 | 满天星光天数、血液化等级、四Week进度 | 核心KPI区 |
| 综合评分体系 | 95分制 | 量化管理质量 | 质量仪表 |
| 关键产出统计 | 14 Skill/17 扣眼/50+质量文档 | 产出追踪 | 产出看板 |
| 血液化进度 L0-L4 | 5级体系 | Agent能力成长 | 替身管理 |
| 产品库（195+条目） | 195+ | 全产品资产管理 | 产品Dashboard |
| 客户库（26+条目） | 26+ | 客户关系追踪 | 客户Dashboard |

### 1.3 关键缺陷

1. **数据孤岛** — localStorage种子数据是一次性写入，无同步机制，信息陈旧
2. **只读展示** — 无法从驾驶舱直接创建/编辑/分配任务
3. **静态数据** — 财务、增长、系统监控等tab数据是硬编码占位
4. **无关联视图** — 任务-客户-产品-替身之间无交叉关联
5. **无预警机制** — 没有截止日期告警、P0堆积告警、里程碑延期告警
6. **无时间轴** — 看不到历史趋势，只有当前快照
7. **无角色视图** — 所有数据平铺，没有「我的任务」「P0聚焦」「今日概览」等用户视角

## 三、架构设计

### 3.1 四层信息架构（对标行业最佳实践）

参考 Alistair Cockburn 的「Information Radiator」理念 + 2026 Dashboard Design Trends：

```
┌─────────────────────────────────────────────────┐
│  L0 · 脉搏层 (Status Bar)                        │
│  倒计时 · 健康灯 · 活跃Cron · 最后同步时间       │
│  这一行永远可见 · 1秒判断"系统是否活着"           │
├─────────────────────────────────────────────────┤
│  L1 · 态势层 (Situation Overview)                │
│  KPI矩阵· P0红区· 里程碑进度· 异常告警           │
│  30秒扫读完 · 知道"哪里需要我关注"                │
├─────────────────────────────────────────────────┤
│  L2 · 操作层 (Actionable Workspace)              │
│  任务/客户/产品/替身/质量 — 可切换 · 可操作       │
│  数据筛选 · 状态变更 · 快速新增 · 批量操作        │
├─────────────────────────────────────────────────┤
│  L3 · 洞察层 (Deep Dive)                         │
│  关联分析 · 趋势图表 · 交叉视图 · 导出报告        │
│  需要深入分析时才展开                             │
└─────────────────────────────────────────────────┘
```

## 四、分期实施路线

### Phase 1 · 心脏重建 (2-3天)

**目标**：建立可操作的指挥中枢核心

- [ ] 新建 `dashboard-v2.html`，独立于 V1 并行开发
- [ ] 四层布局（脉搏层+态势层+操作层+洞察层）
- [ ] 数据模型重构：从 `localStorage` 种子数据升级为结构化数据层
- [ ] 任务CRUD：新增/编辑/删除/状态流转/筛选/搜索
- [ ] 截止日期预警（红色=已过期，黄色=3天内，绿色=正常）
- [ ] KPI矩阵实时计算（不再硬编码完成率等数字）
- [ ] 密码门复用 sessionStorage 方案

### Phase 2 · 数据融合 (2-3天)

**目标**：把飞书驾驶舱的所有有效数据融入

- [ ] 飞书任务(195条)全量导入，字段对齐
- [ ] 客户库(26条)完整导入 + 关联任务
- [ ] 血液化等级 L0-L4 可视化
- [ ] 四Week进度历史 + 综合评分趋势
- [ ] 满天星光/连续执行天数实时计算
- [ ] 产品资产(195+)从 product-catalog 关联

### Phase 3 · 智能增强 (3-5天)

**目标**：从「展示」升级为「预警 + 建议」

- [ ] 异常自动检测（P0堆积、里程碑延期、Cron掉线）
- [ ] 每日摘要：今日概览 + 待办提醒 + 异常告警
- [ ] 关联视图：客户→关联任务、产品→关联客户
- [ ] 时间轴：任务完成趋势、客户增长曲线
- [ ] 替身活跃度追踪（23替身激活次数+贡献值趋势）
- [ ] 导出报告（PDF/飞书文档）

### Phase 4 · 心脏连通 (持续)

**目标**：驾驶舱成为全站信息的真实心脏

- [ ] 与飞书Base API实时同步
- [ ] 从任何产品页面可一键回到驾驶舱
- [ ] 驾驶舱内可直达任何产品/客户/替身详情页
- [ ] Webhook接收外部事件（新客户注册、任务完成、告警触发）

## 五、设计原则（对标全球最佳实践）

### 来自 2026 Dashboard Design Trends 的可落地原则

| 原则 | 来源 | 落实方式 |
|------|------|----------|
| **先问决策，后画图表** | Alistair Cockburn | 每个模块回答一个问题：「看完这个，用户做什么决定？」 |
| **30秒扫读规则** | Information Radiator | L1 态势层保证不必滚动、不必点击、30秒内完成态势感知 |
| **异常驱动设计** | DHCS Medi-Cal案例 | 正常状态不打扰，异常状态才高亮——减少认知负荷 |
| **渐进披露** | WCAG 2.2/认知负荷理论 | L0→L1→L2→L3逐层深入，不在一屏堆满所有信息 |
| **用户视角优先** | Gartner 2026 Agent预测 | 默认展示「我的P0」「今日概览」「异常告警」——不是全量罗列 |
| **配对颜色+形状** | 无障碍设计 | 红黄绿三色始终配对图标/文字，不单靠颜色传达含义 |
| **一致性优先** | 认知负荷理论 | 统一的卡片样式、统一的表格规范、统一的色彩语义 |
| **可操作，不仅是可查看** | 行动导向设计 | L2层的每个数据项都可点击、可编辑、可流转状态 |

### 来自 Joel Test 的工程质量标准

| Joel Test 条目 | 驾驶舱 V2 落实 |
|:---|:---|

## 六、技术决策

| 决策 | 方案 | 理由 |
|------|------|------|
| 部署方式 | 单文件 HTML+CSS+JS | 零依赖，GitHub Pages直出 |
| 数据存储 | localStorage + 结构化模型 | 无需后端，离线可用 |
| 密码认证 | sessionStorage 6位明文 | 已验证可靠，跨浏览器一致性 |
| 数据同步 | 种子预填充 + 手动导入/导出JSON | Phase 1-2不使用API（避免复杂度） |
| 渲染模式 | 纯 JS innerHTML | 已验证的 product-catalog 模式 |
| 事件处理 | `onclick="fn(args, this)"` | 已验证可靠，不依赖 event.target |
| 图表可视化 | 纯CSS进度条 + SVG迷你图 | 不引入 Chart.js/D3 依赖 |
| 响应式 | 桌面优化，最低1200px | 驾驶舱是桌面专用工具 |
| 字体 | 系统字体栈，12-14px为主 | 可读性与密度平衡 |

## 七、数据模型 V2

```javascript
// === 核心实体 ===

// 任务 (升级: 新增负责人/分类/关联/日志)
Task {
  id, task, priority, status, deadline, assignee,
  category, // '产品'|'技术'|'运营'|'学习'|'客户'|'系统'
  relatedCustomer, relatedProduct, // 交叉关联
  created, updated, completed, // 时间戳
  log[] // 状态变更历史

// 客户 (升级: 新增阶段/来源/关联任务列表)
Customer {
  id, name, company, role,
  stage, // '触达'|'试用'|'付费'|'流失'
  source, // '转介绍'|'公众号'|'飞书'|'其他'
  relatedTasks[], // 关联任务ID
  notes, lastContact, nextFollowUp
}

// 产品 (升级: 新增成熟度/版本/在线状态/关联客户)
Product {
  id, name, family, // 章·衡·镜·契·觉
  maturity, // '概念'|'原型'|'线上'|'精品'|'废弃'
  status, url, version,
  relatedCustomers[]
}

// 替身 (升级: 23替身全量)
Avatar {
  id, name, tier, // L0-L5
  element, dimension, // 五行·五维
  activationCount, contributionScore,
  lastActivation, status,
  filePath
}

// 里程碑 (升级: 关联任务)
Milestone {
  id, name, targetDate, status,
  relatedTasks[], progress // 0-100%
}

// 质量指标 (升级: 27条全量)
QualityMetric {
  id, standard, status, // '通过'|'55%'|'待执行'
  priority, category, target, actual

// 决策日志 (新增)
DecisionLog {
  id, date, decision, context,
  preMortemResult, postMortemResult,
  relatedTasks[], relatedCustomers[]
```
