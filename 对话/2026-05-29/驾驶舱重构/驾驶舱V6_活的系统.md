## 零、第一性原理的追问

在写任何方案之前，我问自己：

1. **这个系统如果不被任何人打开，它还能做什么？**
   V1-V4 答案：什么也做不了（面板等人看）
   V6 答案：呼吸、消化、感知、自愈、生长

2. **这个系统最本质的功能是什么？**
   不是「展示信息」，是**维持一个组织的内稳态**——在环境不断变化中，保持核心参数在可接受范围内

3. **为什么用生物作类比而不是机器？**
   机器被设计，生物在生长。机器需要操作员，生物自主运转。机器坏了就停，生物受损会自愈。

### 1.1 边界（细胞膜）——「我是谁」

```
┌─────────────────────────────────────────────┐
│              满意解研究所 · 系统边界            │
│                                             │
│  ┌─────────┐  ┌─────────┐  ┌─────────┐      │
│  │ 文件系统 │  │ Git仓库  │  │ 飞书空间 │      │
│  │ 8122文件 │  │ 126提交 │  │ API连接 │      │

│                                             │
│  内部的: 可以被系统直接读写和调控              │
│  外部的: 只能感知和响应，不能直接控制          │
│  （用户行为、市场变化、竞品动态...）           │

```

**边界的作用**: 
- 定义「什么属于这个系统」
- 控制「什么可以进入」
- 区分「内部调控」和「外部适应」

### 1.2 三大脑系统

**大脑（中央神经系统）— 显意识决策**

```
功能：策略、规划、优先级、资源分配
位置：驾驶舱V6 的「决策面板」
特点：慢、精确、消耗能量、需要注意力
触发：人打开驾驶舱时 / 遇到重大异常时
```

**心脏（自主神经系统）— 无意识自动运转**

```
功能：心跳、呼吸、体温调节、血压维持
位置：Cron系统 + 事件总线 + 自动管道
特点：快、自动、不消耗注意力、24/7运行
触发：时间驱动 + 事件驱动，从不需要人干预

心脏的不同步：即使驾驶舱页面从未被打开，心脏仍在跳：
- 文件扫描 → 发现新资产
- 术语检查 → 发现不一致
- P0监测 → 发现堆积
- Cron健康 → 检测失败
这些都不需要人。系统自己知道。
```

**肠脑（肠道神经系统）— 自动消化与感知**

```
功能：消化外部信息、提取营养、排出废物、感知饱饿
位置：资产激活管道 + 知识提取管道
特点：半自主、可以不听大脑指挥

肠脑的五阶段消化过程：
1. 摄入 (Ingestion)     → 扫描新文件、接收新对话、获取飞书更新
2. 消化 (Digestion)     → 提取元数据、分类、摘要、标签
3. 吸收 (Absorption)    → 结构化数据存入「血液」= localStorage/JSON
4. 同化 (Assimilation)  → 新知识融入已有知识图谱、更新内部模型
5. 排泄 (Excretion)     → 归档无用文件、合并重复、删除过期数据
```

### 1.3 内稳态（Homeostasis）— 核心参数的自稳定

系统定义了 **七个必须维持在可接受范围内的核心参数**：

| # | 内稳态参数 | 理想范围 | 低于阈值 | 高于阈值 | 监测方式 |
|---|-----------|---------|----------|----------|----------|
| 1 | **术语一致性** | =100% | 自动触发术语同步 | — | 每6h扫描 |
| 2 | **P0堆积深度** | <5个 | — | 自动创建减压任务、建议暂停低优先级 | 每小时检查 |
| 3 | **数据完整度** | >70% | 触发资产扫描、标记空白面板 | — | 每日检查 |
| 4 | **备份新鲜度** | <24h | 自动执行备份 | — | 每小时检查 |
| 5 | **Cron健康度** | 100% | 自动重试、告警、降级 | — | 每30min检查 |
| 6 | **知识消化率** | >50% | 调整扫描频率和分类策略 | 增加管道容量 | 每周检查 |
| 7 | **产出节奏** | >3次/周 | 生成激励任务、提醒活跃 | — | 每周检查 |

**内稳态机制**: 不等人发现问题才行动。系统自己持续监测，当参数偏离理想范围时，自动采取纠正行动。

### 1.4 免疫系统 — 识别与防御

```
三层防御体系：

L1 · 皮肤（物理屏障）
  - pre-commit hook: commit前阻止有问题的代码进入仓库
  - gate.html: 未经授权无法访问内部系统

L2 · 先天免疫（模式识别）
  - 自动扫描: event.target / crypto.subtle / 密码泄露
  - 术语一致性扫描: 发现不一致的品牌表述
  - 数据完整性检查: 发现损坏或空白的localStorage

L3 · 获得性免疫（学习记忆）
  - 每次修复后，将模式加入检测规则
  - 每次回滚后，自动标记「已知缺陷模式」
  - 每次成功修复后，生成「免疫记忆」供未来参考
```

### 1.5 昼夜节律（Circadian Rhythm）

```
一日的生命节律:

04:00 · 黎明前扫描
  - 检查Cron整夜状态
  - 扫描夜间文件变化
  - 生成「昨日数据」

06:00 · 苏醒 (日起课)
  - 启动日间活跃模式
  - 生成今日待办摘要
  - 推送: 「早上好，昨天发生了3件事，今天有2个P0」

08:00-18:00 · 活跃期
  - 全功能运转
  - 实时响应事件和操作
  - 不主动打扰（除非紧急）

19:00-22:00 · 回顾期
  - 汇总今日变更
  - 更新知识图谱
  - 生成质量报告

22:00 · 日毕课
  - 当日产出统计
  - 学习进度更新
  - 推送: 「今天做了5件事，P0剩余2个」

23:00-04:00 · 休眠维护
  - 不出打扰（除非系统级紧急）
  - 执行后台维护: 备份、压缩、归档
  - 资产管道批处理
```

### 1.7 环境交换（Respiration）— 与外部世界的双向流动

```
吸入 (Inhalation):
  飞书环境 → 新文件流入
  扣子通信 → 技术知识流入
  外部学习 → 方法论流入
  客户反馈 → 需求流入

呼出 (Exhalation):
  产品更新 → 推送到GitHub Pages
  状态报告 → 推送给Egbertie
  飞书同步 → 推送到飞书Base
  术语传播 → 推送到全站页面

摄入 (Feeding):
  文件下载 → 资产管道
  新对话记录 → 知识提取
  外部搜索 → 学习记录

排泄 (Excretion):
  过期数据 → 归档
  重复文件 → 合并/删除
  废弃产品 → 标记为deprecated
  冗余代码 → 清理
```

### 1.8 生殖与生长（Growth & Evolution）

一个活体系统不仅仅是维持现状——它会生长、进化、变得更适应环境。

```
生长循环:

1. 扩展期 (Expansion)
   - 新文件增加 → 资产膨胀
   - 新客户加入 → 关系网络扩大
   - 新产品上线 → 产品矩阵增长
   - 新知识吸收 → 知识图谱丰富

2. 巩固期 (Consolidation)
   - 重复去重 → 精简
   - 结构整理 → 优化
   - 质量提升 → 精品化
   - 连接建立 → 深化

3. 进化期 (Evolution)
   - 新模式发现 → 能力升级
   - 工具改进 → 效率提升
   - 方法优化 → 管道迭代
   - 自我反思 → 战略调整
```

## 三、器官间的对话协议

### 3.1 心脏→大脑：「有异常需要你关注」

```
心脏(自主): 检测到P0堆积 > 5个
  ↓ 发送信号: { type: 'homeostasis.alert', param: 'p0_depth', value: 7 }
大脑(决策): 接收信号 → 评估 → 决定：
  - 自动暂停低优先级任务
  - 生成P0减压方案
  - 如果人在线 → 推送通知：「P0堆积到7个，建议暂停2个P2任务」
```

### 3.2 肠脑→大脑：「发现了新的营养来源」

```
肠脑(消化): 扫描96个扣子新文件 → 提取7个产品化建议
  ↓ 发送信号: { type: 'digestion.discovery', items: 7, confidence: 0.8 }
大脑(决策): 接收信号 → 排队 → 等待人确认或自动采纳高可信度建议
```

### 3.3 肠脑→心脏：「消化速度跟不上摄入速度，需要调整」

```
肠脑(消化): 未处理文件积压 > 500
  ↓ 发送信号: { type: 'digestion.backlog', count: 523 }
心脏(自主): 收到信号 → 自动增加扫描频率或降低摄入速率
```

### 3.4 免疫→大脑：「发现威胁，已自动处理」

```
免疫(L2扫描): 发现3个页面残留 'event.target'
  ↓ 如能自动修复 → 自动修复 → 报告: { type: 'immune.fix', count: 3, status: 'healed' }
  ↓ 如无法自动修复 → 报告: { type: 'immune.threat', count: 3, status: 'needs_attention' }
```

### 3.5 内部模型→大脑：「现实与理想有差距」

```
selfModel: 数据完整度应该是 >80%
实际状态: 数据完整度 = 8%
  ↓ 差距: 72%
大脑: 评估 → 生成数据初始化任务 → 优先队列
```

## 四、对人类（Egbertie）的界面

### 4.1 人类不是操作者，是共生伙伴

之前所有版本的隐含假设: 人操作驾驶舱，A辅助。

**V6 的新关系**: 系统和人是对等的共生伙伴。

```
只有当以下三种情况发生时，系统才主动接触人类:
1. 超出自动处理范围（需要人的判断）
2. 发现了值得分享的洞察（让人惊喜）
3. 系统自身状态需要人了解（透明度）
```

### 4.2 三种接触模式

| 模式 | 触发条件 | 形式 | 示例 |
|------|----------|------|------|
| **报平安** | 一切正常时，按节律 | 日毕课/周报 | 「今天一切正常，P0为0，昨晚发现了3个新资产连接」 |
| **问决策** | 需要人做判断 | 待确认列表 | 「7个产品化建议，建议优先2个P0，是否确认？」 |
| **求助** | 遇到自身无法处理的问题 | 告警 | 「飞书API掉线超过1小时，已自动降级，需要手动干预」 |

## 六、实施路径

### Phase 0 · 赋予生命（1-2天）

**目标**: 先让系统活起来，哪怕是最简单的生命

- [ ] 建立「心脏」：Cron心跳机制（30min频率）
- [ ] 建立「节律」：日起课(06:00) + 日毕课(22:00)
- [ ] 建立「自我感知」：7个内稳态参数的首次测量
- [ ] 建立「内部模型」：selfModel JSON，明确定义理想状态
- [ ] 建立「呼吸」：Git push/pull + 飞书API连通

### Phase 1 · 消化系统（3-5天）

**目标**: 系统能够自主消化外部信息

- [ ] 建立「摄入」：文件系统扫描 + 飞书API拉取
- [ ] 建立「消化」：元数据提取管道
