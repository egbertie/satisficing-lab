## 二、最关键的缺失：授权与计费中枢

这是你强调的——密码不只是密码，而是整个产品体系的授权和计费引擎。

### 2.1 行业对标

| 概念 | 来源 | 含义 | V4 落实 |
|------|------|------|---------|
| Entitlement Management | Schematic (2026) | 根据付费计划控制用户能访问什么 | ✅ 授权引擎核心 |
| Metered Usage | 38% SaaS公司采用 | 按实际用量计费 | ✅ 用量追踪 |
| Plan & Packaging | SaaS Pricing 2026 | 套餐结构定义包含什么 | ✅ 套餐管理 |
| Seat-based | 传统B2B | 按席位授权 | ✅ 多客户授权 |
| Usage-based | 增长最快模式 | 按调用次数/使用时长 | ✅ 用量计费 |
| Time-limited | 试用/订阅 | 时间段内有效 | ✅ 期限管理 |
| Trial → Paid | PLG 2026 | 试用自动到期→付费转化 | ✅ 试用管理 |
| Feature Flag | 现代SaaS | 按套餐开启/关闭功能 | ✅ 功能开关 |

### 2.2 授权维度矩阵

一笔「产品授权」由以下维度组合决定：

| 维度 | 说明 | 示例 |
|------|------|------|
| **产品范围** | 授权哪些产品 | 单一产品 / 产品组(如「章·衡·镜」) / 全站 |
| **使用次数** | 可使用多少次 | 1次 / 10次 / 无限次 |
| **时间范围** | 授权有效期 | 7天试用 / 30天 / 1年 / 永久 |
| **用户数量** | 可几人使用 | 1人 / 5人(团队) / 无限(企业) |
| **功能层级** | 基础版还是高级版 | 基础 / 专业 / 企业(含不同功能集) |
| **数据权限** | 能看到什么数据 | 仅自己 / 团队 / 全部 |
| **API配额** | API调用次数 | 100次/月 / 1000次/月 / 无限制 |
| **白标权限** | 是否可去品牌化 | 是 / 否 |
| **导出权限** | 是否可导出报告 | 预览 / 下载PDF / API访问 |
| **支持级别** | 客服响应级别 | 社区 / 邮件 / 专属专家 |

### 2.5 密码生成算法

```
密码 = 前缀 + 哈希(产品ID + 客户ID + 套餐ID + 生成时间 + 密钥)

示例：
  产品: decision-theatre (DT)
  客户: 硬科技创始人-A (HC-01)
  套餐: 单次体验 (PKG-001)
  
  → 密码: DT-X7K9M2 (8位字母数字)
  
  验证时:
  gate.html → 读取密码 → 解码→ 检查:
    ① 产品ID是否匹配当前页面
    ② 客户ID是否有效
    ③ 套餐是否未过期
    ④ 使用次数是否未超限
    ⑤ 时间是否在有效期内
```

当一位管理者打开驾驶舱，ta 的心理路径是：

```
1. "一切正常吗？"           → L0 生命线 (3秒扫完)
2. "有什么需要我注意的？"    → L1 态势层 (30秒扫完)
```

### 7.2 每个产品页面的授权流程

```
用户访问产品页面
  ↓
gate.html 拦截（无需密码的L1/L2页面跳过）
  ↓
输入授权密码
  ↓
解码 → 验证:
  ✅ 产品ID是否匹配
  ✅ 客户ID是否有效
  ✅ 套餐是否在有效期内
  ✅ 使用次数是否未超限
  ✅ 功能层级是否满足
  ↓
通过 → 进入产品 | 不通过 → 提示（过期/超限/无效）
  ↓
使用记录回传驾驶舱（用量+1）
```
