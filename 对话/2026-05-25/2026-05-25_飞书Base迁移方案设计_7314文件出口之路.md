# 飞书Base迁移方案设计 · 7314文件的出口之路

> 日期: 2026-05-25
> 相关: 扣子资料整理 · API限制调查
> 后续: 5/29完成全量下载（7410文件/92.6MB）

---

## 背景

扣子阶段的7314个文件（92MB）存储在飞书Base中，需要在满意解研究所独立后全量迁移到本地。但飞书API存在两个已知限制：
1. **文件列表分页限制**：`lark-cli drive files list` 每文件夹最多100条，无法翻页
2. **并发下载限制**：`lark-cli drive +download` 在大批量并发时大量失败

这一问题直到5/29才被解决（通过 `lark_oapi` SDK的 `drive.v1.file.list + next_page_token` 突破分页，通过REST API `drive/v1/files/{token}/download` 稳定下载）。但5/25当天已经开始了调研和方案设计。

---

## 过程

### 技术调研

| 工具 | 能力 | 限制 | 结论 |
|:--|:--|:--|:--:|
| lark-cli drive files list | 列出文件夹内容 | 最多100条·无翻页 | ❌ 不适用 |
| lark_oapi SDK | 文件列表+分页 | 200条/页·需编程 | ⚠️ 需要额外的适配代码 |
| feishu-docx 客户端 | 自动翻页 | 内部8页合并 | ✅ 部分适用（用于读取文档） |
| REST API drive/v1/files/download | 单个文件下载 | 稳定可靠 | ✅ 最终采用 |

### 方案设计

1. **分阶段迁移**：先迁移核心技术文档（满意姐论文·评分引擎·卡牌原型），再迁移完整飞书空间
2. **去重策略**：文件名+大小+MD5三重去重
3. **历史归档**：保留扣子阶段14个原始目录的完整历史副本

---

## 成果

虽然5/25当天未完成实际下载，但明确了技术路线。这一天的调研为5/29的突破性下载（用 `lark_oapi` SDK一次性完成7314文件+96个历史独有补充=7410文件92.6MB）奠定了基础。

### 关键认知

- **选对工具 > 反复尝试**：`lark-cli` 折腾了两天（5/25-5/27），最后发现 `lark_oapi` SDK 一次搞定 → 这是5/29经验总结中「工具优先于修修补补」原则的早期验证
- **去重逻辑在下载前设计**：MD5三重去重避免了下载后的大量手动整理工作

---

## 教训

- 🔴 **API限制应尽早测试**：如果在扣子阶段就开始迁移测试，可以节省2-3天的等待时间
- 🟡 **分页限制是飞书API的已知盲区**：文档中未明确标注文件列表最多100条的限制，这是一个需要实际触发才能发现的隐藏限制
