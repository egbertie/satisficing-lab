## 一、核心根因

### 1. `event` 全局变量在现代浏览器中不可靠 ⚠️⚠️⚠️

**症状**：`onclick="switchTab('tasks')"` 内部使用 `event.target`，点击无任何反应。

**根因**：`event` 作为全局隐式变量是IE时代的遗留特性，Chrome/Safari现代版本在严格模式或某些安全策略下不再支持。

**解决方案**：**函数参数传递 `this`**
```html
<!-- ✅ 正确 -->
<button onclick="switchTab('tasks', this)">任务</button>
<script>
function switchTab(id, btn) {
  btn.classList.add('active');  // 直接用参数，不依赖event
}
</script>

<!-- ❌ 错误 -->
<button onclick="switchTab('tasks')">任务</button>
<script>
function switchTab(id) {
  event.target.classList.add('active');  // 不可靠！
}
</script>
```

**影响范围**：case.html的filter函数、dashboard.html的switchTab、所有有tab切换/筛选按钮的页面。

**检测方法**：`grep -rn 'event\.target' site/*.html`

---

### 2. Web Crypto API（SHA-256）在某些环境下静默失败 ⚠️⚠️

**症状**：输入正确密码，没有任何反应，既不过也不报错。

**根因**：`crypto.subtle.digest('SHA-256', ...)` 在不同浏览器/HTTPS/本地文件协议下行为不一致。GitHub Pages上可能因安全策略静默失败。

**解决方案**：**内部工具用明文比对，不依赖加密API**
```javascript
// ✅ 正确：内部工具，明文足够
if (code === '123654') { openApp(); }

// ❌ 错误：依赖Web Crypto
var hash = await crypto.subtle.digest('SHA-256', ...);
if (hash === storedHash) { ... }
```

**影响范围**：gate.html、dashboard.html、所有密码验证页面。

---

### 3. `innerHTML` 重建DOM后，原绑定函数找不到新元素 ⚠️

**症状**：`openApp()` 里 `document.getElementById('app').innerHTML = '...'` 重建了整个DOM，但后续的 `document.getElementById('kpi')` 在新HTML中找到元素但函数引用错乱。

**根因**：老代码中有两套函数定义（min版旧st/log + 新引擎rt/rk/rc），innerHTML替换DOM后，旧函数试图操作旧元素，新函数找不到新元素。

**解决方案**：**一个script块，所有HTML直接写在body里，不要通过JS动态重建核心DOM**
```html
<!-- ✅ 正确：HTML直接写在body里，JS只改内容 -->
<div id="kpi"></div>
<div id="mc"></div>
<script>
document.getElementById('kpi').innerHTML = renderKPIs();
document.getElementById('mc').innerHTML = renderContent();
</script>

<!-- ❌ 错误：JS重建整个DOM -->
<script>
document.getElementById('app').innerHTML = '<div id="kpi"></div>...';
// 此时kpi刚刚被创建，但可能CSS/事件绑定还没就位
</script>
```

---

### 4. 多个script块容易互相干扰 ⚠️

**解决方案**：**一个HTML文件只有一个 `<script>` 块**，所有逻辑在同一个作用域。

## 二、已验证可工作的架构模式

### 产品库模式（最稳定，直接复用）

```html
<body>
  <!-- HTML全部在body里，不动态重建 -->
  <div class="filter-bar">
    <button onclick="filterFam('衡', this)">衡</button>
  </div>
  <div id="content"></div>
  
  <script>
    // 所有JS在一个块里
    function filterFam(fam, btn) {
      btn.classList.add('active');  // ✅ this传入
      document.getElementById('content').innerHTML = ...;
    }
  </script>
</body>
```

这个模式在 product-catalog.html 中验证通过，217个产品筛选切换正常。

## 四、GitHub Pages缓存注意事项

- GitHub Pages使用CDN缓存，更新可能延迟1-2分钟
- 强制测试：URL后加 `?v=数字` 参数绕过缓存
- `curl -sI` 检查 `last-modified` 确认是否已更新

## 补充：案例库的终极突破（22:38 解决）

**问题**：onclick="fil('股权', this)" 完全正确，函数定义也正确，在诊断页单独测试全部通过，但在完整页面中点击无反应。

**根因**：旧版HTML中残留的 `<style>` CSS、gate-check引用、以及多次修改遗留的代码碎片——虽然没有语法错误，但整体环境导致浏览器静默拦截了某些click事件。

**解决方案**：
1. 用极简诊断页逐一隔离测试每个组件（alert测试、this传参、数据、完整流程）
2. 确认诊断页全部✅后，用诊断模式完整替换目标页面
3. 删除所有旧CSS、旧script、旧标签残留
4. 保持代码极简——只留必要的style和JS

**教训**：当 "代码看起来完全正确但就是不工作" 时——
1. 先不怀疑代码逻辑
2. 怀疑HTML环境（CSS/残留标签/旧脚本）
3. 用极简诊断页逐一验证组件
4. 全部✅后用诊断模式替换整个页面
