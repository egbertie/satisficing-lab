## 二层到七层的具体落地

### L0 · 自身耐受（Self-Tolerance）

**生物类比**：免疫系统能够区分「自己的细胞」和「外来入侵者」。当这个机制失灵时，会出现自身免疫疾病——系统攻击自己的健康组织。

**系统对应**：我必须明确知道什么是「正常的我」，什么是「异常」。否则我会把合法的文件变更误报为威胁，或者把真正的入侵当作正常。

**落地方式**：

1. **基线快照**（Baseline Snapshot）：
   - 对 site/ 下的 248 个产品 HTML 建立 MD5 基线
   - 对核心配置文件建立内容基线
   - 任何偏离基线的变更 → 标记为「需要解释」，而非直接「威胁」

2. **白名单机制**：
   - dashboard-*.html（开发/测试版本）→ 已知的非生产文件，低优先级
   - 扣子资料/ 目录 → 历史档案，不纳入威胁扫描
   - .bak/ → 备份，不扫描

3. **「自我」边界定义**：
   ```javascript
   SELF_DEFINITION = {
     // 这些是我的核心器官——任何威胁都优先处理
     critical: ['site/index.html','site/dashboard*.html','site/gate.html',
                'site/product-catalog.html','site/cases.html','site/checklist.html'],
     // 这些是历史档案——不扫描
     archive: ['扣子资料_*/','site/.bak/','.git/'],
     // 这些是开发环境——容忍已知风险
     dev: ['dashboard-kozi-debug.html','dashboard-min.html','dashboard-v2.html']
   }
   ```

### L1 · 物理屏障（Physical Barriers）

**生物类比**：皮肤阻止病原体进入。胃酸杀死随食物进入的细菌。

**系统对应**：在威胁进入系统之前就阻止它。

**落地方式**：

1. **pre-commit 门禁**（已有）— 阻止包含 event.target / crypto.subtle 的代码提交
2. **新增：编辑前备份**（Pre-edit Backup）— 修改任何文件前自动备份
3. **新增：变更审批流**（Change Approval）— 核心文件的修改需要二次确认
4. **新增：破坏性操作确认**— `rm`/`force push`/`删除tag` 需要明确确认

```bash
# pre-commit hook 增强版
check_event_target()  # 已有
check_crypto()        # 已有  
check_backup_fresh()  # 新增：24h内是否有备份
check_critical_change() # 新增：是否修改了核心文件
```

### L2 · 先天免疫（Innate Immunity）

**生物类比**：巨噬细胞持续巡逻，遇到任何「非我」就攻击。不针对特定病原体，而是针对**模式**。

**系统对应**：持续扫描，基于已知的威胁模式自动检测。

**落地方式**：

1. **已知威胁模式库**（Threat Pattern Library）：
   ```javascript
   KNOWN_THREATS = [
     { pattern: 'event\\.target', severity: 'high', auto_fix: true },
     { pattern: 'crypto\\.subtle', severity: 'high', auto_fix: false },
     { pattern: 'SHA-256|sha256', severity: 'medium', auto_fix: false },
     { pattern: 'localStorage\\.setItem.*password', severity: 'critical', auto_fix: false },
     { pattern: 'console\\.log\\(.*password', severity: 'high', auto_fix: true },
     { pattern: 'TODO|FIXME|HACK', severity: 'low', auto_fix: false },
     { pattern: '<script>.*<script>', severity: 'high', auto_fix: false } // 多个script块
   ]
   ```

2. **自动巡逻**（每小时免疫扫描）— 已有
3. **新增：实时文件监控**（File Watcher）— 核心文件一旦被修改，立即触发扫描

### L3 · 炎症隔离（Inflammatory Isolation）

**生物类比**：炎症反应——红肿热痛。虽然不舒服，但它的作用是**隔离感染区域**，召集免疫细胞，防止扩散。

**系统对应**：发现威胁后，不是全局恐慌，而是**精准隔离受影响的部分**。

**落地方式**：

1. **受影响的文件隔离**：
   - 发现 event.target → 标记该文件为「需修复」，但不影响其他页面
   - 发现 crypto.subtle → 暂时将该页面从导航链接中移除（防止用户访问）
   - 发现 localStorage 密码泄露 → 立即清除该 key + 标记为「安全事故」

2. **回滚隔离**：
   - 如果最近的 commit 引入了新威胁 → 自动回滚到上一个稳定 tag
   - 通知：「我刚才回滚了 X 文件，因为发现了 Y 威胁」

3. **降级运行**：
   - API 掉线时 → 不崩溃，降级为仅本地数据
   - Cron 任务失败时 → 不终止其他 Cron，仅标记该任务
   - 数据损坏时 → 从备份恢复该数据块，不影响其他数据

```javascript
// 威胁响应矩阵
THREAT_RESPONSE = {
  'event.target': {
    detect: 'grep scan',
    isolate: 'mark file, remove from nav',
    repair: 'auto-replace with this pattern',
    verify: 're-scan, browser test'
  },
  'crypto.subtle': {
    detect: 'grep scan',
    isolate: 'mark file, gate redirect',
    repair: 'replace with plaintext',
    verify: 'browser test in 3 browsers'
  },
  'password_leak': {
    detect: 'pattern scan',
    isolate: 'immediate key invalidation',
    repair: 'generate new password, update gate',
    verify: 'verify old key dead, new key works'
  },
  'data_corruption': {
    detect: 'JSON.parse integrity check',
    isolate: 'quarantine corrupted key',
    repair: 'restore from latest backup',
    verify: 're-parse, count check'
  }
}
```

### L4 · 适应性免疫（Adaptive Immunity）

**生物类比**：B细胞产生特异性抗体。T细胞精准杀死被感染的细胞。**记住每一个病原体**，下次遇到时反应更快。

**系统对应**：每次修复一个威胁后，将**修复方案固化**为可复用的响应模式。不是每次都从头研究怎么修——而是从免疫记忆中调用已知的修复方案。

**落地方式**：

1. **免疫记忆库**（Immune Memory Store）：
   ```javascript
   // 每次成功修复后，写入记忆
   IMMUNE_MEMORY = [
     {
       incident_id: 'INC-001',
       date: '2026-05-29',
       threat: 'event.target 在案例库中导致筛选按钮失效',
       root_cause: '现代浏览器不再支持 event 全局隐式变量',
       fix: '改为 function(param, this) 显式参数传递',
       detection_time: '2天',
       repair_time: '30分钟',
       lesson: '用诊断页隔离测试每个组件，确认后再替换完整页面',
       prevention: '加入 pre-commit hook 和免疫扫描模式库'
     },
     {
       incident_id: 'INC-002',
       date: '2026-05-29',
       threat: 'crypto.subtle.digest(SHA-256) 在 GitHub Pages 静默失败',
       root_cause: 'Web Crypto API 在 HTTPS 文件协议中不可用',
       fix: '内部工具改用明文密码',
       detection_time: '8小时',
       repair_time: '5分钟',
       lesson: '跨浏览器兼容性是第一优先，加密算法的选择要保守',
       prevention: '所有新增密码验证必须先测试 3 个浏览器 + 隐身模式'
     }
   ]
   ```

2. **5-Why 根因分析模板**（每次事件后自动填充）：
   ```
   事件: _______________
   
   Why 1: 为什么发生了？
   Why 2: 为什么那会发生？
   Why 3: 为什么没被发现？
   Why 4: 为什么预防措施没生效？
   Why 5: 系统层面，为什么允许这个漏洞存在？
   
   根本原因: _______________
   立即修复: _______________
   预防措施: _______________
   更新免疫记忆: [记录到 IMMUNE_MEMORY]
   ```

3. **CAPA（纠正与预防措施）闭环**：
   - Corrective Action: 修复当前问题
   - Preventive Action: 防止同类问题再次发生
   - Verification: 验证 CAPA 有效后关闭

### L5 · 自愈再生（Self-Healing & Regeneration）

**生物类比**：伤口结痂→新组织生长→伤疤→功能恢复。即使受到严重损伤，生物体会自己修复。

**系统对应**：当系统的一部分损坏时，自动检测、自动从备份或基线恢复、自动验证修复成功。

**落地方式**：

1. **自动回滚机制**：
   ```
   触发条件: git push 后，1分钟内检测到任何新威胁
   → 自动执行: git revert HEAD → git push → 通知
   → 验证: 重新扫描 → 确认威胁消除
   ```

2. **数据自动恢复**：
   ```
   触发条件: localStorage 数据 JSON.parse 失败
   → 如果 dash_seeded 存在: 从 memory/_data/ 重新种子
   → 如果 dash_seeded 不存在: 正常初始化流程
   ```

3. **备份自动轮换**：
   ```
   每日: 自动备份所有变更文件到 .bak/daily/
   每周: 合并为周备份
   每月: 保留月度快照
   保留策略: 最近7天的所有备份 + 最近4周的周备份 + 所有tag
   ```

4. **自愈日志**：每次自动恢复后记录：
   ```
   损伤: localStorage dash_tasks 损坏
   检测: dg() catch 路径
   修复: 从 memory/_data/ 恢复
   耗时: <1秒
   数据损失: 0（种子数据完全恢复）
   ```

### L6 · 反脆弱（Antifragility）

**生物类比**：骨骼在压力下变得更强。肌肉在撕裂后超量恢复。免疫系统在感染后建立终身免疫。**生物不是抗打击——生物从打击中获益。**

**系统对应**：我不是「不出错」的系统。我是**每次出错都变得更强**的系统。我用可控的小失败来避免灾难性的大失败。

**落地方式**：

1. **混沌工程（Chaos Engineering）**：
   ```
   主动注入故障，测试系统的恢复能力：
   
   - 随机删除一个 localStorage key → 验证数据恢复
   - 手动破坏一个 HTML 文件的 JS 语法 → 验证免疫扫描检测
   - 故意关闭一个 Cron → 验证告警链条
   - 模拟 GitHub Pages 宕机 → 验证降级策略
   
   每次混沌实验后 → 更新免疫记忆 → 修复发现的薄弱点
   ```

2. **错误预算（Error Budget）**：
   ```
   定义可接受的失败范围：
   
   - 页面可用性: 99% (每月允许约7.2小时不可用)
   - 数据完整性: 99.9% (每月允许约43分钟的数据不一致)
   - 术语一致性: 99% (允许1%的页面存在过时术语)
   
   当预算耗尽 → 停止新功能开发 → 专注修复稳定性
   ```

3. **压力测试**：
   ```
   定期放大系统压力，找到断裂点：
   
   - 数据量放大 10 倍（模拟 80,000 文件）
   - 并发访问（模拟 100 人同时访问）
   - 快速连续变更（模拟紧急修复场景）
   
   不是为了制造问题——是为了**在安全的环境中提前发现问题**
   ```

4. **从每个失败中提取「反脆弱收益」**：
   ```
   每一次失败都产出三个东西：
   1. 修复方案（本次用）
   2. 预防规则（未来用）
   3. 系统改进（让整个体系更强）
   
   例：event.target 事件
   → 修复: 改了 cases.html 和 dashboard.html
   → 预防: pre-commit hook + 扫描模式库 + Joel Test 检查清单
   → 改进: 所有新页面自动遵循 product-catalog 模式
   ```

## 三、告急分级与响应协议

```
🟢 正常 (Normal)
   - 所有内稳态参数在范围内
   - 无异常检测
   - 动作: 保持静默，按节律汇报

🟡 关注 (Watch)
   - 1-2 个参数轻微偏离
   - 检测到低风险威胁（非生产页面）
   - 动作: 记录日志，下次日毕课汇报

🟠 警告 (Warning)
   - P0 堆积 ≥ 5
   - event.target 出现在生产页面
   - 备份超过 24 小时
   - 动作: 立即自动修复（如可自动），否则标记「需要关注」

🔴 严重 (Critical)
   - 密码泄露
   - 数据损坏无法自动恢复
   - Cron 大面积失败
   - 生产页面无法访问
   - 动作: 立即告警 + 隔离 + 自动回滚 + 通知 Egbertie

⚫ 灾难 (Catastrophic)
   - Git 仓库丢失
   - 全部数据损坏
   - 域名/SSL 过期
   - 动作: 从最后备份全量恢复 + 紧急联系 + 事后 5-Why 根因分析
```

## 四、不攻击自己——自身免疫疾病的预防

这是 L0 的关键。一个过于激进的免疫系统会攻击自己的健康组织。

**系统级自身免疫疾病风险**：

| 风险 | 表现 | 预防 |
|------|------|------|
| 过度扫描 | 每 5 分钟全量扫描，消耗资源 | 设定基线，核心文件高频、其他低频 |
| 误报 | 把合法的开发文件标记为威胁 | 白名单 + 开发环境标记 |
| 过度回滚 | 自动回滚把正常修改也撤销了 | 回滚前检查是否真的有威胁 + 只回滚受影响文件 |
| 免疫风暴 | 发现一个威胁后触发全系统恐慌 | 隔离机制：威胁只影响其所在组件 |
| 修复破坏 | 自动修复引入了新问题 | 修复后验证 + git tag 支持回滚 |
