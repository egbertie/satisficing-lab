# 恶化预警·根因分析报告

> 问题: 免疫系统每小时检测，150+次检测，0次修复——告警复读机
> 蓝色审计发现: Detection-Remediation回路断裂（6/2 连续5天）
> 根因分析: Toyota 5-Why深入

---

## 5-Why根因追溯

### Why 1: 为什么已知异常没有被修复？
因为每次免疫自检都输出"已知异常·非新增威胁·生命体征稳定"。系统看到但不行动。

### Why 2: 为什么系统"看到但不行动"？
因为免疫自检没有给每个异常指定修复Owner(DACI-D)。没有Owner的事 = 所有人的事 = 没有人做的事。

### Why 3: 为什么没有指定DACI-D？
因为免疫系统的设计只到了"检测"层，没有建"修复"层。这是一个设计缺陷——不是执行失误。

### Why 4: 为什么设计只到检测层？
因为在设计免疫架构（七层免疫·5/30）时，L4自适应免疫和L5自愈再生被标记为"Phase 2"——一个永远不到来的阶段。

### Why 5: 为什么Phase 2永远不来？
因为系统的优先级排序机制偏向"新创造" >> "修复旧问题"。新创造有明确的胜利感（完成一个新功能），修复旧问题没有。

**根因**: 系统缺乏"修复预算"机制——没有把修复时间作为强制分配的资源。新创造永远优先于修复。

## 彻底解决方案

### 方案A: 自动修复引擎（首选）

给每个已知异常类型建一个**自动修复脚本**。当检测到异常，自动尝试修复（而非仅仅报告）。只有无法自动修复的才升级为人工任务。

| 异常类型 | 检测方法 | 自动修复脚本 | 当前状态 |
|------|------|------|:--:|
| event.target残留 | `grep "event.target" site/*.html` | `sed -i '' 's/event.target/btn/g'` | ✅ 已清零 |
| crypto.subtle残留 | `grep "crypto" site/*.html` | 豁免判定(密码页)或替换 | ✅ 已清零 |
| SHA-256残留 | `grep "SHA-256" site/*.html` | 豁免或替换为明文 | ✅ 已清零 |
| 24h内无备份 | 检查.bak/时间戳 | 自动触发tar czf备份 | 🔴 待建 |
| 文化密码缺失 | `grep -L "五维相生"` | 自动在</body>前插入 | ✅ 已建 |
| 反馈组件缺失 | `grep -L "反馈"` | 自动插入反馈块 | ✅ 已建 |
| 品牌残留"满意红" | `grep "满意红"` | 自动替换 | ✅ 已建 |
| 缺失返回链接 | `grep -L "go.html"` | 自动插入返回链接 | 🔴 待建 |
| 死链 | 链接→文件检查 | 标注·不自动删(可能误判) | 🟡 需人工 |
| 双副本不同步 | 文件大小对比 | 自动cp site→satisficing-lab | ✅ 已通过smart-git-push实现 |

### 方案B: 修复预算制度

每天分配"修复预时间"——在所有新创造之前，先处理已知异常。
规则: 任一天前5个操作中必须有1个是修复操作。

### 方案C: 72h自动升级

已知异常 > 72h未修复 → P2→P0 → 强制中断当前工作 → 先修复再继续。
