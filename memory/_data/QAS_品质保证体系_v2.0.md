## 零 · 品质哲学

传统QA教条: "测试是为了找bug"。

满意解研究所的品质哲学:

**品质 = 在用户发现问题之前，系统已经自己发现并修复了问题。**

这来自两个核心洞察:
1. 5天150+次检测·0次修复 = 告警复读机 ≠ 品质体系（蓝军审计·6/2）
2. 不是"不出错"——是"出错后能在用户感知之前恢复"（七层免疫·5/30）

## 一 · 品质维度 · 八维借鉴ISO 25010

ISO 25010定义8个软件产品质量特性。满意解研究所将其映射到静态站点的具体检查项:

| ISO 25010 特性 | 满意解研究所映射 | 核心检查 | 血泪来源 |
|------|------|------|------|
| 功能适用性 | L2·功能性 | 死链·JS可执行·返回导航 | 5/28 event.target失效 |
| 性能效率 | L1·结构+加载 | 纯静态·无外部API·秒开 | 302→0外部依赖 |
| 兼容性 | L4·可访问性 | lang·charset·viewport·@media | — |
| 可用性 | L5·用户体验 | 页面可渲染·导航层级·移动响应 | 产品目录过期数据(5/28→未更新) |
| 可靠性 | L2·双副本+备份 | site↔satisficing-lab同步·备份验证 | 6/2发现vi_quick_ref.css缺失 |
| 安全性 | L3·输入安全 | 无明文密码·无eval·gate-check | crypto.subtle静默失败(5/28) |
| 可维护性 | L1·结构完整性 | DOCTYPE·HTML闭合·外部依赖 | innerHTML重建DOM(5/28) |
| 可移植性 | L2·数据一致性 | entities_index必填字段·双副本 | 产品目录硬编码217→327 |

ISO 25010还有5个"使用质量"特性——有效性、效率、满意度、抗风险、语境覆盖。这些映射到我们的人工测试层(L5-UX)。

## 二 · 从血泪经验中提炼的7条工程铁律

### 铁律1: 永远不要依赖event全局变量
**事件**: 5/28-29 驾驶舱·案例库联动 · 子代理15h调试无果
**教训**: Chrome/Safari严格模式不再支持隐式`event`
**规则**: 所有onclick必须传`this`参数。`function handler(id, btn)`而非`function handler(id)` + `event.target`
**检测**: `grep -rn 'event\.target|event\.currentTarget' site/*.html`
**状态**: ✅ 已清零(site/中0残留)

### 铁律2: 内部页面禁用Web Crypto API
**事件**: gate.html密码验证·GitHub Pages上静默失败
**教训**: `crypto.subtle`在不同环境行为不一致
**规则**: 内部工具明文比对·不依赖加密API
**检测**: `grep -rn 'crypto\.subtle|SHA-256' site/*.html`
**状态**: ✅ 已清零(4个残留dashboard已归档到.bak)

### 铁律3: 一个HTML文件只有一个核心script块
**事件**: innerHTML重建DOM后旧函数找不到新元素
**教训**: 多script块互相干扰
**规则**: 所有JS写在一个`<script>`标签中·HTML结构直接写在body里
**检测**: 每个文件检查`<script>`标签数量
**状态**: ✅ 全部符合

### 铁律4: 删除旧代码和新增代码同等重要
**事件**: 6/1 admin-windows 30KB废弃v2代码 = 债务
**教训**: 遗留代码不是"保守"——在每次发布中都会触发验证检查
**规则**: 每次重构必须有"清理清单"·删除旧函数·归档废弃文件
**检测**: 对比当前版本和上一版本的函数数量

### 铁律5: 数据源必须单一
**事件**: product-catalog.html硬编码217产品(5/28)·实际327件·信息断裂
**教训**: 零硬编码是架构纪律
**规则**: 所有面板共享entities_index.json·用fetch动态加载
**检测**: `grep -rn 'const.*data' site/*.html` 检查是否有硬编码数据

### 铁律6: 外部依赖必须本地验证
**事件**: vi_quick_ref.css被217文件引用但在site/中缺失
**教训**: 依赖只需要在一处失败就能让217个页面崩溃
**规则**: 所有`<script src>`和`<link href>`由Cron自动验证可达性
**检测**: L1-03 外部依赖扫描(每小时Cron)

### 铁律7: 品牌绝不能留下旧名称
**事件**: 116页含"满意红"残留·三轮清理才清零
**教训**: 品牌改名需要系统性的追踪替换
**规则**: 每次提交前brand检查·QAT L3-01自动扫描·发现即阻止提交
**检测**: `grep -c "满意红" site/*.html` 必须为0

## 六 · 反模式升级：品质相关

从内部血泪经验提炼的品质反模式：

| 反模式 | 触发条件 | 对应铁律 |
|------|------|:--:|
| 🚫 event隐式依赖 | 任何JS中使用event.target | 铁律1 |
| 🚫 Web Crypto内部使用 | crypto.subtle·SHA-256在内部页面 | 铁律2 |
| 🚫 多script块互扰 | 一个文件>1个`<script>`标签 | 铁律3 |
| 🚫 只增不删重构 | 新function替代旧·旧的不删除 | 铁律4 |
| 🚫 硬编码数据孤岛 | const data = [...] 大数组 | 铁律5 |
| 🚫 外部依赖未经检查 | src/href指向不存在的文件 | 铁律6 |
| 🚫 品牌名称残留 | 全局搜索"满意红"非零 | 铁律7 |
| 🚫 检测不修复 | 已知异常>72h | P0升级 |
