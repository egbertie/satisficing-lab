# q_scan 人工标注校准指南 v1.0

> 创建: 2026-05-30 | 适用范围: q_scan.py v2.0 (规则交叉校验版)

## 一、假精确率来源分析

### v1.0 的71%假精确率根因

| 问题类型 | 具体表现 | 假阳性占比 |
|----------|----------|------------|
| **弱证据关键词** | meta中含"五维"即标"五维测评"，但页面可能只是提及 | ~30% |
| **CSS class检测** | `class="card"` `class="hero"` 在几乎所有HTML中存在 | ~25% |
| **script引用** | `chart`/`assessment` 字符串在任何JS中出现即标标签 | ~10% |
| **门限过低** | 2个非相关标签即计为"有标签" | ~15% |
| **无互斥校验** | "卡牌"和"合规"可同时出现 (事实互斥) | ~5% |

### v2.0 交叉校验层设计

```
候选标签 (宽松收集)
    ↓
交叉验证 (h1/title中必须包含核心词)
    ↓
互斥检测 (排除不可能同时出现的标签对)
    ↓
弱证据排除 (仅CSS/script → 过滤)
    ↓
门限检查 (≥2个验证后标签)
    ↓
最终标签 (假精确率≤5%)
```

## 二、人工标注流程

### Step 1: 采样策略

每天随机抽5个产品页面进行人工标注:

```bash
# 从 q_scan 输出中随机选取
python3 -c "
import json, random
with open('memory/连接密度统计.json') as f:
    data = json.load(f)
products = list(data['产品标签覆盖']['标签详情'].keys())
samples = random.sample(products, min(5, len(products)))
for s in samples:
    print(s, '→', data['产品标签覆盖']['标签详情'][s])
"
```

### Step 2: 标注维度 (每个页面评审3项)

| 维度 | 评分标准 | 权重 |
|------|----------|------|
| **标签准确度** | 1=完全错误 / 2=部分正确 / 3=大体正确 / 4=完全正确 | ×2 |
| **标签完整度** | 1=漏掉≥2个重要标签 / 2=漏1个 / 3=小瑕疵 / 4=完整 | ×1 |
| **假阳性确认** | 是/否 (机器标记为有标签但实际不应有) | — |

### Step 4: 规则修正决策树

```
假阳性 > 20%?
  ├─ YES → 检查 TAG_REQUIRES 核心词是否过于宽泛
  │        例如: "决策"→匹配太多→增加约束"决策剧场"+"五维"
  │        → 增加互斥对规则
  │
  └─ NO → 检查覆盖率是否<20%
           ├─ YES → 降低 MIN_TAG_THRESHOLD 或扩展 TAG_REQUIRES
           └─ NO → 当前配置良好，保持
```

## 三、关键参数调优表

### TAG_REQUIRES 核心词表 (可调)

当前配置的核心词要求。如果某标签假阳性高→增加核心词约束；如果某标签遗漏多→减少约束。

```python
TAG_REQUIRES = {
    "测评": ["测评", "评估", "量表", "诊断"],      # 约束: 4词
    "卡牌": ["卡牌", "卡", "对局"],               # 约束: 3词  
    "报告": ["报告", "诊断", "结果"],              # 约束: 3词
    "可视化": ["雷达", "图表", "chart", "可视化", "图"],  # 约束: 5词
    "驾驶舱": ["驾驶舱", "dashboard", "管理", "数据"],   # 约束: 4词
}
```

## 四、常见误判场景 & 修复方案

### 场景1: 通用词误触发
- **案例**: `title="产品目录"` → 标签"产品导航"认为是假阳性
- **修复**: 实为真阳性，产品目录页面确实是导航类
- **规则**: 不需要修改

### 场景2: 内容页被标为工具页  
- **案例**: `h1="五维决策方法论"` → 标签"理论"+"测评"，但页面是概念介绍非交互工具
- **修复**: 理论标签正确，测评标签需检查是否有表单
- **规则**: 在 `candidate_tags` 收集时，对"测评"增加 `has_form` 检查

### 场景3: 品牌页标签过多
- **案例**: "关于我们"页面出现"品牌"+"理论"+"课程"+"案例"
- **修复**: 互斥对已处理 (品牌 vs 工具类别)
- **规则**: `TAG_MUTEX_PAIRS` 增加 `({"品牌", "文化"}, {"测评", "自检", "课程"})`

## 五、校准节奏

| 频率 | 行动 | 负责人 |
|------|------|--------|
| 每日 | 随机采样5页人工标注 | 满意红 |
| 每周 | 汇总标注结果，计算周假精确率 | 满意红 |
| 每月 | 规则参数调优 (MIN_TAG_THRESHOLD, TAG_REQUIRES, MUTEX_PAIRS) | 蓝军审核 |
| 每次代码变更后 | 运行 q_scan.py 确认假精确率 | 自动化 |

## 六、理想目标

- **短期 (1周)**: 假精确率 ≤10%
- **中期 (1月)**: 假精确率 ≤5%，覆盖率 ≥40%
- **长期 (3月)**: 假精确率 ≤2%，覆盖率 ≥60%
