#### 2. 🤖 Build agents, not pipelines (146 likes)
**来源**: seangoedecke.com | Sean Goedecke | 2026-05-31

**核心命题**: LLM 在程序中的使用只有两种范式——Pipeline vs Agent
- **Pipeline**: 代码控制流为主，LLM 只做单次推理 → 可预测、成本可控，但上下文收集极难
- **Agent**: LLM 管理控制流 → 更智能、更灵活，但时延和成本不可预测（2x到100x波动）
- 关键洞察：RAG 在 2023-24 年被寄予厚望但失败了——"找什么信息是相关的"本身和解决问题一样难
- 多模型 Pipeline（cheap model 预处理 → smart model 决策）往往损失了raw data中的信号
- 结论：**复杂任务必须用 Agent**（coding agent 不可能用 pipeline 实现），但简单务实的任务 Pipeline 更划算

**对我们的意义**:
- 满意红子代理本质是 Agent 模式，符合"复杂任务必须 agent"的判断
- 警惕 pipeline 上下文收集的陷阱（这正是我们案例中反复遇到的前端调试问题）
- RAG 失败教训 → 确认我们的语义+关键词混合检索策略是务实选择
- 多模型 pipeline 的批评 → 考虑是否统一使用 deepseek-v4-pro 而非分级
