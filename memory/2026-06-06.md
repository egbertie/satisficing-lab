## 🚀 腾讯云 CVM 部署 (全程 21:00–23:05)

### 背景
用户购买了腾讯云 CVM 服务器 (ins-h3yc7m0w, IP 101.33.219.144)，要求将满意解研究所部署到云端。原则：不经过 GitHub，全部腾讯云自给自足，发掘最大能力。

### 部署过程
1. **项目同步**：rsync 从本地 Mac 同步 314 文件 (898MB) 到数据盘 /mnt/datadisk0/satisficing-lab/
2. **生产环境**：dnf 安装 Git/Nginx/Python3-pip → pip3 安装 Flask/Flask-CORS/Gunicorn
3. **Gunicorn**：2 workers 替代 Flask dev server，systemd 守护
4. **Nginx**：反向代理 /api/ → 127.0.0.1:5050，静态文件根，安全头
5. **安全加固**：SSH 仅密钥·禁密码 · iptables policy DROP 仅开 22/80/443/ICMP
6. **环境变量**：飞书Secret 从 config.py 明文移入 /etc/sriserver/env (600)
7. **备份体系**：/usr/local/bin/sri-backup.sh · 每日3点tar备份 · 7天保留 · 配置文件备份
8. **云端Cron**：5条定时任务 (备份/健康/清理/监控/轮转)
9. **日志管理**：logrotate 每日轮转 · 7天保留 · 压缩

### 遇到的6个坑
1. macOS tar 打包后解压失败 → 改用 rsync
2. 文件权限 700 → Nginx 403 → chmod -R a+rX
3. config.py PORT=5000 vs Nginx 5050 → 统一为5050
4. SSH sed 误改导致2次断连 → VNC救援 → 改用 iptables 隔离，不再动 sshd Port
5. 飞书 App Secret 提取被截断 → 从本地恢复 → 但仍 invalid，需用户确认
6. Gunicorn 找不到 app 对象 → app.py 末尾添加 `app = create_app()`

### 教训
- **绝不 sed sshd_config 的 Port 行**，端口隔离用 iptables
- **任何危险操作前保存 .orig 备份**
- **VNC 是最后救命通道**，尤其 iptables DROP 策略下
- **Cloud-init/iCloudConfig 无用的元数据** → 用 TAT 执行命令
