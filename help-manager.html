📖 手册说明

本手册是 SRI（满意解研究所）知识资产管理系统的运维参考文档。它面向系统管理员、运维工程师和运营负责人，详细描述了系统从架构到执行的每一个层面。

阅读本手册的读者应具备：

  • 基本的 Linux/macOS 命令行操作能力
  • Python 3 脚本的基本阅读能力
  • 对 Cron 定时任务的基本了解
  • JSON 数据格式的基本理解
⚠️ 重要提示：本手册描述的脚本均位于 memory/_scripts/ 目录下。所有脚本的操作对象是 memory/_data/entities_index.json（单一数据源）。请在执行任何手动操作前，确保已备份该文件。

🗄️ entities_index.json · 单一数据源

🔄 数据更新机制

Cron 定时触发 → Python 脚本执行 → 读取 entities_index.json → 执行分析/加工/修复 → 增量更新 meta 区域 → 写回 entities_index.json → 前端下次 fetch 自动呈现

所有更新均为增量写入（追加 change_log），不覆盖历史记录。遵循事件溯源 (Event Sourcing) 原则。

⚙️ 脚本层 · 18个Python引擎

所有脚本位于 memory/_scripts/ 目录下。按功能域分为六大类别。每个脚本可独立运行（python3 script.py --save），也可由编排器统一调度。

🔥 核心引擎 (2) 飞轮心脏

1. sri_knowledge_flywheel.py 飞轮主引擎

维度详情
职责知识资产飞轮的五层循环引擎：扫描新增文件 → 检测过时实体 → 重新排序 → LLM评分缺口 → 健康自检
输入entities_index.json、扫描路径 (site/ 和 memory/)
输出更新 entities_index.json 的 meta.flywheel 区域；追加 change_log
五循环scan() 扫描新文件 → stale() 检测过时(>7天) → rerank() 重排序 → llm() LLM缺口补齐 → health() 飞轮健康自检
Cron每4小时触发一次（扫描/健康自检/LLM缺口各有独立Cron）
容量设计Phase 0: 单JSON单进程 → Phase 1: 分片JSON多进程 → Phase 2: Bitable后端API → Phase 3: 独立后端 + 脚本演化为orchestrator
健壮性每个方法独立 fitness function；事件溯源(change_log)；不依赖外部服务；绞杀者模式演进

2. sri_orchestrator.py 闭环编排引擎

维度详情
职责15环节闭环编排：将扫描、检测、修复、评分、化学反应、控制论、反脆弱等环节串行为一个完整的大循环
输入entities_index.json + 各个子脚本的调用
输出更新 meta.orchestration_health；每个环节的健康分、熔断状态、成功率
三大机制Circuit Breaker: 任一步骤连续失败3次 → 熔断 → 跳过该环节继续
Bulkhead: 每个环节独立timeout和错误计数
Graceful Degradation: 一个环节熔断不影响其他
15环节文件扫描 → 过时检测 → 一致性检查 → 自动修复 → 养料采集 → 质量门禁 → 标准迭代 → 产品审计 → 生命周期管理 → 组合优化 → 化学引擎 → 化学调控 → VSM审计 → 二阶观察 → 自校准 → 反脆弱训练 → 永续控制
Cron每6小时触发一次完整编排

⚗️ 化学引擎 (3) 化学反应层

3. sri_chemistry_reactor.py 化学反应引擎

维度详情
职责实现60条化学反应链。把产品从被动管理的「物理状态」转化为主动演化的「化学状态」——产品之间产生催化、抑制、合成、裂解等动态关系
输入产品列表、连接图、heating状态
输出更新 meta.chemistry：反应链状态、热力追踪、活化能、催化剂分布
核心概念活化能: 产品被「激活」所需的最低能量阈值
催化剂: 加速反应的产品/事件
热力追踪: 每条反应链的实时温度和反应速率
60链: 9条基础反应链 × 多维度组合
Cron每2小时触发

4. sri_chemical_governor.py 化学调控引擎

维度详情
职责给60条反应链加上负反馈机制。不是增加更多反应链——是给已有的链加上调控、自清理和自休眠能力
输入化学反应引擎的输出 + heating快照
输出热力过高的链自动降温；低活性链标记休眠；清理反应副产物
核心功能负反馈: 检测到热力过高 → 降低活化能注入
自清理: 清除已完成/冗余反应链
自休眠: 持续低活性的链自动休眠（保留，不删除）
Cron每2小时触发（与reactor交替）

5. sri_perpetual_control.py 永续自调控

维度详情
职责基于第二阶控制论，实现无需人工干预的永续自调控。系统观察自身、调整自身、学习自身。
输入所有meta区域的当前快照
输出更新 meta.perpetual_control：设定点集合、调控轨迹、自评报告
核心原理系统不仅观察环境（第一阶），也观察自己的观察方式（第二阶）。通过二阶反馈实现真正的自适应——不依赖外部规则。
Cron每8小时触发

🔄 三层闭环架构

SRI系统的自愈和自调控能力通过三层闭环实现。每一层有独立的故障域和恢复机制。

🟢 微循环 毛细血管

范围：每个Python脚本内部的 try/except 块
机制：单次执行失败 → 记录错误日志 → 返回fallback结果（不中断整个脚本）
示例：flywheel扫描某个文件失败 → 跳过该文件 → 继续扫描下一个
保护：每个方法有独立的fitness function；异常不影响其他方法

🟡 中循环 血管

范围：独立脚本级别的自愈和异常隔离
机制：脚本执行失败 → 独立自愈逻辑 → 异常隔离（不传播到其他脚本）→ 优雅降级
示例：consistency_checker失败 → auto_healer使用上次缓存结果 → 等待下一轮重新检测
保护：Bulkhead模式：每个脚本有独立的错误计数和恢复窗口

🔴 大循环 大动脉

范围：15环节编排器全局控制
机制：编排器串行调度 → Circuit Breaker（连续3次失败熔断）→ 跳过故障环节继续 → 全局健康分汇总
15环节链路：文件扫描 → 过时检测 → 一致性检查 → 自动修复 → 养料采集 → 质量门禁 → 标准迭代 → 产品审计 → 生命周期管理 → 组合优化 → 化学引擎 → 化学调控 → VSM审计 → 二阶观察 → 自校准 → 反脆弱训练 → 永续控制
保护：每个环节独立timeout；全局健康分低于阈值时触发告警

🔴 大循环熔断规则：任何环节连续3次执行失败 → Circuit Breaker 打开（熔断）→ 该环节在接下来3个调度周期中被跳过 → 3个周期后自动尝试恢复（半开状态）→ 成功则关闭熔断器，失败则继续保持熔断。

🩺 处理异常

  1. 查看编排器健康：打开管理窗口或运行编排器健康查询命令，找到健康分低于阈值的环节
  2. 定位故障环节：查看每个环节的成功率、最近错误日志、熔断状态
  3. 判断故障类型：
    • 数据问题（如文件缺失）→ 可手动补充数据
    • 逻辑问题（如脚本bug）→ 查看错误traceback
    • 资源问题（如超时）→ 增加timeout或优化脚本
  4. 选择修复方式：
    • 等待自愈：系统会在下一调度周期自动重试
    • 手动修复：运行对应脚本的 --save 命令
    • 重置熔断器：修改 meta.orchestration_health 中对应环节的熔断计数
  5. 验证恢复：等待下一轮编排器运行或手动触发，确认环节健康分回升

🆘 常见运维场景

🚨 场景一：编排器报警了怎么办

  1. 查看健康仪表盘：打开 admin-windows.html → 编排器健康面板，找到红色/黄色标记的环节
  2. 分类处理：
    • 熔断状态：该环节已连续失败3次。检查错误日志 → 修复根因 → 等待自动恢复（3个周期后自动尝试）或手动重置熔断器
    • 成功率骤降：环节还在运行但成功率下降。查看该脚本的输出日志，可能存在数据质量问题
    • 超时频发：环节耗时超过timeout。检查数据量是否过大或是否有死循环
  3. 快速修复命令： 
    # 手动重置特定环节的熔断器（以consistency为例）
python3 -c "
import json
with open('memory/_data/entities_index.json') as f:
    d = json.load(f)
oh = d['meta']['orchestration_health']
for step in oh.get('steps', []):
    if 'consistency' in step.get('name', ''):
        step['failures'] = 0
        step['breaker_open'] = False
with open('memory/_data/entities_index.json', 'w') as f:
    json.dump(d, f, indent=2, ensure_ascii=False)
print('Circuit breaker reset for consistency')
"
  4. 等待下一轮编排验证：Cron每6小时触发，或手动运行 python3 memory/_scripts/sri_orchestrator.py --save

🔥 场景二：化学热力过高怎么办

⏱️ 场景三：Cron任务超时了怎么排查

📚 术语速查

术语定义
SRI满意解研究所 (Satisfactory Resolution Institute)。整个系统的组织身份。
飞轮 (Flywheel)五层循环引擎：scan → stale → rerank → llm → health。系统的心脏。
编排器 (Orchestrator)15环节闭环编排引擎。负责串行调度所有子系统并管理熔断。
化学反应 (Chemistry)产品之间的动态关系：催化、抑制、合成、裂解。60条反应链。
热力 (Heating)化学反应链的活跃程度指标。过热时需要化学调控降温。
活化能 (Activation Energy)产品被"激活"所需的最低能量阈值。
催化剂 (Catalyst)加速反应但不被消耗的产品/事件。
VSMViable System Model（可行系统模型）。Stafford Beer的组织控制论模型。
System 5VSM的最高层——负责战略方向、身份定义和终极治理。
二阶观察 (Second-Order)控制论概念：不仅观察系统，还观察系统如何观察。构建自我模型。
永续控制 (Perpetual Control)基于二阶控制论的自调控系统。不需要外部干预即可维持稳定。
反脆弱 (Antifragile)Nassim Taleb概念：系统不仅抗压，还能从压力中获益变强。
GABA阶梯反脆弱训练中的渐进式压力递增策略。
Circuit Breaker熔断器模式。连续失败N次后自动跳过该环节。
Bulkhead舱壁隔离模式。每个环节有独立的错误域。
JTBDJobs-to-be-Done。客户视角的产品分类框架。
Stage-Gate产品生命周期管理模型。每个阶段有准入/退出条件。
CODECapture→Organize→Distill→Express。Tiago Forte的知识管理框架。
TOCTheory of Constraints（约束理论）。Goldratt的瓶颈管理五步法。
养料 (Nourishment)从外部采集的知识原材料。经质量门禁过滤后注入系统。
实体 (Entity)系统中的基本数据单元：产品、客户、文档、任务等。
连接 (Connection)实体之间的关系边。当前12,556条。
替身 (Avatar)31个角色化的AI代理。用于LLM批量评分等场景。
设定点 (Set Point)自校准系统中的目标值。
漂移 (Drift)系统指标偏离目标值的趋势。
事件溯源 (Event Sourcing)每次写入追加change_log而非覆盖。
绞杀者模式 (Strangler Fig)演进式架构：在旧系统旁构建新功能，逐步替换。
